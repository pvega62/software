क्लाउड ऐप लॉग्स को एक पाइपलाइन में रूट करें

यह गाइड एक क्लाउड ऐप से एक JSON लॉग को Datadog Log Ingestion API पर भेजती है। इसके बाद आप Log Explorer में इवेंट को ट्रैक करते हैं और उसे किसी डेस्टिनेशन पर रूट करते हैं।

रूट करने से पहले इनजेस्टीशन सत्यापित करें​

पहले इनजेस्टीशन पाथ सत्यापित करें। इवेंट पहुँचने की पुष्टि के बाद ही पार्सिंग नियम बनाएँ या डेटा को महँगे सुरक्षा सूचना और घटना प्रबंधन (SIEM) टूल्स पर रूट करें। यह वर्कफ़्लो तीन बातों की पुष्टि करता है:

  1. आपकी Datadog API कुंजी प्रमाणीकरण करती है।
  2. Log Ingestion API आपकी JSON सरणी स्वीकार करती है।
  3. इवेंट Log Explorer में दिखाई देता है।

शुरू करने से पहले​

सुनिश्चित करें कि आपके पास ये हैं:

  • एक Datadog API कुंजी जिसके पास लॉग इनजेस्टीशन अनुमतियाँ हों। इसे Organization Settings → API Keys में खोजें।
  • आपका Datadog साइट पता, जैसे datadoghq.com या ap2.datadoghq.com.
  • टर्मिनल एक्सेस curl चलाने के लिए, या Postman.

1. एक इंडेक्स बनाएँ या चुनें​

  1. Logs > Configuration > Indexes पर जाएँ।
  2. Add Index चुनें, या वह इंडेक्स चुनें जो आपके क्लाउड ऐप लॉग्स को संग्रहीत करता है।
  3. इंडेक्स का नाम app-logs रखें।
  4. वह रिटेंशन अवधि सेट करें जिसकी आपकी अनुपालन नीति माँग करती है।

2. एक नमूना लॉग इवेंट बनाएँ​

निम्नलिखित सरणी को app-log.json के रूप में सहेजकर एक क्लाउड ऐप लॉग का अनुकरण करें।

app-log.json
[
  {
    "message": "Transaction failed: Gateway timeout",
    "ddsource": "java",
    "ddtags": "env:prod,region:us-east-1",
    "hostname": "payments-host-01",
    "service": "payment-gateway",
    "status": "ERROR",
    "timestamp": "2025-11-15T08:30:00Z",
    "transaction_id": "txn_998877",
    "customer_id": "cus_554433"
  }
]
नोट

timestamp के लिए अंतर्राष्ट्रीय मानकीकरण संगठन (ISO) 8601 समन्वित सार्वत्रिक समय (UTC) प्रारूप का उपयोग करें। Datadog इस मान के साथ Log Explorer में लॉग टाइमलाइन संरेखित करता है। बिना टाइमस्टैम्प वाले लॉग इनजेस्ट समय का उपयोग करते हैं।

3. लॉग इवेंट भेजें​

curl का उपयोग करके लॉग उसी तरह भेजें जैसे ऐप भेजता है।

cURL
export DD_API_KEY="your_datadog_api_key_here"
export DD_SITE="datadoghq.com"

curl -X POST "https://http-intake.logs.$DD_SITE/api/v2/logs" \
  -H "DD-API-KEY: $DD_API_KEY" \
  -H "Content-Type: application/json" \
  -d @app-log.json

अपेक्षित प्रतिक्रिया​

प्रतिक्रिया
{}

खाली JSON बॉडी के साथ 202 Accepted प्रतिक्रिया का अर्थ है कि Log Ingestion API ने पेलोड स्वीकार कर लिया।

4. Log Explorer में अपने लॉग को सत्यापित करें​

  1. Log Explorer खोलें।
  2. service:payment-gateway पर फ़िल्टर करें।
  3. Live Tail चुनें।

इवेंट कुछ सेकंड में दिखाई देता है:

Live Tail आउटपुट
[ERROR] 2025-11-15T08:30:00Z service=payment-gateway msg="Transaction failed..."

5. लॉग्स को एक डेस्टिनेशन पर रूट करें​

ऐसी पाइपलाइन बनाएँ जो त्रुटि इवेंट से मेल खाती हो:

  1. Logs > Configuration > Pipelines पर जाएँ।
  2. New Pipeline चुनें।
  3. फ़िल्टर क्वेरी status:ERROR सेट करें।
  4. पाइपलाइन का नाम error-routing रखें।
  5. Save चुनें।

वही अनुरोध फिर से भेजें। पाइपलाइन इवेंट से मेल खाती है, इसलिए आप उस पर कार्रवाई कर सकते हैं।

  • मेल खाने वाले लॉग्स को संग्रहीत करने के लिए Logs > Configuration > Archives खोलें और अपने S3 बकेट को लक्षित करने वाला s3-archive आर्काइव बनाएँ।
  • मेल खाने वाले लॉग्स पर अलर्ट करने के लिए status:ERROR क्वेरी वाला लॉग मॉनिटर बनाएँ, फिर सूचनाओं को Slack चैनल पर रूट करें।

6. पाइपलाइन को बेहतर बनाएँ​

फ़्लो काम करने के बाद पाइपलाइन में प्रोसेसर जोड़ें:

  • Remapper customer_id को ऐसी विशेषता में ले जाता है जिस पर सहजता से फ़ैसेट और फ़िल्टर हो सके।
  • Grok Parser कच्चे message स्ट्रिंग्स से त्रुटि कोड या ट्रांज़ैक्शन आईडी निकालता है।
  • Lookup Processor service नाम से team_owner टैग जोड़ता है।
  • Sensitive Data Scanner व्यक्तिगत रूप से पहचान योग्य जानकारी (PII) होने पर customer_id को मास्क करता है।

समस्या निवारण​

समस्या / स्थिति कोडसंभावित कारण / समाधान
401 UnauthorizedDD-API-KEY हेडर जोड़ें।
403 Forbiddenसत्यापित करें कि API कुंजी के पास लॉग इनजेस्टीशन अनुमतियाँ हैं।
400 Bad Requestअपना JSON सिंटैक्स सत्यापित करें, और पेलोड को JSON सरणी के रूप में भेजें।
413 Payload Too Largeबैच को विभाजित करें, या पेलोड को Content-Encoding: gzip से संपीड़ित करें।
Log not in Log Explorerजाँचें कि कोई पाइपलाइन फ़िल्टर इवेंट को बाहर नहीं कर रहा, फिर इंडेक्स फ़िल्टर जाँचें।
Timestamp out of orderघटना के 18 घंटे के भीतर ISO 8601 UTC टाइमस्टैम्प भेजें, जैसे 2025-11-15T08:30:00Z.
