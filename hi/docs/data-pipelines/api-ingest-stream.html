डेटाडॉग लॉग इनगेस्शन API के माध्यम से इवेंट्स को भेजें

यह एंडपॉइंट संरचित एवं अर्ध-संरचित डेटा के उच्च-दक्षता वाले एवं रीयल-टाइम इनगेजमेंट का समर्थन करता है।

इस API द्वारा समर्थित कार्य:

इस API द्वारा समर्थित क्रियाएँ​

  • क्लाउड ऐप्स से डेटा सीधे भेजें, बिना Datadog एजेंट इंस्टॉल किए।
  • आने वाले डेटा पर पाइपलाइन प्रोसेसर जैसे Grok Parser, Remapper, और Lookup Processor लागू करें।
  • कंटेंट के आधार पर रूट लॉग्स को इंडेक्स, आर्काइव्स, या अलर्ट डेस्टिनेशन्स में भेजें।
  • इस एंडपॉइंट को सैंपलिंग (sampling) एवं फिल्टरिंग (filtering) नियमों के साथ जोड़कर इंडेक्सिंग लागत (indexing cost) को कम करें।

Log Ingestion API के साथ JSON लॉग इवेंट्स सीधे Datadog Log Management में भेजें। आप क्लाउड ऐप्स, माइक्रोसर्विसेज़, या किसी भी ऐसे सिस्टम से लॉग्स भेज सकते हैं जो टेलीमेट्री उत्पन्न करता है। लॉग्स कुछ ही सेकंड में Log Explorer में दिखाई देते हैं। उन्हें प्रोसेस, रूट और आर्काइव करने के लिए Log Pipelines का उपयोग करें।

नोट

क्रेडेंशियल्स (credentials) प्रबंधित करने के लिए Datadog API एवं एप्लिकेशन कुंजियों को देखें।

शुरू करने से पहले​

यह सुनिश्चित करें कि आपके पास निम्नलिखित है:

  • एक Datadog API कुंजी, जिसमें लॉग इनग्रेशन (log ingestion) के अधिकार हों। इसे Organization Settings → API Keys में खोजें।
  • आपका डेटाडॉग (Datadog) साइट पता। यह पता प्रत्येक क्षेत्र के अनुसार भिन्न होता है:
क्षेत्रसाइट पता
यूएस ईस्टdatadoghq.com
US3 Westus3.datadoghq.com
US5 Centralus5.datadoghq.com
यूरोपीय संघdatadoghq.eu
AP1 जापानap1.datadoghq.com
AP2 ऑस्ट्रेलियाap2.datadoghq.com
  • curl या Postman इंस्टॉल होना चाहिए।
  • JSON-फॉर्मेटेड लॉग पेलोड।

इनगेस्ट एंडपॉइंट​

POST https://http-intake.logs.{dd_site}/api/v2/logs

{dd_site} को अपने क्षेत्र के साइट पते से बदलें, जैसे datadoghq.com या ap2.datadoghq.com।

रिक्वेस्ट हेडर्स​

हेडरमानआवश्यकविवरण
DD-API-KEY<your_api_key>हाँआपकी डेटाडॉग API कुंजी
Content-Typeapplication/jsonहाँपेलोड फॉर्मेट
Content-Encodinggzipवैकल्पिकसंपीड़ित पेलोड फॉर्मेट; डेटाडॉग उच्च मात्रा वाले बैचों के लिए इसकी सलाह देता है।

रिक्वेस्ट बॉडी​

रिक्वेस्ट बॉडी, एक या अधिक लॉग ऑब्जेक्ट्स की एक सरणी है। प्रत्येक लॉग ऑब्जेक्ट निम्नलिखित फील्डों का समर्थन करता है:

फील्डप्रकारआवश्यकविवरण
messageस्ट्रिंगहाँलॉग संदेश का शरीर
ddsourceस्ट्रिंगअनुशंसितलॉग के स्रोत तकनीक का नाम, जैसे python या nginx
ddtagsस्ट्रिंगवैकल्पिककॉमा-द्वारा अलग किए गए टैग, जैसे env:prod,team:payments
hostnameस्ट्रिंगवैकल्पिकलॉग उत्पन्न करने वाले होस्ट का नाम
serviceस्ट्रिंगअनुशंसितऐप या सेवा का नाम
statusस्ट्रिंगअनुशंसितलॉग इवेंट की गंभीरता, जैसे info या ERROR
timestampस्ट्रिंगवैकल्पिकइवेंट का समय, जैसे 2025-11-15T08:30:00Z। टाइमस्टैम्प प्रारूप के बारे में जानकारी देखें।
नोट

message शामिल करें। डेटाडॉग, पाइपलाइनों को फिल्टर, फैसेट एवं मैच करने के लिए service, ddsource, एवं ddtags का उपयोग करता है; अन्य फील्ड वैकल्पिक हैं।

उदाहरण पेलोड​

Payload: single log
[
  {
    "message": "Transaction failed: Gateway timeout",
    "ddsource": "java",
    "ddtags": "env:prod,region:us-east-1",
    "hostname": "payments-host-01",
    "service": "payment-gateway",
    "status": "ERROR",
    "timestamp": "2025-11-15T08:30:00Z",
    "transaction_id": "txn_998877",
    "customer_id": "cus_554433"
  }
]
नोट

timestamp के लिए इंटरनेशनल ऑर्गनाइजेशन फॉर स्टैंडर्डाइजेशन (ISO) 8601 कोऑर्डिनेटेड यूनिवर्सल टाइम (UTC) फॉर्मेट का उपयोग करें। डेटाडॉग, लॉग एक्सप्लोरर में लॉग टाइमलाइन को इस मान के साथ संरेखित करता है; टाइमस्टैम्प के बिना के लॉग, इनगेस्ट समय का उपयोग करते हैं। डेटाडॉग, पिछले 18 घंटों तक का टाइमस्टैम्प स्वीकार करता है।

प्रतिक्रिया कोड​

कोडस्थिति (Status)विवरण (Description)
202स्वीकृत (Accepted)पेलोड स्वीकृत हुआ एवं अनुक्रमण के लिए कतार में है।
400खराब अनुरोध (Bad Request)फॉर्मेटिंग या सत्यापन त्रुटि।
401अनधिकृत (Unauthorized)DD-API-KEY हेडर अनुपस्थित है।
403निषिद्ध (Forbidden)API कुंजी अमान्य है या लॉग इनगेजमेंट अनुमतियाँ नहीं हैं।
408अनुरोध समयावधि समाप्त (Request Timeout)अनुरोध समयावधि समाप्त हो गई; कुछ समय बाद पुनः प्रयास करें।
413पेलोड बहुत बड़ा (Payload Too Large)पेलोड 5 MB से अधिक है।
429अत्यधिक अनुरोध (Too Many Requests)क्लाइंट ने अनुमति सीमा को पार कर दिया।
500आंतरिक सर्वर त्रुटि (Internal Server Error)डेटाडॉग को अप्रत्याशित समस्या आई; कुछ समय बाद पुनः प्रयास करें।
503सेवा उपलब्ध नहीं (Service Unavailable)डेटाडॉग की क्षमता सीमा में है; कुछ समय बाद पुनः प्रयास करें।

202 स्वीकार​

एक 202 Accepted प्रतिक्रिया से पुष्टि होती है कि Datadog ने पेलोड (payload) प्राप्त कर लिया है। प्रतिक्रिया-शरीर (response body) में एक खाली JSON ऑब्जेक्ट होता है। लॉग-इवेंट (log events) कुछ सेकंड के भीतर “लॉग-एक्सप्लोरर” (Log Explorer) में दिखाई देते हैं।

Response: 202 Accepted
HTTP/1.1 202 Accepted
Content-Type: application/json
Response body: 202 Accepted
{}

401 – अनधिकृत एवं 403 – निषिद्ध​

  • गलत JSON सिंटैक्स या अनएस्केप्ड कैरेक्टर।
  • पेलोड में आवश्यक message फील्ड नहीं है।
  • अनकंप्रेस्ड पेलोड 5 मेगाबाइट की सीमा से अधिक है।

डेटाडॉग यह कोड तब लौटाता है जब पेलोड सत्यापन में विफल हो जाता है:

Response: 400 Bad Request
{
  "errors": [
    {
      "detail": "Invalid JSON",
      "status": "400",
      "title": "Bad Request"
    }
  ]
}

401 अनधिकृत एवं 403 प्रतिबंधित​

जब DD-API-KEY हेडर अनुपस्थित होता है, तो Datadog 401 Unauthorized लौटाता है। जब API कुंजी की प्रमाणीकरण प्रक्रिया विफल हो जाती है या लॉग इनग्रेशन (log ingestion) की अनुमति नहीं होती, तो Datadog 403 Forbidden लौटाता है।

Response: 403 Forbidden
{
  "errors": [
    {
      "detail": "Forbidden",
      "status": "403",
      "title": "Forbidden"
    }
  ]
}

413 पेलोड बहुत बड़ा है​

जब अनुरोध का पेलोड (request payload) 5 मेगाबाइट से अधिक होता है (अनकंप्रेस्ड अवस्था में), तो डेटाडॉग (Datadog) यह कोड वापस करता है।

Response: 413 Payload Too Large
{
  "errors": [
    {
      "detail": "Payload too large",
      "status": "413",
      "title": "Payload Too Large"
    }
  ]
}

429 अत्यधिक अनुरोध​

आपने बहुत सारे अनुरोध (requests) भेजे हैं। कम अनुरोध भेजें, या लॉग ऑब्जेक्ट्स (log objects) को एक ही पेलोड (payload) में समूहित करके भेजें।

अन्य पुनरावृत्ति योग्य त्रुटियाँ​

डेटाडॉग (Datadog), अस्थायी विफलताओं के लिए भी 408 Request Timeout, 500 Internal Server Error, और 503 Service Unavailable प्रदान करता है। यदि 408 Request Timeout समस्या जारी रहती है, तो अनुरोध को पुनः प्रस्तुत (रीट्राय) करें।

लॉग इवेंट्स को बैच में भेजना​

एक ही अनुरोध में 1,000 तक लॉग एंट्रीज़ भेजें; डेटाडॉग इसे उच्च-मात्रा वाली सेवाओं के लिए सलाह देता है।

Payload: batched logs
[
  {
    "message": "User login succeeded",
    "service": "auth-service",
    "ddsource": "python",
    "ddtags": "env:prod",
    "status": "INFO"
  },
  {
    "message": "Transaction failed: Gateway timeout",
    "service": "payment-gateway",
    "ddsource": "python",
    "ddtags": "env:prod",
    "status": "ERROR",
    "transaction_id": "txn_998877"
  }
]

सीमाएँ:

  • लोड आकार: 5 एमबी बिना संपीड़ित
  • प्रत्येक लॉग का आकार: 1 एमबी
  • सरणी के प्रविष्टियाँ: 1,000 लॉग ऑब्जेक्ट्स

सामान्य उपयोग के मामले​

  • माइक्रोसर्विसेज से लॉग्स को डेटाडॉग एजेंट (Datadog Agent) डिप्लॉय किए बिना ही इन्गेस्ट (ingest) करना।
  • अमेज़न वेब सर्विसेज (AWS) लैम्ब्डा या गूगल क्लाउड रन जैसे “सर्वरलेस” फंक्शनों से संरचित JSON इवेंट्स को भेजा जाता है।
  • IoT उपकरणों या एज सेवाओं से स्ट्रीमिंग टेलीमेट्री (Streaming telemetry from IoT devices or edge services).
  • घटनाओं को सुरक्षा जानकारी एवं घटना प्रबंधन (SIEM), S3, या लॉग पाइपलाइनों (Log Pipelines) के माध्यम से अलर्ट गंतव्यों तक भेजा जाता है।
  • निरंतर एकीकरण (Continuous Integration) एवं निरंतर वितरण (Continuous Delivery) पाइपलाइनों (pipelines) या डिप्लॉयमेंट श्रेप्ट्स (deployment scripts) से लॉग्स (logs) जमा करना।

समस्या निवारण​

समस्यासंभावित कारणसमाधान
401 Unauthorizedगलत या अनुपस्थित API कुंजीOrg Settings → API Keys में DD_API_KEY की जाँच करें
400 Bad Requestअवैध/गलत स्वरूप (Malformed)भेजने से पहले jq . payload.json के साथ जाँच करें
एक्सप्लोरर में लॉग इन न करेंपाइपलाइन में लॉग शामिल न करेंफिल्टर साफ करें। फिर इंडेक्स रूटिंग नियमों (index routing rules) की जाँच करें।
टाइमस्टैम्प अनुक्रम से बाहर हैयह या तो गैर-यूटीसी (non-UTC) या गैर-आईएसओ 8601 (non-ISO 8601) प्रारूप में है, या 18 घंटों से पुराना है"2025-11-15T08:30:00Z" प्रारूप का उपयोग करें। घटना के 18 घंटे के भीतर लॉग भेजें।
429 Too Many Requestsदर सीमा (Rate Limit) पार हो गई।लॉग ऑब्जेक्ट्स को एक ही ऐरे (array) में संग्रहीत करें।

अगले चरण​

  • क्लाउड ऐप के लॉग्स को पाइपलाइन में भेजें
  • एक पोस्टमैन मॉक सर्वर बनाएँ
