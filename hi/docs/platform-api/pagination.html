कर्सर के साथ पेजिनेशन

GET /animals प्रत्येक बार एक पृष्ठ लौटाता है; प्रत्येक प्रतिक्रिया में रिकॉर्ड, अगले पृष्ठ के लिए कर्सर, एवं यह जानकारी भी शामिल होती है कि क्या कोई अन्य पृष्ठ मौजूद है या नहीं।

200 OK
{
  "data": [
    { "id": "pet_krypto_210", "name": "Krypto", "status": "AVAILABLE" },
    { "id": "pet_luna_118", "name": "Luna", "status": "AVAILABLE" }
  ],
  "next_cursor": "eyJvZmZzZXQiOjQwfQ",
  "has_more": true
}

पैरामीटर​

पैरामीटरप्रकारडिफ़ॉल्टसीमा
limitपूर्णांक201 से 100 तक
cursorस्ट्रिंगकोई नहींपिछले पृष्ठ से प्राप्त next_cursor मान

पहली बार cursor का उपयोग न करें; बाद के सभी कॉलों में पिछली प्रतिक्रिया में प्राप्त मान को ही पुनः भेजें।

पैरामीटर का मान पढ़ें, न कि पूरी सरणी को।​

एक पृष्ठ में limit से कम पंक्तियाँ हो सकती हैं; फिर भी अधिक पंक्तियाँ शेष रह सकती हैं (क्योंकि फ़िल्टर स्लाइसिंग के बाद लागू होते हैं)।

has_more: false, अंत को चिन्हित करता है, एवं next_cursor उसी पृष्ठ पर null को वापस लाता है। एक ऐसा लूप जो एक खाली data सरणी (array) पर आधारित हो, देर से रुक जाएगा एवं संसाधनों की बर्बादी करेगा। जबकि एक ऐसा लूप जो has_more पर आधारित हो, ठीक एक बार ही रुकेगा।

प्रत्येक पृष्ठ पर चलें।​

cursor=""
while :; do
  page=$(curl -s -G https://api.bludhavenpets.com/v1/animals \
    --data-urlencode "status=AVAILABLE" \
    --data-urlencode "limit=100" \
    --data-urlencode "cursor=${cursor}")
  echo "$page" | jq -r '.data[] | [.id, .name] | @tsv'
  has_more=$(echo "$page" | jq -r '.has_more')
  [ "$has_more" = "true" ] || break
  cursor=$(echo "$page" | jq -r '.next_cursor')
done
Node.js
async function listAvailableAnimals(token) {
  const animals = [];
  let cursor = '';

  for (;;) {
    const url = new URL('https://api.bludhavenpets.com/v1/animals');
    url.searchParams.set('status', 'AVAILABLE');
    url.searchParams.set('limit', '100');
    if (cursor) url.searchParams.set('cursor', cursor);

    const response = await fetch(url, {
      headers: { Authorization: `Bearer ${token}` },
    });
    if (!response.ok) throw new Error(`List failed with ${response.status}`);

    const page = await response.json();
    animals.push(...page.data);
    if (!page.has_more) return animals;
    cursor = page.next_cursor;
  }
}
Python
import requests


def list_available_animals(token):
    animals = []
    cursor = ""
    while True:
        params = {"status": "AVAILABLE", "limit": 100}
        if cursor:
            params["cursor"] = cursor
        response = requests.get(
            "https://api.bludhavenpets.com/v1/animals",
            params=params,
            headers={"Authorization": f"Bearer {token}"},
            timeout=20,
        )
        response.raise_for_status()
        page = response.json()
        animals.extend(page["data"])
        if not page["has_more"]:
            return animals
        cursor = page["next_cursor"]

कर्सर को “अपारदर्शी” (अदृश्य) मानें।​

मान, सर्वर द्वारा चुने गए स्थान को दर्शाता है; यदि एन्कोडिंग बदल जाती है, तो क्लाइंट को पुनः शुरूआत करनी होगी।

स्ट्रिंग को बिना किसी परिवर्तन के ही प्रसारित करें। कुछ प्रॉक्सी अनुचित लंबाई को काट सकते हैं, लेकिन पूरा मान बरकरार रखें।

फिल्टरों को स्थिर रखें।​

प्रत्येक पृष्ठ पर status, species, branch_id, temperament_tag को अपरिवर्तित रूप से भेजें।

यदि फिल्टर (filter) को चलते समय बदल दिया जाए, तो परिणामों का सेट (result set) बदल जाएगा; इसलिए फिल्टर बदलने पर पुनः एक खाली cursor से शुरुआत करनी होगी। यही तो खोज बॉक्स (search box) हर बार कुंजी दबाने पर करता है।

सभी जानकारियाँ एक ही समूह में लौटाएँ।​

GET /retail/inventory एवं GET /animals/{animalId}/health-records, एक पूरा ऑब्जेक्ट लौटाते हैं।

वह क्लाइंट (client) जो “envelope shape” (आवरण का आकार) के अनुसार कार्य करता है, Array.isArray(body.data) पर ही दोनों ही स्थितियों (cases) को संभालता है। उसे अनुबंध (contract) में घोषित आकार को ही पढ़ना चाहिए, न कि किसी सूची (list) को मान लेना चाहिए।

संबंधित गाइड।​

  • त्रुटियाँ एवं समस्याओं का विवरण: किसी खराब limit पर 400 क्या लौटाता है?
  • दर सीमाएँ – एक विस्तृत पृष्ठ (wide page) लूप द्वारा ट्रिगर किया जा सकने वाला “429” त्रुटि कोड।
  • इंटरैक्टिव API संदर्भ – “cursor” पैरामीटर को सैंडबॉक्स गेटवे (sandbox gateway) पर चलाएँ।
