पेजिनेशन एवं सूची एंडपॉइंट्स

लिस्ट एंडपॉइंट एक पृष्ठ के परिणाम एवं अगले पृष्ठ का संकेतक लौटाता है। क्लाइंट इस संकेतक का पालन करता है जब तक कि has_more मान “गलत” (false) न हो जाए।

लिस्ट एंडपॉइंट की संरचना​

{
  "object": "list",
  "url": "/v1/charges",
  "has_more": true,
  "data": [
    { "id": "ch_3Rsx4dDtWMrPDtgt1", "object": "charge", "amount": 2120 }
  ]
}
FieldMeaning
dataइस पेज पर मौजूद ऑब्जेक्ट्स।
has_moreजब कोई अन्य पृष्ठ मौजूद हो, तो true.
urlवह एंडपॉइंट पथ जिसने यह पेज उत्पन्न किया।

सबसे नया ऑब्जेक्ट सबसे पहले प्रदर्शित होता है, एवं पृष्ठों के बीच क्रम नहीं बदलता; क्योंकि कर्सर एक ऑब्जेक्ट पर ही इशारा करता है, न कि किसी संख्यात्मक मान पर।

पेज साइज़ सेट करें​

limit पृष्ठ के आकार को नियंत्रित करता है एवं 1 से 100 तक के मान स्वीकार करता है। डिफ़ॉल्ट मान 10 है, जो इंटरैक्टिव डैशबोर्ड के लिए उपयुक्त है; हालाँकि यह बैच जॉब (batch job) में डेटा के अनावश्यक प्रसारण का कारण बन सकता है।

curl -s -G https://api.stripe.com/v1/charges \
  -u "$STRIPE_SECRET_KEY:" \
  -d limit=100 | jq '.data | length, .has_more'

एक बड़ा पेज अनुरोधों की संख्या एवं कुल विलंबता (latency) को कम करता है; हालाँकि, इससे मेमोरी की आवश्यकता बढ़ जाती है, एवं असफल अनुरोधों का प्रभाव भी अधिक हो जाता है। इसलिए 100 आइटम सबसे उपयुक्त संख्या है।

कर्सर का पालन करें।​

पृष्ठ पर अंतिम ऑब्जेक्ट का id मान पढ़ें एवं उसे starting_after के रूप में पास करें। यह प्रक्रिया तब तक दोहराएँ जब तक has_more का मान “false” न हो जाए।

curl -s -G https://api.stripe.com/v1/charges \
  -u "$STRIPE_SECRET_KEY:" \
  -d limit=100 \
  -d starting_after=ch_3Rsx4dDtWMrPDtgt1
Node.js
async function listAllCharges() {
  const charges = [];
  let startingAfter;

  while (true) {
    const url = new URL("https://api.stripe.com/v1/charges");
    url.searchParams.set("limit", "100");
    if (startingAfter) url.searchParams.set("starting_after", startingAfter);

    const response = await fetch(url, {
      headers: { Authorization: `Bearer ${process.env.STRIPE_SECRET_KEY}` },
    });

    if (!response.ok) throw new Error(`Stripe returned ${response.status}`);

    const page = await response.json();
    charges.push(...page.data);

    if (!page.has_more) break;
    startingAfter = page.data.at(-1).id;
  }

  return charges;
}
सुझाव

आधिकारिक लाइब्रेरियाँ आपके लिए पृष्ठों को प्रबंधित करती हैं। Node में, stripe.charges.list({ limit: 100 }) को for await के साथ पुनरावृत्त करें; Python में, वापस की गई सूची पर .auto_paging_iter() को कॉल करें; Java में, StripeCollection पर autoPagingIterable() को कॉल करें। इसका उपयोग करने से पहले अपने इंस्टॉल किए गए SDK संस्करण की जाँच करें।

सर्वर पर ही फ़िल्टरिंग करें।​

फ़िल्टरिंग से परिणामों का सेट संकुचित हो जाता है; क्लाइंट पर फ़िल्टरिंग करने से पूरी सूची को पढ़ना आवश्यक हो जाता है।

फ़िल्टरउदाहरणदायरा
समय-सीमाcreated[gte]=1735689600&created[lt]=1738368000शुल्क, रिफंड, बैलेंस लेन-देन
स्थितिstatus=availableबैलेंस लेन-देन
ग्राहकcustomer=cus_QyJ8...शुल्क, भुगतान, बिल
भुगतानpayout=po_1N...एक भुगतान में सभी बैलेंस लेन-देन

फ़िल्टरों को एक साथ जोड़ें ताकि “रिकॉन्सिलिएशन जॉब” (Reconciliation Job) एक ही पृष्ठ में आ सके। ऐसा दैनिक कार्य, जिसमें कल के शुल्कों को created की सीमा के साथ पढ़ा जाता है, एक ही पृष्ठ में फिट हो जाता है।

कर्सर पेजिनेशन (Cursor Pagination) एवं ऑफसेट पेजिनेशन की तुलना​

ऑफसेट पेजिनेशन में पृष्ठ 2 को पंक्ति 100 पर माँगा जाता है। जब नए डेटा के आने से डेटाबेस में परिवर्तन होता है, तो पंक्ति 100 पंक्ति 101 बन जाती है एवं एक रिकॉर्ड दो बार दिखाई देता है। कर्सर उस अंतिम ऑब्जेक्ट की ओर इशारा करता है जिसे आपने देखा। नए डेटा कर्सर के आगे दिखाई देते हैं, लेकिन पहले वाले डेटा पर कोई प्रभाव नहीं पड़ता।

इस डिज़ाइन के आपके क्लाइंट पर दो प्रभाव पड़ते हैं:

  • कोई पृष्ठ-क्रमांक नहीं है। मानक सूची एंडपॉइंट्स page=2 एवं total_count प्रदान नहीं करते। यदि आपको कुल संख्या चाहिए, तो उसे अपने स्टोर में ही गिनें। खोज एंडपॉइंट्स (search endpoints) अलग-अलग होते हैं।
  • अगले पृष्ठ को पढ़ने हेतु उस टोकन को starting_after के रूप में वापस भेजें। प्रतिक्रिया में ending_before दिया जाता है, जो पेजिनेशन प्रक्रिया के समाप्त होने का संकेत है।

एंडपॉइंट प्रकार | कर्सर पैरामीटर | अंतिम संकेत​

खोज एंडपॉइंट्स एक क्वेरी-स्ट्रिंग (query string) स्वीकार करते हैं एवं एक next_page टोकन (token) वापस करते हैं, न कि किसी ऑब्जेक्ट का कर्सर।

curl -s -G https://api.stripe.com/v1/charges/search \
  -u "$STRIPE_SECRET_KEY:" \
  -d query="amount>1000 AND status:'succeeded'" | jq '.next_page'

अगले पेज को पढ़ने के लिए टोकन को page के रूप में वापस भेजें। next_page: null के साथ आने वाला प्रतिक्रिया-संदेश पेज के अंत को दर्शाता है। सर्च प्रक्रिया में starting_after का कोई उपयोग नहीं होता, इसलिए अपने क्लाइंट में दोनों पेजिनेशन (पृष्ठ-निर्देशन) मॉडलों को अलग-अलग रखें।

एंडपॉइंट प्रकारकर्सर पैरामीटरएंड सिग्नल
मानक सूचीstarting_afterhas_more: false
खोजpagenext_page: null

बड़ी मात्रा में डेटा पढ़ने की क्रियाओं को दर सीमाओं (rate limits) के भीतर ही रखें।​

एक वर्ष के भुगतानों का “बैकफिल” (backfill) हजारों अनुरोधों को जन्म दे सकता है; भार को फैलाएँ एवं जब स्ट्राइप (Stripe) प्रतिक्रिया दे तो उसके अनुसार कार्य करें।

  • प्रति बार केवल एक पृष्ठ पढ़ें। एक ही संग्रह (collection) पर एक समय में अधिक कार्य करने से समानांतरता (concurrency) की सीमा पार हो जाएगी।
  • 429 पर दिए गए Retry-After हेडर का पालन करें। अधिक जानकारी के लिए Errors and retries देखें।
  • अंतिम कर्सर (cursor) को टिकाऊ भंडारण (durable storage) में संग्रहीत करें, ताकि पुनः शुरुआत करने की आवश्यकता न पड़े।
  • पूरी संग्रह-सूची को पढ़ने के बजाय, सीमित created रेंज का उपयोग करें।

अगले चरण​

  • नेस्टेड ऑब्जेक्ट्स (nested objects) का विस्तार करके पृष्ठ को समृद्ध बनाना, बिना किसी अतिरिक्त अनुरोध (request) के।
  • बल्क पढ़ाई संबंधी नीतियों के बारे में Errors and retries में जानकारी प्राप्त करें।
  • प्रत्येक पंक्ति के पीछे दी गई विशेषता सूची (attribute list) के लिए “बैलेंस लेन-देन प्राप्त करें”.
