प्रमाणीकरण एवं कुंजी प्रबंधन

स्ट्राइप के लिए किए गए अनुरोधों में Authorization हेडर में एक API कुंजी शामिल होती है। यह कुंजी आपके खाते का प्रतिनिधित्व करती है एवं उस भूमिका (role) के अधिकारों को अनुसरण करती है जिसने इसे बनाया। एक लीक हुई गोपनीय कुंजी (secret key) आपके खाते से संबंधित सभी लेन-देन, ग्राहकों एवं भुगतानों को उजागर कर सकती है।

कुंजी के प्रकार​

प्रत्येक खाते में तीन प्रकार की कुंजियाँ होती हैं; इनमें से केवल एक ही सर्वर पर उपयोग की जा सकती है।

कुंजी (Key)प्रीफिक्स (Prefix)ब्राउज़र में सुरक्षित है (Safe in a browser)उपयोग के लिए:
प्रकाशन योग्यpk_test_, pk_live_हाँक्लाइंट-साइड टोकनाइजेशन एवं Stripe.js; यह API एक्सेस प्रदान नहीं करता।
गोपनीयsk_test_, sk_live_नहींसर्वर-साइड API कॉल; पूरे खाते के अधिकार।
प्रतिबंधितrk_test_, rk_live_नहींसर्वर-साइड कॉल केवल नामित संसाधनों एवं संचालनों तक सीमित हैं।

एक “सीक्रेट की” (Secret Key) उस खाते के सभी डेटा को पढ़ एवं लिख सकती है। “प्रतिबंधित कुंजियाँ” (Restricted Keys) उपयोगकर्ता की पहुँच को सीमित कर देती हैं; उदाहरण के लिए, केवल पढ़ने की अनुमति वाले डेटा तक ही पहुँच होती है। ऐसी प्रतिबंधित कुंजियों का उपयोग तभी करें, जब किसी इंटीग्रेशन (Integration) को पूरे खाते तक पहुँच की आवश्यकता न हो।

खतरा

कभी भी कोई गोपनीय या प्रतिबंधित कुंजी क्लाइंट कोड, मोबाइल बाइनरी, सार्वजनिक रिपॉजिटरी या सपोर्ट टिकट में न रखें; जो भी उस कुंजी को रखता है, वह पैसा स्थानांतरित कर सकता है।

कुंजी भेजें​

कुंजी को “Basic Auth” उपयोगकर्ता नाम के रूप में एवं खाली पासवर्ड के साथ पास करें। स्ट्राइप (Stripe) “Bearer Token” के रूप में भी इसी मान को स्वीकार करता है; लेकिन cURL के लिए दस्तावेजीकृत फॉर्म में यह “उपयोगकर्ता नाम” (username) फील्ड में होना चाहिए।

curl https://api.stripe.com/v1/balance \
  -u "$STRIPE_SECRET_KEY:"
Node.js
const response = await fetch("https://api.stripe.com/v1/balance", {
  headers: { Authorization: `Bearer ${process.env.STRIPE_SECRET_KEY}` },
});
Python
import os, requests

response = requests.get(
    "https://api.stripe.com/v1/balance",
    auth=(os.environ["STRIPE_SECRET_KEY"], ""),
)

अनुरोधों में HTTPS का उपयोग अवश्य किया जाना चाहिए। साधारण HTTP का उपयोग करने पर स्ट्राइप कुंजी को पढ़ने से पहले ही अनुरोध विफल हो जाएगा।

कुंजी को संग्रहीत करें​

कुंजी को रनटाइम पर पर्यावरण (environment) से लोड करें। इसे कभी भी संग्रहीत (commit) न करें, एवं इसका लॉग (log) भी न बनाएँ।

.env
STRIPE_SECRET_KEY=sk_test_51N...
server.js
if (!process.env.STRIPE_SECRET_KEY) {
  throw new Error("STRIPE_SECRET_KEY is not set");
}

पर्यावरण फ़ाइल (environment file) को .gitignore में जोड़ें। होस्टेड प्लेटफॉर्म (hosted platforms) इस मान को एक गुप्त भंडारण स्थल में रखती हैं एवं इसे प्रक्रिया पर्यावरण (process environment) में इंजेक्ट करती हैं; ताकि कुंजी रिपॉजिटरी (repository) एवं बिल्ड लॉग (build logs) में न आए।

कनेक्शन की पुष्टि करें​

एक “पढ़ने का अनुरोध” (read request) भेजें। 200 से प्राप्त प्रतिक्रिया में “बैलेंस ऑब्जेक्ट” (balance object) कुंजी, आधार पता (base address), एवं नेटवर्क पथ (network path) की पुष्टि करता है।

curl -s https://api.stripe.com/v1/balance -u "$STRIPE_SECRET_KEY:" | jq '.object, .livemode'

परीक्षण हेतु आउटपुट में "balance" एवं false दिखाए जाते हैं। 401 का अर्थ है कि कुंजी गलत है, निरस्त कर दी गई है, या अनुपस्थित है। 403 का अर्थ है कि प्रतिबंधित कुंजी को उस संसाधन (resource) के लिए अनुमति नहीं है।

प्रतिबंधित कुंजी का दायरा निर्धारित करें​

प्रतिबंधित कुंजी में प्रत्येक संसाधन (resource) के लिए अनुमतियाँ (permissions) सूचीबद्ध होती हैं; इंटीग्रेशन (integration) को आवश्यक न्यूनतम अनुमतियाँ ही प्रदान की जानी चाहिए।

| इंटीग्रेशन | सुझाई गई अनुमतियाँ (Integration | Suggested permissions) |---|---| | रिपोर्टिंग जॉब | शुल्कों, लेन-देनों एवं भुगतानों के बारे में जानकारी प्रदान करता है। | | चेकआउट सर्वर | भुगतान संबंधी इरादों एवं रिफंडों के बारे में जानकारी प्रदान करता है; ग्राहकों के बारे में भी जानकारी प्रदान करता है। | | वेबहुक सत्यापक (Webhook Verifier) | घटनाओं (events) के बारे में जानकारी प्रदान करता है; लेखन की अनुमति नहीं है। |

प्रत्येक कुंजी (key) को उस सेवा के नाम से ही नामित करें जिसके लिए उसका उपयोग किया जाता है। जैसे, checkout-api-prod जैसा नाम इन्सिडेंट समीक्षा (incident review) को तेज़ बनाता है, क्योंकि ऑडिट लॉग (audit log) दिखाता है कि कौन-सी कुंजी ने कार्य किया।

कुंजियों का रोटेशन​

  1. उसी अनुमतियों वाली एक नई कुंजी बनाएँ।
  2. उसे “सीक्रेट स्टोर” में नए नाम के साथ जोड़ें।
  3. उस नई कुंजी का उपयोग करने वाली सेवा को तैनात करें।
  4. पुष्टि करें कि नई कुंजी सफलतापूर्वक काम कर रही है।
  5. डैशबोर्ड में पुरानी कुंजी को रद्द कर दें।
  6. तैनाती के बाद पुरानी कुंजी से आए अनुरोधों का लॉग की समीक्षा करें।
चेतावनी

पहले कुंजी को रद्द करने से उत्पादन प्रक्रिया प्रभावित हो जाती है। पुरानी कुंजी को रद्द करने से पहले नई कुंजी को तैनात करें, एवं इन दोनों कदमों के बीच त्रुटि-दर (error rate) को देखें।

लीक (Leak) की स्थिति में क्या करें?​

किसी रिपॉजिटरी (repository), लॉग (log), या चैट संदेश (chat message) में मौजूद गोपनीय कुंजी (secret key) को “संकटग्रस्त” (compromised) मानें।

  1. डैशबोर्ड (Dashboard) में Developers → API Keys विकल्प के तहत कुंजी को रद्द करें।
  2. एक नई कुंजी बनाएँ एवं उसे तैनात करें।
  3. अज्ञात आईपी पतों (unknown IP addresses) या असामान्य एंडपॉइंट्स (unusual endpoints) के लिए अनुरोध-लॉग (request log) की समीक्षा करें।
  4. ऐसी गतिविधियों की जाँच करें जिन्हें आपने शुरू नहीं किया।
  5. यदि अनधिकृत गतिविधियाँ पाई जाएँ, तो स्ट्राइप सपोर्ट (Stripe support) से संपर्क करें।

कुंजी को रद्द करने का प्रभाव तुरंत लागू हो जाता है; रद्द की गई कुंजी अगला अनुरोध पूरा नहीं कर पाएगी।

सामान्य त्रुटियाँ​

लक्षण (Symptom)कारण (Cause)समाधान (Fix)
401 Invalid API Key providedकुंजी अधूरी है, रद्द की गई है, या किसी अन्य खाते से है।डैशबोर्ड से कुंजी की प्रति दोबारा नकल करें।
403 एक संसाधन परएक प्रतिबंधित कुंजी को अनुमति की कमी है।अनुमति जोड़ें या अधिक व्यापक दायरे वाली कुंजी का उपयोग करें।
401 केवल उत्पादन (production) मेंउस डिप्लॉयमेंट में पर्यावरण चर (environment variable) खाली है।उत्पादन वातावरण के लिए “सीक्रेट स्टोर” (secret store) की जाँच करें।
अनुरोध रुक जाते हैं, फिर विफल हो जाते हैंएक प्रॉक्सी (proxy) आउटबाउंड HTTPS को api.stripe.com तक पहुँचने से रोक रहा है।पोर्ट 443 पर होस्ट (host) को अनुमति दें।

अगले चरण​

  • अप्रभावी अनुरोध (Idempotent requests) पुनः प्रयास किए गए POST को सुरक्षित बनाने के लिए।
  • त्रुटियाँ एवं पुनः प्रयास – प्रत्येक विफलता को एक ठीक करने के चरण (recovery step) से जोड़ें।
  • API संस्करण निर्धारण एवं अपग्रेड – प्रतिक्रिया के पैटर्न को स्थिर रखने के लिए।
