API संस्करणन (API Versioning) एवं अपग्रेड

Stripe पूरे API का ही संस्करणन करता है, न कि केवल विशेष एंडपॉइंट्स (endpoints) का। “संस्करण स्ट्रिंग” (version string), फील्डों (fields) एवं व्यवहार (behavior) का एक स्नैपशॉट (snapshot) दर्शाती है। आपका खाता एक निश्चित संस्करण को निर्धारित करता है; ओवरराइड (override) के बिना प्रत्येक अनुरोध उसी संस्करण का उपयोग करता है।

संस्करण स्रोत​

स्तर (Layer)सेटिंग (Setting)दायरा (Scope)
खाता (Account)डैशबोर्ड में डिफ़ॉल्ट API संस्करण (Default API version in the Dashboard)वे सभी अनुरोध जिनमें हेडर (header) नहीं है
अनुरोधStripe-Version हेडरएक अनुरोध
क्लाइंट लाइब्रेरी (Client Library)SDK रिलीज़ के साथ आने वाला संस्करण (Version bundled with the SDK release)उस क्लाइंट के माध्यम से भेजे गए सभी अनुरोध (Requests sent through that client)

खाते द्वारा निर्धारित संस्करण, परिवर्तनों से सुरक्षा प्रदान करता है। यदि Stripe नया डिफ़ॉल्ट संस्करण जारी करे, तो भी आपका इंटीग्रेशन पिछले संस्करण के अनुसार ही कार्य करता रहेगा।

संस्करण को ओवरराइड करना​

अपने खाते के डिफ़ॉल्ट संस्करण को बदले बिना, अलग संस्करण का परीक्षण करने हेतु Stripe-Version का उपयोग करें।

curl https://api.stripe.com/v1/payment_intents/pi_3Rsx4dDtWMrPDtgt0mUrePJ9 \
  -u "$STRIPE_SECRET_KEY:" \
  -H "Stripe-Version: 2024-06-20"
Node.js
const stripe = new Stripe(process.env.STRIPE_SECRET_KEY, {
  apiVersion: "2024-06-20",
});

हेडर में एक तारीखवार संस्करण (जैसे 2024-06-20) दर्ज किया जाता है। कुछ रिलीजों में एक कोडनेम भी जोड़ा जाता है, जिसे आपको डैशबोर्ड से ठीक उसी रूप में कॉपी करना होगा।

नोट

“ओवरराइड” (override) किसी अनुरोध (request) के व्यवहार को बदलता है, न कि केवल उसके फील्डों को। पहले चेंजलॉग (changelog) पढ़ें।

क्या बदल सकता है?​

कुछ परिवर्तन सभी संस्करणों पर लागू होते हैं; अन्य परिवर्तनों के लिए एक नया संस्करण आवश्यक है। तालिका इन परिवर्तनों को वर्गीकृत करती है।

परिवर्तनकिसी भी संस्करण में उपलब्धनए संस्करण की आवश्यकता है
नया वैकल्पिक अनुरोध पैरामीटरहाँनहीं
नया प्रतिक्रिया फील्डहाँनहीं
वेबहुक्स (webhooks) के लिए नया इवेंट प्रकारहाँनहीं
नाम बदला गया फील्डनहींहाँ
फील्ड का प्रकार बदल गयानहींहाँ
हटाया गया फील्डनहींहाँ
डिफ़ॉल्ट मान बदला गयानहींहाँ

वह क्लाइंट जो अज्ञात फील्डों को नजरअंदाज करता है, हर जोड़े गए परिवर्तन को स्वीकार कर लेता है; लेकिन वे क्लाइंट जो प्रतिक्रियाओं (रिस्पॉन्सेस) की जाँच एक निश्चित स्कीमा (स्कीमा) के आधार पर करते हैं, पहले ही नए फील्ड के कारण विफल हो जाते हैं।

एक ऐसा पार्सर (पार्सर) बनाएँ जो भविष्य के संस्करणों (फ्यूचर वर्जन्स) के साथ संगत हो।​

केवल उन्हीं फील्डों को पढ़ें जिनकी आवश्यकता है, बाकी को नजरअंदाज कर दें। किसी अतिरिक्त कुंजी (एक्स्ट्रा की) के कारण प्रतिक्रिया को विफल न करें।

Node.js
function readAmount(intent) {
  const amount = intent.amount;

  if (typeof amount !== "number") {
    throw new Error("amount is missing from the PaymentIntent response");
  }

  return amount;
}

यह जाँच उस फील्ड की पुष्टि करती है जिस पर आप निर्भर हैं; बाकी भागों पर कोई प्रभाव नहीं पड़ता, इसलिए नया amount_details कुंजी या नया स्थिति मान पार्सर (parser) को नष्ट नहीं करेगा।

चेतावनी

पूरी प्रतिक्रिया संरचना (पूरी रिस्पॉन्स स्ट्रक्चर) पर निर्भर न रहें; उदाहरण के लिए, कुंजियों की तुलना किसी निश्चित सूची (फिक्स्ड लिस्ट) से न करें। स्ट्राइप (Stripe) अपने अधिकांश संस्करणों में नए फील्ड जोड़ता है, और सख्त तुलना अगले संस्करण में विफल हो जाएगी।

परीक्षण मोड (टेस्ट मोड) में ही अपग्रेड (अपग्रेड) करें।​

अकाउंट पिन (Account Pin) को स्थानांतरित करने से पहले इस क्रम को अवश्य चलाएँ।

  1. API चेंजलॉग खोलें और अपने संस्करण एवं लक्ष्य संस्करण के बीच के प्रत्येक परिवर्तन को पढ़ें।
  2. अपने कोड द्वारा पढ़े गए फील्डों एवं भेजे गए अनुरोध पैरामीटर्स (Request Parameters) पर ध्यान दें।
  3. लक्ष्य संस्करण के लिए वास्तविक अनुरोधों (रियल रिक्वेस्ट्स) का नमूना भेजें, एवं उनमें Stripe-Version हेडर (Header) को सही रूप से सेट करें।
  4. प्रतिक्रियाओं की तुलना अपने पार्सर के आधार पर करें, केवल दृश्य अंतर (विजुअल डिफर) के आधार पर नहीं।
  5. लक्ष्य संस्करण के लिए एकीकरण परीक्षण सूट (Integration Test Suite) चलाएँ।
  6. पुराने एवं नए प्रतिक्रिया प्रारूपों को संभालने वाला कोड तब लॉन्च करें, जब ऐसी आवश्यकता हो।
  7. डैशबोर्ड में खाते के डिफ़ॉल्ट सेटिंग्स को बदलें।
  8. एक पेमेंट चक्र के दौरान त्रुटि-दर एवं वेबफ़ुक विफलता-दर की निगरानी करें।
सुझाव

सूट में उपलब्ध संसाधनों तक सीमित एक “रिस्ट्रिक्टेड कुंजी” (restricted key) के साथ परीक्षण करें; पूर्ण “सीक्रेट कुंजी” (full secret key) का उपयोग करने से खाते में अनचाहे ऑब्जेक्ट शेष रह सकते हैं।

SDK एवं API संस्करणों को समन्वित रखें।​

SDK के रिलीज़ होने पर एक डिफ़ॉल्ट API संस्करण भी उपलब्ध हो जाता है; लाइब्रेरी को अपग्रेड करने से आपके अनुरोध नए संस्करण पर भेजे जाएंगे, भले ही खाते की सेटिंगें न बदलें।

कार्रवाईAPI संस्करण पर प्रभाव
SDK को अपग्रेड करें एवं उसके डिफ़ॉल्ट संस्करण को स्वीकार करेंअनुरोध उसी संस्करण का उपयोग करेंगे जो SDK के साथ आया है।
SDK को अपग्रेड करें एवं apiVersion को सेट करेंअनुरोध उसी संस्करण का उपयोग करेंगे जिसे आपने नामित किया है।
डैशबोर्ड की डिफ़ॉल्ट सेटिंग्स बदलेंऐसे अनुरोधों पर प्रभाव पड़ेगा जिनमें हेडर एवं क्लाइंट apiVersion शामिल न हो।

लाइब्रेरी को अपग्रेड करते समय apiVersion को स्पष्ट रूप से सेट करें; इससे API संस्करण स्थिर रहेगा, जबकि आप SDK में हुए परिवर्तनों की समीक्षा कर सकेंगे।

विभिन्न संस्करणों में वेबफ़ुक्स (webhooks) का सही ढंग से प्रबंधन करें।​

एक वेबफिक संघटना (Webhook event) उस API संस्करण को दर्ज करती है जिसने इसे बनाया, जो api_version के अंतर्गत है। स्ट्राइप (Stripe) घटनाओं को उस संस्करण के साथ भेजता है जो एंडपॉइंट (endpoint) पर लगा होता है, न कि उस संस्करण के साथ जो खाते (account) पर लगा होता है।

दोनों पथों (paths) पर एक ही हैंडलर (handler) साझा करने से पहले इसके परिणामों (consequences) को पढ़ें।

  • अलग-अलग पिन (pins) रखें। एक एंडपॉइंट, आपके API कॉल (API calls) द्वारा उपयोग किए जाने वाले संस्करण से अलग संस्करण पर घटनाएँ पहुँचा सकता है।
  • फील्ड ड्रिफ्ट (Field drift): API प्रतिक्रिया (API response) से पढ़ा गया कोई फील्ड, घटना पेलोड (event payload) में मौजूद नहीं हो सकता।

पेलोड (payload) को लॉग करते समय घटना का api_version पढ़ें, एवं हैंडलर को आवश्यक फील्डों (fields) की पुष्टि करें, न कि पूरे ऑब्जेक्ट (object) की।

अगले कदम​

  • त्रुटियाँ एवं पुनरावृत्तियाँ: जब संस्करण-परिवर्तन (version change) प्रोडक्शन में किसी प्रक्रिया को बाधित कर देता है।
  • [अप्रभावी अनुरोध (Idempotent Requests)]0) अपग्रेड के दौरान पुनरावृत्ति (Retry) व्यवहार के लिए।
  • प्रत्येक संस्करण के पीछे Stripe API चेंजलॉग है।
