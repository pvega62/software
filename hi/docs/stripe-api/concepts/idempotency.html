इडेम्पोटेंट अनुरोध

टाइमआउट के कारण परिणाम अज्ञात रह सकता है – अनुरोध से कार्ड से शुल्क लिया जा सकता है, लेकिन प्रतिक्रिया वापस नहीं मिल सकती। कुंजी के बिना पुनः प्रयास करने पर दूसरा शुल्क लिया जा सकता है।

“Idempotency-Key” हेडर इस जोखिम को दूर करता है; स्ट्राइप (Stripe) पहले अनुरोध का परिणाम उस कुंजी के तहत संग्रहीत कर देता है, तथा हर पुनः प्रयास पर वही परिणाम वापस करता है।

कुंजी तंत्र​

  1. क्लाइंट, प्रत्येक तार्किक कार्य के लिए एक अद्वितीय कुंजी जनरेट करता है।
  2. “POST” अनुरोध, हेडर में कुंजी के साथ स्ट्राइप तक पहुँचाया जाता है।
  3. स्ट्राइप अनुरोध चलाता है एवं प्रतिक्रिया को 24 घंटों तक उस कुंजी के साथ संग्रहीत रखता है।
  4. उसी कुंजी के साथ पुनः प्रयास करने पर पहले ही संग्रहीत प्रतिक्रिया ही वापस की जाती है।

स्ट्राइप (Stripe) त्रुटियों के साथ-साथ सफलताओं को भी कैश (cache) में संग्रहीत करता है। यदि पहला अनुरोध 400 लौटाता है, तो उसी कुंजी के साथ होने वाला प्रत्येक पुनर्प्रयास भी 400 ही लौटाएगा।

एक कुंजी भेजें​

curl https://api.stripe.com/v1/payment_intents \
  -u "$STRIPE_SECRET_KEY:" \
  -H "Idempotency-Key: a1b2c3d4-0001-4f8e-9a1c-7d2e3f4a5b6c" \
  -d "amount=2120" \
  -d "currency=usd"
Node.js
const key = crypto.randomUUID();

const response = await fetch("https://api.stripe.com/v1/payment_intents", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.STRIPE_SECRET_KEY}`,
    "Content-Type": "application/x-www-form-urlencoded",
    "Idempotency-Key": key,
  },
  body: new URLSearchParams({ amount: "2120", currency: "usd" }),
});
Python
import os, uuid, requests

response = requests.post(
    "https://api.stripe.com/v1/payment_intents",
    auth=(os.environ["STRIPE_SECRET_KEY"], ""),
    headers={"Idempotency-Key": str(uuid.uuid4())},
    data={"amount": 2120, "currency": "usd"},
)

कुंजी मान चुनें​

कुंजी प्रत्येक ऑपरेशन के लिए अद्वितीय होनी चाहिए एवं पुनरावृत्तियों (retries) में स्थिर रहनी चाहिए। 255 अक्षरों तक का कोई भी स्ट्रिंग उपयोग किया जा सकता है। अधिकांश एकीकरण (integrations) दो रणनीतियों में से किसी एक का उपयोग करते हैं।

रणनीतिकुंजी-मानसमझौता (Tradeoff)
जनरेटेड (Generated)एक सार्वभौमिक रूप से अद्वितीय पहचानकर्ता (UUID), जो प्रत्येक ऑपरेशन के लिए एक बार बनाया जाता है एवं पुनरावृत्ति प्रक्रिया में पास किया जाता है।निर्माण में तेज़; क्लाइंट को ऑपरेशन पूरा होने तक इस कुंजी को संरक्षित रखना होता है।
डेराइव्ड (Derived)एक स्थिर मान, जैसे order-4471-charge-1।लॉगों (logs) में पढ़ने योग्य; इसकी अद्वितीयता को आपको नियंत्रित करना होता है।
चेतावनी

कुंजी को पुनरावृत्ति लूप (retry loop) के बाहर ही जनरेट करें। पुनरावृत्ति के दौरान crypto.randomUUID() का उपयोग करने से प्रत्येक प्रयास के लिए एक नयी कुंजी बन जाती है, जिससे प्रत्येक पुनरावृत्ति एक नई अनुरोध बन जाती है।

तीन परिणामों को संभालें​

परिणामअर्थकार्रवाई (Action)
एक ही प्रतिक्रिया, एक ही डेटास्ट्राइप पहले संग्रहीत परिणाम को दोबारा प्रदान करता है।इसे सामान्य सफलता या असफलता के रूप में मानें।
409 Conflictइस कुंजी के साथ का अनुरोध अभी भी चल रहा है।प्रतीक्षा करें, फिर उसी कुंजी के साथ पुनः प्रयास करें।
400 के साथ idempotency_errorअनुरोधकर्ता ने अलग पैरामीटरों के साथ उसी कुंजी का उपयोग किया।नए ऑपरेशन के लिए एक नई कुंजी का उपयोग करें।

idempotency_error का मामला किसी त्रुटि (bug) का संकेत हो सकता है; वही कुंजी अलग मात्रा, मुद्रा या पैरामीटर सेट के साथ प्राप्त हुई। स्ट्राइप (Stripe) यह नहीं जान सकता कि कॉलर का क्या अर्थ था।

{
  "error": {
    "message": "Keys for idempotent requests can only be used with the same parameters they were first used with.",
    "type": "idempotency_error"
  }
}

रिटेंशन विंडो सेट करें​

स्ट्राइप (Stripe) परिणामों को 24 घंटों तक संग्रहीत रखता है। इस कारण तीन परिस्थितियाँ उत्पन्न होती हैं:

  • व्यवहार की जाँच करें​

  • विलंबित मिलान। कल के अनुरोधों को फिर से चलाने वाला काम उसी अंतराल को हिट करता है। पुनः लिखने के बजाय आईडी से ऑब्जेक्ट पढ़ें।
  • दिनों में कुंजी का पुन: उपयोग। दिनांक-आधारित कुंजी जैसे charge-2026-11-09 कल उसी कुंजी के पुनः प्रयास के साथ टकराती है। कुंजी में केवल दिनांक नहीं, ऑब्जेक्ट आईडी शामिल करें।

व्यवहार को सत्यापित करें​

उस कुंजी (Key) का उपयोग हर उस POST पर करें जो पैसे का निर्माण या परिवर्तन करता है:

KEY=$(uuidgen)

curl -s https://api.stripe.com/v1/payment_intents \
  -u "$STRIPE_SECRET_KEY:" \
  -H "Idempotency-Key: $KEY" \
  -d "amount=2120" -d "currency=usd" | jq -r '.id'

curl -s https://api.stripe.com/v1/payment_intents \
  -u "$STRIPE_SECRET_KEY:" \
  -H "Idempotency-Key: $KEY" \
  -d "amount=2120" -d "currency=usd" | jq -r '.id'

दोनों कमांड “pi_...” मान प्रिंट करते हैं। अब दूसरी बार कॉल करते समय “amount” को बदल दें एवं कुंजी (key) को उसी रूप में रखें। “Stripe” “idempotency_error” मान वापस करता है।

इसे कहाँ लागू करें​

प्रत्येक POST पर एक कुंजी (key) लागू करें जो पैसा बनाती है या बदलती है:

  • पेमेंटइंटेंट (PaymentIntent), रिफंड (Refund), पेआउट (Payout), या सब्सक्रिप्शन (Subscription) बनाना।
  • अधिकृत शुल्क का संग्रहण।
  • कॉलर द्वारा पुनः प्रयास (रीट्राई) किए जाने पर ग्राहक (कस्टमर) का निर्माण किया जाता है।

GET एवं DELETE पर दिए गए हेडरों को छोड़ दें। GET कुछ भी नहीं बदलता, एवं DELETE का दोहराया जाना पुनः वही परिणाम देता है।

अगले कदम​

  • त्रुटियाँ एवं पुनर्प्रयास: पुनर्प्रयासों की योजना एवं नियमों संबंधी जानकारी।
  • पैसे स्ट्राइप के माध्यम से कैसे आगे बढ़ते हैं: ऐसे अनुरोधों से बनने वाले डेटा संबंधी जानकारी।
