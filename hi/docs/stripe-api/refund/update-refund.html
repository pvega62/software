रिफंड को अपडेट करें

आप किसी भी समय रिफंड को अपडेट कर सकते हैं; हालाँकि रिफंड की राशि या गंतव्य कार्ड के विवरणों में परिवर्तन नहीं किया जा सकता।

POST https://api.stripe.com/v1/refunds/{id}

अपरिवर्तनीय वित्तीय डेटा

आप किसी भी समय रिफंड (refund) के दौरान metadata को अपडेट कर सकते हैं। हालाँकि, आप रिफंड की राशि या गंतव्य कार्ड (destination card) के विवरणों में परिवर्तन नहीं कर सकते।

उदाहरण​

  • cURL
  • Node.js
  • Python
cURL
curl -X POST https://api.stripe.com/v1/refunds/re_1Nispe2eZvKYlo2Cd31jOCgZ \
  -u "sk_test_51Mz0...:" \
  -H "Idempotency-Key: refund_meta_ticket_8821" \
  -d "metadata[internal_support_ticket]=ticket_8821" \
  -d "metadata[approved_by]=ops_manager_2"
Node.js
import Stripe from 'stripe';
const stripe = new Stripe(process.env.STRIPE_SECRET_KEY);

const refund = await stripe.refunds.update(
  're_1Nispe2eZvKYlo2Cd31jOCgZ',
  {
    metadata: {
      internal_support_ticket: 'ticket_8821',
      approved_by: 'ops_manager_2',
    },
  },
  {
    idempotencyKey: 'refund_meta_ticket_8821',
  }
);

console.log('Updated metadata:', refund.metadata);
Python
import os
import stripe

stripe.api_key = os.environ["STRIPE_SECRET_KEY"]

refund = stripe.Refund.modify(
    "re_1Nispe2eZvKYlo2Cd31jOCgZ",
    metadata={
        "internal_support_ticket": "ticket_8821",
        "approved_by": "ops_manager_2",
    },
    idempotency_key="refund_meta_ticket_8821",
)

print(f"Updated metadata: {refund.metadata}")

पैरामीटर​

पथ चर​

पैरामीटरप्रकारआवश्यकविवरण
idस्ट्रिंगआवश्यकरिफंड के लिए अद्वितीय पहचानकर्ता; इसके सामने re_ प्रत्यय होता है।

हेडर पैरामीटर​

पैरामीटरप्रकारआवश्यकविवरण
Idempotency-Keyस्ट्रिंगअनुशंसितक्लाइंट-जनरेटेड कुंजी जो पुनः प्रयासित अपडेट को सुरक्षित बनाती है। जब कुंजी एवं अनुरोध-शरीर (request body) मेल खाते हैं, तो Stripe संग्रहीत प्रतिक्रिया (stored response) को 24 घंटों तक पुनः प्रस्तुत करता है।

बॉडी पैरामीटर्स​

पैरामीटरप्रकारआवश्यकविवरण
metadataऑब्जेक्टवैकल्पिकआंतरिक संदर्भों के लिए कुंजी-मान जोड़े। किसी कुंजी को खाली स्ट्रिंग ("") पर सेट करने से वह कुंजी हट जाती है। अधिकतम 50 कुंजियाँ।
expand[]स्ट्रिंग्स का सरणीवैकल्पिकलौटाए गए ऑब्जेक्ट पर नेस्टेड एट्रिब्यूट्स (nested attributes) की पहचान करता है ताकि उन्हें इनलाइन (inline) विस्तारित किया जा सके।

प्रतिक्रियाएँ​

कोडस्थितिविवरण
200ठीक है।अपडेटेड रिफंड ऑब्जेक्ट (Updated Refund Object) वापस करता है।
400खराब अनुरोध (Bad Request)मेटाडेटा कुंजियाँ (metadata keys) वर्ण सीमा (character limits) से अधिक होने पर पैरामीटर सत्यापन विफल हो गया।
400खराब अनुरोध (Bad Request)पुनः उपयोग किया गया डेटा (Idempotency-Key), लेकिन इसमें अलग अनुरोध-शरीर (request body) है।
401अनधिकृतगायब या समाप्त हुआ गुप्त कुंजी।
404नहीं मिलास्ट्राइप (Stripe) को मेल खाने वाला रिफंड रिकॉर्ड नहीं मिला।
409संघर्षवही Idempotency-Key वाला अनुरोध अभी भी प्रक्रिया में है।

प्रतिक्रिया के विशेषताएँ​

विशेषताप्रकारविवरण
idस्ट्रिंगरिफंड का यूनिक पहचानकर्ता, re_ से प्रारंभ होता है।
objectस्ट्रिंगस्थिर पहचानकर्ता; हमेशा refund लौटाता है।
amountपूर्णांककुल रिफंड की राशि (सबसे छोटी मुद्रा इकाई में)।
metadataऑब्जेक्टइस रिकॉर्ड पर संग्रहीत कस्टम कुंजी-मान जोड़े।
statusस्ट्रिंगनिपटान की स्थिति; संभावित मान pending, requires_action, succeeded, failed, या canceled हैं।

त्रुटि प्रतिक्रियाएँ​

HTTP स्थितित्रुटि प्रकारकोडसमाधान
400invalid_request_errormetadata_key_too_longमेटाडेटा कुंजियों के नाम 40 अक्षरों से कम होने चाहिए।
404invalid_request_errorresource_missingयह सत्यापित करें कि रिफंड पहचानकर्ता वर्तमान वातावरण में मौजूद है।
400idempotency_errorकुछ नहीं; संदेश बताता है कि कुंजी किसी अन्य पैरामीटर सेट से संबंधित है।एक ही बॉडी के लिए केवल एक कुंजी का उपयोग करें; बदले गए बॉडी के लिए नई कुंजी की आवश्यकता है।
409idempotency_errorकोई परिणाम नहीं। संदेश में कहा गया है कि एक अनुरोध प्रक्रिया में है।पहले अनुरोध के पूरा होने का इंतज़ार करें, फिर उसका परिणाम पढ़ें।

400: Bad Request

Response

    "param": "metadata"

इडेम्पोटेंसी​

अपडेट को दोबारा करना सुरक्षित लग सकता है, लेकिन ऐसा नहीं है; दोबारा करने से डेटा डुप्लिकेट हो सकता है या मौजूदा डेटा ओवरराइट हो सकता है।

  • कनेक्शन टूटने से परिणाम छिप जाता है, और बिना जानकारी के दोबारा प्रयास करने से डेटा फिर से लिखा जाता है।
  • नेटवर्क में टाइमआउट होने से दो अलग-अलग मेटाडेटा वाले अनुरोध प्रक्रिया में रह जाते हैं; बाद का अनुरोध पहले वाले को ओवरराइट कर देता है, और यह पता नहीं चल पाता कि कौन-सा मान सही है।

हर अपडेट पर Idempotency-Key भेजें; स्ट्राइप प्रतिक्रिया 24 घंटों तक संग्रहीत रखता है, फिर जब कुंजी एवं बॉडी मेल खाते हैं तो उसे पुनः प्रस्तुत करता है। प्रत्येक परिवर्तन के लिए नई कुंजी बनाएँ (जैसे refund_meta_ticket_8821); नया मेटाडेटा मान का मतलब है कि नई कुंजी की आवश्यकता है।

जब पहले अनुरोध चल रहा हो, तो एंडपॉइंट (endpoint) 409 Conflict लौटाता है; पहले अनुरोध के पूरा होने का इंतज़ार करें, फिर परिणाम पढ़ें। जब एक ही कुंजी के साथ अलग बॉडी का उपयोग किया जाता है, तो एंडपॉइंट 400 एवं idempotency_error लौटाता है, क्योंकि संग्रहीत प्रतिक्रिया अब आपके अनुरोध का वर्णन नहीं करती।

संबंधित एंडपॉइंट एवं अवधारणाएँ​

  • वापसी की राशि प्राप्त करें: मौजूदा वापसी के लिए विस्तृत जानकारी देखें।
  • वापसी की राशि बनाएँ: ग्राहक के लिए नई वापसी प्रक्रिया शुरू करें।
  • विस्तार एवं मेटाडेटा: मेटाडेटा फील्डों की सीमाएँ एवं कैरेक्टर एन्कोडिंग को समझें।
