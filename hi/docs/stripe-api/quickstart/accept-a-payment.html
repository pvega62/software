कार्ड भुगतान स्वीकार करें

  • लक्षित दर्शक: वे डेवलपर जो पहली बार Stripe API के माध्यम से भुगतान कर रहे हैं।
  • पूर्वापेक्षाएँ: टेस्ट मोड में Stripe खाता, पर्यावरण में “सीक्रेट की” (secret key), एवं Node.js 18 या उससे अधिक का संस्करण।
  • लक्ष्य: कार्ड भुगतान एकत्र करें, उसकी स्थिति जानें, एवं केवल तभी ऑर्डर को पूरा करें जब सर्वर भुगतान की पुष्टि कर दे।

अंत तक, आपके पास ऐसा सर्वर एंडपॉइंट होगा जो “PaymentIntent” बनाता है, एवं ऐसा क्लाइंट जो इसे पुष्टि करता है। पूरी प्रक्रिया को चलाने में कोई लागत नहीं आएगी।

अनुरोध प्रवाह​

चरण | चलता है | प्रमाण-पत्र

PaymentIntent बनाएँ | आपका सर्वर | सीक्रेट की

स्टेजप्रमाणपत्र (Credential)
PaymentIntent बनाएँआपका सर्वरगुप्त कुंजी
कार्ड विवरण एकत्र करेंक्लाइंटप्रकाशन योग्य कुंजी (Publishable key)
भुगतान की पुष्टि करेंक्लाइंटclient_secret
परिणाम की रिपोर्ट करेंस्ट्राइप (Stripe)वेबहुक हस्ताक्षर (Webhook signature)

भुगतान वेबहुक्स का प्रबंधन अंतिम चरण को कवर करता है; यह पृष्ठ सत्यापित स्थिति पर समाप्त हो जाता है।

1. PaymentIntent बनाएँ​

सर्वर पर प्रत्येक ऑर्डर के लिए एक Intent बनाएँ। प्रतिक्रिया में client_secret शामिल होता है, जिसका उपयोग क्लाइंट भुगतान की पुष्टि करने के लिए करता है।

server.js
import express from "express";

const app = express();
app.use(express.json());

app.post("/create-payment-intent", async (req, res) => {
  const orderId = req.body.orderId;

  if (!orderId) {
    return res.status(400).json({ error: "orderId is required" });
  }

  const params = new URLSearchParams({
    amount: "2120",
    currency: "usd",
    "automatic_payment_methods[enabled]": "true",
    "metadata[order_id]": orderId,
  });

  const response = await fetch("https://api.stripe.com/v1/payment_intents", {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.STRIPE_SECRET_KEY}`,
      "Content-Type": "application/x-www-form-urlencoded",
      "Idempotency-Key": `order-${orderId}`,
    },
    body: params,
  });

  if (!response.ok) {
    const failure = await response.json();
    return res.status(response.status).json({ error: failure.error.message });
  }

  const intent = await response.json();
  res.json({ clientSecret: intent.client_secret });
});

app.listen(4242, () => console.log("Listening on port 4242"));
  • amount सबसे छोटी मुद्रा इकाई का उपयोग करता है। 2120 की फीस $21.20 है, न कि $2,120।
  • Idempotency-Key ऑर्डर आईडी का पुन: उपयोग करता है। पुनः प्रयासित अनुरोध मूल Intent को वापस करता है, नया Intent नहीं बनाता।
  • metadata[order_id] Intent को आपके ऑर्डर से जोड़ता है। वेबहुक हैंडलर इसे डेटाबेस खोज के बिना पढ़ता है।
चेतावनी

client_secret केवल एक ऑर्डर के लिए ब्राउज़र में होता है; इसे लॉग न करें, और अलग-अलग ग्राहकों के बीच पुनः उपयोग न करें।

किसी भी क्लाइंट कोड को लिखने से पहले एंडपॉइंट (endpoint) की प्रतिक्रिया की पुष्टि करें।

curl -X POST http://localhost:4242/create-payment-intent \
  -H "Content-Type: application/json" \
  -d '{"orderId":"ord_8842"}'

प्रतिक्रिया में pi_ से शुरू होने वाला clientSecret मान होता है, जिसमें _secret_ शामिल होता है।

क्लाइंट में भुगतान की पुष्टि करें।​

Stripe.js लोड करें एवं ग्राहक के कार्ड की जानकारी की पुष्टि करें। Stripe, कार्ड जानकारी का प्रसंस्करण स्वयं करता है; इसलिए कार्ड नंबर कभी भी आपके सर्वर तक नहीं पहुँचता।

checkout.html
<div id="card-element"></div>
<script src="https://js.stripe.com/v3/"></script>
<script>
  const stripe = Stripe("pk_test_REPLACE_WITH_YOUR_KEY");
  const elements = stripe.elements();
  const cardElement = elements.create("card");
  cardElement.mount("#card-element");

  async function pay() {
    const response = await fetch("/create-payment-intent", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ orderId: "ord_8842" }),
    });

    const { clientSecret } = await response.json();

    const result = await stripe.confirmCardPayment(clientSecret, {
      payment_method: { card: cardElement },
    });

    if (result.error) {
      showDecline(result.error.message, result.error.decline_code);
      return;
    }

    if (result.paymentIntent.status === "succeeded") {
      showConfirmation();
    } else {
      showPending();
    }
  }
</script>

status फ़ील्ड यह तय करता है कि कौन-सी शाखा चलेगी। succeeded स्थिति का अर्थ है कि जारीकर्ता ने भुगतान स्वीकृत कर दिया है। requires_action स्थिति का अर्थ है कि ग्राहक को अभी भी एक चुनौती पूरी करनी है, और Stripe.js उसे confirmCardPayment के दौरान खोलता है।

सर्वर पर ऑर्डर की स्थिति की जाँच करें।​

क्लाइंट परिणाम बताता है, लेकिन ब्राउज़र झूठ भी बोल सकता है। कोई भी डेवलपर टूल्स खोलकर नकली स्टेटस भेज सकता है। सामान भेजने से पहले स्ट्राइप (Stripe) से उद्देश्य पूछ लें।

server.js
app.get("/orders/:orderId/status", async (req, res) => {
  const intentId = await lookupIntentId(req.params.orderId);

  const response = await fetch(
    `https://api.stripe.com/v1/payment_intents/${intentId}`,
    { headers: { Authorization: `Bearer ${process.env.STRIPE_SECRET_KEY}` } }
  );

  const intent = await response.json();

  res.json({
    fulfilled: intent.status === "succeeded",
    status: intent.status,
    amountReceived: intent.amount_received,
  });
});

amount_received की तुलना amount से भी करें। आंशिक जानकारी के कारण amount_received, amount के नीचे रह जाता है। यह अंतर बताता है कि कितना रिफंड किया जाना चाहिए या कितना जारी किया जाना चाहिए।

सुझाव

प्रत्येक ऑर्डर के लिए परिणाम को कुछ सेकंडों के लिए कैश (cache) में संग्रहीत करें। तेज़ चेकआउट पेज पर प्रति सेकंड API को कई बार अनुरोध किए जा सकते हैं।

केवल पुष्टि की गई स्थिति पर ही ऑर्डर पूरा करें।​

payment_intent.succeeded वेबफ़ंक्शन (webhook) ब्राउज़र की तुलना में अधिक सुरक्षित तरीके से ऑर्डर पूरा करने में मदद करता है; यह एक बार ही आता है, भले ही ग्राहक टैब बंद कर दे, एवं इसमें प्रमाणीय हस्ताक्षर (verifiable signature) भी शामिल होता है।

fulfillment.js
async function handleSucceeded(intent) {
  const orderId = intent.metadata.order_id;

  if (!orderId) {
    console.warn("No order_id on intent", intent.id);
    return;
  }

  if (intent.amount_received < intent.amount) {
    console.warn("Underpaid intent", intent.id);
    return;
  }

  await markOrderPaid(orderId, intent.id);
}

ऑर्डर आईडी (order ID), चरण 1 में सेट किए गए मेटाडेटा (metadata) से प्राप्त होती है; इससे बाद में ऑर्डर की जानकारी खोजने की आवश्यकता नहीं पड़ती।

असफल भुगतान प्रक्रियाओं (जैसे “डिक्लाइन” – decline) का प्रबंधन करें।​

अस्वीकृत कार्ड के कारण लेन-देन का प्रयास (intent) requires_payment_method में ही रह जाता है। राशि एवं ग्राहक दोनों अपरिवर्तित रहते हैं; इसलिए ग्राहक उसी इरादे के साथ किसी अन्य कार्ड का उपयोग करके पुनः प्रयास कर सकता है।

client.js
function showDecline(message, code) {
  const copy = {
    insufficient_funds: "That card can't cover this order. Try another card.",
    expired_card: "That card has expired. Add a new one.",
    incorrect_cvc: "The security code doesn't match. Check it and try again.",
  };

  showMessage(copy[code] ?? "That card was declined. Try another payment method.");
}

decline_code को अपनी स्वयं की प्रति (कॉपी) से जोड़ें; मूल message को न दिखाएँ। मूल टेक्स्ट कार्ड जारी करने वाली कंपनी की जानकारी देता है, जो चेकआउट फॉर्म में उपयुक्त नहीं है।

चारों संभावित परिणामों (outcomes) का परीक्षण करें।​

परीक्षण मोड में प्रत्येक कार्ड नंबर का परीक्षण करें एवं उसका व्यवहार सुनिश्चित करें।

कार्डअपेक्षित परिणामजाँचने योग्य बात (What to verify)
4242 4242 4242 4242भुगतान सफल हो जाता है।स्थिति succeeded पर पहुँच जाती है, एवं ऑर्डर “पेड” (paid) के रूप में दर्ज हो जाता है।
4000 0000 0000 9995अपर्याप्त धन के कारण अस्वीकार किया गया।अस्वीकृति का संदेश प्रदर्शित होता है, एवं इच्छा अभी भी खुली हुई है।
4000 0025 0000 3155प्रमाणीकरण आवश्यक है।चुनौती शुरू हो जाती है, और उसके बाद प्रक्रिया पुनः जारी रहती है।
4000 0000 0000 0002सामान्य असफलता।बैकअप प्रति (fallback copy) प्रदर्शित होती है, एवं ऑर्डर अभी भी अदा नहीं किया गया है।

फिर उसी “आइडेम्पोटेंसी कुंजी” (idempotency key) के साथ पुनः पुष्टि कॉल (confirm call) करें। स्ट्राइप (Stripe) मूल इरादे (original intent) को वापस करता है, जिससे शुल्क की राशि एक ही बार ली जाती है।

लाइव हो जाएँ​

एक ही बार में टेस्ट मोड से लाइव मोड में स्थानांतरित करें।

  1. प्रोडक्शन सीक्रेट स्टोर में टेस्ट कुंजी जोड़े को लाइव कुंजियों से बदल दें।
  2. उत्पादन वेबफंक (production webhook) एंडपॉइंट को पंजीकृत करें एवं हस्ताक्षरण गुप्त कोड (signing secret) संग्रहीत करें।
  3. एक कम-मूल्य वाला लाइव शुल्क (low-value live charge) भेजें एवं उसे वापस कर दें।
  4. भुगतान की योजना एवं फाइल में उल्लिखित बैंक खाते (bank account) की पुष्टि करें।
  5. 5xx प्रतिक्रियाओं एवं विफल वेबफंकों (failed webhooks) के लिए अलर्ट सेट करें।

अगले चरण​

  • भुगतान वेबफंकों को संभालें ताकि सत्यापित इवेंटों से ऑर्डर पूरे हो सकें।
  • आइडेम्पोटेंट अनुरोध (Idempotent requests) का उपयोग रिट्राय प्रक्रियाओं के लिए करें।
  • त्रुटियाँ एवं पुनरावृत्तियाँ (Errors and retries) को डिक्लाइन कोडों (decline codes) एवं बैकऑफ नीतियों के संदर्भ में देखें।
  • पूरी पैरामीटर सूची के लिए “पेमेंट इंटेंट” (Payment Intent) बनाएँ।
