परिचय

मेरे तकनीकी लेखन पोर्टफोलियो में आपका स्वागत है!​

यह साइट मेरे तकनीकी लेखन पोर्टफोलियो से सॉफ्टवेयर दस्तावेज़ीकरण नमूने एकत्र करती है। Docusaurus प्रत्येक पृष्ठ को मार्कअप एवं MDX स्रोत से बनाता है। इस सेट में डेवलपर गाइड, हैंड-राइटेड एवं अनुबंध-आधारित API संदर्भ, तथा उत्पाद दस्तावेज़ीकरण शामिल है। प्रत्येक नमूना उसके पीछे की कार्यप्रणाली (वर्कफ्लो) को भी दिखाता है।

पोर्टफोलियो नेविगेशन​

नमूनों को डिलीवरेबल प्रकार एवं डोमेन के आधार पर देखें:

डेवलपर एवं सिस्टम गाइड​

  • गूगल क्रोम में थीम इंस्टॉल एवं लागू करना: इंटरैक्टिव यूआई टैब एवं रिस्पॉन्सिव लेआउट के साथ ब्राउज़र कस्टमाइज़ेशन का चरण-दर-चरण विवरण।
  • माइक्रोसॉफ्ट वर्ड से गिटहब विकी तक का वर्कफ्लो (Writage के साथ): वर्ड में मार्कअप लिखने एवं गिटहब डेस्कटॉप के साथ विकी संशोधन करने का गाइड।
  • पोस्टमैन का उपयोग करके स्ट्राइप API से कनेक्ट होना: पोस्टमैन में प्रमाणीकरण एवं API अनुरोध करने का गाइड।
  • पोस्टमैन मॉक सर्वर बनाना: वेबफिक्स एकीकरण एवं API स्कीमाओं का परीक्षण करने हेतु मॉक सर्वर कॉन्फ़िगर करने का व्यावहारिक ट्यूटोरियल।
  • क्लाउड ऐप के लॉग्स को पाइपलाइन में भेजें: क्लाउड ऐप के डेटा को इनपुट करने एवं उसे फिल्टर करने हेतु एक प्रक्रिया।
  • ऑब्जेक्ट डेटा कैसे प्राप्त करें: Sui TypeScript SDK का उपयोग करके डेटा प्राप्त करने संबंधी जानकारी।
  • ट्रांजैक्शन भेजने हेतु “राइट ऑपरेशन” का उपयोग: प्रोग्रामेबल ट्रांजैक्शनों को साइन करने एवं प्रसारित करने हेतु दिशानिर्देश।

Sweepy नौकरी खोज दस्तावेज़ीकरण​

Sweepy, आवेदकों की जानकारी को खोजता है एवं प्रत्येक पोस्टिंग को उनके रिज्यूमे के आधार पर रैंक करता है; यह ओपन-सोर्स टूल है। Sweepy: आवेदकों की जानकारी एकत्र करने एवं उनके रिज्यूमे का मूल्यांकन करने हेतु एक पायथन टूल; ओपन सोर्स है।

आरंभ करें​

  • Sweepy के बारे में: Sweepy का कार्य, पाइपलाइन के चरण, एवं रिज्यूमे के मूल्यांकन की प्रक्रिया।
  • Sweepy की स्थापना: विंडोज, मैकओएस, एवं लिनक्स पर Sweepy को स्थापित करने की विधि।
  • Sweepy को सेटअप करना: सेटअप विजार्ड या YAML फ़ाइल का उपयोग करके Sweepy को सेटअप करना।
  • अपना पहला “स्वीप” (sweep) चलाएँ: प्रोफ़ाइल बनाने से लेकर प्रगति की जानकारी प्राप्त करने तक की पूरी प्रक्रिया।

परिणाम पढ़ें​

  • अपने परिणामों को समझना: PDF कार्डों की संरचना का विश्लेषण करता है; प्रतिशतों की तुलना करता है; एप्लिकेशनों के प्रमाणपत्र (badges) दिखाता है; एवं CSV फ़ाइलों में ट्रैकिंग संबंधी कॉलमों को प्रदर्शित करता है।
  • रिज्यूमे एवं मैच स्कोर: पार्सर के लिए रिज्यूमे फॉर्मेटिंग एवं रिज्यूमे से मैच प्रतिशत तक की प्रक्रिया का वर्णन है।
  • स्वीपी (Sweepy) कैसे रिज्यूमे का मूल्यांकन करता है: प्रत्येक प्रतिशत के पीछे के शब्दावली मेल की व्याख्या एवं ऐसी चीजों का उल्लेख जिन्हें स्कोर माप नहीं सकता।

संदर्भ एवं एकीकरण​

  • स्वीपी कमांड एवं कॉन्फ़िगरेशन संदर्भ: सभी कमांडों, प्रोफ़ाइल सेटिंगों एवं समर्थित नौकरी स्रोतों की सूची है।
  • स्वीपी MCP एकीकरण: बिल्ट-इन MCP सर्वर को Antigravity, Claude Desktop या VS Code से जोड़ने का विवरण है।
  • स्वीपी MCP टूल संदर्भ: सभी तेरह टूलों, उनके पैरामीटरों एवं उनके रिटर्न पेलोड का विवरण है।

स्वीपी दस्तावेज़ीकरण इंडेक्स: इंस्टॉलेशन, पहला स्कैन, डेवलपर नोट्स एवं यूएक्स लेखन केस स्टडी सहित सभी पृष्ठों का संग्रह है।

API संदर्भ​

  • स्ट्राइप API: भुगतान इंफ्रास्ट्रक्चर संबंधी विस्तृत जानकारी; प्रत्येक एंडपॉइंट के लिए अलग पृष्ठ, साथ ही संबंधित अवधारणाओं एवं शुरुआती जानकारी के पृष्ठ।
    • बैलेंस API
    • पेमेंट इंटेंट API
    • रिफंड API
  • Blüdhaven Pets API: एंटरप्राइज़ के साथी जानवरों का प्रबंधन, नगरपालिका लाइसेंसिंग, एवं खुदरा इन्वेंट्री; एक OpenAPI 3.1 अनुबंध के आधार पर दस्तावेजीकृत।
    • इंटरैक्टिव API संदर्भ
    • डोमेन मॉडल
    • प्रमाणीकरण एवं दायरे
    • त्रुटियाँ एवं समस्या विवरण
    • पेजिनेशन
    • दर सीमाएँ एवं बैकऑफ़
    • संस्करणन एवं परिवर्तन नीति
    • वेबहुक्स एवं हस्ताक्षर
    • परीक्षण अनुरोध
    • समस्या निवारण
    • गोद लेने संबंधी प्रक्रियाएँ एवं समानांतरता
    • शुल्क एवं रिफंड
    • अनुपालन एवं लाइसेंसिंग
  • डेटाडॉग लॉग इनगेस्टिशन एपीआई: बैच टेलीमेट्री डेटा जमा करने हेतु स्ट्रीमिंग एपीआई।
  • सुई (Sui) टाइपस्क्रिप्ट एसडीके (SDK) संदर्भ:
    • SuiClient.getObject
    • SuiClient.multiGetObjects
    • SuiClient.getOwnedObjects

आर्किटेक्चर एवं सैद्धांतिक दस्तावेजीकरण​

  • स्ट्राइप एपीआई का परिचय: भुगतान चक्र, कुंजियाँ, पुनरावृत्तियाँ, पृष्ठ-निर्माण (पेजिनेशन), एवं संस्करण-निर्धारण (वर्जनिंग) का सैद्धांतिक अवलोकन।
  • स्ट्राइप एपीआई की अवधारणाएँ: पैसे स्ट्राइप के माध्यम से कैसे आगे बढ़ते हैं; प्रत्येक एंडपॉइंट (endpoint) का साझा व्यवहार – प्रमाणीकरण (authentication), आइडेम्पोटेंस (idempotency), त्रुटियाँ (errors), पृष्ठ-निर्माण, संस्करण-निर्धारण, एवं परीक्षण मोड (test mode)।
  • स्ट्राइप एपीआई क्विकस्टार्ट: कार्ड भुगतान स्वीकार करने एवं सत्यापित वेबफिक (webhook) के माध्यम से ऑर्डर पूरा करने की प्रक्रिया।
  • इवेंट स्ट्रीम्स एवं ऑब्जर्वेबिलिटी पाइपलाइन्स: स्ट्रीम प्रोसेसिंग (stream processing), एज रूटिंग (edge routing), एवं डेटा रूपांतरण (data transformation) का आर्किटेक्चरल अवलोकन।
  • क्लाउड एवं एआई (AI) के लिए समानांतर अवलोकन क्षमता (Parallel Observability for Cloud and AI): एंटरप्राइज़ सिस्टमों के लॉग रूटिंग मॉडलों की तुलना करने वाला आर्किटेक्चरल गाइड।
  • The SuiClient: यह बताता है कि वितरित RPC क्लाइंट्स स्टेट क्वेरीज़ (state queries) को कैसे निर्देशित करते हैं।

कमिट संदेश एवं पुल रिक्वेस्ट​

  • F-ऑर्डर्ड सरणियों (F-ordered Arrays) संबंधी प्रॉब्लेमों का समाधान: एक लेखन अभ्यास से प्राप्त कमिट संदेश एवं पुल रिक्वेस्ट का विवरण; संबंधित पैच भी प्रदान किया गया है।
  • JAX के तहत ‘ak.mean’ को डिफरेंसिएबल (differentiable) बनाना (Making ‘ak.mean’ Differentiable under JAX): एक लेखन अभ्यास से प्राप्त कमिट संदेश एवं पुल रिक्वेस्ट का विवरण; संबंधित पैच भी प्रदान किया गया है।

केस स्टडीज़​

  • ‘Artie’, एक एआई दस्तावेज़ीकरण सहायक (Designing Artie, an AI Documentation Assistant): प्रॉम्प्ट इंजीनियरिंग (Prompt Engineering), एलएलएम (LLM) सुरक्षा (LLM Security), एवं आरएजी (RAG) पुनर्प्राप्ति आर्किटेक्चर (RAG Retrieval Architecture) का विश्लेषण।
  • जब “92%” का अलग-अलग अर्थ होता है (When “92%” Means Different Things): ‘Sweepy’ टर्मिनल इंटरफ़ेस में स्कोर लेबलों (Score Labels), स्टेट लाइनों (Status Lines), एवं प्रॉम्प्ट सुझावों संबंधी यूएक्स (UX) लेखन अभ्यास।

इन दस्तावेज़ों के मूल मार्कडाउन (Markdown) स्रोतों को देखने हेतु, गिटहब रिपॉजिटरी (GitHub Repository) पर जाएँ।

“डॉक्स-जैसा कोड (Docs-as-Code)” वर्कफ्लो​

  • वीएस कोड (VS Code) एवं एंटीग्रेविटी (Antigravity) का उपयोग करके मार्कडाउन/एमडीएक्स में लेखन।
  • वाल (Vale) का उपयोग करके पाठ एवं शैली की जाँच.
  • इंटरनेशनलाइजेशन एवं अनुवाद के लिए DeepL एवं Lara का उपयोग किया जाता है।
  • सिस्टम आर्किटेक्चर डायग्रामिंग के लिए Mermaid का उपयोग किया जाता है।
  • प्रत्येक रिलीज़ के हिस्से के रूप में, कमांड-लाइन टूल एवं उसके MCP सर्वर के लिए उत्पाद दस्तावेज़ीकरण तैयार किए जाते हैं।
  • गिट (Git) एवं गिटहब (GitHub) का उपयोग संस्करण नियंत्रण एवं सहयोगात्मक कोड समीक्षा हेतु किया जाता है।
  • पोस्टमैन (Postman) एवं स्वैगर/ओपनएपीआई (Swagger/OpenAPI) का उपयोग API की जाँच एवं प्रमाणीकरण हेतु किया जाता है।
  • ओपनएपीआई 3.1 के अनुसार कॉन्ट्रैक्ट तैयार किए जाते हैं, एवं उन्हें स्केलर (Scalar) के माध्यम से प्रस्तुत किया जाता है।
  • डॉक्युसैरस (Docusaurus) का उपयोग निरंतर डिप्लॉयमेंट हेतु किया जाता है।

तकनीकी स्टैक​

  • डॉक्युसैरस – डॉक्युसैरस – स्थैतिक वेबसाइटें, नेविगेशन साइडबार, एवं स्थानीयकृत संस्करण तैयार करता है।
  • वीएस कोड – मार्कडाउन एवं MDX लेखन हेतु प्राथमिक संपादन उपकरण है।
  • पोस्टमैन – API एंडपॉइंट्स की प्रमाणीकरण करता है, एवं अनुरोध/प्रतिक्रिया उदाहरण तैयार करता है।
  • ओपनएपीआई 3.1 एवं स्केलर – ब्लूडहेवन पेट्स (Blüdhaven Pets) के कॉन्ट्रैक्ट को परिभाषित करते हैं, एवं उन्हें इंटरैक्टिव रूप में प्रस्तुत करते हैं।
  • OpenAPI 3.1 एवं स्केलर (OpenAPI 3.1 and Scalar): ब्लूडहेवन पेट्स (Blüdhaven Pets) के अनुबंध (contract) को परिभाषित करता है, एवं इसे एक इंटरैक्टिव (interactive) तीन-पैन (three-pane) संदर्भ (reference) के रूप में प्रस्तुत करता है।
  • Vale: तकनीकी दस्तावेज़ों की जाँच करता है ताकि गूगल डेवलपर दस्तावेज़ीकरण दिशानिर्देशों (Google Developer Documentation Guidelines) का पालन हो सके।
  • Git एवं GitHub: शाखाओं में हुए परिवर्तनों का ट्रैक रखता है एवं साइट को अपडेट करता है।
  • Mermaid: फ्लोचार्ट (flowcharts) एवं डेटा पाइपलाइन डायग्राम (data pipeline diagrams) बनाता है।
  • Python एवं MCP: “Sweepy” स्वीप इंजन (sweep engine) चलाता है, एवं उस उपकरण का सर्वर जो इसे एआई सहायकों (AI assistants) से जोड़ता है।
  • DeepL एवं Lara: दस्तावेज़ों का अन्य भाषाओं में अनुवाद स्वचालित रूप से करते हैं।

प्रत्येक पृष्ठ का एक Markdown या MDX फ़ाइल है, जो उसी रिपॉजिटरी (repository) में है; प्रस्तुत आउटपुट की तुलना उसी फ़ाइल के मूल पाठ से की जाती है।

प्रत्येक नमूना (sample) अनुसंधान, मसौदा तैयारी, परीक्षण, समीक्षा एवं प्रकाशन की प्रक्रिया का पालन करता है।
