प्रोफ़ाइल कॉन्फ़िगरेशन संदर्भ

यह पृष्ठ Sweepy प्रोफ़ाइल द्वारा स्वीकृत प्रत्येक सेटिंग की सूची प्रदान करता है; प्रोफ़ाइल संपादित करते समय इसे खुला रखें। मार्गदर्शित विवरण के लिए Sweepy की सेटअप प्रक्रिया देखें।

प्रोफ़ाइल कहाँ संग्रहीत होती हैं?​

Sweepy, आपकी Sweepy डायरेक्टरी के अंदर की profiles/ फ़ोल्डर से प्रोफ़ाइलें पढ़ता है। प्रत्येक प्रोफ़ाइल YAML प्रारूप में होती है, जो इंडेंटेशन एवं कॉलनों द्वारा संगठित होती है। इसे Notepad, VS Code या किसी अन्य टेक्स्ट एडिटर में खोलें।

config.sample.yaml से या किसी पूर्वनिर्धारित मान (जैसे profiles/paralegal_nyc.yaml) से शुरू करें। एक टेम्पलेट की कॉपी लें, उसका नाम बदलें, और उसमें मौजूद मान संपादित करें।

Terminal
copy config.sample.yaml profiles\my_search.yaml
notepad profiles\my_search.yaml

प्रोफ़ाइल में आपकी समस्त कॉन्फ़िगरेशन जानकारी होती है; जितनी चाहें प्रोफ़ाइलें बनाएँ (प्रत्येक शहर/पद के लिए एक)। Sweepy, प्रोफ़ाइल के अलावा अन्य जगहों (डिस्कवरी कैश, हिस्ट्री डेटाबेस आदि) में भी प्रोफ़ाइल जानकारी संग्रहीत रखता है।

Terminal
sweepy --profile profiles/my_search.yaml
नोट

एक प्रोफ़ाइल में आपकी समस्त कॉन्फ़िगरेशन जानकारी संग्रहीत होती है। आप जितने चाहें प्रोफ़ाइल बना सकते हैं – प्रत्येक शहर या भूमिका-समूह के लिए एक प्रोफ़ाइल। Sweepy, प्रोफ़ाइल के बाहर “स्वीप स्टेट” (sweep state) को “डिस्कवरी कैश” (discovery cache), “हिस्ट्री डेटाबेस” (history database), एवं फ़ोल्डरों logs/ एवं results/ में रखता है।

सावधानी

अंतर (स्पेस) से इंडेंट करें, कभी भी टैब से नहीं। YAML टैब को अस्वीकार करता है, और एक भी अकेला टैब पूरे प्रोफ़ाइल को अपठनीय बना देता है।

पूर्ण प्रोफ़ाइल उदाहरण​

नीचे दिया गया उदाहरण एलेक्स का पूरा प्रोफाइल दिखाता है। वे पंक्तियाँ जो # से शुरू होती हैं, कमेंट के रूप में कार्य करती हैं, और स्वीपी (Sweepy) उन्हें नजरअंदाज कर देता है:

profiles/paralegal_nyc.yaml
# ─────────────────────────────────────────────────
# Sweepy — Alex's Paralegal Profile (New York City)
# ─────────────────────────────────────────────────

# Your name. It appears in the PDF report header.
name: "Alex Rivera"

# Set true to write rotating debug logs under logs/.
debug: false

# ─── Job search ───────────────────────────────────
search:
  # Every title Sweepy searches at the same time.
  titles:
    - "Paralegal"
    - "Legal Assistant"
    - "Litigation Support Specialist"
    - "Legal Secretary"

  # Your target market.
  location: "New York, NY"

  # true keeps remote roles only. false keeps remote, hybrid, and on-site roles.
  remote_only: false

  # false removes hybrid roles from every report.
  include_hybrid: true

  # Annual salary floor. Use 0 to skip salary filtering.
  min_salary: 65000

  # true reads pay from the posting text when a board omits structured pay.
  salary_from_description: true

# ─── Resume ───────────────────────────────────────
resume:
  # Path to a PDF or DOCX resume. Forward slashes work on Windows.
  path: "Alex_Rivera_Resume.pdf"

  # Terms that carry the most weight when Sweepy scores a posting.
  must_have_skills:
    - "Westlaw"
    - "LexisNexis"
    - "e-discovery"
    - "Contract Review"
    - "Legal Research"

  # 1.0 is standard. Raise it to reward exact skill matches.
  keywords_weight: 1.5

  # Interchangeable terms. Sweepy matches every member of a group either way.
  synonyms:
    - ["e-discovery", "ediscovery", "electronic discovery"]
    - ["legal research", "case law research"]
    - ["docketing", "case calendaring"]
    - ["legal assistant", "legal secretary"]
    - ["contract review", "contract analysis", "agreement review"]

  # Optional: one resume per role family. Sweepy picks the best fit for each posting.
  tracks:
    - name: "Paralegal Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Paralegal.pdf"
      color: "#1D4ED8"
      route_keywords: ["paralegal", "litigation", "e-discovery"]
    - name: "Legal Assistant Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Legal_Assistant.pdf"
      color: "#7E22CE"
      route_keywords: ["legal assistant", "legal secretary", "scheduling"]

# ─── Platforms ────────────────────────────────────
platforms:
  greenhouse: true
  ashby: true
  lever: true
  workable: true
  aggregators: false

  # Extra ATS domains. Sweepy labels matching postings with this name.
  custom:
    - name: "SmartRecruiters"
      domain: "smartrecruiters.com"
      enabled: true
    - name: "Breezy HR"
      domain: "breezy.hr"
      enabled: true

# ─── Sources ──────────────────────────────────────
sources:
  jobspy:
    linkedin: true
    indeed: true
    glassdoor: true
    zip_recruiter: true

  # Leave a list empty to fall back to the seed lists in data/sources/.
  ashby:
    orgs:
      - "crosby"
      - "normlaw"
      - "hargrove-firm"
      - "lawhive"
  workable:
    slugs:
      - "shegerianand-associates-1"
      - "harper-james"
      - "legalvision"
  builtinnyc:
    enabled: true
    categories:
      - "jobs/legal"
      - "jobs/legal/search/paralegal"

# ─── Cache and history ────────────────────────────
cache:
  enabled: true
  ttl_seconds: 3600       # reuse discovery results for an hour

history:
  enabled: true
  retention_days: 4       # hide a reported posting for four days
  match: "url+role"       # "url" matches only an identical posting address
  path: null              # null uses ~/.sweepy/history.db

orchestrator:
  timeout_per_source_seconds: 180
  circuit_breaker:
    failure_threshold: 5
    cooldown_seconds: 30

# ─── Report layout ────────────────────────────────
report:
  style: "cards"          # "cards" (default) or "legacy"
  cards_per_page: 6       # cards on each PDF page
  max_cards: 24           # 0 or less shows every match
  destinations: []        # extra folders for a copy of the PDF
  assessment: "agent"     # "keyword" accepts reports without agent judgments

# ─── Exports ──────────────────────────────────────
export:
  format: "pdf,csv,json"  # add "png" for page images
  output_dir: "results"
  tracking: true          # job-tracking columns in the CSV
  description_chars: 1000 # posting excerpt length in the CSV and JSON
  timezone: "local"       # clock behind the report filename stamp

प्रत्येक सेटिंग​

यदि आप कोई सेटिंग छोड़ देते हैं, तो Sweepy नीचे दिए गए डिफ़ॉल्ट मानों का उपयोग करता है। Sweepy को अभी भी search.titles, search.location, और resume.path की आवश्यकता है ताकि उपयोगी परिणाम प्राप्त किए जा सकें।

अनुभागकुंजीआवश्यकडिफ़ॉल्टविवरण
शीर्ष स्तरnameनहीं"Job Seeker"आपका नाम। पीडीएफ रिपोर्ट हेडर में दिखाई देता है।
शीर्ष स्तरdebugनहींfalsetrue को logs/ में रोटेटिंग डीबग लॉग लिखने के लिए सेट करें।
searchtitlesहाँ[]वे नौकरी के शीर्षक जिन्हें आप लक्षित करते हैं। Sweepy एक साथ हर शीर्षक की खोज करता है।
searchlocationनहीं"""City, State" को सेट करके केवल दूरस्थ पदों को शामिल करें।
searchremote_onlyनहींfalse“Set true” को केवल रिमोट भूमिकाओं (remote roles) के लिए सेट करें।

searchmin_salaryनहीं0वार्षिक वेतन की न्यूनतम सीमा। 0 फ़िल्टर को निष्क्रिय कर देता है।
searchsalary_from_descriptionनहींtrueजब कोई बोर्ड संरचित वेतन जानकारी (structured pay) प्रकाशित नहीं करता है, तो वेतन सीमाएँ (pay ranges) पोस्टिंग टेक्स्ट से पढ़ी जाती हैं।
resumepathहाँ""आपके रिज़्यूमे की PDF या Word फ़ाइल का पथ। Sweepy उस पाठ को स्कोरिंग के लिए पढ़ता है, और MCP get_jobs उपकरण उस पाठ को आपके सहायक को भेज देता है।
resumemust_have_skillsनहीं[]वे शब्द जिन्हें सबसे अधिक अंक मिलते हैं।
resumekeywords_weightनहीं1.0कौशल-मेल वाले पदों के लिए गुणाकार। उच्च मानों को अधिक इनाम मिलता है।
resumesynonymsनहीं[]परस्पर-प्रतिस्थापनीय शब्दों के समूह। रिज्यूमे सिंनॉनिम्स देखें।
resumetracksनहीं[]प्रत्येक भूमिका-परिवार के लिए एक ही रिज्यूमे। रिज्यूमे ट्रैक्स देखें।
resume.tracks[]nameहाँन/उपलब्धयह लेबल रिपोर्ट कार्ड पर एवं ट्रैक-बैज में दिखाया जाता है।
resume.tracks[]pathहाँन/उपलब्धउस ट्रैक के रिज्यूमे-PDF या DOCX फ़ाइल का पथ।
resume.tracks[]colorनहीं#1D4ED8बैज का रंग हेक्स-कोड या रंग-नाम (जैसे navy) के रूप में।
resume.tracks[]route_keywordsनहीं[]ऐसे कीवर्ड जो किसी पद को इस ट्रैक से जोड़ते हैं।

sourcesenabledनहीं["jobspy", "ats"]चलाने योग्य इंजन। प्रत्येक इंजन को इंस्टॉल करने के बाद hirehunt, openroles, jobdrop, या apify जोड़ें। स्रोत एवं प्लेटफॉर्म देखें।
sourcesjobspy.sitesनहीं["linkedin", "indeed", "glassdoor", "zip_recruiter"]“JobSpy” बोर्डों को सूची के रूप में प्रदर्शित करें। ये “jobspy.linkedin” शैली के बूलियन की तुलना में प्राथमिकता रखते हैं।
sourcesjobspy.fetch_descriptionsनहींtrueस्कोरिंग हेतु पूरा पोस्टिंग पाठ प्राप्त करें। कम स्कोर वाली पोस्टिंगों के लिए “false” का उपयोग करें।
sourcesjobspy.proxiesनहीं[]“Proxy” लक्ष्य “user:pass@host:port” के रूप में लिखे जाते हैं। “Proxy” क्रेडेंशियल आपके कंप्यूटर पर ही रहते हैं।
sourcesjobspy.user_agentनहींnull“JobSpy” अनुरोधों हेतु उपयोग किया जाने वाला यूजर एजेंट (user agent)। डिफ़ॉल्ट रूप से “Chrome” का मान ही उपयोग किया जाता है।
cacheenabledनहींtrueअलग-अलग स्कैनों के बीच परिणामों का पुनः उपयोग करें।
cachettl_secondsनहीं3600“Sweepy” किसी कैश्ड परिणाम का पुनः उपयोग करता है।

historyenabledनहींtrueउन पोस्टिंग्स को छिपाएँ जिनकी रिपोर्ट पहले ही की जा चुकी है।
historyretention_daysनहीं4“Sweepy”, रिपोर्ट की गई पोस्टिंग को उसके फिर से प्रकाशित होने से पहले ही छिपा देता है।
historymatchनहीं"url+role"url केवल एक ही पोस्टिंग पते से मेल खाता है।

orchestratortimeout_per_source_secondsनहीं180“Sweepy” इसे रोकने से पहले एक स्रोत कुछ सेकंड तक चल सकता है।
orchestratorcircuit_breaker.failure_thresholdनहीं5“Sweepy” उस स्रोत को छोड़ देता है यदि लगातार विफलताएँ होती हैं।
orchestratorcircuit_breaker.cooldown_secondsनहीं30“Sweepy” द्वारा किसी छोड़े गए स्रोत (source) को पुनः प्रयास करने से पहले प्रतीक्षित समय (seconds)।
reportstyleनहीं"cards"रिपोर्ट लेआउट: cards या legacy.

exportformatनहीं"pdf,csv"pdf, csv, json, और png का कोई भी मिश्रण, अल्पविराम से अलग किया गया।
exportoutput_dirनहीं"results"आपकी रिपोर्ट फ़ाइलों के लिए एक फ़ोल्डर। Sweepy इसे तब बनाता है जब यह अनुपस्थित हो।

exporttimezoneनहीं"local"प्रत्येक रिपोर्ट फ़ाइल के नाम में तारीख एवं समय के पीछे “क्लॉक” (Clock) शब्द होता है। local मशीन के अनुसार काम करता है, UTC “समन्वित वैश्विक समय” (Coordinated Universal Time) को दर्शाता है; IANA जैसा कि America/New_York नाम उसी टाइमज़ोन को दर्शाता है, एवं -05:00 ऐसा ऑफसेट (Offset) है जो टाइमज़ोन डेटाबेस के बिना काम करता है। विंडोज़ पर, IANA नामों के लिए tzdata पैकेज़ की आवश्यकता होती है, जिसे Sweepy अपनी आवश्यकताओं के साथ इंस्टॉल कर देता है।
सुझाव

स्रोतों एवं प्लेटफॉर्म सपोर्ट के विवरण Sources and Platforms में उपलब्ध हैं। वहाँ दिए गए नियम बताते हैं कि platforms.* एवं sources.* कैसे एक साथ काम करते हैं। वैकल्पिक ब्लॉक्स hirehunt, openroles, jobdrop, एवं apify भी sources के अंतर्गत हैं; कमांड संदर्भ में उनकी सेटिंग्स सूचीबद्ध हैं।

रिज़्यूमे ट्रैक​

ट्रैक एक नामित रिज़्यूमे है। जब आप दो अलग-अलग भूमिकाओं/पदनामों को लक्षित कर रहे हों और प्रत्येक पोस्टिंग को सही दस्तावेज़ के विरुद्ध स्कोर करना चाहें, तो ट्रैकों का उपयोग करें।

profiles/paralegal_nyc.yaml
resume:
  tracks:
    - name: "Paralegal Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Paralegal.pdf"
      color: "#1D4ED8"
      route_keywords: ["paralegal", "litigation", "e-discovery"]
    - name: "Legal Assistant Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Legal_Assistant.pdf"
      color: "#7E22CE"
      route_keywords: ["legal assistant", "legal secretary", "scheduling"]

Sweepy, पोस्टिंगों को कीवर्डों के ओवरलैप के आधार पर आवंटित करता है। यह पोस्टिंग के शीर्षक एवं विवरण की तुलना प्रत्येक ट्रैक के नाम से करता है; सबसे अधिक मेल खाने वाले ट्रैक को पोस्टिंग आवंटित की जाती है। यदि दो ट्रैक बराबर हों, तो पहले ट्रैक का ही उपयोग किया जाता है।

  • name ट्रैक को लेबल करता है। रिपोर्ट कार्ड में यह लेबल दिखता है, इसलिए एक या दो शब्द लिखें।
  • path उस ट्रैक के रिज़्यूमे की PDF या DOCX फ़ाइल की ओर इशारा करता है।
  • color बैज (badge) का रंग निर्धारित करता है। हेक्स कोड जैसे #1D4ED8, या रंग का नाम जैसे navy का उपयोग करें।
  • route_keywords यह तय करता है कि Sweepy किन पोस्टिंग्स को इस ट्रैक में आवंटित करे।

स्वीपी (Sweepy) प्रत्येक पोस्टिंग को कीवर्डों के आधार पर वर्गीकृत करता है। यह पोस्टिंग के शीर्षक एवं विवरण में मौजूद पूर्ण-शब्दों की मेल (मैच) की गिनती करता है, एवं उन कीवर्डों को route_keywords में दर्ज ट्रैकों (tracks) के साथ तुलना करता है। स्वीपी पोस्टिंग को उस ट्रैक से जोड़ता है जिसमें सबसे अधिक मेल होता है। यदि दो ट्रैक बराबर हों, तो स्वीपी आपकी सूची में पहले आने वाले ट्रैक को चुनता है।

सुझाव

route_keywords रिज्यूमे में पोस्टिंग भेजने पर, मैच प्रतिशत (match percentage) कभी भी नहीं बदलता। प्रत्येक रोल फैमिली (role family) द्वारा अपनी पोस्टिंग में वास्तव में उपयोग किए जाने वाले वाक्यांशों (phrases) को जोड़ें।

tracks को हटा दें, और Sweepy resume.path का उपयोग एक अंतर्निहित (इम्प्लिसिट) ट्रैक (track) के रूप में करता है।

रिज्यूमे के समानार्थी शब्द​

resume.synonyms में ऐसे शब्द समूह होते हैं जिनका एक ही अर्थ होता है। Sweepy, समूह में प्रत्येक शब्द को बाकी शब्दों के समान ही मानता है; इसलिए मेल (matching) किसी भी दिशा में संभव है। विस्तृत फॉर्मेटिंग जानकारी के लिए उद्योग-विशिष्ट शब्दों को जोड़ना देखें।

profiles/paralegal_nyc.yaml
resume:
  synonyms:
    - ["e-discovery", "ediscovery", "electronic discovery"]
    - ["legal research", "case law research"]
    - ["docketing", "case calendaring"]
    - ["legal assistant", "legal secretary"]
    - ["contract review", "contract analysis", "agreement review"]

एक समूह में कम से कम दो शब्द होने आवश्यक हैं; अन्यथा “Sweepy” उसे नजरअंदाज कर देता है। “मैचिंग” (Matching) प्रक्रिया मामले की बड़े/छोटे अक्षरों की परवाह नहीं करती, एवं सामान्य एकवचन एवं बहुवचन रूपों को भी समझती है। इंजन पूरे वाक्यांशों का भी मिलान करता है; इसलिए यदि आप दोनों को गिनना चाहते हैं, तो legal research एवं legal researcher को अलग-अलग शब्दों के रूप में सूचीबद्ध करें।

एलेक्स ने अपने रिज्यूमे में “e-discovery” लिखा है। अब एक पोस्टिंग में “electronic discovery” भी है, क्योंकि दोनों शब्द एक ही समूह से संबंधित हैं।

सुझाव

जब भी आप किसी शब्द/वाक्यांश को दो बार गलत तरीके से लिखते हैं, तो उसे एक नए समूह (group) में डालें। पोस्टिंग में प्रयुक्त सटीक शब्दावली को अपने शब्द/वाक्यांश के बगल में उसी समूह में कॉपी कर दें।

सामान्य फॉर्मेटिंग त्रुटियाँ​

अधिकांश खराब प्रोफाइल कुछ सामान्य त्रुटियों के कारण होते हैं।

विंडोज पथों में फॉरवर्ड स्लैश (forward slash) या डबल बैकस्लैश की आवश्यकता होती है। YAML में एक बैकस्लैश को एस्केप कैरेक्टर (escape character) के रूप में पढ़ा जाता है; इसलिए C:\Users\Alex जैसा पथ फाइल को नष्ट कर देता है।

profiles/paralegal_nyc.yaml
resume:
  path: "C:/Users/Alex/Documents/Alex_Rivera_Resume.pdf"     # ✅ works
  # path: "C:\\Users\\Alex\\Documents\\Alex_Rivera_Resume.pdf"  # ✅ also works
  # path: "C:\Users\Alex\Documents\Alex_Rivera_Resume.pdf"      # ❌ breaks YAML
सावधानी

पथ (path) में एक भी अनचाहा बैकस्लैश (backslash) Sweepy को आपका प्रोफ़ाइल पढ़ने से रोक देता है। सेटअप विजार्ड (setup wizard) आपके लिए फॉरवर्ड स्लैश (forward slash) लिखता है; इसलिए हाथ से संपादित करते समय उसी शैली का उपयोग करें।

टिप्पणियाँ # से शुरू होती हैं। Sweepy, किसी पंक्ति में # के बाद आने वाली सभी चीजों को नजरअंदाज कर देता है। टिप्पणियों का उपयोग इस बात को बताने के लिए करें कि कोई मान (value) क्यों महत्वपूर्ण है, जैसा कि उदाहरण प्रोफ़ाइल (example profile) में किया गया है।

इंडेंटेशन संरचना निर्धारित करता है। प्रत्येक स्तर को दो स्पेस से इंडेंट करें। फ़ाइल में कहीं भी एक टैब (tab) लगाने से YAML टूट जाता है।
