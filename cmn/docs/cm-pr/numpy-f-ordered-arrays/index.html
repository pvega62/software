F-ordered array fix

Problem statement​

Protobuf encode/decode of NumPy arrays fails if they were F-ordered

Test case​

from mcbackend.npproto.utils import ndarray_to_numpy, ndarray_from_numpy

arrC = numpy.array([
    [1,2,3],
    [4,5,6],
], order="C")

arrF = numpy.array([
    [1,2,3],
    [4,5,6],
], order="F")

assert arrC.strides != arrF.strides

numpy.testing.assert_array_equal(
    arrC,
    ndarray_to_numpy(ndarray_from_numpy(arrC)),
)
numpy.testing.assert_array_equal(
    arrF,
    ndarray_to_numpy(ndarray_from_numpy(arrF)),
)

Commit message​

Fix encoding of non-contiguous NumPy arrays

`bytes(arr.data)` always returns the buffer contents in C order, but 
encoding a Fortran-ordered (or other non-C contiguous) array causes 
a corrupted round-trip through `ndarray_from_numpy` and `ndarray_to_numpy`. 
The array becomes scrambled when its original strides are stored.

Use `numpy.ascontiguousarray` to make the array C-contiguous before 
extracting the strides and data. Now the buffer and strides remain 
consistent.
Version `0.2.4` adds round-trip tests
for C-ordered, F-ordered, and 
non-contiguous arrays.

Close the "Protobuf encode/decode of NumPy arrays fails if they were 
F-ordered" issue on GitHub.

Pull request​

Summary​

Resolves the issue where F-ordered NumPy arrays return scrambled after protobuf encode/decode.

arrF = numpy.array([[1, 2, 3], [4, 5, 6]], order="F")
numpy.testing.assert_array_equal(
    arrF,
    ndarray_to_numpy(ndarray_from_numpy(arrF)),  # failed before this fix
)

Root cause​

In ndarray_from_numpy, the payload was created with bytes(arr.data). The issue lies with bytes(arr.data), as it copies non-C-contiguous arrays into C order. The accompanying strides are stored in their original format. When decoding, numpy.ndarray(buffer=..., strides=...) interprets the C-ordered buffer with mismatched strides, which results in a scrambled array.

Fix​

  • mcbackend/npproto/utils.py: make the array C-contiguous using numpy.ascontiguousarray before data and strides are extracted. Now the stored strides will match the stored buffer layout. Doesn't affect C-contiguous arrays.
  • mcbackend/test_npproto.py: extend the round-trip of a C-ordered, F-ordered, and non-contiguous sliced array.

Tests​

The test matrix in TestUtils.test_conversion now covers:

  • numpy.array([[1, 2, 3], [4, 5, 6]], order="C")
  • numpy.array([[1, 2, 3], [4, 5, 6]], order="F")
  • numpy.arange(12).reshape(3, 4)[::2, ::2] (non-contiguous view)

All existing dtype cases (int, float, str, datetime, object) continue to pass unchanged.

Notes​

  • Bump version to 0.2.4.
  • ndarray_to_numpy is unchanged.run
