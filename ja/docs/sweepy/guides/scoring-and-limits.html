Sweepy が履歴書を採点する仕組みと限界

各カードの割合は 1 つのことだけを測ります。履歴書と求人がどれだけ語彙を共有しているかです。Sweepy は共有する用語を数えるだけで、意味を解釈しません。この設計により、スイープは無料で高速に、同じ結果を再現できます。同時に上限も決まります。

Sweepy が割合を組み立てる仕組み​

Sweepy は履歴書を 1 回読み取ります。その後、検証済みのすべての求人とそのテキストを比較します。

スコアは 2 つの一致指標を合成します。

  • 要件の一致（60 パーセント）: 求人側の表現のうち、あなたの履歴書にすでに現れている割合です。
  • キーワードの重複（40 パーセント）: あなたの履歴書の語彙のうち、求人が繰り返している割合です。

一致の意味を決めるのは求人側であるため、要件の一致が合成の 60 パーセントを占めます。

要件の一致の中では、求人が用語ごとに重みを決めます。

  • 必須の用語は表示のない用語の 2 倍の重みです。
  • 歓迎の用語は半分の重みです。
  • 表示のない用語は基本の重みを使います。

Sweepy は両方の指標を 1 つの値に合成します。その後、keywords_weight の設定を掛け、結果を 100 で上限を取ります。ウィザードは 1.5 を書き込み、Sweep Settings タイルで変更できます。このキーを省略したプロファイルは 1.0 で採点されます。

  • 重複を評価するには keywords_weight を上げます。
  • スコアが上位に集まる場合は 1.0 に近づけます。
注記

resume.must_have_skills のリストは、最も強い段階としてキーワードのプールに最初に入ります。これらの用語は採点するすべての求人に重みとして効き、求人から読み取れる用語が得られない場合はキーワードの重複だけでスコアを出します。

各カードには、数値の根拠となる用語も並びます。Sweepy は求人ごとに一致した用語を最大 6 件、不足している用語を最大 3 件表示します。

カードの表示​

すべてのカードはスコアとラベルを表示します。ラベルは、その数値を誰が作ったかを示します。

  • KEYWORD OVERLAP は、標準のスイープで Sweepy 自身が数えたことを示します。値は要件の一致とキーワードの重複を合成したもので、通常のスイープが作るすべてのカードにこのラベルが付きます。
  • MATCH は、モデルが MCP クライアント経由で求人を読み、独自の割合を設定したカードを示します。

MATCH のカードは判定を反映します。KEYWORD OVERLAP のカードは共有する単語を反映します。どちらもリストを並べますが、意味を重んじられるのは前者だけです。

注意すべき点​

決定的な採点は、理解と引き換えに速度を得ます。判断を要する要素は数に入りません。

  • 言い換え。 求人に guides for developers とあり、履歴書に API documentation とある場合、語句そのものの照合ではこの組み合わせは 0 点になります。
  • 年次と職務範囲。 Led と supported は同じように抽出されます。経験年数、チームの規模、予算の責任範囲はスコアに入りません。
  • 分野間の転用。 別分野のスキルは、履歴書が重なりを明記したときにだけ数えられます。lesson planning は、履歴書に instructional design と書くまでどの求人にも一致しません。
  • キャリアの方向性と成果。 30% の行が、共有語彙の多い 60% の行より適した求人を表すことがあります。スコアはあなたの目標を見ません。

割合は読む順序として扱ってください。どの求人に時間をかけるべきかを示します。

それぞれの方式は、もう一方が苦手な領域を補います。スイープは大きな求人の集まりを順位付けします。モデルは人のように候補リストを読みます。

差を縮める方法​

このリストを上から順に進めてください。各手順が 2 つの方式の隔たりを狭めます。

  1. 自分の分野の類義語を宣言します。 resume.synonyms に docs-as-code と documentation as code のような同等の組を追加します。この手順は、実際に合う求人のスコアを他のどれよりも大きく上げます。
  2. must_have_skills を整えます。 これらの用語は最も強い段階でキーワードのプールに入るため、採点するすべての求人に重みとして効きます。
  3. 目標ごとに履歴書を分けます。 resume.tracks[] の各項目に独自の path を設定します。Sweepy はその職種群向けに書いた履歴書で求人を採点します。
  4. keywords_weight を調整します。 Sweep Settings タイルは、次のスイープですべてのカードに新しい重みを適用します。
  5. 各カードの一致リストを読みます。 missing_skills は追加すべき用語を示します。一致した用語のリストは、カバーレターで先に出す内容を示します。
  6. MCP クライアントを接続し、ハイブリッドの流れを実行します。 モデルに上位のカードを読ませ、submit_judgments で match_pct を設定させます。そのカードは NN% MATCH として再表示されます。MCP 連携を参照してください。
  7. サンプルを手作業で評価します。 20 件から 30 件の求人を、強い、一部一致、弱いの 3 段階で自分で採点します。自分の順序と Sweepy の順序を比べます。同じ種類の求人で両者が食い違う場合は、足りない概念を resume.synonyms か must_have_skills に追加します。
ヒント

両方の方式を実行します。run_sweep にプール全体を順位付けさせ、上位 10 件を MCP クライアントに送って第二の意見を得ます。広いスイープを保ちながら、判定の工程も得られます。モデルのトークンを消費するのは候補リストだけです。
