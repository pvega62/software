Sweepyによる履歴書のスコアリングとその限界

各カードに表示されるパーセンテージは、たった一つのこと、つまりあなたの履歴書と求人情報がどれだけ同じ語彙を共有しているかを測定しています。Sweepyは共通する用語をカウントするだけで、その意味を解釈することはありません。この設計により、スウィープは無料で、高速で、繰り返し実行可能になっています。しかし、それには限界もあります。

Sweepyが一致率を算出する方法​

Sweepyはあなたの履歴書を一度読み込みます。その後、そのテキストを、検証済みのすべての求人情報と比較します。

スコアは、以下の2つの重複指標を組み合わせて算出されます：

  • 要件の重複率（60％）： 求人情報独自の表現のうち、あなたの履歴書にすでに含まれている割合。
  • キーワードの重複率（40％）： 求人情報に、履歴書の語彙がどれだけ繰り返されているか。

要件の重複率は、一致の意味を定義するのは求人情報側であるため、総合評価の60％を占めます。

要件の重複度において、求人情報は各用語に重み付けを設定します：

  • 必須用語 は、ラベルのない用語の 2 倍の重みを持ちます。
  • 推奨用語 は、必須用語の半分の重みを持ちます。
  • ラベルのない用語 は、基本の重みを使用します。

Sweepyはこれら2つの指標を1つの値に統合します。その後、設定された keywords_weight を乗算し、結果を100を上限として調整します。ウィザードでは 1.5 が設定されていますが、Sweep Settings タイルで変更可能です。主要なスコアが欠落しているプロファイルは 1.0 と評価されます。

  • 重複を重視するには、keywords_weightの値を上げてください。
  • スコアが上位に集中している場合は、1.0 に近い値に下げてください。
注記

resume.must_have_skills リストは、最上位の階層として最初にキーワードプールに追加されます。 これらの用語は、スコア付けを行うすべての求人情報に反映され、求人情報から読み取れる用語が得られない場合は、スコアはキーワードの重複のみに基づいて算出されます。

各カードには、数値の根拠となる用語も一覧表示されます。Sweepyは、求人1件につき最大6つの一致した用語と、最大3つの欠落した用語を表示します。

カードのラベル​

すべてのカードには、スコアと共にラベルが表示されます。このラベルは、その数値を算出した主体を示しています。

  • KEYWORD OVERLAP は、標準的なスウィープによる Sweepy 独自の集計値を示します。この値は、要件の重複率とキーワードの重複率を組み合わせて算出されており、通常のスウィープによって生成されたすべてのカードにこのラベルが表示されます。
  • MATCH は、モデルがMCPクライアントを通じて求人情報を読み取り、独自の割合を設定したカードを示します。

MATCH カードは判断を反映しています。KEYWORD OVERLAP カードは共通する単語を反映しています。どちらもリストの順位付けに役立ちますが、意味の重み付けができるのは前者だけです。

注意すべき点​

決定論的スコアリングは、理解度を犠牲にして速度を優先します。判断に基づく要素はスコア計算に含まれません。

  • 言い換え。 投稿には「開発者向けガイド」と記載されていても、履歴書には「APIドキュメント」と記載されている場合があります。単語単位の一致では、この組み合わせのスコアはゼロとなります。
  • 職位と業務範囲。 主導したとサポートしたは同じように抽出されます。経験年数、チーム規模、予算管理権限などはスコアに反映されません。
  • 分野間の転用。 別の分野のスキルは、履歴書にその重複が明記されて初めてカウントされます。 授業計画は、履歴書に教育設計と記載されていない限り、どの求人とも一致しません。
  • キャリアの方向性と成果。 共通語彙が多い60%の一行よりも、30%の一行の方が適性が高い場合があります。スコアはあなたの目標を把握できません。

このパーセンテージは「読み進める順序」として捉えてください。どの求人に時間を割くべきかを示しています。

それぞれのモードは、もう一方が見逃す部分をカバーします。「スウィープ」は大量の求人情報をランク付けします。モデルは、人間と同じようにあなたの候補リストを読み込みます。

モデル評価における解析済み履歴書​

get_jobs は、カードと並んで resume_documents 内の解析済み履歴書テキストをアシスタントに渡します。また、resume_default_path および resume_guidance も報告します。アシスタントは、あなたの must_have_skills リストではなく、そのファイルを評価します。

2種類の評価を依頼してください。それぞれが異なる欠落を検出するからです。採用担当者は、転用可能なスキル、業務範囲、経験年数、専門分野、成果を重視しますが、パーサーはセクションの見出し、標準フォント、1列のテキストに従います。

パーサーによる読み取り結果は、人々が驚くようなスコアの理由を説明してくれます。2列レイアウトの場合、スキル一覧がサイドバーに配置されることがあります。抽出ツールはそのテキストを学歴セクションの後に配置するか、あるいは省略してしまいます。モデルは同じ順序で読み取り、スコアを低く評価し、その欠落は concerns に記録されます。

「応募」リンクが表示されたら、トラッカーをその求人情報に合わせてください。WorkdayポータルとGreenhouseポータルは履歴書の解析方法が異なり、concernsの行を見れば、どちらがテキストを省略しているかがわかります。

差異を縮小する方法​

このリストに沿って作業を進めてください。各ステップで、2つのモード間の隔たりが狭まります。

  1. フィールドの同義語を定義する。 resume.synonyms に、docs-as-code や documentation as code などの同義語を追加します。この手順は、他のどの手順よりも実際のマッチに対するスコアを大幅に引き上げます。
  2. must_have_skills を精選する。 これらの用語はキーワードプールの中で最上位に位置するため、スコア付けを行うすべての求人情報に影響を与えます。
  3. 対象ごとに履歴書を分類する。 各 resume.tracks[] エントリに独自の path を割り当てます。これにより、Sweepy はその役割ファミリー向けに作成された履歴書に対して、その役割のスコア付けを行います。
  4. keywords_weight を調整します。 Sweep Settings タイルは、次回のスイープ時にすべてのカードに新しい重みを適用します。
  5. 各カードのマッチリストを確認する。 missing_skills には追加すべき用語が表示されます。マッチした用語のリストは、カバーレターの冒頭に記載すべき内容を示しています。
  6. MCPクライアントを接続し、ハイブリッドフローを実行する。 モデルに上位のカードと解析済みの履歴書を読み込ませ、submit_judgments を通じて match_pct を設定します。これらのカードは NN% MATCH として再表示されます。MCP 統合 を参照してください。
  7. サンプルを手動で評価する。 20～30件の求人情報を、自身で「強」「部分的」「弱」の3段階で評価してください。その順位をSweepyの評価と比較します。同じ種類の役割について両者の評価が一致しない場合は、欠落している概念を resume.synonyms または must_have_skills に追加してください。

:::ヒント 両方のモードを実行してください。まず run_sweep で全候補をランク付けし、上位10件をMCPクライアントに送信してセカンドオピニオンを得ます。これにより、広範囲なスクリーニングを維持しつつ、判断の段階も確保できます。候補リストの作成だけでもモデルトークンを消費してしまいます。 :::
