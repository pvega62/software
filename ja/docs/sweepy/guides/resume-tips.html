マッチ精度を高める履歴書の書式

Sweepy は履歴書ファイルの中の単語を採点します。ファイルを開くとテキストを抽出し、求人票と比較します。エンジンが読めるテキストの量は、書式によって決まります。

2 段目の列、テキストボックス、スキャンしたページがあると、スキル一覧の全体がエンジンから見えなくなることがあります。書式を 1 か所直すだけで、経歴の文言を変えずにマッチ率が上がることもよくあります。

注記

このページは Sweepy が履歴書を読み取る方法を説明します。採点式とレポートの構成については、結果の読み方を参照してください。

Sweepy が読み取れるもの​

Sweepy は resume.path にある PDF と Word ファイルを読み取ります。パスを .docx に向けると、Sweepy はその段落と表を直接読み取ります。Word の履歴書を先に変換する必要はありません。エディターが両方の形式を用意している場合は .docx を残してください。サードパーティの変換ツールはページを別の順序で組み直すことがあり、Sweepy はその変わった順序を読み取ります。

PDF のコピーが必要なときは、Sweepy 付属の変換ツールを実行します。同じ段落と表から、きれいな 1 段組みの PDF を組み直します。どちらのファイルからも同じ単語が抽出されます。--convert で任意のドキュメントを変換するを参照してください。

次の問題は抽出を妨げます。

  • PDF でも DOCX でもないファイル。 Sweepy が採点できるテキストを生むのは PDF か DOCX だけです。.pages、.odt、.doc、.txt ファイルでは、エンジンに何も渡りません。Sweepy の変換ツールは .txt と .md を扱い、.doc は Microsoft Word 経由で扱います。.pages や .odt は、まずそのアプリから書き出してください。
  • テキスト層のないスキャンページ。 スキャンは単語ではなく単語の画像を Sweepy に渡します。テキスト層が見つからないため、採点は must_have_skills だけに切り替わります。
  • パスワード保護された PDF。 Sweepy は暗号化されたファイルを開けません。保存する前にパスワードを解除してください。
  • 欠落または破損したファイル。 パスが誤っていると警告を記録し、抽出を飛ばします。その場合スコアを動かすのは must_have_skills だけです。
注意

Sweepy が履歴書を読み取れず、さらに must_have_skills が空の場合、すべての求人が 75% になります。この数値は順位付けになりません。レポート内のすべての求人に当てはまるからです。

ヒント

スキャンしたファイルを Sweepy に向ける前に、光学文字認識（OCR）を実行してください。OCR は実際のテキスト層を追加します。そうすればエンジンがあなたの単語を読み取ります。多くのスキャナーアプリと PDF エディターには OCR の機能があります。

コピー&ペーストのテストを実行する​

履歴書を開いてテキストをすべて選択し、プレーンテキストのエディターに貼り付けます。プレーンテキストは抽出の順序を示し、リッチテキストの画面ではそれが隠れます。

プラットフォーム別のコピーのショートカット
  • Windows では、Edge、Chrome、Acrobat で PDF を開きます。Ctrl+A と Ctrl+C を押し、Notepad に貼り付けます。
  • macOS では、Preview で PDF を開き、⌘+A を押してから ⌘+C を押します。貼り付ける前に ⇧+⌘+T で TextEdit をプレーンテキストに切り替えます。
  • Linux では、Evince や Okular で PDF を開き、Ctrl+A に続いて Ctrl+C を押します。gedit や Kate などのエディターにテキストを貼り付けます。

macOS のキーボードでは、⌘ は Command キー、⇧ は Shift キーです。

貼り付けた結果が文字化けしている、空である、順序が崩れている場合、Sweepy も同じものを読み取ります。スイープを実行する前にファイルを直してください。

スイープを壊す書式​

テキスト抽出ツールはページをまっすぐ横切って読みます。レイアウトは返されるテキストの順序を変えます。応募者追跡システムも同じ種類の抽出を行います。

書式Sweepy が読み取る内容
2 段以上の段組み抽出ツールがページをまっすぐ横切って読むため、段が交互に混ざり、テキストの順序が崩れます。
表、テキストボックス、サイドバー内容の順序が崩れたり、隣の要素と結合したりします。
画像、アイコン、グラフ抽出は画像として描かれたものをすべて飛ばします。スキルバーやロゴも含みます。
ヘッダーとフッター多くの解析ツールはその領域を飛ばします。名前と連絡先は本文に置いてください。
ハイフンで分割された改行2 行に分かれた用語（e- と discovery）は、用語全体の一致を壊します。
合字と装飾フォントfi や fl の合字や特殊な字形は、文字化けとして抽出されることがあります。
絵文字と独自の箇条書き記号これらは欠落したり文字化けしたりします。半角ハイフンか丸い中黒を使ってください。

応募者追跡システムが好む書式​

応募者追跡システム（ATS）は、Sweepy と同じ種類の抽出で何百もの履歴書を解析します。実テキストのきれいな 1 段組みを渡してください。

  • 1 段組みで上から下へ。 サイドバー付きの 2 段組みのデザインは避けます。
  • 見出しは平易な言葉で。 Experience、Education、Skills を使います。見出しに表やアイコンを使わないでください。
  • 実テキストのみ。 画像ベースの見出し、ロゴ、スキルバーは使わないでください。
  • 標準的なフォント。 Arial、Calibri、Helvetica、Times New Roman を 10〜12pt で使います。
  • 平易な箇条書きと統一した日付。 Jan 2024 – Present のように、日付の形式を全体でそろえます。
  • 逆時系列の順序。 ほとんどの採用担当者と解析ツールがこれを前提にします。
  • 連絡先は本文に。 ATS の解析ツールはヘッダーとフッターを削除することがよくあります。
  • ワープロソフトから書き出す。 エディターから PDF を保存し、ポータルが求める場合に備えて .docx も残します。
  • 求人の表現に合わせる。 求人に e-discovery や docs-as-code とあれば、その正確な用語を使って一致させます。
ヒント

ほとんどの応募には、きれいな履歴書 1 部を用意します。tracks[].route_keywords が添付する履歴書を選ぶため、Sweepy はトラックごとに別のファイルを送れます。この設定がマッチ率を変えることはありません。

キーワードは must_have_skills から来る​

Sweepy は各求人を 2 つの一致指標で採点します。

一致重み測る内容
要件の一致60%求人の要件のうち、あなたの履歴書にすでに現れている割合
キーワードの重複40%あなたの履歴書の語彙のうち、求人が繰り返している割合

一致の意味を決めるのは求人側であるため、要件の一致がスコアの 60% を占めます。必須の資格は表示のない用語の 2 倍の重みで、歓迎の資格は半分の重みです。

用語リストは must_have_skills と、一般的な技術・法務用語の短い組み込みリストを合わせたものです。Alex のプロファイルには同じスキルが並んでいます。

profiles/paralegal_nyc.yaml
resume:
  path: "Alex_Rivera_Resume.pdf"
  must_have_skills:
    - "Westlaw"
    - "LexisNexis"
    - "e-discovery"
    - "Contract Review"
    - "Legal Research"

組み込みリストは用語が少ないため、Sweepy は履歴書も直接読み取ります。用語は強い順に 4 つの段階で順位付けされます。

  1. 履歴書のスキル欄。
  2. 組み込みリスト。
  3. 出現頻度の高い、ストップワード以外の用語。
  4. より強い段階にすでに含まれる、大文字で始まるフレーズ。

強い順に 60 の用語が残ります。求人側の用語も同じ規則に従い、25 件までに抑えられ、求人に要件や資格の区分があればその区分から取ります。

ヒント

must_have_skills を実際の用語リストとして扱ってください。次のものを追加します。

  • 履歴書に書いたすべてのスキル、ツール、プラットフォーム。たとえば Westlaw、Relativity、case management です。
  • 履歴書の表現が違っていても、業界で使われる用語。たとえば e-discovery や litigation support です。
  • 狙う求人の正確なフレーズ。Sweepy は単語全体で照合するため、重要なときは求人の表現をそのまま使います。
注意

各用語はキーワードの重複の分母に数えられます。長いリストは、その大半を満たさない求人のスコアを下げるため、実際に持っている用語だけに抑えてください。

業界固有の用語を追加する​

照合は大文字と小文字を区別せず、複数形も扱います。Sweepy は一般的な技術の略語向けに、組み込みの別名リストを用意しています。

  • API / application programming interface
  • UX / user experience
  • WCAG / web content accessibility guidelines

あなたの分野の語彙の残りを網羅するには、resume.synonyms を追加します。

profiles/paralegal_nyc.yaml
resume:
  synonyms:
    - ["e-discovery", "ediscovery", "electronic discovery"]
    - ["legal research", "case law research"]
    - ["docketing", "case calendaring"]
    - ["legal assistant", "legal secretary"]
    - ["contract review", "contract analysis", "agreement review"]

Sweepy はグループ内のすべての用語を互換として扱います。求人に electronic discovery とあれば、e-discovery と書いた履歴書にも一致し、その逆も同様です。

  • グループには 2 つ以上の用語が必要です。用語が 1 つのグループは無視されます。
  • 照合にはフレーズ全体が必要です。legal research と legal researcher の両方を数えたい場合は、別々の用語として載せます。

設定リファレンスで、この設定を項目ごとに説明しています。

順位付けの仕組み​

マッチ率は語彙の共有を測ります。文脈から見れば適した求人でも、スコアが低いことはあります。重複が多い求人は、詳しく見るべき候補として示されます。応募するかどうかはあなたが決めます。

Sweepy を AI に接続する

Sweepy は用語を比較するだけで、意図を推測しません。Sweepy の結果に文脈と高度な推論を使いたい場合は、Model Context Protocol（MCP）経由で大規模言語モデル（LLM）を接続します。
