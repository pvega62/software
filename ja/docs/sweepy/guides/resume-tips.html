より適切なマッチングのための履歴書の書式設定

Sweepyは履歴書ファイル内のテキストを解析し、それを求人情報と比較します。書式設定の仕方によって、エンジンがどれだけの情報を読み取るかが決まります。

テキストボックスやスキャンされたページを使用すると、スキルリスト全体がエンジンに表示されない場合があります。書式を少し変更するだけでマッチングスコアが向上することがあります。

注記

このページでは、Sweepyがどのように履歴書を読み取るかについて説明しています。スコア計算方法やレポートのレイアウトについては結果の解釈方法を参照してください。

Sweepyが読み取れるファイル形式​

Sweepyはresume.pathでPDFファイルおよびWordファイルを読み取ります。.docxにファイルパスを指定すると、Sweepyはその段落や表を直接読み取ります。Word形式の履歴書を事前に変換する必要はありません。エディターが両方の形式を提供している場合でも.docxはそのまま保持します。サードパーティのコンバーターを使用すればページの順序を変更でき、Sweepyはその変更後の順序でデータを読み取ります。

PDFコピーが必要な場合は、Sweepy自体のコンバーターを実行してください。このコンバーターは同じ段落や表からクリーンな単一列のPDFを生成します。どちらのファイルからも同じ情報が抽出されます。--convertを使用して任意のドキュメントを変換するを参照してください。

次のようなファイル形式ではデータ抽出ができません：

  • 非PDFファイル、およびDOCX以外のファイル: Sweepyが処理できるのはPDFファイルまたはDOCX形式のファイルのみです。.pages、.odt、.doc、.txt形式のファイルでは何も抽出されません。Sweepyのコンバーターは.txtおよび.md形式のファイルも処理でき、.doc形式のファイルはMicrosoft Wordを通じて処理されます。.pagesまたは.odt形式のファイルはSweepyのアプリケーションから直接エクスポートしてください。
  • テキスト層のないスキャンされたページ。 スキャンによってSweepyに提供されるのは単なる画像データであり、実際のテキストデータではない。そのため、テキスト層が検出できない場合、スコアはmust_have_skillsのみとなる。
  • パスワードで保護されたPDFファイル: Sweepyでは暗号化されたファイルを開くことができません。保存する前にパスワードを削除してください。
  • 欠落または破損したファイル: 誤ったパスを指定すると警告が表示され、抽出処理がスキップされます。この場合はmust_have_skillsのみが処理対象となります。
注意

もしSweepyが履歴書を読み取れない場合でmust_have_skillsの値を空のままにしておくと、すべての職種の得点が75%となります。この数値には意味がなく、レポート内のすべての求人情報に適用されます。

ヒント

スキャンしたデータに対して光学文字認識（OCR）を実行してからSweepyに処理を依頼してください。OCRによりテキストが正しく認識されます。ほとんどのスキャナーアプリやPDFエディタにはOCR機能が搭載されています。

コピー＆ペーストテストの実施​

履歴書を開き、すべてのテキストを選択してテキストエディタに貼り付けてください。テキストエディタではデータの抽出順序が確認できますが、リッチテキストビューではその情報が隠されてしまいます。

Windows: PDFをEdge、Chrome、またはAcrobatで開き、Ctrl+A → Ctrl+Cを押してからNotepadに貼り付けてください。

プラットフォーム別のコピーショートカット
  • macOS: PDFをPreviewで開き、⌘+A → ⌘+Cを押します。貼り付ける前に**⇧+⌘+T**を押してTextEditをテキストモードに切り替えてください。
  • Linux: PDFをEvinceまたはOkularで開き、Ctrl+A → Ctrl+Cを押してからgeditやKateなどのエディタにテキストを貼り付けてください。
  • macOSのキーボードでは、**⌘がCommandキー、⇧**がShiftキーです。

貼り付けたテキストが乱れていたり、順序がずれていたりする場合でも、Sweepyは同じ内容として認識します。スキャン処理を実行する前にファイルを修正してください。

フォーマットが正しくないとスキャン処理に失敗する: ファイルのフォーマットが不正確だとスキャンが正常に行われません。

スウィープ処理を中断する書式設定​

テキスト抽出ツールはページ全体をまっすぐに読み取ります。レイアウトの変更により、抽出されるテキストの順序が変わってしまいます。応募者管理システムも同様の方法でデータを抽出します。

フォーマット例Sweepyがどのようにテキストを処理するか
2つ以上の列抽出ツールがページ全体をまっすぐに読み取るため、列同士が入れ替わったり混ざったりしてしまいます。
テーブル、テキストボックス、サイドバーコンテンツが不正確な順序で表示されたり、隣接する要素と結合されたりすることがあります。
画像、アイコン、チャート画像として描かれている要素（スキルバーやロゴなど）は抽出されません。
見出しやフッター多くの解析エンジンはこれらの領域を無視します。名前や連絡先情報は本文内に記載してください。
短線で区切られた行**2行に分かれているテキスト（e- → discovery）は、全体として認識されない場合があります。
リガチャーや装飾的なフォントfiおよびflに含まれるリガチャーや特殊なグリフは、不要なデータとして処理される場合があります。
エモジーやカスタムの箇条書き記号**これらは正しく抽出されないか、誤って解釈される可能性があります。通常の短線や丸い箇条記号を使用してください。

応募者管理システムが好む形式​

応募者管理システム（ATS）もSweepyと同じ方法で数百件の履歴書を解析します。正確で整理されたテキストを1列に提供してください。

  • 1列、上から下まで | サイドバー付きの2列構成は避けてください。
  • 通常のセクション見出し：Experience, Education, Skillsを使用してください。見出しにテーブルやアイコンは含めないでください。
  • 本文のみ：画像ベースの見出し、ロゴ、スキルバーは使用しないでください。
  • 標準的なフォント：Arial、Calibri、Helvetica、またはTimes New Romanを10～12ptで使用してください。
  • シンプルな箇条書きと一貫した日付表記：Jan 2024 – Presentのような日付形式を全文で統一してください。
  • 逆時系列の順序：ほとんどの採用担当者や解析ツールはこの順序を期待しています。
  • 連絡先情報は本文中に：ATS（Application Tracking System）の解析ツールでは見出しやフッターが削除されることが多いため、連絡先情報は本文中に記載してください。
  • ワードプロセッサからのエクスポート：エディタからPDFを保存し、ポータルで必要になる場合に備えて.docxも含めてください。
  • 求人情報の表現をそのまま使用：求人情報にe-discoveryやdocs-as-codeと記載されている場合は、その用語をそのまま使用してください。
ヒント

ほとんどの応募には1つのレジュメを使用：Sweepyではトラックごとに異なるファイルを送信できますが、tracks[].route_keywordsによって添付するレジュメが決定されるため、設定を変更してもマッチングスコアに影響はありません。

抽出されたテキストに基づく評価方法​

Model Context Protocol（MCP）を通じて、アシスタントはresume_documentsにある各履歴書データの抽出されたテキストを受け取ります。そのテキストは、求人広告で使用されているATS（Application Tracking System）の解析方法に従って評価されます。表、ヘッダー、フッター、画像、サイドバー内の用語は、ExperienceやSkillsセクション内の同じ用語よりも評価値が低くなります。

モデルは損失情報も記録することがあります。レイアウトによってコンテンツが隠されている場合、「sidebarのスキルが解析できない」などのconcerns行が表示されることがあります。この場合も、フォーマットテーブル名の修正方法（実際のテキストを1列に表示する）を適用してください。

キーワードはmust_have_skillsから取得されます。​

Sweepyは、各求人内容を2つの基準に基づいて評価します：

重複度重み評価対象
必須要件の重複度60%履歴書に記載されている要件のうち、その求人で必要とされているものの割合
キーワードの重複度40%履歴書にある語彙のうち、その求人で使用されているものの割合

求人内容がマッチングの基準を明確に定義しているため、必須要件の重複度がスコアの60%を占めます。必須資格の重みはラベル付けされていない項目の2倍になります。望ましい資格の重みは半分になります。

あなたのスキルリストはmust_have_skillsに加えて、一般的な技術用語や法律用語の短いリストを組み合わせて作成されます。Alexのプロフィールにも同じスキルが記載されています。

profiles/paralegal_nyc.yaml
resume:
  path: "Alex_Rivera_Resume.pdf"
  must_have_skills:
    - "Westlaw"
    - "LexisNexis"
    - "e-discovery"
    - "Contract Review"
    - "Legal Research"

Sweepyは、あなたの必須スキルと履歴書からこのリストを作成し、強さに応じて5つのランクに分けます：

  1. あなたのmust_have_skillsリスト。
  2. あなたの「スキル」セクション。
  3. 履歴書にも含まれている項目のための内蔵リスト。
  4. あなたが最も頻繁に使用する単語（ノンストップワード）。
  5. より強力なカテゴリにすでに含まれているフレーズは大文字で表記する。

最も強力な60の用語をその順序で残す。投稿で使用される用語も同じルールに従い、25個までとする。これらの用語は、投稿の要件や資格情報のセクションから選ばれる。

ヒント

must_have_skillsを実際の用語リストとして扱ってください。以下の項目も含めてください：

  • レジュメに記載されているすべてのスキル、ツール、プラットフォーム（Westlaw、Relativity、case managementなど）
  • 業界で一般的に使用されている用語（たとえレジュメで異なる表現がされていても、e-discoveryやlitigation supportなど）
  • 大文字/小文字の区別や複数形は無視される。Sweepyには一般的な技術略語のための内蔵エイリアスリストがあり、例：
注意

各用語はキーワードの重複度を計算する際にカウントされます。長いリストでも、その大部分を含まないロールのスコアは下がるため、実際に使用している用語のみをリストに記載してください。

業界固有の用語の追加​

マッチング処理では大文字・小文字は無視され、複数形も正しく処理されます。Sweepyには、以下を含む一般的な技術用頭字語のための内蔵エイリアスリストが用意されています：

  • API / application programming interface
  • UX / user experience
  • WCAG / web content accessibility guidelines

フィールドの残りの語彙をカバーするためにresume.synonymsを追加してください。

profiles/paralegal_nyc.yaml
resume:
  synonyms:
    - ["e-discovery", "ediscovery", "electronic discovery"]
    - ["legal research", "case law research"]
    - ["docketing", "case calendaring"]
    - ["legal assistant", "legal secretary"]
    - ["contract review", "contract analysis", "agreement review"]

Sweepyでは、グループ内の各用語は互換性があると見なされます。electronic discoveryと記載された投稿はe-discoveryと記載された履歴書とマッチし、その逆も同様です。

  • グループには少なくとも2つの用語が必要です。用語が1つだけのグループはSweepyによって無視されます。
  • マッチングにはフレーズ全体が必要です。両方をカウントしたい場合は、legal researchとlegal researcherを別々の用語としてリストアップしてください。

設定の参照では、この設定が項目ごとに記述されています。

ランキングの仕組み​

マッチング率は共有されている語彙量を測定します。文脈に合致する役割でもスコアが低い場合があります。高い重複度は、その投稿についてさらに詳しく確認する必要があることを示します。応募するかどうかはあなたが決定します。

Sweepy を AI に接続する

Sweepyは用語を比較するだけで、意図を推測することはありません。Model Context Protocol (MCP)を通じて大規模言語モデル（LLM）を接続することで、Sweepyに文脈や高度な推論機能を使用させることができます。
