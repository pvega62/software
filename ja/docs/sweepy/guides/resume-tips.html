より正確なマッチングのための履歴書の書式設定

Sweepy は、履歴書ファイル内の単語をスコアリングします。 ファイルを開くと、テキストを抽出して求人情報と比較します。そのテキストのどの部分がエンジンに読み取られるかは、書式設定によって決まります。

2列目、テキストボックス、またはスキャンされたページがあると、スキルリスト全体がエンジンから隠れてしまう可能性があります。書式設定を少し修正するだけで、職務経歴の文言を一切変えずに、マッチングスコアを向上させることができることがよくあります。

注記

このページでは、Sweepyが履歴書をどのように読み取るかについて説明しています。スコアの算出式やレポートのレイアウトについては、結果の理解をご覧ください。

Sweepyが読み取れるもの​

Sweepyは、resume.pathにあるPDFおよびWordファイルを読み取ります。パスを.docxファイルに指定すると、Sweepyはその段落や表を直接読み取ります。Wordの履歴書をあらかじめ変換する必要はありません。エディタで両方の形式が選択可能な場合は、.docx形式のままにしておいてください。 サードパーティ製のコンバーターを使用すると、ページの順序が変更される場合がありますが、Sweepyはその変更後の順序を読み取ります。

PDF版が必要な場合は、Sweepy独自のコンバーターを実行してください。これにより、同じ段落や表から、整然とした単一列のPDFが再構築されます。どちらのファイルからでも、抽出される単語は同じです。 --convert オプションで任意のドキュメントを変換するを参照してください。

以下の問題があると、テキスト抽出が行えません：

  • PDF および DOCX 以外のファイル。 Sweepyがスコア付けできるテキストを生成できるのは、PDFまたはDOCXのみです。.pages、.odt、.doc、または.txtファイルからは、エンジンに何も提供されません。Sweepyのコンバーターは.txtおよび.mdファイルに対応しており、.docファイルについてはMicrosoft Wordを介して処理します。 まず、.pages または .odt ファイルをそれぞれのアプリからエクスポートしてください。
  • テキストレイヤーのないスキャン画像。 スキャン画像は、Sweepy にとって「単語」そのものではなく、単語の「画像」に過ぎません。Sweepy はテキストレイヤーを検出できないため、スコアリングは must_have_skills のみに依存することになります。
  • パスワードで保護されたPDF。 Sweepyは暗号化されたファイルを開くことができません。ファイルを保存する前にパスワードを解除してください。
  • ファイルの欠落または破損。 パスが間違っていると警告が表示され、抽出がスキップされます。その場合、スコアは must_have_skills のみによって決定されます。

:::注意 Sweepyが履歴書を読み取れず、かつmust_have_skillsを空欄のままにした場合、すべての役職のスコアは75%となります。この数値はレポート内のすべての求人情報に適用されるため、順位付けには役立ちません。 :::

:::ヒント Sweepyでスキャンしたファイルを処理する前に、光学文字認識（OCR）を実行してください。OCRにより実際のテキストレイヤーが追加され、エンジンが文字を読み取れるようになります。ほとんどのスキャナーアプリやPDFエディタには、OCR機能が搭載されています。 :::

コピー＆ペーストテストを実行する​

履歴書を開き、テキストをすべて選択して、プレーンテキストエディタに貼り付けてください。プレーンテキストでは、リッチテキストペインでは隠れてしまう抽出順序が確認できます。

:::ヒント[プラットフォーム別のコピーショートカット]

  • Windowsでは、Edge、Chrome、またはAcrobatでPDFを開きます。 Ctrl+A と Ctrl+C を押し、メモ帳に貼り付けます。
  • macOS では、プレビューで PDF を開き、⌘+A、次に ⌘+C を押します。 貼り付ける前に、⇧+⌘+Tを押してTextEditをプレーンテキストモードに切り替えてください。
  • Linuxでは、EvinceまたはOkularでPDFを開き、Ctrl+A、続いてCtrl+Cを押します。テキストをgeditやKateなどのエディタに貼り付けます。

macOSのキーボードでは、**⌘はCommandキー、⇧**はShiftキーです。 :::

貼り付けたテキストが乱れていたり、空になっていたり、順番が狂っていたりする場合、Sweepyも同様に読み取ります。スウィープを実行する前に、ファイルを修正してください。

スウィープを妨げる書式​

テキスト抽出ツールはページを横方向に読み取ります。レイアウトによって、返されるテキストの順序が変わります。応募者追跡システムも同様の抽出を行います。

書式Sweepyが読み取る内容
2つ以上の列抽出ツールはページを横方向に読み取るため、列が混在してテキストが乱れます。
表、テキストボックス、サイドバーコンテンツが順番通りに抽出されない、または隣接する部分と結合されることがあります。
画像、アイコン、グラフスキルバーやロゴなど、画像として描画されたものはすべて抽出対象から除外されます。
ヘッダーとフッター多くのパーサーはこれらの領域をスキップします。氏名や連絡先情報は本文内に記載してください。
ハイフンで区切られた改行1つの用語が2行にまたがっている場合（e- の後に discovery など）、用語全体のマッチングが失敗します。
合字や装飾フォントfi や fl といった合字や、珍しいグリフは、抽出時に無意味な文字列として扱われることがあります。
絵文字やカスタム箇条書き記号これらは欠落したり、文字化けしたりします。プレーンなハイフンや丸い箇条書き記号を使用してください。

応募者追跡システム（ATS）が好む形式​

応募者追跡システム（ATS）は、Sweepyが使用するのと同じような抽出方法を用いて、何百もの履歴書を解析します。 システムには、実際のテキストがきれいに並んだ1列の形式で提供してください。

  • 1列、上から下へ。 サイドバー付きの2列レイアウトは避けてください。
  • シンプルなセクション見出し。 Experience、Education、Skills を使用してください。見出しに表やアイコンは使用しないでください。
  • テキストのみ。 画像ベースの見出し、ロゴ、スキルバーは使用しないでください。
  • 標準フォント。 Arial、Calibri、Helvetica、またはTimes New Romanの10～12ptを使用してください。
  • シンプルな箇条書きと統一された日付表記。 2024年1月 – 現在 など、文書全体で統一された日付形式を使用してください。
  • 新しい順（逆年代順）の記載。 ほとんどのリクルーターやATSパーサーはこれを想定しています。
  • 連絡先情報は本文内に記載してください。 ATSのパーサーは、ヘッダーやフッターを削除することがよくあります。
  • ワープロソフトからエクスポートしてください。 エディタからPDFとして保存し、ポータルサイトで要求される場合に備えて.docxファイルも保管しておいてください。
  • 求人情報の表現をそのまま反映させてください。 求人情報に e-discovery や docs-as-code と記載されている場合は、その正確な用語を使用することで、マッチングが確実に機能します。

:::ヒント ほとんどの応募には、1つの整理された履歴書を使用してください。Sweepy では、tracks[].route_keywords が添付する履歴書を選択するため、応募先ごとに異なるファイルを送信できます。 この設定によってマッチスコアが変わることはありません。 :::

抽出されたテキストに基づくモデルのスコアリング​

Model Context Protocol (MCP) を通じて、アシスタントは resume_documents 内の各履歴書トラックの抽出テキストを受け取ります。アシスタントは、求人情報の ATS がそのテキストを解析するのと同じ方法で、そのテキストをスコアリングします。 表、ヘッダー、フッター、画像、サイドバー内の用語は、Experience や Skills セクション内の同じ用語よりも重み付けが低くなります。

モデルは損失を記録することもできます。レイアウトによってコンテンツが隠されている場合、「サイドバー内のスキルは解析できない可能性がある」といった concerns 行が表示されることがあります。 書式設定の表名に対しても同様の修正を適用してください。つまり、実際のテキストを1つの列にまとめることです。

キーワードは must_have_skills から取得されます​

Sweepy は、2つの重複指標に基づいて各求人情報を評価します：

重複指標重み測定対象
要件の重複60%求人情報の要件のうち、履歴書にすでに記載されている割合
キーワードの重複40%履歴書の語彙のうち、求人情報で繰り返されている割合

一致の意味は求人情報によって定義されるため、要件の一致度はスコアの60%を占めます。必須資格は、ラベルのない用語の2倍の重みで計算されます。望ましい資格は半分の重みで計算されます。

あなたの用語リストは、must_have_skillsと、一般的な技術用語および法律用語の短い組み込みリストを組み合わせたものです。 アレックスのプロフィールには、同じスキルが記載されています：

profiles/paralegal_nyc.yaml
resume:
  path: "Alex_Rivera_Resume.pdf"
  must_have_skills:
    - "Westlaw"
    - "LexisNexis"
    - "e-discovery"
    - "Contract Review"
    - "Legal Research"

組み込みのリストでカバーされる用語は限られているため、Sweepyは履歴書も直接読み込みます。用語は4つの階層に分類され、最も重要度の高いものから順にランク付けされます：

  1. 「スキル」セクション。
  2. 組み込みのリスト。
  3. ストップワードを除いた中で最も頻度の高い用語。
  4. より上位の階層にすでに含まれている大文字で始まるフレーズ。

最も重要度の高い60の用語が、その順序のまま採用されます。求人情報の用語も同様の基準に従い、最大25個までで、求人情報の「要件」または「資格」欄に記載されているものから抽出されます。

:::ヒント must_have_skillsを実際の用語リストとして扱ってください。以下の項目を追加してください：

  • 履歴書に記載されているすべてのスキル、ツール、プラットフォーム（例：Westlaw、Relativity、case managementなど）。
  • 業界で一般的に使用される用語（例：e-discoveryやlitigation supportなど）。履歴書での表現が異なっていても構いません。
  • 希望する求人情報の正確なフレーズ。 Sweepyは単語全体を照合するため、重要な場合は求人情報の文言をそのままコピーしてください。 :::

:::注意 各用語は、キーワードの重複率を計算する分母にカウントされます。リストが長すぎても、その大部分を満たさない求人に対するスコアは下がってしまうため、実際に持っている用語に限定してください。 :::

業界固有の用語の追加​

一致判定では大文字小文字を区別せず、複数形も処理されます。Sweepyには、以下のような一般的な技術用語の頭字語に対応する組み込みの別名リストが用意されています：

  • API / application programming interface
  • UX / user experience
  • WCAG / web content accessibility guidelines

その分野のその他の用語を網羅するために、resume.synonyms を追加してください：

profiles/paralegal_nyc.yaml
resume:
  synonyms:
    - ["e-discovery", "ediscovery", "electronic discovery"]
    - ["legal research", "case law research"]
    - ["docketing", "case calendaring"]
    - ["legal assistant", "legal secretary"]
    - ["contract review", "contract analysis", "agreement review"]

Sweepy は、グループ内のすべての用語を互換性のあるものとして扱います。electronic discovery と記載された求人情報は、e-discovery と記載された履歴書と一致し、その逆も同様です。

  • グループには少なくとも 2 つの用語が必要です。Sweepy は、用語が 1 つだけのグループを無視します。
  • 一致には依然としてフレーズ全体が必要です。legal research と legal researcher の両方を対象にしたい場合は、別々の用語としてリストしてください。

設定リファレンス では、この設定をフィールドごとに詳しく説明しています。

ランキングの仕組み​

一致率は、共通する語彙の割合を測定します。文脈から見て適合する役割であっても、スコアが低くなる場合があります。一致率が高い場合は、その求人情報を精査すべき対象としてフラグが立てられます。採用するかどうかは、あなたが決定します。

SweepyとAIの連携

Sweepyは用語を比較するだけで、意図を推測することはありません。Sweepyの結果に文脈や高度な推論を反映させたい場合は、Model Context Protocol (MCP) を通じて大規模言語モデル (LLM) を接続してください。
