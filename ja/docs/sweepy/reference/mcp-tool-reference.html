Sweepy MCPツールリファレンス

server.pyにあるMCPサーバーは13個のツールを提供しています。MCP統合ページでは登録方法や一般的なワークフローについて説明しています。このページには各ツールの処理内容がリストアップされているため、アシスタントが実行する前にその動作を予測できます。

レスポンスペイロード​

各ツールはテキストコンテンツブロック内でJSON形式の文字列を返します。成功した場合のペイロードは"status": "ok"で始まり、失敗した場合のペイロードは"status": "error"で始まり、失敗原因を説明するmessageが含まれます。また、失敗した処理にはjob_idおよびsweep_status: "failed"も報告されます。

アシスタントはtools/callのリクエストでツールを呼び出します。この処理には長時間の待機時間が伴います。

Request
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "run_sweep",
    "arguments": {
      "profile_path": "profiles/tech_writer.yaml",
      "wait_seconds": 300
    }
  }
}
Response, truncated
{
  "status": "ok",
  "sweep_status": "completed",
  "job_id": "b41e9c0d7a12",
  "discovered_count": 137,
  "new_count": 41,

  "active_count": 137,
  "top_match": {

完全なペイロードにはtop_roles、job_ids、skipped_sources、debug_logが含まれます。

プロファイルおよびスイープツール​

create_profile​

有効な各エンジンを検証した後、プロフィールファイルを作成する。

パラメータタイプデフォルト値説明
name文字列必須プロフィールに記載されるフルネーム。
titles文字列配列必須対象となる職務タイトル（例：["Technical Writer", "UX Writer"]）。
location文字列必須対象となる所在地（例："New York, NY"）。
resume_path文字列必須PDFまたはDOCX形式の履歴書のパス。
resume_tracksオブジェクト配列null履歴書ごとに1つのエントリー。各エントリーにはnameおよびオプションのpathが含まれる。Sweepyは各投稿を対応するトラックに基づいて評価する。
portfoliosオブジェクト配列nullポートフォリオのエントリー。各エントリーにはtrack、url、path、piecesがオプションで含まれる。
pieces_per_card整数3各ポートフォリオエントリーの件数（1～10）。
remote_onlyブール値false結果を100％リモートワークの職務に限定する。
include_hybridブール値trueハイブリッドワークの職務も結果に含める。
min_salary整数0年間最低基本給。0の場合、最低基本給は設定されていません。
must_have_skills文字列配列nullマッチングを促進するスキル用語。
synonyms配列の配列null代替可能な用語グループ（例：[["docs-as-code", "documentation as code"]]）。
platformsオブジェクトnullプロフィールのplatformsブロックに統合されるプラットフォーム情報。
sources_configオブジェクトnullエンジンの選択内容がsourcesブロックに統合されました。すべてのエンジンは書き込み前に検証されます。
cache_configオブジェクトnullキャッシュ設定（enabledおよびttl_seconds）。
orchestrator_configオブジェクトnullタイムアウトおよびサーキットブレーカー設定。
history_configオブジェクトnullスウィーピング処理で除外される投稿を制御する設定。
job_trackingブール値trueCSVにジョブ追跡用の列を追加し、以前の値も引き継ぐ。
assessment文字列"agent"レポート制御機能。「agent」は、いずれかのカードにキーワードの重複がある場合にレポートの生成をブロックする。「keyword」はキーワードのみを含むレポートの生成を許可する。
output_filename文字列nullカスタムパス。「profiles/{name}_{title}.yaml」をデフォルト値とする。「Sweepy」は両方の部分を小文字に変換し、非英数字の文字をすべて「_」で置き換える。

orchestrator_configは、timeout_per_source_secondsおよびcircuit_breakerオブジェクトを受け取り、その中のfailure_thresholdとcooldown_secondsを処理します。

history_config は enabled、retention_days、match、path を受け取ります。retention_days はデフォルトで 4 となります。match は url または url+role を受け付け、path はデフォルトで ~/.sweepy/history.db となります。

portfolios オンラインURL、ローカルPDF、Markdown、テキストファイル、またはファイルリストを受け取る。エントリにtrackを指定して各トラックごとに別のポートフォリオを保持し、選択したファイルをsubmit_judgmentsにportfolio_highlightとして渡す。set_portfolioを使用して既存のプロフィールのポートフォリオを変更する。

profile_path、enabled_engines、engines_not_enabled、および新しいプロフィールのresume_documentsを返す。各履歴書エントリはpathとそれを使用するトラックを表示するが、解析されたテキストは含まない。

set_portfolio​

保存されたプロフィールが指定したポートフォリオを追加または置き換える。ユーザーがポートフォリオの名前を指定した後にこの処理を実行する。

パラメータタイプデフォルト値説明
profile_path文字列必須既存のプロフィールファイル（YAML）へのパス。
portfoliosオブジェクトの配列null追加するエントリー。trackがないエントリーはすべてのトラックに適用されます。replaceを空のリストとして渡すと、すべてのポートフォリオが削除されます。
replaceブール値false新しいポートフォリオを追加する前に、保存されているポートフォリオを削除します。false 新しいエントリーの名前が既存のエントリーと同じ場合は、その保存データを保持します。
pieces_per_card整数3カードごとにリストアップされるポートフォリオ作品の数（1～10）。未設定の場合は保存された値のまま保持。

portfolios、pieces_per_card、あるいはその両方を渡します。各エントリには、オプションの track、オプションの url または path、およびオプションの {title, url, tags} からなる pieces リストを指定します。

profile_path、resume_tracks、portfolio_configured、portfolio_sources、portfolio_pieces_per_card、portfolio_guidanceを返します。プロフィールにポートフォリオがない場合は、portfolio_guidanceでユーザーに何を尋ねるべきかが示されます。

run_sweep​

5段階のパイプラインを開始し、確定的なキーワードの重複スコアを返します。LLM（大規模言語モデル）の判断は行いません。

パラメータタイプデフォルト値説明
profile_path文字列nullプロファイルのパス YAML。省略された場合、Sweepyは最後に保存されたプロファイルを使用し、次にprofiles/にある最新のプロファイルを使用し、その後ディスク上の最初の従来のプロファイル（profiles/custom_profile.yaml、profiles/paralegal_nyc.yaml、またはconfig.sample.yaml）を使用する。
deduplicateブール値trueこの実行では、異なるボードから重複するURLやマッチする投稿を統合します。
include_seenブール値false以前のスキャンで取得した投稿内容を表示し、その履歴を更新する。
wait_seconds整数45コールが処理結果を返すまでの最長待機時間。値の範囲は0から600です。
timestampstringnullレポートファイル名に使用されるユーザーのローカル時間。形式はYYYY-MM-DD-HHMMSSまたはISO 8601です。アシスタントが会話から既に把握している時間を渡し、各レポートにはサーバーの時間ではなくユーザーの時間が表示されます。

ライブスキャンの実行時間はクライアントのタイムアウトよりも長くなることが多いため、パイプラインはバックグラウンドスレッドで処理を行います。sweep_status: "running"を返す呼び出しにはjob_idが含まれており、そのIDをget_sweep_statusに渡します。状態がcompletedになるまでそのIDを使用します。

同じプロファイルとフラグを使用した2回目の呼び出しは、新たなジョブを開始するのではなく、実行中のジョブに追加されます。サーバープロセスは継続して実行されなければなりません。スウィーピー（Sweepy）のジョブIDはメモリ内に常に保持されており、再起動するとこれらのIDはクリアされます。

以下のいずれかのペイロードが返されます：

  • 実行中：sweep_status、job_id、progress。step、total、label、elapsed_seconds、debug_log、messageも含まれています。
  • 完了済み：sweep_status、job_id、discovered_count、new_count、previously_seen_count、active_count、top_match、top_roles、reports、job_ids、card_count、assessed_count、assessment_mode、assessment_required、skipped_sources、elapsed_seconds、debug_log、およびmessage。top_rolesには最初の5つの役割が含まれています。
  • 失敗: status: "error", message, job_id, および sweep_status: "failed"。

job_id が開始したスウィープの進捗状況を待機します。

発見された投稿がすべて重複している場合、previously_seen_countは合計数を報告し、active_countは0を報告します。include_seenをtrueに設定した上でrun_sweepを呼び出してこれらの投稿を確認してください。

MCPスウィープ処理では、コマンドラインで指定されたアーティファクト名そのままが書き出され、mcpというマーカーが付加されます（例：results/tech_writer_mcp_2026-10-27-223115.pdfおよびそれに対応する.csv、.jsonファイル）。一方、CLIやウィザードを使用した場合はマーカーなしでファイル名が書き出されるため、フォルダ内でどのパスから各レポートが生成されたかがわかります。timestampを指定することで、ファイルにユーザー自身の日時がスタンプされます。これを指定しない場合、Sweepyはプロフィール内のexport.timezoneから現在時刻を読み取ります。

get_sweep_status​

run_sweepによって開始された処理が完了するのを待ち、その進捗状況を報告する。

パラメータタイプデフォルト値説明
job_id文字列nullrun_sweep からスウィープ処理のIDを取得する。デフォルトでは最新のジョブが使用される。
wait_seconds整数45コールが処理結果を返すまでの最長待機時間。値の範囲は0から600です。

各レスポンスは、対応するrun_sweepの結果と同じフィールドを返します。job_idが欠落している場合や未知の場合は、run_sweepを参照するエラーが返されます。

完了したスウィープ処理では、そのカードもライブセッションに読み込まれるため、get_jobs、submit_judgments、render_reportは「completed」という状態になった時点で動作します。

get_jobs​

現在のセッションに保存されているカード記録を、キーワードの重複度または提出されたマッチスコアに基づいてランク付けして返します。

パラメータタイプデフォルト値説明
profile_stem文字列null保存されたセッションを読み込むために使用されるプロファイル識別子。例：pedro_writer。
results_dir文字列"results"report_session.json を含むフォルダー。
limit整数null返却するカードの数。0を指定するとすべてのカードが返される。Sweepyでは最低1枚の返却が必須となっている。
needs_descriptionブール値nulltrueは投稿内容のないカードのみを返します。falseは投稿内容のあるカードのみを返します。

アクティブなプロフィールのcount、session_count、needs_description_count、jobs、および履歴書（resume）データを返します。スキャン処理が実行中には、ペイロード（payload）にsweep_status、running_job_id、progress、そしてそのスキャン処理以前のカード情報を警告するmessageが追加されます。

レジュームドキュメント​

resume_documents には、履歴ファイルごとに 1 つのエントリがリストされます。各エントリには、path、そのファイルを使用する tracks、および解析済みのドキュメントである text が記載されています。同じファイルを共有するトラックは 1 つのエントリを共有するため、Sweepy ではテキストが重複することはありません。 また、ペイロードには resume_default_path、resume_configured、および resume_guidance も含まれます。

アシスタントがそのテキストを評価します。プロフィールのmust_have_skillsおよびsynonymsに基づいてキーワードの一致を判断します。評価対象は候補者ではなくYAMLです。

アシスタントは、採用担当者がファイルを読む方法そのままでファイルを解析します。転職可能なスキル、経験年数、専門分野、使用するツール、および各項目の内容を考慮してスコアを算出します。その後、求人広告に使用されている応募者管理システム（ATS: Applicant Tracking System）の解析方法に従ってファイルにスコアを付けます。

  • 標準的なExperienceまたはSkillsセクションに記載されている用語は、証拠として扱われます。
  • 表、ヘッダー、フッター、画像、または2列のサイドバー内にある同じ用語は評価対象外となります。
  • 応募リンクからATSの名称（Workday、Greenhouse、Lever、Ashby、iCIMS、Taleo、Workable、SmartRecruitersなど）が判明した場合、それをアシスタントが明記します。
  • パーサーが認識できない情報はconcernsに記載されます。

ファイルが欠落している場合や読み取れない場合、textの値は空のままとなりますが、エラーは表示されません。ファイルのパス自体は表示されるため、アシスタントは問題を報告できます。

submit_judgments​

アシスタントの評価結果は1つのカードにまとめられるか、一括で処理されます。nullでないフィールドのみが変更されます。

パラメータタイプデフォルト値説明
job_id文字列nullrun_sweepまたはget_jobsから取得した安定したカードID。judgmentsを指定しない限り必須です。
match_pct整数null0から100までのマッチ率。まずresume_documentsを参照し、その後求人広告のATSの解析方法に従ってファイルにスコアを付けます。この値を指定するとカードのラベルがMATCHに変更されます。
resume_track文字列nullカードに表示される履歴書のトラック（追跡情報）。
resume_color文字列nullそのトラックに関連するバッジの色。
domain文字列nullカードに表示される役割の専門分野。
summary文字列nullカードの要約テキスト。
requirements文字列null経歴書の内容と役割の関連性を示す説明文。
alignment文字列null履歴書の証拠資料をその役職に関連付けることに注意してください。
concerns文字列null候補者に不利な点：満たされていない要件、経験年数のギャップ、専門分野の不一致、現場での期待との差異、基本給以下の給与、またはパーサーが処理できないデータなど。
has_extended_response文字列null応募フォーマット（ポータルやメールなど）。
app_format文字列null給与に関する情報。
comp文字列null福利に関する情報。
benefits文字列nullカードのテーマ設定。
page_theme文字列nullカードテーマのオーバーライド。
portfolio_fit整数null0から100のポートフォリオスコア。このカードではPORTFOLIO FITとして表示される。
portfolio_highlight文字列nullこのアプリケーションで送信する情報の名称です。この項目がないカードは、プロフィールに保存されている情報を表示します。
description文字列nullスウィーピー（Sweepy）が解析できなかったカードのURLから読み取られた投稿内容です。
judgments配列null判断対象となるオブジェクトの一覧で、各オブジェクトにはjob_idおよびそれに続く任意のフィールドが含まれます。これをjob_idと組み合わせてはいけません。

プロフィールではなく、ドキュメント自体を評価してスコアを付けます。get_jobsは解析された履歴書のテキストをresume_documentsとして返し、must_have_skillsおよびsynonymsは解析処理の結果のみを提供します。サイドバーのグラフィック内に表示されるスキルセットなど、解析エンジンが見落とす可能性のある情報もconcernsに記録します。

統合されたカードデータをjobとして返します。一括処理の場合はapplied、jobs、rejectedのすべてが返されます。rejectedではセッション内に存在しないエントリーのIDが示されます。

import_jobs​

独立した調査で発見・検証された役割情報を追加します。スウィーピーはデフォルトでこれらの情報を確認しません。

パラメータタイプデフォルト値説明
jobs_json文字列必須JSON カードデータの配列。
validateブール値falseインポート前に各URLをリンクチェッカーで確認します。

importedおよびskippedの両方を返します。レート制限やボット防止のための応答は未確認として扱われ、そのため投稿が無効であることを証明しません。

render_report​

現在のセッションからカードデータをPDF形式で出力します。

パラメータタイプデフォルト値説明
profile_stem文字列null保存されたセッションを読み込むために使用されるプロファイル識別子。
results_dir文字列"results"デフォルト出力用および保存されたセッション用のフォルダ名。
output_filename文字列nullPDFファイルのパス。ワークスペース内に存在する必要があります。空の値の場合、{profile_stem}_mcp_{YYYY-MM-DD-HHMMSS}.pdfに「」が書き込まれ、results_dirにもその名前が反映されます。この名前はコマンドラインで指定された日付と一致し、mcpマーカーも追加されます。
playbook文字列""プレインテキスト形式の戦略メモです。スウィーピーは&および角括弧をエスケープ処理し、**bold**を太字で表示します。改行はそのまま保持されます。スウィーピーはテキストをセッションと共に保存するため、後で同じ処理を再度実行する際には保存されたテキストが再利用されます。保存されたテキストがない場合は空の値が使用されます。
timestamp文字列nullデフォルトファイル名のためのユーザーのローカル時間（YYYY-MM-DD-HHMMSSまたはISO 8601形式）。output_filenameが空の場合のみ適用されます。

pdf_report、pages、card_count、playbook_savedのすべてを返します。

プロフィールのデフォルト設定ではreport.assessment: "agent"が有効であり、キーワードの重複がある場合はレンダリングがブロックされます。エラーリストにはunassessed_job_idsおよびunassessed_titlesが記載されるため、アシスタントはどのように評価すべきかを把握できます。report.assessment: "keyword"を設定して混合されたレポートを許可するか、SWEEPY_REQUIRE_JUDGMENTS=1を使用してすべてのプロフィールに適用するかを選択できます。またはexport_reportを設定して特定の条件を適用することもできます。

結果および履歴ツール​

get_results​

ディスクから最新のスウィーピー処理結果を読み取ります。再処理や再評価は行いません。

パラメータタイプデフォルト値説明
profile_stem文字列null結果ファイルをフィルタリングするプロファイル識別子。これを省略すると、最新の結果ファイルが読み取られる。
results_dir文字列"results"結果ファイルが保存されているフォルダー。
limit整数10返すトップロールの数。範囲は1から100まで。

result_file、pdf_report、csv_report、total_roles、top_rolesを返す。各ロールにはtitle、company、location、match_score、match_kind、resume_track、domain、url、playbookが含まれる。

「KEYWORD OVERLAP」とラベル付けされたスコアは、最初の処理で得られた確定的な値です。マッチとして表示する前にget_jobsおよびsubmit_judgmentsを使用してください。

export_report​

既存のスウィープデータからレポートファイルを再構築する。

パラメータタイプデフォルト値説明
json_source文字列nullスウィープ処理の実行パス（JSON）。これはprofile_stemよりも優先される。
profile_stem文字列null最新のマッチを見つけるために使用されるプロファイル識別子（JSON）。
results_dir文字列"results"結果ファイルが保存されているフォルダー。
formats文字列配列["pdf"]出力形式：pdf、png、csv、またはjson。
candidate_name文字列"Job Seeker"PDFヘッダー内の名前。
output_dir文字列null出力フォルダー。デフォルトではソースファイル（JSON）が保存されているフォルダーが使用される。
job_trackingブール値nullCSVエクスポートにジョブ追跡用の列を追加するかどうか。設定しない場合は、プロファイルのexport.tracking設定に従う。

source_file、roles_exported、generated、errorsを返す。generatedオブジェクトにはpdf、pdf_pages、png、csv、csv_rows、jsonが含まれる。PNG形式のリクエストの場合はPDFが優先的に出力される。JSONの出力は{stem}_export.jsonを上書きしない。

clear_history​

報告された投稿内容を破棄し、次のスウィープ処理で再度報告できるようにする。

パラメータタイプデフォルト値説明
profile_path文字列nullプロファイル（YAML）のパス。
profile_stem文字列nullプロファイル識別子（例：pedro_writer）。

scope、cleared、remainingを返す。履歴データはプロファイルごとに管理される。スウィープ処理後に両方のパラメータを指定しない場合、使用されたプロファイルの情報がクリアされる。この場合はprofile_pathまたはprofile_stemを指定する必要がある。

ドキュメント変換ツール​

convert_document​

.docx、.doc、.txt、.md、.pdfをPDF形式に変換します。PDFソースファイルはそのまま変更されずに処理されます。レガシーな.docファイルにはMicrosoft Wordが必要です。

パラメータタイプデフォルト値説明
document_path文字列必須変換対象のファイルのパス。
pdf_path文字列null出力先のパス。デフォルトはソースフォルダ。

pdf_path および source_path を返す。

convert_docx​

python-docx と reportlab を使用して DOCX 形式の履歴書を PDF に変換する。Microsoft Word が利用可能な場合は docx2pdf を使用する。

パラメータタイプデフォルト値説明
docx_path文字列必須.docx ファイルのパス。
pdf_path文字列null出力先のパス。デフォルトは DOCX フォルダ。

pdf_path を返す。

書き込みパス​

出力結果は必ず Sweepy フォルダ内に保存される。Sweepy フォルダ外に出力するには SWEEPY_ALLOW_EXTERNAL_WRITES を 1 に設定する必要がある。処理で開くことができる任意のパスを指定できる。
