Sweepy開発者リファレンス

SweepyはシンプルなPythonプロジェクトとして動作しており、このページでは各パイプラインステージがどのモジュールによって実行されているかを示しているため、変更を加えるべき場所がわかります。

対象読者​

Sweepyのコードを変更したり、ジョブソースを追加したい場合はこのページを読んでください。レビュアーはこのページを参考にしてプルリクエストを処理できます。このページでは内部構造（モジュール、依存関係、Pythonのバージョン）のみについて説明しています。

ヒント

スウィープ処理を実行したい場合はこのページをスキップしてください。インストールから始めてください。

パイプラインのステージとモジュール​

swee.pyは順番に5つのステージを実行します。ターミナルでは、各ステージが[1/5]から[5/5]までとして表示されます。

ステージモジュール機能
1. プロフィールの読み込みengine/config.pyプロフィールを読み込み、検証します。同じモジュール内にあるウィザードがプロフィールを作成します。
2. ロールの発見engine/discovery.pyクエリアグリゲーターがpython-jobspyを通じて各プラットフォームを分類する。
2. ロールの検索engine/sources/公開エンドポイントからGreenhouse、Ashby、Lever、Workable、Built In NYCのボードデータを取得する。
2. 重複データの除去swee.pyアグリゲーターとソースの結果を各ジョブリンクごとに1枚のカードに統合する。
3. URLの検証engine/validator.pyHTTP HEADリクエストとGETフォールバックを使用して各リンクをチェックし、不要な投稿を削除する。
4. 経歴書とのマッチング評価engine/scorer.py投稿内容と経歴書の用語を抽出し、要件やキーワードの一致度を評価する。書面による回答が必要な投稿にはタグを付ける。
5. 経歴書情報のルーティングengine/enrich.py用語の一致度が最も高い経歴書情報を選択し、対応するバッジの色を割り当てる。
5. カードの詳細表示engine/enrich.pyカードの要約、給与情報、カスタマイズされたヒントテキストを生成する。
5. カードのPDF出力engine/report.pyデフォルトで1ページに6枚のカードを表示し、ページ数を返す。
5. レガシーテーブルPDFengine/pdf_builder.pyプロファイル設定によってテーブルのレイアウトが表示されます（report.style: legacy）。
5. データのエクスポートengine/exporter.pyCSVおよびJSONファイルを生成する。リクエストに応じてPNG画像をレスタライズする。
5. ジョブの追跡engine/tracking.py追跡用の列を追加し、以前のエクスポートデータを読み込んで入力した値を再利用する。

engine/session.py | ステートフルモデルコンテキストプロトコル（MCP）のフローにおいてカードデータを保持する。各ジョブリンクの安定したハッシュ値でカードを管理する。

変更を加える場所​

あなたは変更したいと思っています。Start in
仕事の情報源またはそのエンドポイントengine/sources/、およびdata/sources/内にあるシードリスト
スコアの比較方法engine/scorer.py
カードに表示される内容engine/enrich.py、その後 engine/report.py
リンクのチェック方法engine/validator.py
コマンドラインフラグswee.py
MCP ツールserver.py
ヒント

server.pyはコマンドラインツールと同じエンジンモジュールをインポートします。エンジンの変更後はMCPパスをテストしてください。なぜなら、1つの修正が両方のエントリーポイントに影響を与えるからです。

モジュールリファレンス​

エントリーポイント​

モジュール（Module）目的（Purpose）
swee.py5段階のパイプラインにおける主要なオーケストレーターおよびargparseコマンドラインエントリーポイント。
server.py「Model Context Protocol（stdio）」サーバーは、AIアシスタントにエンジンツールを提供する。get_jobs 解析された履歴書のテキストを返し、アシスタントがその内容を評価する。プロフィール情報のキーワードリストではない。

エンジンモジュール​

モジュール（Module）目的（Purpose）
engine/config.pyインタラクティブなウィザード機能およびYAMLの読み込み・検証処理。
engine/discovery.pypython-jobspy用のスクレイパー処理、申請者追跡システム（ATS）の検出、重複データの除去。
engine/validator.pyリンクの稼働状況チェックおよびソフト404エラーの検出。検証不能なリンクは処理を続行する。
engine/scorer.py履歴書からの情報抽出、パーセンテージマッチング、タグ付け、各項目のスコアリング。
engine/enrich.py概要表示用のカードデータの充実処理、給与情報の表示、トラックのルーティング、カスタマイズされたヒントの提供。
engine/session.pyスレッドセーフなカードストレージ機能。MCPフローにおいて安定したIDを使用。
engine/report.pyデフォルトのカードレイアウト用PDFファイル。
engine/pdf_builder.pyreport.style: legacy用のレガシーなテーブルレイアウトPDFファイル。
engine/exporter.pyCSVおよびJSON形式でのデータ出力、報告書PDFのPNG画像化処理。
engine/tracking.pyトラッキング用の列および、以前のエクスポートデータの継続的な読み込み処理。
engine/docx.pyDOCXを使ってpython-docxおよびreportlabと共にPDF形式に変換し、Microsoft Wordでも閲覧可能にする。
engine/documents.py--convert向けのドキュメント配信処理およびMCPコンバーターの使用。対応フォーマットはDOC、テキスト、Markdown、PDF。
engine/logging.pylogs/でオプションとしてデバッグログを記録する。
engine/cache.pyクエリ内容とエンジン設定に基づいてSQLiteからデータをスクレイピングし、キャッシュする。キャッシュの有効期限は1時間。
engine/circuit_breaker.py絶え間ないソースエラーの発生回数をカウントし、冷却期間中は呼び出しを一時停止する。
engine/engine_defaults.py共通のデフォルトサイトリストおよびエンジン設定です。サイクルを避けるため、インポートは不要です。
engine/engines.pyhirehunt、openroles、apify、jobdropエンジン用のアダプターレジストリおよびインストーラー。
engine/history.py既に報告された求人情報の永続的な記録。毎日のスキャンでは新規の求人情報のみを報告する。
engine/normalize.py生のエンジンデータを共有された投稿用の列に正規化する。
engine/salary.pyボードが構造化された給与情報を省略している場合、投稿テキストから給与情報を抽出する。
engine/sweep_config.pyプロフィール設定に共有されたエンジンのデフォルト値を適用する。
engine/updater.pyチェックアウト時のGitベースの更新チェックおよび依存関係の再インストール。

定型的なソースコード（Deterministic sources）​

モジュール（Module）目的（Purpose）
engine/sources/__init__.pydata/sources/からのデータ取得およびシードリストの読み込みを行うフェッチャー（Fetcher）。
engine/sources/_common.pyHTTPのヘッダー処理、タイトルの事前フィルタリング、およびHTMLからテキストへの変換を行うための共通ヘルパーモジュール（Shared helpers）。
engine/sources/greenhouse.pyグリーンハウス（Greenhouse）の求人情報取得用フェッチャー。
engine/sources/ashby.pyアシュビー（Ashby）の求人情報取得用フェッチャー。
engine/sources/lever.pyレバー（Lever）の求人情報取得用フェッチャー。
engine/sources/workable.pyワークアブル（Workable）ウィジェット用APIの取得モジュール。
engine/sources/builtinnyc.py「Built In NYC」カテゴリのスクレイパーモジュール。

エンジンアダプター（Engine adapters）​

モジュール（Module）目的（Purpose）
engine/adapters/__init__.py各エンジン名をそのアダプタにマッピングするレジストリ。
engine/adapters/base.pyScraperAdapter 基礎クラス、共通のUser-Agentヘッダー、および結果の形状を処理するヘルパーファンクション。
engine/adapters/jobspy_adapter.pypython-jobspy LinkedIn、Indeed、Glassdoor、ZipRecruiter向けのアグリゲーターアダプター。
engine/adapters/ats_adapter.pyengine/sources/内の決定的なATSフェッチャーを上書きするアダプタ。
engine/adapters/hirehunt_adapter.pyオプションとして利用可能なhirehuntエンジンアダプタ。
engine/adapters/openroles_adapter.pyオプションとして利用可能なopenrolesエンジンアダプタ。
engine/adapters/apify_adapter.pyオプションとして利用可能なApifyアクターアダプタ。
engine/adapters/jobdrop_adapter.pyオプションとして利用可能なjobdropエンジンアダプタ。

データ、スクリプト、テスト​

パス目的
data/sources/*.txtボード、企業、組織、カテゴリ用のシードリスト。
scripts/make_sample.pydocs/に保存されているサンプルレポートを生成するためのビルダー。
tests/pytestスイートで、各機能領域ごとにファイルが分かれている：アダプター、設定、ドキュメント、docxファイル、エンジン、データの処理、履歴記録、ログ記録、レポート作成用のファイルなど。その他にも給与情報、スコアリング機能、サーバー処理、セッション管理、ソースコード、追跡機能、更新処理、検証処理用のファイルがある。
注記

discovery.py, exporter.py, pdf_builder.pyを変更した場合は、専用のテストファイルを作成し、そのファイルをtests/に配置する。

必要条件およびサポートされているPythonバージョン​

項目詳細
Pythonの要件SweepyはPython 3.10以降が必要であり、すべてのモジュールでは3.10のシンタクスが使用されている。
テスト対象範囲.github/workflows/ci.ymlのCIワークフローではUbuntu上でPython 3.10、3.11、3.12が実行される。
チェック対象の規則pyproject.tomlではrufftarget-version = "py310"が設定されている。より新しいバージョンのみがチェック対象となる。
行の長さruffでは行の長さが100文字以下でなければならず、E501の設定は無視される。
CI（継続的インテグレーション）ステップジョブは必要なファイルをインストールした後、ruff check .を実行し、その後pytestを実行する。
注記

pyproject.tomlによってrequires-python = ">=3.10"が宣言されているため、インストール時に古いPythonインタプリタは使用できない。CIの設定とruffの規則によってテスト対象範囲が決定される。Python 3.13は実際には動作するが、この範囲には含まれていない。

Python 3.13

pymupdfパッケージは、事前にビルドされたバイナリ（wheel）が存在しない場合でもソースからコンパイルすることができます。Microsoft C++ Build Toolsをインストールし、依存関係をインストールする前に「Desktop development with C++」ワークロードを選択してください。

リポジトリの構成​

Repository layout
swee.py              CLI entry point and sweep orchestrator
server.py            MCP server over stdio
engine/              Pipeline modules
engine/sources/      Deterministic ATS fetchers
engine/adapters/     Aggregator and optional engine adapters
data/sources/        Seed lists for each fetcher
profiles/            YAML search profiles
results/             Generated PDF, CSV, JSON, and PNG files
logs/                Opt-in debug logs
styles/              Vale style rules for the docs
tests/               pytest suite

server.py内のツールの設定を変更した場合は、同じコミットでMCPツールの参照情報も更新してください。
