Sweepy 開発者リファレンス

Sweepyは、フラットな構造を持つ小規模なPythonプロジェクトとして動作します。このページでは、各パイプラインステージを実行するモジュールを一覧表示しており、変更を加えるべき箇所を把握できます。

対象読者​

Sweepyのコードを変更したり、求人ソースを追加したりする予定がある場合は、このページをお読みください。 レビュー担当者は、プルリクエストを作成する際の参考としてこのページを利用できます。このページでは、モジュール、依存関係、Python バージョンといった内部構造についてのみ説明しています。

ヒント

スイープを実行したい場合は、このページをスキップしてください。インストール から始めてください。

パイプラインのステージとモジュール​

swee.py は 5 つのステージを順番に実行します。ターミナルには、各ステージが [1/5] から [5/5] の形式で表示されます。

ステージモジュール機能
1. プロファイルの読み込みengine/config.pyYAMLプロファイルを読み込み、検証します。同じモジュール内のウィザードがプロファイルを作成します。
2. ロールの検出engine/discovery.pypython-jobspy を通じてアグリゲーターフィードをクエリし、各プラットフォームを分類します。
2. ロールの検出engine/sources/公開エンドポイントから Greenhouse、Ashby、Lever、Workable、および Built In NYC の求人掲示板を取得します。
2. 重複排除swee.pyアグリゲーターとソースの結果を統合し、求人リンクごとに 1 枚のカードにまとめます。
3. URLの検証engine/validator.pyHTTP HEAD リクエストと GET フォールバックを使用してすべてのリンクをチェックします。無効な求人情報を削除します。
4. 履歴書との照合engine/scorer.py求人情報と履歴書から用語を抽出し、要件とキーワードの重複度をスコアリングします。記述式回答を要求する求人情報にはタグを付けます。
5. 履歴書のトラックの割り当てengine/enrich.py用語の重複率が最も高いトラックを選択し、一致するバッジの色を割り当てます。
5. カードの充実engine/enrich.pyカードの要約、報酬情報、およびカスタマイズされたヒントテキストを作成します。
5. デフォルトのカードPDFengine/report.pyカードレイアウトをレンダリングし（デフォルトでは1ページあたり6枚）、ページ数を返します。
5. レガシー形式の表PDFengine/pdf_builder.pyプロフィールで report.style: legacy が設定されている場合、表レイアウトをレンダリングします。
5. データのエクスポートengine/exporter.pyCSV および JSON ファイルを出力します。要求に応じて、ページの画像を PNG 形式でラスタライズします。
5. ジョブ追跡engine/tracking.py追跡用カラムを追加し、以前のエクスポートデータを読み込むことで、入力した値が反映されるようにします。

engine/session.py には、ステートフルな Model Context Protocol (MCP) フロー用のカードストアが格納されています。各ジョブリンクの安定したハッシュをインデックスとして、スレッドセーフなマップにカードを保持します。

変更を行う場所​

変更したい内容開始場所
ジョブソースまたはそのエンドポイントengine/sources/、および data/sources/ 内のシードリスト
マッチのスコアリング方法engine/scorer.py
カードの表示内容engine/enrich.py、続いて engine/report.py
リンクの検証方法engine/validator.py
コマンドラインフラグswee.py
MCPツールserver.py
ヒント

server.py は、コマンドラインツールと同じエンジンモジュールをインポートします。エンジンの変更後は、MCP パスを必ずテストしてください。1 つの修正が両方のエントリポイントに影響を与えるためです。

モジュールリファレンス​

エントリポイント​

モジュール目的
swee.py5段階のパイプラインにおける主要なオーケストレーターおよび argparse によるコマンドラインエントリポイント。
server.pyモデルコンテキストプロトコル （stdio）サーバー。AIアシスタントに対してエンジンツールを公開します。get_jobsは解析済みの履歴書テキストを返すため、アシスタントはプロフィールのキーワードリストではなく、文書そのものを評価します。

エンジンモジュール​

モジュール目的
engine/config.py対話型ウィザード、およびYAMLの読み込みと検証。
engine/discovery.pypython-jobspyおよび決定論的ソース向けのスクレイパーオーケストレーション、応募者追跡システム（ATS）の検出、および重複排除。
engine/validator.pyリンクの稼働状況チェックとソフト404の検出。検証不可能なリンクも処理対象に含まれる。
engine/scorer.py履歴書からの用語抽出、一致率の算出、タグ付け、およびトラックごとのスコアリング。
engine/enrich.py概要、報酬、トラックのルーティング、および個別に最適化されたアドバイスのためのカード情報充実化。
engine/session.pyステートフルな MCP フロー向けの、安定した ID を持つスレッドセーフなカードストア。
engine/report.pyデフォルトのカードレイアウト PDF。
engine/pdf_builder.pyreport.style: legacy 用のレガシーな表形式レイアウトのPDF。
engine/exporter.pyCSVおよびJSONへのエクスポート、ならびにレポートPDFのPNGラスタライズ。
engine/tracking.py追跡列および過去のエクスポートデータの引き継ぎ読み取り。
engine/docx.pypython-docx および reportlab を使用した DOCX から PDF への変換、および Microsoft Word によるフォールバック。
engine/documents.py--convert および MCP コンバータ向けのドキュメント配信。DOCX、DOC、テキスト、Markdown、PDF を対象とする。
engine/logging.pylogs/ ディレクトリへのデバッグログ出力（オプトイン）。
engine/cache.pyクエリとエンジンセットをキーとする SQLite スクレイピングキャッシュ。有効期限は 1 時間。
engine/circuit_breaker.py連続するソースエラーをカウントし、クールダウン期間中は呼び出しを一時停止する。
engine/engine_defaults.py共有されるデフォルトのサイトリストおよびエンジン設定。循環参照を避けるため、インポートを行わないように設計されている。
engine/engines.pyオプションの hirehunt、openroles、apify、jobdrop エンジン用のアダプタレジストリおよびインストーラ。
engine/history.pyすでに報告済みの求人情報の永続的な記録。毎日のスイープ処理により、新規の求人情報のみが報告される。
engine/normalize.py生のエンジン行データを、共有の求人情報カラムに正規化する。
engine/salary.py求人掲示板に構造化された給与情報が記載されていない場合、求人文から給与情報を抽出する。
engine/sweep_config.pyプロファイル設定に共有エンジンデフォルト値を適用します。
engine/updater.pyGit ベースの更新チェックおよびチェックアウトの依存関係の再インストールを行います。

決定論的ソース​

モジュール目的
engine/sources/__init__.pydata/sources/ からのフェッチャーのエクスポートおよびシードリストの読み込み。
engine/sources/_common.pyHTTPヘッダー、タイトルの事前フィルタリング、HTMLからテキストへの変換のための共有ヘルパー。
engine/sources/greenhouse.pyGreenhouse求人サイトのフェッチャー。
engine/sources/ashby.pyAshby求人サイトのフェッチ機能。
engine/sources/lever.pyLeverの求人情報のフェッチ機能。
engine/sources/workable.pyWorkableウィジェットAPIのフェッチ機能。
engine/sources/builtinnyc.pyBuilt In NYCのカテゴリスクレイパー。

エンジンアダプタ​

モジュール目的
engine/adapters/__init__.py各エンジン名をそのアダプタにマッピングするレジストリ。
engine/adapters/base.pyScraperAdapter の基底クラス、共有 User-Agent ヘッダー、および結果形式のヘルパー。
engine/adapters/jobspy_adapter.pyLinkedIn、Indeed、Glassdoor、ZipRecruiter 向けの python-jobspy アグリゲーター・アダプター。
engine/adapters/ats_adapter.pyengine/sources/ にある決定論的な ATS フェッチャーをラップするアダプター。
engine/adapters/hirehunt_adapter.pyオプションの hirehunt エンジンアダプター。
engine/adapters/openroles_adapter.pyオプションの openroles エンジンアダプタ。
engine/adapters/apify_adapter.pyオプションの Apify アクターアダプタ。
engine/adapters/jobdrop_adapter.pyオプションの jobdrop エンジンアダプタ。

データ、スクリプト、およびテスト​

パス目的
data/sources/*.txtボード、企業、組織、カテゴリのシードリスト。
scripts/make_sample.pydocs/ に保存されているサンプルレポート用のビルダー。
tests/各領域（アダプター、設定、ドキュメント、docx、エンジン、エンリッチ、履歴、ロギング、レポート）ごとにファイルが配置された pytest スイート。さらに、給与、スコアラー、サーバー、セッション、ソース、swee、トラッキング、アップデーター、バリデータに関するファイルも含まれます。
注記

discovery.py、exporter.py、または pdf_builder.py を変更した場合は、専用のテストファイルを追加してください。そのファイルは tests/ ディレクトリに配置してください。

依存関係​

実行時パッケージは requirements.txt から取得されます。以下のバージョンはそのファイルに準拠しています。

パッケージバージョンSweepy における役割

beautifulsoup44.15.0Greenhouse、Lever、Workable、およびBuilt In NYCのソースからHTMLを解析します。
pyyaml6.0.3YAMLプロファイルの読み書きを行います。
questionary2.1.1対話型ウィザードの質問を処理します。
prompt-toolkit3.0.53ウィザードの対話型テキスト入力を処理します。
python-jobspy1.2.0API 認証情報なしで LinkedIn、Indeed、Glassdoor、ZipRecruiter からデータを収集します。
pandas2.2.3求人情報を構造化し、CSV および JSON 形式のエクスポートデータを生成します。

requirements.txt には、1つのオプションパッケージも記載されています。WordでPDFを作成する必要がある場合は、docx2pdf のコメントを外してください。

  • docx2pdf (0.5.2、オプション) は、Windows上のMicrosoft Wordを通じてDOCXをPDFに変換します。Sweepyは、マシンにMicrosoft Wordがインストールされている場合にこれを呼び出します。
注記

mcpは意図的に1.xのままにしています。2.x SDKは2026年7月28日時点のプロトコル時代のみに対応しています。 server/discover をプローブした後、initialize ハンドシェイクにフォールバックするクライアントは、-32022 エラーを受け取ります。VS Code Copilot はこのフォールバックに従います。

ヒント

pandas は意図的に 2.x のままにしています。Pandas 3.x には Python 3.11 以降が必要ですが、CI マトリックスでは依然として Python 3.10 でのテストが行われています。

要件およびサポートされる Python バージョン​

項目詳細
Pythonの最低バージョンSweepyはPython 3.10以降を必要とし、すべてのモジュールで3.10の構文を対象としています。
テスト範囲.github/workflows/ci.yml内のCIワークフローは、Ubuntu上でPython 3.10、3.11、および3.12を実行します。
リンティング対象pyproject.toml では ruff の target-version = "py310" が設定されています。これより新しいバージョンのみを使用する記述があると、リンティングジョブが失敗します。
行の長さRuff は 100 文字の行長制限を適用し、E501 は無視します。
CI ステップこのジョブでは、両方の要件ファイルをインストールし、pytest の実行前に ruff check . を実行します。

:::注 pyproject.toml では requires-python = ">=3.10" と宣言されているため、インストール時に pip はそれより古いインタプリターを拒否します。 CIマトリックスとruffターゲットによって、テスト対象の範囲が定義されています。Python 3.13は実際には動作しますが、その範囲外となります。 :::

Python 3.13

pymupdfパッケージは、あらかじめビルドされたwheelが存在しない場合、ソースからコンパイルされる可能性があります。 依存関係をインストールする前に、Microsoft C++ Build Tools をインストールし、「C++ によるデスクトップ開発」 ワークロードを選択してください。

リポジトリの構成​

リポジトリの構成

server.py stdio 経由の MCP サーバー
engine/ パイプラインモジュール
engine/sources/ 決定論的 ATS フェッチャー
engine/adapters/     アグリゲーターおよびオプションのエンジンアダプター
data/sources/ 各フェッチャー用のシードリスト

results/ 生成された PDF、CSV、JSON、および PNG ファイル
logs/ オプションのデバッグログ
styles/ ドキュメント用の Vale スタイルルール
tests/ pytest スイート
