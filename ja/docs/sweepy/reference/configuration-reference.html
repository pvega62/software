プロファイル設定リファレンス

このページにはSweepyのプロファイルが受け入れるすべての設定項目が記載されています。プロファイルを編集している間はこのページを開いたままにしてください。ガイド付きの手順については「Sweepyの設定方法」を参照してください。

プロファイルの保存場所​

profiles/から始めるか、YAMLのようなプリセットから始めてください。テンプレートをコピーし、名前を変更して値を編集してください。

config.sample.yaml または profiles/paralegal_nyc.yaml のようなプリセットから始めます。テンプレートをコピーし、名前を変更して値を編集します。

Terminal
copy config.sample.yaml profiles\my_search.yaml
notepad profiles\my_search.yaml

そのファイルをスウィーピー（Sweepy）の対象として指定します。

Terminal
sweepy --profile profiles/my_search.yaml
注記

プロファイルにはすべての設定情報が保存されます。都市や役割ごとにプロファイルを作成できます。スウィーピーはプロファイル内のデータだけでなく、ディスカバリーキャッシュ、ヒストリーデータベース、および logs/ および results/ フォルダ内にもスキャン状態を保持します。

注意

インデントにはスペースを使用し、タブは決して使わないでください。YAML はタブを受け付けず、タブが 1 つ混入するだけでプロファイル全体が読めなくなります。

完整なプロフィール例​

下記の例はAlexの完全なプロフィールを示しています。#で始まる行はコメントとして機能し、Sweepyはこれらを無視します：

profiles/paralegal_nyc.yaml
# ─────────────────────────────────────────────────
# Sweepy — Alex's Paralegal Profile (New York City)
# ─────────────────────────────────────────────────

# Your name. It appears in the PDF report header.
name: "Alex Rivera"

# Set true to write rotating debug logs under logs/.
debug: false

# ─── Job search ───────────────────────────────────
search:
  # Every title Sweepy searches at the same time.
  titles:
    - "Paralegal"
    - "Legal Assistant"
    - "Litigation Support Specialist"
    - "Legal Secretary"

  # Your target market.
  location: "New York, NY"

  # true keeps remote roles only. false keeps remote, hybrid, and on-site roles.
  remote_only: false

  # false removes hybrid roles from every report.
  include_hybrid: true

  # Annual salary floor. Use 0 to skip salary filtering.
  min_salary: 65000

  # true reads pay from the posting text when a board omits structured pay.
  salary_from_description: true

# ─── Resume ───────────────────────────────────────
resume:
  # Path to a PDF or DOCX resume. Forward slashes work on Windows.
  path: "Alex_Rivera_Resume.pdf"

  # Terms that carry the most weight when Sweepy scores a posting.
  must_have_skills:
    - "Westlaw"
    - "LexisNexis"
    - "e-discovery"
    - "Contract Review"
    - "Legal Research"

  # 1.0 is standard. Raise it to reward exact skill matches.
  keywords_weight: 1.5

  # Interchangeable terms. Sweepy matches every member of a group either way.
  synonyms:
    - ["e-discovery", "ediscovery", "electronic discovery"]
    - ["legal research", "case law research"]
    - ["docketing", "case calendaring"]
    - ["legal assistant", "legal secretary"]
    - ["contract review", "contract analysis", "agreement review"]

  # Optional: one resume per role family. Sweepy picks the best fit for each posting.
  tracks:
    - name: "Paralegal Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Paralegal.pdf"
      color: "#1D4ED8"
      route_keywords: ["paralegal", "litigation", "e-discovery"]
    - name: "Legal Assistant Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Legal_Assistant.pdf"
      color: "#7E22CE"
      route_keywords: ["legal assistant", "legal secretary", "scheduling"]

# ─── Platforms ────────────────────────────────────
platforms:
  greenhouse: true
  ashby: true
  lever: true
  workable: true
  aggregators: false

  # Extra ATS domains. Sweepy labels matching postings with this name.
  custom:
    - name: "SmartRecruiters"
      domain: "smartrecruiters.com"
      enabled: true
    - name: "Breezy HR"
      domain: "breezy.hr"
      enabled: true

# ─── Sources ──────────────────────────────────────
sources:
  jobspy:
    linkedin: true
    indeed: true
    glassdoor: true
    zip_recruiter: true

  # Leave a list empty to fall back to the seed lists in data/sources/.
  ashby:
    orgs:
      - "crosby"
      - "normlaw"
      - "hargrove-firm"
      - "lawhive"
  workable:
    slugs:
      - "shegerianand-associates-1"
      - "harper-james"
      - "legalvision"
  builtinnyc:
    enabled: true
    categories:
      - "jobs/legal"
      - "jobs/legal/search/paralegal"

# ─── Cache and history ────────────────────────────
cache:
  enabled: true
  ttl_seconds: 3600       # reuse discovery results for an hour

history:
  enabled: true
  retention_days: 4       # hide a reported posting for four days
  match: "url+role"       # "url" matches only an identical posting address
  path: null              # null uses ~/.sweepy/history.db

orchestrator:
  timeout_per_source_seconds: 180
  circuit_breaker:
    failure_threshold: 5
    cooldown_seconds: 30

# ─── Report layout ────────────────────────────────
report:
  style: "cards"          # "cards" (default) or "legacy"
  cards_per_page: 6       # cards on each PDF page
  max_cards: 24           # 0 or less shows every match
  destinations: []        # extra folders for a copy of the PDF
  assessment: "agent"     # "keyword" accepts reports without agent judgments

# ─── Exports ──────────────────────────────────────
export:
  format: "pdf,csv,json"  # add "png" for page images
  output_dir: "results"
  tracking: true          # job-tracking columns in the CSV
  description_chars: 1000 # posting excerpt length in the CSV and JSON
  timezone: "local"       # clock behind the report filename stamp

省略した設定については、Sweepyはデフォルト値を使用します。有用な検索結果を得るためには、search.titles、search.location、resume.pathが必要です。

ヒント

ソースおよびプラットフォームサポートの詳細については「ソースとプラットフォーム」に記載されています。そこにあるガーティングルール（gating rules）により、platforms.*およびsources.*がどのように連携して動作するかが説明されています。オプションのhirehunt、openroles、jobdrop、apifyブロックもsourcesの下にあり、「コマンドリファレンス」にはこれらの設定値を設定するためのフラグが一覧表示されています。

レザーブ（Resume）トラック​

「トラック」とは名前付けられた履歴書のことです。異なる役割/タイトルを対象とし、各投稿を正しいドキュメントに基づいて評価したい場合に使用します。

profiles/paralegal_nyc.yaml
resume:
  tracks:
    - name: "Paralegal Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Paralegal.pdf"
      color: "#1D4ED8"
      route_keywords: ["paralegal", "litigation", "e-discovery"]
    - name: "Legal Assistant Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Legal_Assistant.pdf"
      color: "#7E22CE"
      route_keywords: ["legal assistant", "legal secretary", "scheduling"]

各エントリには4つのフィールドがあります：

  • name：トラックのラベルです。レポートカードにこのラベルが表示されるため、1〜2語で表現してください。
  • path はそのトラックの履歴書 PDF または DOCX ファイルを指します。
  • color はバッジの色を設定します。#1D4ED8 のような16進数コード、または navy のような色名を使用してください。
  • route_keywords は、Sweepyがどのトラックに投稿を割り当てるかを決定します。

Sweepyは投稿のタイトルや説明と各トラックの route_keywords との間で単語全体の一致を調べ、一致数が最も多いトラックに投稿を割り当てます。複数のトラックで一致数が同じ場合は、リスト内で最初に記載されているトラックが選ばれます。

ヒント

route_keywords は投稿を履歴書に振り分けますが、マッチ率を変えることはありません。各職種が実際に投稿で使うフレーズを追加してください。

tracks を省略すると、Sweepyは resume.path をデフォルトのトラックとして使用します。

履歴書用の同義語​

resume.synonyms は同じ意味を持つ単語群を表します。グループ内の各単語は同等と見なされ、どちらの順番でもマッチングが行われます。業界固有の用語の追加方法 を参照してください。

profiles/paralegal_nyc.yaml
resume:
  synonyms:
    - ["e-discovery", "ediscovery", "electronic discovery"]
    - ["legal research", "case law research"]
    - ["docketing", "case calendaring"]
    - ["legal assistant", "legal secretary"]
    - ["contract review", "contract analysis", "agreement review"]

グループには少なくとも2つの単語が必要です。大文字/小文字は区別されず、単数形/複数形も問題ありません。フレーズ全体もマッチング対象となるため、両方をカウントしたい場合は legal research と legal researcher を別々の項目としてリストアップしてください。

Alexは履歴書に e-discovery を記載しています。electronic discovery と記載された投稿もマッチするようになります（両方が同じグループに属するからです）。

ヒント

同じフレーズが2回以上登場する場合は、そのフレーズを新しいグループに追加してください。投稿の正確な文言を自分の用語の横にコピーしてください。

一般的な書式ミス​

多くの不具合はいくつかの共通のエラーに起因しています。

Windowsのパスにはフロントスラッシュ（/）またはダブルバックスラッシュ（\）が必要です。 YAMLではバックスラッシュがエスケープ文字として解釈されます。C:\Users\Alexのようなパスはファイルを破損させる可能性があります。

profiles/paralegal_nyc.yaml
resume:
  path: "C:/Users/Alex/Documents/Alex_Rivera_Resume.pdf"     # ✅ works
  # path: "C:\\Users\\Alex\\Documents\\Alex_Rivera_Resume.pdf"  # ✅ also works
  # path: "C:\Users\Alex\Documents\Alex_Rivera_Resume.pdf"      # ❌ breaks YAML
注意

パス内にバックスラッシュが1つでも含まれていると、Sweepyはプロフィールデータを正しく読み取れません。セットアップウィザードが自動的にフロントスラッシュを生成するので、手動で編集する際も同じ形式を使用してください。

コメントは#で始まります。 Sweepyはその行の#以降の内容を無視します。例のプロフィールデータのように、値がなぜ重要かを説明するためにコメントを利用してください。

インデントが構造を決定します。 各レベルは2つのスペースでインデントしてください。ファイル内のどこかにタブ（Tab）を使用するとYAMLの意味が変わってしまいます。
