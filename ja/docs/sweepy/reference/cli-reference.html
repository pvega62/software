コマンドラインリファレンス

Sweepyはsweepyという1つのコマンドでインストールできます。このコマンドを入力してEnterキーを押します。コマンドにデフォルト設定以上のオプションが必要な場合はフラグを追加してください。すべてのプロファイル、スウィープ処理、レポートはここから開始されます。

Terminal
sweepy

アレックスは毎朝これらのコマンドを2つ使用します。まず--runを使って最後に保存したプロファイルでスウィープ処理を実行し、その後--logsを使って実行結果に問題があった場合の詳細を確認します。

注記

すべてのコマンドはsweepyフォルダ内から実行してください。前回の操作以降にターミナルを閉じた場合は、ターミナルを再起動してからcd sweepyを実行してください。

コマンドリファレンス​

フラグを指定しないでsweepyを実行するとランチパッドが開きます。以下の表は各フラグが実行する処理を分類しています。

コマンドの形式

sweepyフォルダ内でpip install -e .を実行してください。このコマンドは自動的に必要な情報を表示します。もしシェルでsweepyが見つからない場合は、ターミナルを再起動するかpython swee.pyを代わりに実行してください。

スイープとプロファイル​

フラグ機能
--run最後に保存したプロファイルでスウィープ処理を実行する。
--profile <path>YAML プロファイルからスウィープ処理を実行します。
--setup検索やプロファイル設定のための検索ラウンチパッドを開きます。
--non-interactiveプロンプトではなくフラグに基づいてプロファイルを作成または更新します。--setup と組み合わせて使用してください。

1回の実行による上書き​

フラグ機能
--no-dedupe同じボード内の重複する投稿を一回のスウィープ処理で区別します。
--include-seen以前のスウィープ処理で報告された投稿も含めて表示します。
--reset-historyプロファイルに既に報告された投稿を忘れます。

ドキュメント​

フラグ機能
--docx <path>DOCX ファイルを PDF に変換した後、終了します。
--convert <path>サポートされているドキュメントをソースファイルと共に PDF に変換した後、終了します。

求人検索エンジン​

フラグ機能
--list-enginesすべての求人サイトを一覧表示し、それぞれが読み取る求人情報源やインストール状況を示す。
--install-engines [names]オプションで指定した求人サイトのデータをダウンロードする。
--allow-engine-conflicts既にインストールされている求人サイトと競合するデータがある場合はそのサイトのインストールを中止し、--install-enginesと組み合わせて処理する。

更新情報とバージョン​

フラグ機能
--update最新のSweepyコードを取得し、依存関係を再インストールする。
--check-update新しいSweepyバージョンが存在するかどうかを確認する。
--version求人サイトのバージョン情報およびその依存関係を表示する。

ロギング​

フラグ機能
--debuglogs/ の下でデバッグログの記録を有効にする。
--log-dir <dir>デバッグログフォルダーの場所を変更する。
--logs最新のデバッグログエントリを表示する。

ヘッドレスセットアップの値​

--setup を追加すると、これらのフラグがプロファイルに記載される。各値には対応するフラグが必要であり、プロファイルで指定されていない限り --name、--titles、--location、--resume も必須となる。

フラグ機能
--sources <names>これらのエンジンを有効にする（カンマで区切る）。
--jobspy-sites <sites>JobSpy のボードを設定する（カンマで区切る）。
--hirehunt-sources <sources>HireHunt のソースを設定する（カンマで区切る）。
--jobdrop-sites <sites>JobDrop のボードを設定する（カンマで区切る）。
--openroles-companies <slugs>OpenRoles の会社名を設定する（カンマで区切る）。
--apify-actor <actor>Apify のアクターIDを設定する。
--timeout <seconds>各ソースのタイムアウトを設定します。
--cache-ttl <seconds>ディスカバリーキャッシュの有効期間を設定します。
--no-cacheディスカバリーキャッシュを無効にします。
--history-days <days>报告された投稿が再び表示されるまでの日数を設定します。
--no-history実行ごとにすべての投稿を報告します。
--job-tracking / --no-job-trackingCSVジョブ追跡用の列をオン/オフに切り替えます。
--name <name>プロフィールの名前を設定します。
--titles <titles>目標となるタイトルをカンマで区切って設定します。
--location <location>目標となる場所を設定します。
--resume <path>レザーブレットのパスを設定します。
--portfolio <value>スウェープ処理で使用するポートフォリオを追加します。URL、ローカルのPDFファイル、Markdownファイル、またはテキストファイルを指定できます。複数のソースに対してはこの処理を繰り返し、値の前にTRACK=を付けて特定のレザーブレットトラックに関連付けます。
--portfolio-track <track>TRACK= プレフィックスのない --portfolio 値に対して、履歴書のトラックを設定します。

Sweepyはまず--logs、--version、--update、--check-update、--list-engines、--install-enginesを処理し、その後でドキュメントを変換します。--setupが次に実行され、最後にスウィープ処理（sweep）が実行されます。各コマンドごとに1つのジョブが実行されます。

--run オプションで、最後に保存したプロファイルを実行します。​

プロファイルを1回保存したら、1つの短いコマンドでスウィープ処理を実行します。Sweepyは最後に保存したプロファイルをprofiles/.last_profileに保存し、それを再利用します。

Terminal
sweepy --run

コマンドは以下の順序でプロファイルを検索します：

  1. profiles/.last_profile内のパス
  2. profiles/内の最新のプロファイル
  3. profiles/custom_profile.yaml、profiles/paralegal_nyc.yaml、config.sample.yamlの順

これらのいずれも存在しない場合、Sweepyはエラーを報告し、--setupを参照するように指示します。

--setup オプションを使用してプロファイルを作成する​

ウィザードが検索ランチパッドを開き、YAMLプロファイルを自動的に作成します。

Terminal
sweepy --setup
ランチパッドのタイル機能
スウィープの開始開いたプロファイルを使用してスウィープ処理を実行します。ステータスラインには警告が表示されますが、プロファイルを開くまで続きます。
プロファイルの読み込み次回のスウィープ処理で使用する保存済みプロファイルを選択できます。
スウィーピーのツールボックス下記にリストされているツールボックスの項目を開きます。
プロファイルの作成平易な英語で質問をし、新しいプロファイルを保存します。
スウィープ設定キーワードの重み、カードの制限、レポートのスタイル、履歴の表示方法、およびCSV内のジョブ追跡用の列を変更できます。
スウィーピーの終了変更内容を保存し、シェルに戻ります。

Sweepy's Toolboxには以下の機能が含まれます：

ツールボックスの項目各機能の詳細
既存プロファイルの編集profiles/からプロファイルを読み込み、ジョブ追跡用の列の表示/非表示を含めて編集できます。
ジョブエンジンの管理エンジンのオン/オフの切り替えや設定の編集ができます。
ジョブエンジンのダウンロード確認後にオプションのエンジンをインストールできます。
アグリゲーターの追加/編集フィードの表示/非表示の切り替えやカスタムアグリゲーターの管理ができます。
デバッグログの表示/非表示プロファイル内のdebugの値を切り替えます。
ヘルプを表示ウィザードの使用方法に関するガイダンスを表示します。
最新のログを表示最新のデバッグログを表示します。
ドキュメントをPDFに変換（ボーナス機能）DOCX、DOC、TXT、MD、またはPDFファイルをPDFに変換し、ツールボックスに戻します。
Sweepyを更新最新のコードを取得し、依存関係を再インストールします。
終了ツールボックスからウィザードを閉じます。

いつでもウィザードを再実行して新しいプロファイルを作成したり、既存のプロファイルを編集したりできます。古いプロファイルは削除されません。Sweepyの設定ページでは各手順が説明されています。

ドキュメントをPDFに変換（ボーナス機能）​

Sweepyのツールボックスはプロファイルがなくてもドキュメントを変換できます。「ドキュメントをPDFに変換（ボーナス）」を選択し、Sweepyにファイルパスを指定してください。

入力Sweepyが実行する処理内容です。
.docxpython-docxおよびreportlabを使用してテキストを再構築し、必要に応じてMicrosoft Wordを使用します。
.docMicrosoft Wordを通じてテキストをレンダリングします。これにはdocx2pdfパッケージが必要です。
.txt, .md見出しや箇条書きを含めてテキストをレンダリングします。
.pdfファイルを通過させたり、指定した出力パスにコピーしたりします。

誤ったパスが指定された場合、Sweepyは警告を表示してプロンプトを再開します。入力ミスがあるとウィザード画面に戻ります。

プロファイルに直接移動する​

--profile を追加すると、ランチパッドを使わずにプロフィールを開いて編集できます。

Terminal
sweepy --setup --profile profiles/paralegal_nyc.yaml

ウィザードはそのファイルの現在の設定値をレビュー画面に表示します。

プロンプトを表示せずにプロファイルを作成する​

すべてのマシンで同じ設定が必要な場合は、スクリプトを使用してプロフィールを作成します。--setup --non-interactive を追加し、各設定値をフラグとして渡します。

Terminal
sweepy --setup --non-interactive `
  --name "Alex Rivera" `
  --titles "Technical Writer,UX Writer" `
  --location "New York, NY" `
  --resume C:\Users\Alex\sweepy\resume.pdf `
  --sources jobspy,openroles `
  --openroles-companies figma,stripe,notion `
  --timeout 120 --no-cache

Sweepyは書き込み前に有効なエンジンをすべてチェックします。OpenRolesの会社名などの設定値が欠落している場合、Error: を表示して1コードで終了します。--profile を指定しない場合、Sweepyはユーザーの名前と最初のタイトルからファイル名を自動生成するため、Alexのプロフィールはprofiles/alex_rivera_technical_writer.yamlに保存されます。既存のファイルを更新するには--profile <path>を追加してください。

Sweepyの更新​

最新のコードを取得し、依存関係を再インストールします。

Terminal
sweepy --update

Sweepyは遠隔リポジトリからoriginを取得し、現在のブランチをファストフォワードしてpython -m pip install -r requirements.txtを実行します。追跡中のファイルに未コミットの変更がある場合は実行を拒否するため、ローカルでの編集内容は破棄されません。アップデートがあるかどうかを確認するには読み取り専用モードを使用してください。

Terminal
sweepy --check-update

Sweepyのツールボックス内の「Sweepyを更新」を実行すると、同じアップデートが行われます。

エンジンの一覧表示とインストール​

オプションのエンジンをダウンロードする：

Terminal
sweepy --list-engines

オプションのエンジンをダウンロードします：

Terminal
sweepy --install-engines all

all の設定では、JobSpy が競合するピンを保持している間は JobDrop をスキップします。JobDrop は --allow-engine-conflicts を使用して別途インストールします：

Terminal
sweepy --install-engines jobdrop --allow-engine-conflicts

エンジンをインストールすると、その機能はオフのままになります。プロファイル内で sources.enabled に追加するか、ヘッドレスセットアップ時に --sources を指定してください。インストールに失敗すると、コマンドは 1 のコードで終了します。オプションのエンジン では各エンジンについて説明しています。

--profile オプションを使用してスイープを実行する​

各都市や役割タイプごとにプロファイルを1つずつ保持し、--profile を目的のプロファイルに向けます。残りの処理は Sweepy が行います。

Terminal
sweepy --profile profiles/paralegal_nyc.yaml

ファイル名を適宜変更してください。Sweepyに最後に保存したプロファイルを再利用させたい場合は、--run オプションを使用することをお勧めします。

ヒント

各都市または役割タイプごとに1つのプロフィールを保存する。検索を切り替えるにはファイル名を変更する。

1回の実行をオーバーライドする​

--runおよび--profileは3つのオーバーライド設定を受け付けます。各オーバーライド設定は該当するコマンドにのみ適用され、プロファイル自体には影響しません。

Terminal
sweepy --run --no-dedupe
sweepy --run --include-seen
sweepy --run --reset-history

--no-dedupeは、2つのボードが同じロールを投稿した場合でも、それぞれのボードのリストを保持します。sweepコマンドは新しい投稿のみを報告し、プロフィール設定のhistory.retention_daysではデフォルトで表示期間が4日間に設定されています。--include-seenは非表示の投稿も含めて報告します。--reset-historyコマンドを単独で実行すると、その履歴をクリアしてsweepを実施せずにページを閉じることができます。

スウィープの実行中に何が起こるか​

すべての実行は同じ5つのステージを同じ順序で進む。

ステージ起こること
1. プロファイルの読み込みYAMLファイルを読み取り、設定を確認する。
2. ディスカバリー有効に設定されたプラットフォームでスクレイパーを実行し、投稿内容を収集する。
3. 検証無効なリンクや404エラーを除去する。検証できなかった投稿はそのまま処理を続ける。
4. スコアリング経歴書のPDFまたはDOCXファイルを解析し、求人内容との重複を確認した後、各職務に対して「応募ヒント」を作成する。
5. 生成日付が記載されたPDF、CSV、JSONファイルを作成する。pngファイルもエクスポートフォーマットに追加する。

実行中、ターミナルには各ステージの進捗状況（[1/5]から[5/5]まで）が表示される。初回のスウィーピー実行では全出力が確認できる。

--docx オプションを使用して DOCX を PDF に変換する​

--docxファイルをWord形式に変換し、SweepyがそれをPDFに変換して保存した後、終了する。

Terminal
sweepy --docx path/to/resume.docx

その後、SweepyはPDFの保存先をユーザーに尋ねる。

Terminal output
Where should the PDF go? (leave blank to save next to the DOCX):

空の答えを入力してEnterキーを押すと、PDFファイルがDOCXの横に同じ名前で保存されます。別の場所に保存したい場合は、完全なパスを入力してください。いずれの場合も、SweepyはPDF saved:と最終的な保存先を表示します。

注記

SweepyはまずDOCXのテキストからPDFを再生成します。マシンにMicrosoft Wordがインストールされている場合は、より見た目が一致するようにdocx2pdfを使用します。

--convert オプションであらゆるドキュメントを変換できます​

--convertはプロンプトなしで実行され、PDFファイルを元のファイルの横に保存します。.docx、.doc、.txt、.md、.pdfのいずれかのファイルを指定してください。

Terminal
sweepy --convert path/to/resume.docx
Terminal output
PDF saved: C:\Users\Alex\sweepy\resume.pdf

出力結果では元のファイル名はそのまま保持され、拡張子が交換される。例えば、notes.mdは同じフォルダ内でnotes.pdfになる。.pdfというファイルはそのまま残されるため、SweepyはThis file is already a PDF:という新しいファイルを生成し、元のファイルはそのまま残される。

入力Sweepyが実行する処理内容です。
.docxpython-docxおよびreportlabを使用してテキストを再構築し、必要に応じてMicrosoft Wordを使用します。
.docMicrosoft Wordを通じてテキストをレンダリングします。これにはdocx2pdfパッケージが必要です。
.txt, .md見出しや箇条書きを含めてテキストをレンダリングします。
.pdfファイルをそのままにして、そのパスを報告する。

ファイルが存在しない場合やサポートされていない場合、Error: が出力され、コマンドは 1 のコードで終了します。これにより、スクリプトやスケジュールジョブ内での安全な実行が可能になります。

PDFファイルが準備できたら、プロフィール内のresume.pathをそのファイルに向けて設定し、sweepコマンドを実行してください。

--version オプションでバージョンを確認してください。​

このコマンドを使用して、エンジンおよびそのライブラリが正しくインストールされているかを確認してください。

Terminal
sweepy --version
Terminal output
Sweepy v3.1.0
Python 3.13.1 | pymupdf 1.28.2 | reportlab 5.0.1
Ready to sweep.

もしpymupdfまたはreportlabの出力がMISSINGであれば、依存関係を再インストールしてください。インストール方法にその手順が記載されています。

デバッグログを有効にする​

デバッグログにはエンジンの動作内容がステップごとに記録されます。フラグ、プロファイル設定、または環境変数を使ってデバッグログを有効にできます。

方法設定場所有効期間
--debugフラグターミナルコマンドに追加その実行回限り有効です。
debug: trueYAMLプロファイルに追加フラグを削除するまで毎回実行時に有効です。
SWEEPY_DEBUG=1環境変数として設定ターミナルを閉じるまで毎回実行時に有効です。

任意の処理にこのフラグを適用してください。

Terminal
sweepy --debug --profile profiles/paralegal_nyc.yaml

またはプロファイル内でデバッグログを常に有効にすることもできます。

profiles/paralegal_nyc.yaml
# Write a rotating debug log under logs/ on every run.
debug: true

あるいは環境変数を設定する方法もあります。

Terminal
$env:SWEEPY_DEBUG = "1"
sweepy --profile profiles/paralegal_nyc.yaml

macOSやLinuxでは、最初の行をexport SWEEPY_DEBUG=1に置き換えてください。

Sweepyはログをアプリケーションフォルダ内のlogs/に書き込みます。別の場所に送信するには--log-dirを使用してください。

Terminal
sweepy --debug --log-dir C:\Users\Alex\sweepy-logs --profile profiles/paralegal_nyc.yaml

ファイルを開かずに最新のエントリを読むには、以下のコマンドを実行してください：

Terminal
sweepy --logs
注記

--logsコマンドは、デバッグログが存在するまでNo debug logs found. Run Sweepy with --debug to enable logging.を出力します。

毎日の実行をスケジュールする​

採用チームは週中を通じて新しい求人情報を公開します。毎朝同じコマンドを実行すると、これらの情報を早期に把握できます。

Terminal
sweepy --profile profiles/paralegal_nyc.yaml

新しい投稿が見つかると、Sweepyはレポートファイルを作成します。Sweepyは各レポートファイル名にプロフィール情報、日付、時間を含めます（例：paralegal_nyc_2026-10-08-081500.pdf、paralegal_nyc_2026-10-08-081500.csv）。MCPを走行させると、ファイル名にmcpが追加されます（例：paralegal_nyc_mcp_2026-10-08-081500.pdf）。これにより、2つのファイルを区別できます。日付と時間はexport.timezone内の時計から取得され、デフォルト値はlocalです。必要に応じてUTCやAmerica/New_Yorkのような名前、または-05:00のようなオフセット値を設定して、ファイルに別のタイムゾーン情報を記録できます。この仕組みにより、同じ検索の結果が重複して書き込まれるのを防ぎます。そのため、resultsには検索の全履歴が保存されます。

Sweepyは新しい求人情報のみをレポートし、デフォルトでは各求人情報を4日間記憶します。新しい情報が見つからない場合、No new postings since your last sweepが出力され、レポートファイルは作成されません。また、すべてのリンクが有効期限を過ぎた場合も同様です。

Windows でのスケジュール設定​

  1. スタートメニューからタスクスケジューラーを開きます。
  2. 基本タスクの作成を選択し、例えばSweepy morning sweepといった名前を付けます。
  3. 毎日を選択し、開始時間（例：午前8時）を設定します。
  4. アクションとして、「プログラムの起動」を選択してください。
  5. プログラム/スクリプトには、使用するPython実行ファイルを指定してください。PowerShellで(Get-Command python).Sourceを実行すると、そのパスが表示されます。
  6. 引数の追加には、swee.pyの完全なパスに"C:\Users\Alex\sweepy\swee.py" --profile profiles\paralegal_nyc.yamlを加えたものを指定してください。
  7. 実行場所には、sweepyがあるフォルダーを指定してください。エンジンはそのフォルダーからprofilesを見つけてresultsを書き出します。

macOS および Linux でのスケジュール設定​

  1. crontab -eを使ってcrontabを開いてください。
  2. 毎日午前8時にスキャン処理を実行する行を追加してください（マシンが使用しているタイムゾーンに合わせて）。
Terminal
0 8 * * * cd /path/to/sweepy && python3 swee.py --profile profiles/paralegal_nyc.yaml

cdの部分は重要です。エンジンは指定したフォルダーを基準にprofilesを読み取り、resultsを書き出します。Sweepyのパッケージをインストールする際に使用したpython3を使用してください。python3 -c "import swee"で動作を確認してください。

注意

スケジュールされた実行はターミナルウィンドウなしで開始されるため、以前のセッションで設定したシェル設定は適用されません。一度手動でコマンドを実行して動作を確認してからスケジュールしてください。
