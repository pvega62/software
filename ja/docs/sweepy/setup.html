Sweepy のセットアップ

Sweepyのインストールが完了しました！次はプロファイルの設定が必要です。

設定プロファイルは、Sweepyに対して、検索する求人と、それらを評価するための履歴書を指定します。また、希望勤務地も設定します。

プロファイルは、YAML形式の小さなテキストファイルです。YAML（キャメルと韻を踏む）は、インデント、コロン、改行を用いてデータを整理します。 コードを書く必要はありません。買い物リストが読めれば、YAMLも読めます。

オプション A: 対話型のセットアップウィザードを実行する​

セットアップウィザードは、簡単な回答から実用的なプロファイルを作成します。質問票の前に検索ランチャーを開き、設定ファイルを自動的に作成します。

次のコマンドを実行してください：

Terminal
sweepy --setup

ウィザードはバナーを表示した後、ランチャパッドを表示します。タイルの下にあるステータス行には、読み込まれたプロファイル（例：Current profile: Alex Rivera / 4 titles / Ready）が表示されます。まだ何も読み込まれていない場合は、Current profile: none loaded / build one to start と表示されます。

ランチャーには6つのタイルが表示されます。Start Sweep は読み込まれたプロファイルを実行します。Load Profile は保存された検索を開きます。Build Profile は新しい検索を開始し、平易な英語で質問を行います。Sweep Settings はランキング、カード、履歴を制御します。Sweepyのツールボックスには、プロファイルの編集、エンジンの管理、アグリゲーターの管理、デバッグの切り替え、ヘルプ、最近のログ、ドキュメントの変換、および更新機能が含まれています。Sweepyを終了を選択すると、変更内容が保存され、ウィザードが閉じられます。

コマンドリファレンス には、各エントリに対応するフラグが一覧表示されています。

:::ヒント 新しいプロファイルを作成したり、既存のプロファイルを編集したりするには、いつでも sweepy --setup を再実行してください。ウィザードは指定されたファイルに書き込みを行い、他のプロファイルには影響を与えません。

ランチャーをスキップして保存済みのプロファイルをすぐに編集するには、--profile フラグを指定します：

Terminal
sweepy --setup --profile profiles/paralegal_nyc.yaml

:::

オプション B: 設定ファイルを手動で編集する​

設定を直接入力するには、サンプルテンプレートをコピーし、メモ帳や VS Code などのプレーンテキストエディタで開きます。ワードプロセッサは、一重引用符をカーリー引用符に置き換えて YAML を破損させるため、使用しないでください。

  • Windows
  • macOS / Linux
Terminal
copy config.sample.yaml profiles\alex_rivera_paralegal.yaml
notepad profiles\alex_rivera_paralegal.yaml
Terminal
cp config.sample.yaml profiles/alex_rivera_paralegal.yaml
open profiles/alex_rivera_paralegal.yaml    # macOS
# または: nano profiles/alex_rivera_paralegal.yaml   # Linux

Alexのプロファイル​

ウィザードはこのファイルを profiles/alex_rivera_paralegal.yaml に書き込みます。 # で始まる行はコメントです。これらは各設定の説明であり、Sweepy はこれらを無視します。Sweepy は、省略されたセクションや設定に対してデフォルト値を自動的に設定します。

profiles/alex_rivera_paralegal.yaml
# ─────────────────────────────────────────────────
# Sweepy — アレックスのパラリーガルプロフィール
# ─────────────────────────────────────────────────

# 氏名（PDFレポートのヘッダーに表示されます）
name: "Alex Rivera"

# ─── 求人検索設定 ──────────────────────────
search:
  # 検索したいすべての職種名を列挙します。
  # 検索エンジンはこれらの職名をすべて同時に検索します。
  titles:
    - "パラリーガル"
    - "リーガルアシスタント"
    - "訴訟支援スペシャリスト"
    - "リーガルセクレタリー"

  # 対象の都市と州。
  location: "New York, NY"

  # リモート勤務の求人のみを表示するには true に設定してください。
  # リモート、ハイブリッド、およびオンサイトの求人をすべて表示するには false に設定してください。
  remote_only: false

  # ハイブリッド勤務の求人を除外するには false に設定してください。
  include_hybrid: true

  # 最低年収フィルター（オプション）。
  # 年収フィルターをスキップするには、0のままにするか、この行を削除してください。
  min_salary: 65000

# ─── 履歴書設定 ─────────────────────────────
resume:
  # コンピュータ上の履歴書PDFファイルへのフルパス。
  # Windowsでは、バックスラッシュ（\）を2つ、またはスラッシュ（/）を使用してください。
  path: "Alex_Rivera_Resume.pdf"

  # マッチ率の算出において優先すべき必須スキル。
  must_have_skills:
    - "Westlaw"
    - "LexisNexis"
    - "e-discovery"
    - "Contract Review"
    - "Legal Research"

  # 職務評価において、キーワードの一致をどの程度重視するか。
  # 1.0 = 標準の重み。スキルの完全一致を
  # 評価の主軸にしたい場合は、2.0 に増やしてください。
  keywords_weight: 1.5

# ─── プラットフォーム設定 ────────────────────────────
# 各プラットフォームを true または false に設定して、有効または無効にします。
platforms:
  greenhouse: true
  ashby: true
  lever: true
  workable: true
  aggregators: false   # Remotive、Adzuna などの無料フィード

  # オプション：カスタム ATS エンドポイントまたは企業の採用サイトドメイン
  custom:
    - name: "SmartRecruiters"
 domain: "smartrecruiters.com"
 enabled: true
    - name: "Breezy HR"
 domain: "breezy.hr"
 enabled: true

# ─── エクスポート設定 ──────────────────────────────
export:
  # 出力形式のカンマ区切りリスト。
  # オプション: pdf, csv, json
  format: "pdf,csv"

  # 出力ファイルの保存先。
  # フォルダが存在しない場合、エンジンが自動的に作成します。
  output_dir: "results"

:::注意 Windowsの場合： YAMLのパスでは、バックスラッシュ（\\）またはスラッシュ（/）を2つ続けて使用してください。バックスラッシュ（\）を1つだけ使用すると、YAMLのフォーマットが破損します。

✅ 正しい例: "C:\\Users\\Alex\\Documents\\resume.pdf" または "C:/Users/Alex/Documents/resume.pdf"

❌ 誤った例: "C:\Users\Alex\Documents\resume.pdf"

:::

プリセットプロファイルの使用​

Sweepy には、profiles/ フォルダ内にすぐに使えるプロファイルのプリセットが含まれています。以下の 4 つは、一般的な検索に対応しています：

ファイルキャリアパス検索対象の役職
paralegal_nyc.yaml法務パラリーガル、リーガルアシスタント、訴訟サポートスペシャリスト、リーガルセクレタリー
frontend_developer.yamlソフトウェアエンジニアリングフロントエンド開発者、React開発者、UIエンジニア
tech_writer.yamlテクニカルライティングテクニカルライター、UXライター、コンテンツデザイナー
template_custom.yamlあらゆる職種置き換えることができる職名の例。各設定にはコメントが付いています。

プリセットを使用するには、スウィープを実行する際にそのファイル名を指定します：

Terminal
sweepy --profile profiles/frontend_developer.yaml
ヒント

プロファイルはいくつでも作成できます。職種ごとのバリエーションやターゲットとする都市ごとに、それぞれ異なるプロファイルを保存しておきましょう。--profile フラグを使用すれば、瞬時に切り替えることができます。

オプション C: チャットアシスタントによる自動化​

チャットアシスタントが、プロファイルの作成やスイープの実行を代行してくれます。 SweepyにはModel Context Protocol (MCP) サーバーが組み込まれているため、アシスタントはプロファイルを直接読み書きできます。 MCP 統合ガイド では、Antigravity、Claude Desktop、VS Code 向けのクライアント設定について解説しており、MCP ツールリファレンス には Sweepy のすべてのツールが記載されています。

すべての設定を確認する​

設定リファレンスには、debugやresume.tracksからsources.*やreport.*に至るまで、プロファイルで指定可能なすべての設定が記載されています。プロファイルを編集する際は、このページを開いたままにしておくと便利です。

Sweepyが求人を検索する場所を確認する​

Sweepyはデフォルトで、4つの公開応募者追跡システム（Greenhouse、Ashby、Lever、Workable）にクエリを実行します。また、ニューヨークの求人掲示板であるBuilt In NYCにもクエリを実行します。 LinkedIn、Indeed、Glassdoor、ZipRecruiterからのアグリゲーターフィードは、プロファイルで有効化されている場合、python-jobspyを介して処理されます。

オプションのエンジンを使用すると、求人掲示板を追加できます。選択肢は、HireHunt、OpenRoles、JobDrop、Apifyです。OpenRolesは実行前に企業リストが必要です。Apifyには APIFY_TOKEN が必要です。JobDropはJobSpyの依存関係ピンと競合します。 セットアップウィザードの**「求人エンジンをダウンロード」**オプションを選択すると、これらがインストールされます。

ソースとプラットフォームのページでは、オプションのエンジン、シードファイル、カスタムプラットフォームエントリ、および互換性に関する注意事項について解説しています。

プロファイルの準備は完了しました。さあ、最初のスイープを実行しましょう。
