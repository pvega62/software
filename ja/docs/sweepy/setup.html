Sweepy のセットアップ

Sweepy をインストールできました。次にプロファイルが必要です。

設定プロファイルは、探す求人と、採点に使う履歴書を Sweepy に指定します。希望の勤務地も設定します。

プロファイルは YAML 形式の小さなテキストファイルです。YAML は camel と韻を踏む名前で、インデント、コロン、改行でデータを整理します。コードを書く必要はありません。買い物リストが読めれば、YAML も読めます。

方法 A: 対話形式のセットアップウィザードを実行する​

セットアップウィザードは、質問への回答だけから動作するプロファイルを作ります。質問の前に検索ランチパッドを開き、設定ファイルを自動で書き出します。

次のコマンドを実行します。

ターミナル
sweepy --setup

ウィザードはバナーを表示し、続いてランチパッドを表示します。タイルの下のステータス行には、読み込んだプロファイルが表示されます（例: Current profile: Alex Rivera / 4 titles / Ready）。まだ何も読み込んでいない場合は Current profile: none loaded / build one to start と表示されます。

ランチパッドには 6 つのタイルがあります。Launch Sweep は読み込んだプロファイルを実行します。Load Profile は保存済みの検索を開きます。Build Profile は新しい検索を始め、平易な言葉で質問します。Sweep Settings はランキング、カード、履歴を管理します。Sweepy's Toolbox には、プロファイルの編集、エンジンの管理、アグリゲーターの管理、デバッグの切り替え、ヘルプ、最近のログ、ドキュメントの変換、更新が入っています。Exit Sweepy は変更を保存してウィザードを閉じます。

コマンドリファレンスに、各項目の背後にあるフラグをまとめています。

ヒント

プロファイルを新しく作るときも既存のものを編集するときも、いつでも sweepy --setup を再実行できます。ウィザードは指定されたファイルだけに書き込み、他のプロファイルには触れません。

ランチパッドを飛ばして保存済みのプロファイルをすぐに編集するには、--profile フラグを渡します。

ターミナル
sweepy --setup --profile profiles/paralegal_nyc.yaml

方法 B: 設定ファイルを手動で編集する​

設定を直接入力するには、サンプルのテンプレートをコピーし、Notepad や VS Code などのプレーンテキストエディターで開きます。ワープロソフトは直線の引用符を曲線の引用符に置き換えて YAML を壊すため、避けてください。

  • Windows
  • macOS / Linux
ターミナル
copy config.sample.yaml profiles\alex_rivera_paralegal.yaml
notepad profiles\alex_rivera_paralegal.yaml
ターミナル
cp config.sample.yaml profiles/alex_rivera_paralegal.yaml
open profiles/alex_rivera_paralegal.yaml    # macOS
# or: nano profiles/alex_rivera_paralegal.yaml   # Linux

Alex のプロファイル​

ウィザードはこのファイルを profiles/alex_rivera_paralegal.yaml に書き出します。# で始まる行はコメントです。各設定を説明する行で、Sweepy は無視します。省略したセクションや設定には、Sweepy が既定値を入れます。

profiles/alex_rivera_paralegal.yaml
# ─────────────────────────────────────────────────
# Sweepy — Alex's Paralegal Profile
# ─────────────────────────────────────────────────

# Your name (appears in the PDF report header)
name: "Alex Rivera"

# ─── Job Search Settings ──────────────────────────
search:
  # List every job title you want to find.
  # The engine searches for ALL of these titles simultaneously.
  titles:
    - "Paralegal"
    - "Legal Assistant"
    - "Litigation Support Specialist"
    - "Legal Secretary"

  # Your target city and state.
  location: "New York, NY"

  # Set to true to ONLY see remote roles.
  # Set to false to see remote, hybrid, and on-site roles.
  remote_only: false

  # Set to false to exclude hybrid positions.
  include_hybrid: true

  # Minimum annual salary filter (optional).
  # Leave as 0 or remove this line to skip salary filtering.
  min_salary: 65000

# ─── Resume Settings ─────────────────────────────
resume:
  # The full path to your resume PDF on your computer.
  # On Windows, use double backslashes (\\) or forward slashes (/).
  path: "Alex_Rivera_Resume.pdf"

  # Must-have skills to prioritize for the match percentage.
  must_have_skills:
    - "Westlaw"
    - "LexisNexis"
    - "e-discovery"
    - "Contract Review"
    - "Legal Research"

  # How heavily to weigh keyword matches when scoring roles.
  # 1.0 = standard weight. Increase to 2.0 if you want
  # exact skill matches to dominate the score.
  keywords_weight: 1.5

# ─── Platform Settings ────────────────────────────
# Set each platform to true or false to enable or disable it.
platforms:
  greenhouse: true
  ashby: true
  lever: true
  workable: true
  aggregators: false   # Free feeds like Remotive, Adzuna

  # Optional: custom ATS endpoints or company career domains
  custom:
    - name: "SmartRecruiters"
      domain: "smartrecruiters.com"
      enabled: true
    - name: "Breezy HR"
      domain: "breezy.hr"
      enabled: true

# ─── Export Settings ──────────────────────────────
export:
  # Comma-separated list of output formats.
  # Options: pdf, csv, json
  format: "pdf,csv"

  # Where to save the output files.
  # The engine creates this folder if it does not exist.
  output_dir: "results"
注意

Windows の場合: YAML のパスには二重のバックスラッシュ（\\）またはスラッシュ（/）を使います。バックスラッシュ 1 つ（\）は YAML の書式を壊します。

✅ 正しい: "C:\\Users\\Alex\\Documents\\resume.pdf" または "C:/Users/Alex/Documents/resume.pdf"

❌ 誤り: "C:\Users\Alex\Documents\resume.pdf"

プリセットのプロファイルを使う​

Sweepy には、profiles/ フォルダーにすぐ使えるプロファイルのプリセットが入っています。次の 4 つが一般的な検索を網羅します。

ファイルキャリアの方向性検索する職種
paralegal_nyc.yaml法務Paralegal, Legal Assistant, Litigation Support Specialist, Legal Secretary
frontend_developer.yamlソフトウェアエンジニアリングFront End Developer, React Developer, UI Engineer
tech_writer.yamlテクニカルライティングTechnical Writer, UX Writer, Content Designer
template_custom.yaml任意のキャリア差し替えて使うサンプルの職種です。各設定にコメントが付いています。

プリセットを使うには、スイープを実行するときにファイル名を渡します。

ターミナル
sweepy --profile profiles/frontend_developer.yaml
ヒント

プロファイルはいくつでも作れます。職種の呼び方が違う場合や対象の都市ごとに、別のプロファイルを保存してください。--profile フラグで即座に切り替えられます。

方法 C: チャットアシスタントで自動化する​

チャットアシスタントにプロファイルの作成とスイープの実行を任せられます。Sweepy には Model Context Protocol（MCP）サーバーが組み込まれており、アシスタントがプロファイルを直接読み書きします。MCP 連携ガイドでは Antigravity、Claude Desktop、VS Code のクライアント設定を説明し、MCP ツールリファレンスでは Sweepy のすべてのツールを一覧しています。

すべての設定を調べる​

設定リファレンスには、debug や resume.tracks から sources.* や report.* まで、プロファイルが受け付けるすべての設定を載せています。プロファイルを編集する間は、このページを開いたままにしてください。

Sweepy が求人を探す場所を確認する​

Sweepy は既定で 4 つの公開応募者追跡システムに問い合わせます。Greenhouse、Ashby、Lever、Workable の 4 つです。ニューヨークの求人サイトである Built In NYC にも問い合わせます。LinkedIn、Indeed、Glassdoor、ZipRecruiter のアグリゲーターフィードは、プロファイルで有効にすると python-jobspy 経由で動作します。

任意のエンジンを追加すると、対象のサイトが増えます。選択肢は HireHunt、OpenRoles、JobDrop、Apify です。OpenRoles は実行前に企業リストが必要です。Apify には APIFY_TOKEN が必要です。JobDrop は JobSpy の依存バージョン指定と衝突します。セットアップウィザードの Download job engines でインストールできます。

ソースとプラットフォームのページでは、任意のエンジン、シードファイル、カスタムプラットフォームの項目、互換性の注意点を説明しています。

プロファイルの準備ができました。初回スイープを実行する時です。
