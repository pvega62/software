Sweepy の概要

Sweepy は多くの採用プラットフォームを横断して求職活動を自動化します。コマンド 1 つで募集中の求人を集め、履歴書を読み取ります。その後 Sweepy は各求人をあなたのスキルと照合して採点し、日次のマッチレポートを出力します。

Sweepy は設定ファイルを通じてあなたの進路に合わせて動きます。パラリーガル、アナリスト、コーディネーターなどの職種を選べます。

Alex の紹介​

このガイドでは、Alex と一緒に進めます。Alex は政治学の学位を取ったばかりで、ニューヨーク市で パラリーガルと法務アシスタントの職を探しています。Alex はターミナルを使ったことも、コードを書いたことも、YAML ファイルを見たこともありません。

このガイドは、セットアップから完全に自動化された求人スイープまで、あなたと Alex を導きます。Sweepy は実際の履歴書に対して上位の求人を採点し、毎日使える PDF ディレクトリを生成します。

注記

Sweepy を使うのにプログラミングの経験は要りません。このガイドはすべての手順を一から説明します。

機能​

Sweepy には、次の職をより早く見つけるために必要な機能がそろっています。

  • 複数プラットフォームの検索は Greenhouse、Ashby、Lever、Workable を走査します。これらは公開求人サイトを運営する 4 つの応募者追跡システムです。Built In New York City のサイトも読み取り、有効にすれば LinkedIn、Indeed、Glassdoor、ZipRecruiter のフィードも読み取ります。
  • 履歴書のスマート採点は、履歴書の PDF または Word ファイルを読み取り、スキルを抽出します。Sweepy は各求人を 1 つの履歴書トラックに振り分け、そのトラックの履歴書と照合して採点します。エンジンは API キーも有料サービスもなしで動作します。
  • 壊れたリンクの除外は、表示前にすべての求人を確認します。リンクが gone ステータス、ソフト 404 ページ、接続エラーを返すと、Sweepy はその求人を除外します。レート制限、ボット遮断、サーバーエラーの場合は求人をレポートに残し、unverified と表示します。
  • 日次 PDF レポートは結果を高密度の PDF ディレクトリにまとめます。各ページには既定で 6 枚のカードが入り、クリックできるリンク、開示された給与レンジ、色分けしたバッジが付きます。
  • パイプライン管理スプレッドシートは、すべてのカード項目に加えて 1,000 文字の求人抜粋を含む CSV を出力し、他のツール向けに JSON ファイルも出力します。CSV の末尾には、応募日、ステータス、面接段階、オファー、フォローアップ日、連絡先、メモという管理用の列が付きます。入力した値は、同じプロファイルの次のスイープに引き継がれます。CSV は Microsoft Excel、Google Sheets、Notion で開けます。PDF は応募リンク付きの 1 回の読み通しに向きます。スプレッドシートは、PDF のカード上限を超えた求人も含めてパイプライン全体を記録します。

仕組み​

スイープが成功するまでには、5 つの段階を踏みます。

  1. プロファイルを読み込みます。 Sweepy は職種、勤務地、履歴書のパスが入った設定ファイルを読み取ります。
  2. 求人を検出します。 Sweepy は採用プラットフォームと求人フィードに一致する求人を問い合わせます。
  3. リンクを検証します。 Sweepy はすべてのリンクを確認し、gone ステータス、ソフト 404 ページ、接続エラーを返す求人を除外します。リンクを検証できない求人は実行に残り、unverified と表示されます。
  4. マッチを採点します。 Sweepy は履歴書の PDF または Word ファイルを解析し、各求人の重み付きマッチ率を算出します。
  5. レポートを生成します。 Sweepy は結果を整形した PDF と CSV または JSON のエクスポートにまとめます。

制限事項​

Sweepy は設計上、求人市場の狭い範囲だけを扱います。Model Context Protocol（MCP）サーバーを通じて言語モデルと組み合わせると、機械的な既定値をモデルが引き継ぎます。Solo ウィザードと MCP の列が同じ動作を示す場合、その制限は Sweepy の両方のバージョンに当てはまります。

制限事項Solo ウィザードMCP サーバー併用時回避策
マッチ率履歴書と求人で共有するキーワードを数えます。カードの表示は KEYWORD OVERLAP です。submit_judgments が独自の割合を設定し、カードの表示は MATCH になります。Sweep Settings タイルで resume.keywords_weight を上げ、resume.synonyms のグループを手動で追加します。ウィザードは類義語を自動では設定しません。
給与と福利厚生開示された給与レンジを表示します。値は構造化されたサイトの項目か求人本文から読み取ります。福利厚生は常に Not disclosed と表示されます。submit_judgments がいずれの値も指定します。CSV エクスポートの comp 列と benefits 列に入力します。
バッジと応募形式エンジン内の固定キーワード一覧から Amber か Slate を推測します。submit_judgments が両方の項目を上書きします。実際の求人と照らしてバッジを確認してから判断します。
要約、要件、応募のヒント求人から本文を抽出し、履歴書と照合して採点します。submit_judgments がこれらを書き換え、render_report は独自のプレイブックを受け取ります。CSV または JSON エクスポートで項目を編集します。
履歴書のテキストPDF と Word ファイルのテキスト層を読み取ります。スキャン画像では採点対象が得られません。モデルがスキャンを画像として読み取り、スキルを渡します。resume.must_have_skills にスキルを列挙します。ウィザードの必須スキルの手順がこれを担います。
対象範囲名前付きの企業サイト 41 件と Built In NYC の 5 カテゴリに問い合わせます。import_jobs がどこからでも求人を追加します。sources.greenhouse.boards、sources.ashby.orgs、sources.lever.companies、sources.workable.slugs に対象を追加します。
求人フィード有効にするまで停止しています。各フィードは職種ごとに直近 3 日間の求人を最大 25 件返します。切り替えは同じです。sources.jobspy でサイトを有効にします（例: glassdoor）。
リンクの確認接続エラーの求人は除外されます。同じです。JSON エクスポートを保存し、企業サイトで上位の候補を再確認します。
PDF の長さPDF のカードを 24 枚までに制限します。同じです。report.max_cards を設定します。値が 0 なら上限がなくなり、CSV と JSON のエクスポートには全求人が並びます。
スクレイパーの脆弱性サイトのマークアップが変わったりレート制限が厳しくなったりすると動作が止まります。同じです。--debug を付けて実行し、続いて --logs でソースのエラーを一覧します。ソースのエラーでスイープが止まることはありません。

ガイドの道筋​

このガイドは 4 つの手順を順に説明します。

  1. Sweepy をパソコンにインストールします。インストールを参照してください。
  2. Alex のニューヨーク市パラリーガル向けプロファイルのように、自分用の求職プロファイルを設定します。Sweepy のセットアップを参照してください。
  3. 初めての自動求人スイープを実行し、動作を確認します。初回スイープを参照してください。
  4. 生成された PDF レポートを読み、マッチ率、バッジ、応募戦略を理解します。結果の読み方を参照してください。
