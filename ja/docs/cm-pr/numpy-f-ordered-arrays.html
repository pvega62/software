F順序配列の修正

問題の定義​

NumPy配列がF順序である場合、Protobufによるエンコード／デコードが失敗する

テスト​

import numpy

from mcbackend.npproto.utils import ndarray_from_numpy, ndarray_to_numpy

arrC = numpy.array([
    [1,2,3],
    [4,5,6],
], order="C")

arrF = numpy.array([
    [1,2,3],
    [4,5,6],
], order="F")

assert arrC.strides != arrF.strides

numpy.testing.assert_array_equal(
    arrC,
    ndarray_to_numpy(ndarray_from_numpy(arrC)),
)
numpy.testing.assert_array_equal(
    arrF,
    ndarray_to_numpy(ndarray_from_numpy(arrF)),
)

コミットメッセージ​

F順のNumPy配列のエンコード/デコードを修正

`bytes(arr.data)`はバッファの内容をC順で具現化するため、Fortran順の配列をエンコードすると、C順のバイトとFortranのストライドが組み合わされてしまいます。その結果、デコード時に誤ったストライドでそれらのバイトが読み込まれ、順が乱れた配列が返されてしまいます。

`Ndarray`メッセージの新しい`order`フィールドにメモリ順序を記録し、そのフィールドが「F」を返した場合は、`ndarray_to_numpy`に転置とリシェイプを行わせる。0.2.4より前にエンコードされたバッファは`order`フィールドが空であるため、それらをデコードするとC順の配列が得られる。

Closes #63

プルリクエスト​

概要​

Protobufでのラウンドトリップ処理により、Fortran順のNumPy配列が破損します。Fortran順の配列は、値の位置がずれた状態で返されます。デコーダは例外を発生させず、呼び出し元は順序が乱れた配列を受け入れてしまいます。

Round-trip test
arrF = numpy.array([[1, 2, 3], [4, 5, 6]], order="F")
numpy.testing.assert_array_equal(
    arrF,
    ndarray_to_numpy(ndarray_from_numpy(arrF)),  # returns [[1, 3, 5], [2, 4, 6]] without the fix
)

根本原因​

ndarray_from_numpyは、配列のストライドの隣に生のバッファを格納しますが、これら2つの値は異なるメモリレイアウトを表しています：

  1. エンコード：bytes(arr.data) はバッファを C 順で実体化するため、Fortran 順のソース配列から C 順のバイト配列が生成されます。
  2. ストライド：ndarray_from_numpy は strides を変更せずにコピーするため、これらは依然として Fortran のレイアウトを表しています。
  3. デコード：numpy.ndarray(buffer=..., strides=...)は、C順のバイト配列にFortranのストライドを適用します。その結果、オフセットが誤ったセルを指し、誤った値が返されます。

修正​

エンコード時にメモリの順序を記録し、デコード時にそれを再現する。

  • protobufs/npproto/ndarray.protoおよび生成されたmcbackend/npproto/__init__.pyでは、Ndarrayメッセージにorderという文字列フィールド（タグ5）が追加されます。
  • mcbackend/npproto/utils.pyは、エンコード時にorder="CF"[arr.flags.f_contiguous]を書き込みます。Fortran順の配列には"F"が格納されます。デコード時、ndarray_to_numpyは、nda.order == "F"の場合、転置とリシェイプを行います。この処理により、C順のバイト列からFortran順のレイアウトが再構築されます。
  • mcbackend/test_npproto.py には、test_byteorders が追加されており、これにより shape と order を一緒にパラメータ化できるようになっています。

テスト​

TestUtils.test_byteordersは、shapeとorderを組み合わせてパラメータ化します。(5,)、(2, 3)、(2, 3, 5)、(5, 2, 1, 7)の各ケースは、メモリ順序ごとに1回ずつ、計2回実行されます。各ケースでは、nda.orderがarr.flags.f_contiguousと一致することを確認した後、配列をencodeとdecodeを通じて往復処理します。

TestUtils.test_conversionでは、依然としてint、float、scalar、string、object、datetimeの各データ型が対象となっています。

注記​

  • バージョンを0.2.4に更新しました。
  • ndarray_to_numpyには転置処理が追加され、既存のバッファおよびデータ型の扱いは維持されます。
  • 0.2.4より前にエンコードされたバッファは、orderフィールドが空になっています。こうしたバッファをデコードすると、C順の配列が得られます。

テストの方法​

Verify the fix
pytest mcbackend/test_npproto.py

このスイートでは、新しいtest_byteordersのテストケースを両方のメモリ順序で実行し、既存のdtypeのテストケースを再実行します。
