Stripeを通じてお金がどのように動くか

支払いが銀行口座に振り込まれる前に、5つのオブジェクトを経由します。各オブジェクトは処理の一部を記録しています。順番に確認すれば、最初の試みから最終的な支払いまでの全ての流れをたどることができます。

支払いの段階​

段階オブジェクト記録内容
1PaymentIntent顧客が支払おうとした金額、およびその試みが成功したかどうか。
2Chargeお金を移動させた支払い方法、および実際に振り込まれた金額。
3BalanceTransaction移動にかかる手数料、および口座残高に反映された純額。
4Balance現在、アカウントから支払える金額です。
5Payout口座に残っていた金額とその時期は？

ステージは順番に実行されます。各ステージは互いにリンクしているため、後から任意のステージを開いても元の意図に戻ることができます。

ステージ1：インテントは試行内容を記録する​

PaymentIntentには金額、通貨、およびステータスが保存されている。試行に失敗してもその情報は保持されるため、顧客は別のカードを使用して同じインテントで再試行できる。

ステータス意味次の手順
requires_payment_methodまだ利用可能な支払い方法がない。方法を選択して確認してください。
requires_confirmation確認準備ができました。インテントを確認してください。
requires_action発行者が顧客の認証をリクエストしています。クライアント側で認証を完了してください。
processingネットワークは正常に動作しています。Webhookの応答を待ってください。
requires_capture認可はされたが決済が完了していない。認可期間内に決済を完了してください。
succeededお金が移動しました。注文を履行してください。
canceled支払いに永続的な障害が発生しました。新しいインテントを作成して再試行してください。
警告

クライアントから結果が報告されるが、最終的な判断はサーバーが下す。クライアントからのsucceededの情報はヒントとして扱い、注文を履行する前にWebhookまたはリトリーブコールでステータスを確認してください。

ステージ2：決済によりお金が移動する​

確認処理によりChargeが生成されます。この処理では、支払い方法、請求金額、およびカードネットワークからの処理結果が記録されます。1つの成功した処理につき1件の請求が発生します。請求金額は決済後に変更されることはありません。

権限認証と金額の取得を同時に行うことも、別々に行うことも可能です。capture_methodをmanualに設定すると、現時点で資金を保留し、後で実際に移動させることができます。請求前に商品を配送するマーケットプレイスではこの分割処理が必要です。保留期間が終了する前に金額を取得してください。

ステージ3：残高変更処理では費用が記録されます。​

すべての資金移動についてBalanceTransactionが生成されます。この記録には3つの金額が含まれます：

  • amount. 最小通貨単位での全額移動金額。
  • fee. Stripeがその移動に対して請求した料金。
  • netオブジェクトは資金を2つの配列に分割します：

返金処理により、マイナス額の取引がもう一つ追加されます。支払い処理においても同様です。この帳簿と照合してください。手数料に関する記録は他にありません。

ステージ4：残高には確定した資金が含まれています​

Balanceオブジェクトは資金を2つの配列に分割します：

配列意味
available今すぐ支払ったり振り込んだりできる資金です。
pendingまだ決済されていない請求からの資金。

3番目のフィールド「refund_and_dispute_prefunding」には、将来の返金や紛争、またはマイナス残高のために予約された資金が保管されています。各配列には通貨ごとに1つのエントリが記載されています。

注記

残高は支払い可能な金額を示しますが、収益は表示されません。収益報告のためには、指定された期間内の残高取引における「net」の合計値を計算してください。

ステージ5：支払いがアカウントから行われます。​

「Payout」により、利用可能な資金が登録されている銀行口座に送金されます。支払いスケジュールは日次、週次、月次、または手動で設定できます。決済の遅延は国や支払い方法によって異なります。

1回の支払いで複数の請求が処理されます。1回の支払いをその元となる請求と照合するには、「payout={payout_id}」をフィルターとして使用し、関連する残高取引を一覧表示します。

実際の例​

顧客が月額プランを21.20ドルで購入します。プラットフォームは標準のカード手数料（2.9％）に加えて0.30ドルを請求します。

ステージオブジェクト金額備考
1PaymentIntent pi_...2120amount=2120、currency=usdで作成されました。
2Charge ch_...2120発行者が請求を承認しました。
3BalanceTransaction txn_...amount: 2120fee: 91, net: 2029, type: charge.
4バランスavailable: 2029計算遅延後に資金が表示されます。
5支払い金額（po_...）（2029）他の決済済み料金と一緒に支払われた。

手数料は91セントです。2.9%の手数料が61.48セントかかり、固定手数料が30セント加わって合計91セントになります。アカウントの残高は20.29ドルに増え、21.20ドルではありません。

パスが変更される場合​

支払いが拒否された場合​

支払いが拒否されると、料金は請求されずに処理が終了します。その際、残高はrequires_payment_methodの状態に戻り、金額は保持されます。同じ意図で再試行すると、重複した注文を避けることができます。

拒否の種類は、再試行が成功するかどうかによって分かれます：

  • ハードディスカウント。 発行者がカードを完全に拒否する場合（例：lost_cardやstolen_card）。再試行は不要です。
  • ソフトディスカウント。 発行者がこの試行を拒否する場合（例：insufficient_funds）。後で再試行すれば成功する可能性があります。

返金​

返金するとRefundオブジェクトが作成され、負の金額を持つ別のバランス取引が行われます。返金では元の処理手数料は返金されません。

返金タイプバランス取引残高への影響
完全な返金amount: -2120, fee: 0, net: -2120全額が返金されます。
部分的な返金amount: -1000, fee: 0, net: -1000一部の金額が返金されます。
2回以上の部分的な返金返金ごとに1件のトランザクションが生成されます。各返金は別々のレジストリエントリとして記録されます。

アカウントは元の91セントの手数料を引き続き支払います。完全な返金には、返金額に加えてその手数料として21.20ドルがかかります。

紛争処理​

チャージバックにより請求が取り消され、紛争手数料が加算されます。発行者が紛争を開始すると、Stripeはavailableから該当金額を引き出します。その後、アメリカでは15ドルの固定紛争手数料が請求されます。

紛争処理によりレジストリに3件のトランザクションが追加されます。最初のエントリで金額が引き出され、次にプラットフォームが固定の紛争手数料を請求します。銀行の判断が利用者に有利な場合、3番目のエントリで金額が復元されます。状況はDisputeオブジェクトを通じて追跡します（残高のみではありません）。

一部の金額の取得​

手動による金額の取得では、認可された金額未満が引き出されることがあります。40ドルを取得した場合、4000には40ドルが記録され、残りの10ドルが顧客に返金されます。1件のバランストランザクションで40ドルが記録されます。

次に進む方法​

  • 認証とキー管理：最初のリクエストを送信するための手順。
  • 非再帰的なリクエスト：請求を重複させずに再試行するための方法。
  • エラーや再試行処理：拒否処理、レートリミットの超過、サービス停止に対応するための処理。
  • 残高情報の取得：全ての属性リストを含む残高情報を取得するための処理。
