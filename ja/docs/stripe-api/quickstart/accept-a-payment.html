カード支払いの受け付け

  • 対象読者：Stripe APIを使って初めて支払いを行う開発者
  • 前提条件：テストモードのStripeアカウント、環境変数に格納されたシークレットキー、Node.js 18以降
  • 目標：カード支払い情報を取得し、そのステータスを確認し、サーバーが請求を確認した後にのみ注文を完了させる

最終的には、PaymentIntentを生成するサーバーエンドポイントとそれを確認するクライアントができるようになる。すべての処理はテストモードで行われ、実行に費用はかからない

リクエストフロー​

カード支払い処理はサーバー、クライアント、Stripeの間で行われる。サーバーがシークレットキーを保持し、クライアントがカード情報を収集して支払い意図を確認する。Stripeは結果を2回報告する（クライアントに1回、Webhookに1回）

各段階はそれぞれ別の場所で実行され、使用されるキーの種類はその場所に応じて決まる

階段実行場所使用する認証情報
PaymentIntentを作成するあなたのサーバーシークレットキー
カード情報の収集クライアント公開可能なキー
支払いの確認クライアントclient_secret
結果の報告StripeWebhookシグネチャ

支払いWebhookの処理は最終段階をカバーしています。このページでは検証済みのステータスで処理が終了します。

1. PaymentIntentの作成​

サーバー上で各注文ごとに1つのPaymentIntentを作成します。応答にはclient_secretが含まれており、クライアントはこれを使用して支払いを確認します。

server.js
import express from "express";

const app = express();
app.use(express.json());

app.post("/create-payment-intent", async (req, res) => {
  const orderId = req.body.orderId;

  if (!orderId) {
    return res.status(400).json({ error: "orderId is required" });
  }

  const params = new URLSearchParams({
    amount: "2120",
    currency: "usd",
    "automatic_payment_methods[enabled]": "true",
    "metadata[order_id]": orderId,
  });

  const response = await fetch("https://api.stripe.com/v1/payment_intents", {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.STRIPE_SECRET_KEY}`,
      "Content-Type": "application/x-www-form-urlencoded",
      "Idempotency-Key": `order-${orderId}`,
    },
    body: params,
  });

  if (!response.ok) {
    const failure = await response.json();
    return res.status(response.status).json({ error: failure.error.message });
  }

  const intent = await response.json();
  res.json({ clientSecret: intent.client_secret });
});

app.listen(4242, () => console.log("Listening on port 4242"));
  • amountは最小通貨単位を使用します。 2120の料金は21.20ドルであり、2,120ドルではありません。
  • Idempotency-Keyは注文IDを再利用します。 再試行されたリクエストでは新しいIntentが作成されず、元のIntentが返されます。
  • metadata[order_id]はIntentを注文にリンクします。 Webhookハンドラーはデータベースの照会なしでそれを読み取ります。
警告

1つの注文に対してclient_secretはブラウザ内でのみ使用されます。ログに記録したり、他の顧客間で再利用したりしないでください。

クライアントコードを書く前に、エンドポイントの応答内容を確認してください。

curl -X POST http://localhost:4242/create-payment-intent \
  -H "Content-Type: application/json" \
  -d '{"orderId":"ord_8842"}'

応答にはpi_で始まり、_secret_を含むclientSecret値が含まれています。

クライアント側で支払いを確認してください。​

Stripe.jsを読み込み、顧客のカード情報を確認してください。Stripeがカード入力処理を行うため、カード番号は決してお客様のサーバーには送信されません。

checkout.html
<div id="card-element"></div>
<script src="https://js.stripe.com/v3/"></script>
<script>
  const stripe = Stripe("pk_test_REPLACE_WITH_YOUR_KEY");
  const elements = stripe.elements();
  const cardElement = elements.create("card");
  cardElement.mount("#card-element");

  async function pay() {
    const response = await fetch("/create-payment-intent", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ orderId: "ord_8842" }),
    });

    const { clientSecret } = await response.json();

    const result = await stripe.confirmCardPayment(clientSecret, {
      payment_method: { card: cardElement },
    });

    if (result.error) {
      showDecline(result.error.message, result.error.decline_code);
      return;
    }

    if (result.paymentIntent.status === "succeeded") {
      showConfirmation();
    } else {
      showPending();
    }
  }
</script>

status フィールドがブランチの状態を決定します。succeeded 状態は発行者が請求を承認したことを意味します。requires_action 状態は顧客がまだチャレンジを完了する必要があることを意味し、Stripe.js はconfirmCardPayment の際にそのチャレンジを表示します。

サーバー側でも状態を確認してください。​

結果はクライアントから通知されますが、ブラウザが偽のデータを表示する可能性もあります。商品を送る前に、Stripeからの確認情報を必ず確認してください。

server.js
app.get("/orders/:orderId/status", async (req, res) => {
  const intentId = await lookupIntentId(req.params.orderId);

  const response = await fetch(
    `https://api.stripe.com/v1/payment_intents/${intentId}`,
    { headers: { Authorization: `Bearer ${process.env.STRIPE_SECRET_KEY}` } }
  );

  const intent = await response.json();

  res.json({
    fulfilled: intent.status === "succeeded",
    status: intent.status,
    amountReceived: intent.amount_received,
  });
});

amount_received と amount の値も比較してください。部分的なキャプチャでは、amount_received が amount を下回ります。この差額が返金または解放の対象額です。

ヒント

各注文ごとに結果を数秒間キャッシュしておきましょう。そうしないと、高速なチェックアウトページで毎秒1回 API が呼び出されてしまいます。

確認済みの状態でのみ商品を配送してください。​

payment_intent.succeeded ワイルドカード（Webhook）はブラウザよりも信頼性の高い配送トリガーです。顧客がタブを閉じても一度だけ通知が届き、検証可能な署名も含まれています。

fulfillment.js
async function handleSucceeded(intent) {
  const orderId = intent.metadata.order_id;

  if (!orderId) {
    console.warn("No order_id on intent", intent.id);
    return;
  }

  if (intent.amount_received < intent.amount) {
    console.warn("Underpaid intent", intent.id);
    return;
  }

  await markOrderPaid(orderId, intent.id);
}

注文IDはステップ1で設定したメタデータから取得されます。この情報があれば後で意図を再確認する必要がありません。

カードの利用拒否に対応してください。​

カードの利用が拒否された場合、requires_payment_method フィールドにその情報が残ります。金額や顧客情報は保持されるため、顧客は別のカードで同じ処理を再試行できます。

client.js
function showDecline(message, code) {
  const copy = {
    insufficient_funds: "That card can't cover this order. Try another card.",
    expired_card: "That card has expired. Add a new one.",
    incorrect_cvc: "The security code doesn't match. Check it and try again.",
  };

  showMessage(copy[code] ?? "That card was declined. Try another payment method.");
}

decline_codeを自分のコピーに置き換えて表示し、元のmessageは表示しないでください。元のテキストにはカード発行者の情報が含まれており、チェックアウトフォームには適していません。

4つの結果をテストします。​

テストモードおよびテストカードに記載されている各カード番号を実行し、その動作を確認してください。

カード期待される結果確認すべき内容
4242 4242 4242 4242支払いに成功。ステータスがsucceededと表示され、注文状態が「支払済み」に変わる。
4000 0000 0000 9995資金不足で拒否される。拒否のメッセージが表示され、注文状態は「未払い」のまま。
4000 0025 0000 3155認証が必要。認証プロセスが開始され、その後処理が続行される。
4000 0000 0000 0002一般的な理由で拒否される。フォールバックメッセージが表示され、注文状態は「未払い」のまま。

同じIDEMPOTENTYキーを使用して確認コールを再度実行してください。Stripeは元の注文内容を返し、注文状態は「1回の請求」となります。

ライブ環境に移行します。​

テストモードからライブモードへ一度で切り替えてください。

  1. プロダクション用の秘密鍵ストア内でテスト用の鍵ペアをライブ用の鍵に置き換えてください。
  2. プロダクション用のWebhookエンドポイントを登録し、署名用の秘密鍵を保存する。
  3. 低額な実際の請求を行い、その後返金する。
  4. 支払いスケジュールおよびファイルに記載されている銀行口座情報を確認する。
  5. 5xxからのレスポンスやWebhookの失敗に対してアラートを発動するよう設定する。
