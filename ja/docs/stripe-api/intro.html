Stripe APIの紹介

Stripe APIは、顧客間、お客様のプラットフォーム、および銀行口座間でお金をやり取りします。このリファレンスに記載されているすべてのエンドポイントは、共通のオブジェクトセットを使用して動作します。初めてリクエストを送信する前に、このページを必ず読んでください。

すべてのエンドポイントは同じ基本アドレス（https://api.stripe.com）を使用します。

支払いオブジェクトモデル​

支払い処理には5つのオブジェクトが関与します。チェックアウトから銀行口座までの流れをこれらのオブジェクトを追ってください。各オブジェクトは処理の段階を記録しているため、後で全体の処理経路を監査できます。

オブジェクトIDプレフィックス機能
Customercus_支払人情報、保存された支払い方法、請求履歴を格納します（一度限りの支払いでは省略可能）。
PaymentIntentpi_支払いの試みを追跡します。支払額、通貨、現在の状態が含まれます。
Chargech_支払い方法ごとのお金の移動を記録します。正常に処理された場合、1つのChargeが生成されます。
BalanceTransactiontxn_Charge、返金、または支払いによる残高の変動（手数料も含む）を記録します。
Payoutpo_支払い予定日に決済された残高をお客様の銀行口座に振り込みます。

支払いは「インテント（Intent）」として開始されます。「PaymentIntent」は支払い金額とステータスを記録し、支払い方法が確認するまでその状態が維持されます。確認が完了すると「Charge」が生成され、資金が移動します。その後、「BalanceTransaction」が総額、Stripeの手数料、および純額を記録します。決済された資金は残高に反映され、「Payout」を通じて銀行口座に振り込まれます。

Stripeにおける資金の流れでは、拒否処理、返金、紛争などを含む各段階を具体的な例を交えて説明しています。

用語規約​

リクエストとレスポンスの内容はプラットフォーム全体で統一された規則に従います。このリファレンスに記載されているコードサンプルもこれらの規則に基づいています。

用語規則例
金額最小通貨単位で表される整数。小数は使用しない。2120はUSDで21.20ドルを請求します。
タイムスタンプUTC時間（秒単位）1754447247
通貨小文字のISO 4217コードusd, eur, jpy
フィールド名snake_casepayment_method_types
オブジェクトの種類すべてのレスポンスでは、その種類がobjectに繰り返し記載されている。"object": "payment_intent"
ナルレブリティ（Nullability）設定されていない、または空のフィールドはnullを返します。フィールド自体はそのまま残ります。"customer": null
注記

JPYのような小数点以下がない通貨では、金額は整数として扱われます。1000では¥1,000が請求され、¥10.00ではありません。

認証の概要​

すべてのリクエストに秘密APIキーを含めて送信します。これはBasic認証で、パスワードは空のままです。テスト用のキーはsk_test_で始まり、本番用のキーはsk_live_で始まります。秘密キーにはアカウントの全権限が付与されるため、サーバーコードからのみ送信してください。

curl https://api.stripe.com/v1/balance \
  -u "$STRIPE_SECRET_KEY:"

認証とキー管理では、制限付きキーやキーのローテーションについて説明しています。また、キーを外部に漏らさずに保存する方法も紹介しています。

テストモードと本番モード​

各アカウントには2つの独立した環境があります。テストモードで作成されたデータは実際のお金を動かしません。

モード（Mode）キープレフィックス（Key Prefix）データ（Data）使用目的（Use for）
テスト（Test）sk_test_本番データとは別のデータ開発、自動化テスト、デモ
本番（Live）sk_live_実際の請求と支払い本番環境

テストモードでは、カード番号が特定の結果にマッピングされます（例：カードの拒否処理や認証失敗など）。テストモードとテスト用カードには、このドキュメントで使用されているカードの一覧が記載されています。

エラーの概要​

エラー発生時には、安定した状態を示すtypeと人間が読み取り可能なエラーメッセージを含むmessageを持つJSONというエンベロープが返されます。codeおよびparamには、エラーの原因に関する詳細情報が記載されています。

{
  "error": {
    "code": "parameter_invalid_integer",
    "doc_url": "https://stripe.com/docs/error-codes/parameter-invalid-integer",
    "message": "Invalid integer: 21.20",
    "param": "amount",
    "type": "invalid_request_error"
  }
}
HTTP 状態エラータイプ一般的な原因
400invalid_request_errorパラメータが欠落しているか、形式が不正確か、範囲外です。
401invalid_request_errorキーが欠落している、無効になっている、または別のアカウントに属している。
402card_error発行者が請求を拒否した。
403invalid_request_errorこのリソースに対するアクセス権限が不足している。
404invalid_request_errorこのモードでは該当するオブジェクトが存在しない。
429rate_limit_errorキーの使用頻度が制限値を超えている。

エラーと再試行では、各エラータイプに対応する復旧手順が記載されており、どのようなエラーが安全に再試行可能かが説明されている。

APIバージョン​

StripeはアカウントにAPIバージョンを固定します。Stripe-Versionヘッダーがないリクエストはその固定されたバージョンが使用されるため、サーバーのアップグレードによってもレスポンスの形式が変更されることはありません。変更をテストする際には、リクエストごとにバージョンを指定する必要があります。

curl https://api.stripe.com/v1/balance \
  -u "$STRIPE_SECRET_KEY:" \
  -H "Stripe-Version: 2024-06-20"

APIバージョニングとアップグレードでは、APIバージョンの管理方法やアップグレードの手順が説明されており、バージョン固定が何を保護するのかも解説されている。

再試行を安全に行うための「単純性（idempotency）」の活用​

ネットワークのタイムアウトにより、Stripeがリクエストを処理したかどうかが不明確になる場合は、各POSTのリクエストにIdempotency-Keyヘッダーを送信し、再試行時にも同じキーを使用してください。そうすることでStripeは二重に請求するのではなく、元の結果を返します。

【恒等操作のリクエスト（Idempotent Requests）】0この項目では、キーの選択方法やStripeが結果をどれくらい保持するかについて説明しています。また、新しいパラメータを使用して同じキーを再利用した際に発生するエラーについても解説しています。
