イベントストリームとオブザーバビリティパイプライン

現代のシステムは大量のテレメトリを出力します。ログ、メトリクス、トレース、セキュリティイベント、大規模言語モデル（LLM）のインタラクションが同時に届きます。このドキュメントでは、オブザーバビリティパイプラインがそのデータをリアルタイムに収集、整形、ルーティング、評価する仕組みを説明します。あわせて、Datadog と Galileo がどこで力を発揮するかも示します。

オブザーバビリティパイプラインが重要な理由​

生のテレメトリはコストがかかり、多くはノイズが多く形も不揃いです。オブザーバビリティパイプラインは、アプリとモニタリングツールの間に位置してこの問題を解決します。

  • コスト削減: 大容量のログを高価なストレージやセキュリティ情報およびイベント管理（SIEM）ツールに届く前にフィルタリングまたはサンプリングします。
  • データ品質の向上: パース、正規化、メタデータのエンリッチで品質を高めます。
  • プライバシー保護: パイプラインの早い段階で個人を特定できる情報（PII）をマスクまたは削除します。
  • 品質の測定: 運用テレメトリと並行して LLM のインタラクションを記録し、評価します。

エンジニアリング、サイトリライアビリティエンジニアリング（SRE）、AI の各チームは、具体的な修正につながる高速なデータを必要としています。

運用テレメトリとモデルテレメトリ​

従来のクラウドサービスと LLM を活用した機能を組み合わせたスタックは、2 つの異なるテレメトリレイヤーを抱えます。各レイヤーには専用のツールが必要です。

Datadog による運用テレメトリ​

Datadog はインフラストラクチャとアプリのレイヤーを処理します。ログとメトリクスを収集し、パイプラインを通じてイベントをアラートとアーカイブに振り分けます。payment-gateway のエラーログを送信し、Grok パーサーを適用して transaction_id を抽出できます。そこから status:error イベントを Slack アラートまたは S3 アーカイブに振り分けます。

Datadog は取り込みとパイプライン処理に Log Management を提供します。Observability Pipelines は自社インフラのワーカーから大規模にテレメトリを振り分けます。Log Explorer はリアルタイム検索と Live Tail を追加します。

Galileo によるモデルテレメトリ​

Galileo は LLM のレイヤーを処理します。各モデル呼び出しをトレースし、すべてのスパンの入力、出力、レイテンシを記録します。その後、評価メトリクスで各応答を採点します。payment-query LLM 関数が正確で、根拠があり、簡潔な回答を返しているかどうか、そしてデプロイでそれが変わるかどうかを確認できます。

Galileo は AI アプリを対象とします。評価とオブザーバビリティを組み合わせ、Python SDK と TypeScript SDK は主要な LLM プロバイダーに接続します。

これらのレイヤーは連携して機能します。Datadog は問題が起きたことを報告します。Galileo はモデル品質がなぜ下がったかを明らかにします。

イベントストリームの概念​

イベントストリームは、テレメトリデータを時刻順に、欠落なく届けます。現代のアプリスタックでは、イベントストリームが多くのソースから同時に届きます。

  • payment-gateway のエラーイベントなどのアプリログ
  • CPU 負荷、メモリ、レイテンシなどのインフラメトリクス
  • アプリケーションパフォーマンスモニタリング（APM）ツールからの分散トレースのスパン
  • セキュリティ監査ログと認証ログ
  • プロンプト、完了、レイテンシ、トークン数を含む LLM 呼び出しの記録
  • コンテナと Kubernetes のイベント
  • IoT デバイスのテレメトリ

LLM 呼び出しの記録がこのリストに加わったのは最近です。AI 機能を追加するアプリが増えるにつれ、そうしたインタラクションの記録と評価は、従来のアプリログの記録と同じくらい重要になっています。

パイプラインの主要コンポーネント​

1. 取り込みレイヤー​

生のテレメトリは取り込みレイヤーでシステムに入ります。

運用データの場合は、JSON ペイロードを Datadog Log Ingestion API に送信します。リクエストの送信先を https://http-intake.logs.{dd_site}/api/v2/logs に設定し、DD-API-KEY ヘッダーで認証します。{dd_site} は、datadoghq.com や datadoghq.eu など、利用するリージョンのホストに置き換えます。

Datadog は、JSON の形式が不正な場合に 400 Bad Request を返します。

LLM データの場合は、関数を @log デコレーターまたは GalileoLogger インスタンスでラップします。Galileo SDK がトレースを記録します。

Galileo SDK は GALILEO_API_KEY 環境変数からキーを読み取り、GALILEO_PROJECT と GALILEO_LOG_STREAM から対象のプロジェクトとログストリームを解決します。

2. 処理レイヤー​

データが Datadog のパイプラインに入ると、プロセッサがルーティング前にデータを変換します。

  • Sensitive Data Scanner: 下流のストレージに届く前に PII を難読化します。メールアドレスやクレジットカード番号などのパターンを検出します。
  • Grok パーサー: 生のログ文字列から構造化フィールドを抽出します。
  • リマッパー: meta.customer_id などのネストした属性をトップレベルの属性に リマップし、フィルタリングとファセットを容易にします。
  • ルックアッププロセッサ: service 名を team_owner タグにマッピングするなど、 外部の参照データでログをエンリッチします。

Galileo では、各ログストリームに メトリクスを設定します。Luna SLM スコアラーが、記録したすべての応答を正確性、コンテキストへの準拠、トーンで採点します。

3. ルーティングレイヤー​

ルーティングレイヤーは、処理済みイベントの送信先を制御します。ルーティングルールは、内容、ビジネス要件、コンプライアンス要件に従います。Datadog では Log Pipelines と Indexes を通じてルーティングを設定します。

  • status:error ログをオンコールアラートと S3 アーカイブの両方に同時に振り分けます。
  • サンプリングルールを適用して、インデックスに届く status:info ログの量を減らします。
  • セキュリティに関係するイベントを SIEM インテグレーションに転送します。
  • Log Forwarding 機能を使用して、特定のログのサブセットを外部の HTTP エンドポイントに送信します。

Galileo では、レコードをプロジェクトとログストリームにグループ化してテレメトリを振り分けます。この構造により、dev、staging、production のトレースを評価し、比較できます。

4. 送信先レイヤー​

オブザーバビリティパイプラインは、処理済みイベントを単一の役割に特化した下流の送信先に届けます。

送信先の種類例
オブジェクトストレージAmazon S3、Google Cloud Storage（GCS）、Azure Blob Storage
SIEMSplunk、Chronicle、QRadar
検索と分析Elastic、OpenSearch、Snowflake
モニタリングとアラートDatadog Log Explorer、ダッシュボード、モニター
AI 評価Galileo ログストリーム、実験結果

ルーティングを絞り込むと、コストとクエリ時間が下がります。SIEM に流し込む生ログは、オブザーバビリティ予算の大きな割合を消費します。

一般的なユースケース​

Datadog による運用テレメトリ​

  • エラーアラート: payment-gateway の status:error ログを PagerDuty または Slack にリアルタイムで振り分けます。
  • コスト削減: インデックス作成前に status:info ログへ 10% のサンプリングルールを適用します。
  • セキュリティ分析: 認証の失敗と監査ログを SIEM に転送します。
  • データ正規化: Grok パーサーを使用して、異なる言語で書かれたサービス間でログ形式を標準化します。

Galileo による品質シグナル​

  • LLM トレース: AI 機能からのすべてのプロンプトと完了を、セッションとトレースごとにグループ化して記録します。
  • 応答の評価: Luna スコアラーを適用して、モデル出力を正確性とコンテキストへの準拠で採点します。
  • プロンプトの実験: production ログストリームにデプロイする前に、Galileo Experiments でプロンプト変更の A/B テストを実行します。
  • 環境間の比較: 同じ基準を使用して、staging と production のモデル動作を比較します。

パイプライン設計の原則​

  • 現代のアプリは 2 つのテレメトリストリームを生成します。1 つは運用ログ、もう 1 つは LLM インタラクションの記録です。
  • Datadog は、高スループットのインフラデータ向けに設計されたパイプラインベースの モデルで、運用データの取り込み、処理、ルーティングを処理します。
  • Galileo は、SDK で計測するトレースとメトリクスベースの評価を通じて、AI を活用した機能の AI テレメトリを処理します。
  • 処理はデータをクレンジングし、エンリッチします。ルーティングは各レコードを必要とする送信先に届けます。
  • 適切に設計されたパイプラインはコストを削減し、データの信頼性を保ちます。1 つのオブザーバビリティ戦略の中で、インフラの品質シグナルとモデル品質のシグナルを並べて報告します。
