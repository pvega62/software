Blüdhaven Petsのドメインモデル

Blüdhaven Petsプラットフォームは、3つの実店舗およびオンラインの里親募集カタログを通じて、ペットの受け入れ、法的な市町村ライセンスの発行、獣医による健康診断、在庫管理を一元的に行っています。

アーキテクチャの概要

本ドキュメントでは、Blüdhaven Pets OpenAPI 3.1契約の背後にあるビジネスロジック、ステートマシン、および規制要件について説明しています。

ブランチ​

Blüdhavenをサポートする施設は3つあり、これらの施設の識別子はBranchIdというエンム（enum）で表されています。すべての受け入れ記録、里親候補者の情報、供給注文にはこの識別子が使用されます。

フィールド型制約説明
idstringBranchId enumloc_harbor_04, loc_downtown_01, or loc_westend_08.
name文字列-施設の商号
kind文字列エンムintake、retail、またはtransitional
city文字列-その施設がサービスを提供する自治体。
address文字列-顧客が訪問する際の住所。
phone文字列+1 国家コードフロントデスクの電話番号。
services文字列の配列フリーテキスト預約可能なサービス（例：spay-neuterなど）。

動物​

個々のペットが自治体の受け入れ、獣医ケア、そして里親募集の過程を追跡するための中央管理システム。

フィールド型制約説明
id文字列プレフィックス pet_ユニークなプラットフォーム識別子。
name文字列最大60文字付与されたペットの名前。
species文字列列挙型使用可能な値：dog、cat、rabbit、bird、small_mammal。
breed文字列最大100文字主に認識されている品種または雑種。
age_months整数0以上受け入れ時の月齢（整数）。
sex文字列列挙型male または female。
weight_kg数値浮動小数点数最後の健康診断時の体重（キログラム）。
microchip_id文字列正確に15桁ISO 11784および11785規格に準拠したマイクロチップ識別子。
status文字列列挙型ステートマシンの状態。
intake_branch_id文字列BranchId 列挙型Branchに記載されている3つの施設のうちの出身施設。
intake_date文字列（日付）ISO 8601公式な引き渡しまたは救出のタイムスタンプ。
adoption_fee_cents整数セント配置料。Harbor支店では犬1匹につき15,000セント（150ドル）が請求されます。
temperament_tags文字列の配列フリーテキスト養子募集時のフィルター条件となる特徴（例：good-with-cats）。
health_recordオブジェクトAnimalHealthRecord動物の詳細な臨床記録。
photo_urlsURIの配列絶対URLメディアホストから提供されるギャラリー画像のURL。

健康記録​

臨床評価結果、法的な予防接種記録、および義務的な検疫手続きの進捗状況が保存されています。

フィールド型制約説明
rabies_tag_number文字列フォーマット RB-YYYY-XXXX犬狂病予防接種のための市の必要な証明書コード。
rabies_expiration_date文字列（日付）ISO 8601形式、必須犬狂病証明書の有効期限。期限切れの場合は手続きが停止される。
spay_neuter_certifiedブール値必須市の規則における引き取り手続き完了の法的要件。
quarantine_release_date文字列（日時）空値可咬傷や受け入れのケースにおいて、14日間の観察期間が義務付けられている。
veterinarian_license文字列フォーマット DVM-XXXXX証明を行う医師の州のライセンス番号。
last_exam_date文字列（日付）ISO 8601形式最終的な臨床検査の日付。

引き取り保留​

対面面接および身元調査の期間中、対象者を確保するための独占的な予約。

フィールド型制約説明
id文字列プレフィックス hld_独一のホールド記録識別子。
animal_id文字列外キー参照対象の動物。
applicant_id文字列プレフィックス usr_参考となる採用者プロフィール。
branch_id文字列外部キー面接が行われるブランチ。
expires_at文字列（日時）ISO 8601作成後30分で有効期限が切れる。
seconds_remaining整数計算値リードルートが返すカウントダウン値。これによりクライアントはタイムスタンプを解析する必要がない。
status文字列列挙型状態は ACTIVE、EXPIRED、RELEASED、または CONVERTED になり得る。

動物の状態ライフサイクル​

すべての動物は厳格な状態機械を通過する。未登録または未認証の状態では 422 Unprocessable Content に戻る。

  • Diagram
  • ASCII
[INTAKE]
   │
   ▼
[VET_CLEARANCE] ──(Fails quarantine / illness)──► [MEDICAL_QUARANTINE]
   │                                                     │
   │ (Passes exam & rabies log)                          │ (Cured & certified)
   ▼                                                     │
[AVAILABLE] ◄────────────────────────────────────────────┘
   │
   ▼
[RESERVED_HOLD] ──(30-min TTL expires / cancelled)──► [AVAILABLE]
   │
   │ (Adoption fee paid & license filed)
   ▼
[ADOPTED]

ライフサイクルの状態​

  • INTAKE：市立シェルターや迷子動物の救助により収容された動物。カタログでの表示はオフ。
  • VET_CLEARANCE：臨床検査および法的なマイクロチップ装着中の動物。
  • MEDICAL_QUARANTINE：感染症や咬傷の疑いがあるため隔離されている動物。クライアントはその記録を閲覧または入手できない。
  • AVAILABLE：免許を持つ獣医師によって検査を受け、spay_neuter_certified: true の状態になった動物。ウェブカタログおよび小売店舗で表示される。
  • RESERVED_HOLD：店舗スタッフまたはクライアントアプリによって作成される、30分間の予約ロック。二重予約を防ぐためのものです。
  • ADOPTED：市のペットライセンス料金の支払いが完了し、マイクロチップ情報が登録システムに移行されたことを意味します。

規制および自治体の遵守事項​

  1. Atomic hold placementとは、ターゲットとなるアニマルがPOST /adoptions/holdsをロックレコードに書き込む前にstatus: "AVAILABLE"を保持しているかをチェックする処理です。
  2. 競合への対応：その動物に対してすでにアクティブな保留が存在する場合、RFC 9457 の ProblemDetails を使用して HTTP 409 Conflict を返します。
  3. 自動期限切れ処理：申請者が1,800秒以内に支払いを行わない場合、その動物のステータスはAVAILABLEに戻されます。adoption.hold.expiredのWebhookがパートナー側に送信されます。

規制および自治体のコンプライアンス​

ブリュードヘイブン市の動物に関する条例では、3つの変更不可能な制約が定められている：

  1. 完全な制限により、spay_neuter_certified: trueの検証を受けていない動物はAVAILABLEまたはADOPTEDの状態に入ることができません。
  2. 法定マイクロチップのフォーマットでは、microchip_idはISO規格に準拠し、正確に15桁の数字で構成されている必要があります。
  3. 狂犬病予防タグの有効化により、12週齢を超えた犬および猫はVET_CLEARANCEを出発する前に有効なrabies_tag_numberを記録する必要があります。
