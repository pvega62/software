Référence de la configuration du profil

Cette page liste tous les paramètres acceptés par un profil Sweepy. Gardez-la ouverte pendant que vous modifiez votre profil. Pour une démarche guidée, consultez Configuration de Sweepy.

Où se trouvent les profils ?​

Commencez par le fichier profiles/ ou par un modèle préétabli. Copiez un modèle, renommez-le, puis modifiez ses valeurs.

Un profil contient toute votre configuration. Créez autant de profils que vous le souhaitez (un pour chaque ville ou famille de rôles). Sweepy conserve l’état de vos recherches en dehors du profil, dans la mémoire cache, la base de données d’historique, ainsi que dans les dossiers config.sample.yaml et profiles/paralegal_nyc.yaml.

Terminal
copy config.sample.yaml profiles\my_search.yaml
notepad profiles\my_search.yaml

Utilisez des espaces pour l’indentation ; les tabulations ne sont pas acceptées. Une seule tabulation peut rendre tout le profil illisible.

Terminal
sweepy --profile profiles/my_search.yaml
Remarque

Un profil contient toute votre configuration. Créez autant de profils que vous le souhaitez : un pour chaque ville ou famille de rôles. Sweepy conserve l’état des opérations de nettoyage en dehors du profil, dans la mémoire cache de découverte, la base de données d’historique, ainsi que dans les dossiers logs/ et results/.

attention

Utilisez des espaces pour l’indentation, jamais des tabulations. Le format YAML ne tolère pas les tabulations ; une seule tabulation erronée peut rendre tout le profil illisible.

Exemple de profil complet​

L’exemple ci-dessous présente le profil complet d’Alex. Les lignes qui commencent par # sont des commentaires et Sweepy les ignore.

profiles/paralegal_nyc.yaml
# ─────────────────────────────────────────────────
# Sweepy — Alex's Paralegal Profile (New York City)
# ─────────────────────────────────────────────────

# Your name. It appears in the PDF report header.
name: "Alex Rivera"

# Set true to write rotating debug logs under logs/.
debug: false

# ─── Job search ───────────────────────────────────
search:
  # Every title Sweepy searches at the same time.
  titles:
    - "Paralegal"
    - "Legal Assistant"
    - "Litigation Support Specialist"
    - "Legal Secretary"

  # Your target market.
  location: "New York, NY"

  # true keeps remote roles only. false keeps remote, hybrid, and on-site roles.
  remote_only: false

  # false removes hybrid roles from every report.
  include_hybrid: true

  # Annual salary floor. Use 0 to skip salary filtering.
  min_salary: 65000

  # true reads pay from the posting text when a board omits structured pay.
  salary_from_description: true

# ─── Resume ───────────────────────────────────────
resume:
  # Path to a PDF or DOCX resume. Forward slashes work on Windows.
  path: "Alex_Rivera_Resume.pdf"

  # Terms that carry the most weight when Sweepy scores a posting.
  must_have_skills:
    - "Westlaw"
    - "LexisNexis"
    - "e-discovery"
    - "Contract Review"
    - "Legal Research"

  # 1.0 is standard. Raise it to reward exact skill matches.
  keywords_weight: 1.5

  # Interchangeable terms. Sweepy matches every member of a group either way.
  synonyms:
    - ["e-discovery", "ediscovery", "electronic discovery"]
    - ["legal research", "case law research"]
    - ["docketing", "case calendaring"]
    - ["legal assistant", "legal secretary"]
    - ["contract review", "contract analysis", "agreement review"]

  # Optional: one resume per role family. Sweepy picks the best fit for each posting.
  tracks:
    - name: "Paralegal Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Paralegal.pdf"
      color: "#1D4ED8"
      route_keywords: ["paralegal", "litigation", "e-discovery"]
    - name: "Legal Assistant Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Legal_Assistant.pdf"
      color: "#7E22CE"
      route_keywords: ["legal assistant", "legal secretary", "scheduling"]

# ─── Platforms ────────────────────────────────────
platforms:
  greenhouse: true
  ashby: true
  lever: true
  workable: true
  aggregators: false

  # Extra ATS domains. Sweepy labels matching postings with this name.
  custom:
    - name: "SmartRecruiters"
      domain: "smartrecruiters.com"
      enabled: true
    - name: "Breezy HR"
      domain: "breezy.hr"
      enabled: true

# ─── Sources ──────────────────────────────────────
sources:
  jobspy:
    linkedin: true
    indeed: true
    glassdoor: true
    zip_recruiter: true

  # Leave a list empty to fall back to the seed lists in data/sources/.
  ashby:
    orgs:
      - "crosby"
      - "normlaw"
      - "hargrove-firm"
      - "lawhive"
  workable:
    slugs:
      - "shegerianand-associates-1"
      - "harper-james"
      - "legalvision"
  builtinnyc:
    enabled: true
    categories:
      - "jobs/legal"
      - "jobs/legal/search/paralegal"

# ─── Cache and history ────────────────────────────
cache:
  enabled: true
  ttl_seconds: 3600       # reuse discovery results for an hour

history:
  enabled: true
  retention_days: 4       # hide a reported posting for four days
  match: "url+role"       # "url" matches only an identical posting address
  path: null              # null uses ~/.sweepy/history.db

orchestrator:
  timeout_per_source_seconds: 180
  circuit_breaker:
    failure_threshold: 5
    cooldown_seconds: 30

# ─── Report layout ────────────────────────────────
report:
  style: "cards"          # "cards" (default) or "legacy"
  cards_per_page: 6       # cards on each PDF page
  max_cards: 24           # 0 or less shows every match
  destinations: []        # extra folders for a copy of the PDF
  assessment: "agent"     # "keyword" accepts reports without agent judgments

# ─── Exports ──────────────────────────────────────
export:
  format: "pdf,csv,json"  # add "png" for page images
  output_dir: "results"
  tracking: true          # job-tracking columns in the CSV
  description_chars: 1000 # posting excerpt length in the CSV and JSON
  timezone: "local"       # clock behind the report filename stamp

Traces de résumés​

Une trace est un résumé nommé. Utilisez les traces lorsque vous visez deux rôles ou titres différents et souhaitez que chaque offre soit évaluée par rapport au bon document.

Chaque entrée dans un fichier de rapport contient quatre champs :

profiles/paralegal_nyc.yaml
resume:
  tracks:
    - name: "Paralegal Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Paralegal.pdf"
      color: "#1D4ED8"
      route_keywords: ["paralegal", "litigation", "e-discovery"]
    - name: "Legal Assistant Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Legal_Assistant.pdf"
      color: "#7E22CE"
      route_keywords: ["legal assistant", "legal secretary", "scheduling"]

Chaque entrée dans le profil comprend quatre champs.

  • La piste est identifiée par la étiquette name. Le rapport affiche cette étiquette ; écrivez donc une ou deux mots pour la décrire.
  • path fait référence au PDF du CV de cette piste ou au fichier DOCX correspondant.
  • color définit la couleur de l’icône. Utilisez un code hexadécimal comme #1D4ED8, ou un nom de couleur comme navy.
  • route_keywords indique les publications que Sweepy associe à cette catégorie.

Sweepy réoriente chaque publication en fonction du chevauchement des mots-clés. Il compte les correspondances de mots entiers entre le titre et la description de la publication ainsi que les termes spécifiés dans route_keywords pour chaque catégorie. La publication est attribuée à la catégorie ayant le plus grand nombre de correspondances. En cas d’égalité, Sweepy utilise la première catégorie de la liste.

astuce

Les valeurs de route_keywords ne sont pas modifiables ; elles définissent les critères de correspondance utilisés par Sweepy pour l’assignation des publications.

Si vous omettez tracks, Sweppy utilisera automatiquement resume.path comme catégorie par défaut.

Synonymes pour “Résumé”​

resume.synonyms contient des groupes de mots ayant le même sens. Sweepy traite tous les mots d’un groupe de manière égale lors de la recherche de correspondances. Pour plus de détails sur la syntaxe, consultez Ajout de termes spécifiques à un secteur.

profiles/paralegal_nyc.yaml
resume:
  synonyms:
    - ["e-discovery", "ediscovery", "electronic discovery"]
    - ["legal research", "case law research"]
    - ["docketing", "case calendaring"]
    - ["legal assistant", "legal secretary"]
    - ["contract review", "contract analysis", "agreement review"]

Un groupe doit contenir au moins deux termes ; sinon, Sweepy l’ignorera. La recherche prend en compte la casse et les formes singulière et plurielle des mots. Les phrases complètes sont également prises en compte. Si vous souhaitez que les deux termes soient comptés séparément, listez-les dans legal research et legal researcher.

Par exemple, si Alex mentionne e-discovery dans son CV, une publication contenant electronic discovery sera associée à cette catégorie, car ces deux termes appartiennent au même groupe.

astuce

Ajoutez un nouveau groupe chaque fois que vous constatez une duplication de termes similaires. Copiez le texte exact de la publication dans le groupe correspondant.

Erreurs courantes de formatage​

La plupart des problèmes de fonctionnement des profils proviennent de quelques erreurs récurrentes.

Les chemins sous Windows nécessitent des barres obliques ou des doubles barres obliques. La notation C:\Users\Alex interprète une seule barre oblique comme un caractère d’échappement ; cela peut provoquer des problèmes lors de l’ouverture du fichier.

profiles/paralegal_nyc.yaml
resume:
  path: "C:/Users/Alex/Documents/Alex_Rivera_Resume.pdf"     # ✅ works
  # path: "C:\\Users\\Alex\\Documents\\Alex_Rivera_Resume.pdf"  # ✅ also works
  # path: "C:\Users\Alex\Documents\Alex_Rivera_Resume.pdf"      # ❌ breaks YAML
attention

La présence d’une seule barre oblique dans un chemin empêche Sweepy de lire votre profil correctement. Le guide d’installation utilise des barres obliques ; conservez donc ce format lorsque vous modifiez le fichier manuellement.

Les commentaires commencent par #. Sweepy ignore tout ce qui suit # dans la même ligne. Utilisez les commentaires pour expliquer pourquoi une valeur est importante, comme le fait l’exemple de profil fourni.

L’indentation définit la structure du fichier. Indentez chaque niveau de texte de deux espaces. L’utilisation d’un tabuleau (tab) à n’importe quel endroit dans le fichier peut entraîner des problèmes avec la syntaxe.
