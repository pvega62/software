Référence des outils MCP de Sweepy

Le serveur MCP (désigné par server.py) expose ces treize outils. La page Intégration MCP explique la procédure d’enregistrement et les workflows courants. Cette page liste toutes les fonctionnalités des outils, ce qui vous permet de prévoir le résultat d’une appel avant que l’assistant ne l’exécute.

Contenu de la réponse​

Chaque outil renvoie une chaîne JSON dans un bloc de contenu texte. Les réponses réussies commencent par "status": "ok". Les réponses en échec commencent par "status": "error" et incluent un message qui explique la cause. Un balayage en échec indique aussi job_id et sweep_status: "failed".

Un assistant appelle un outil à l'aide d'une requête tools/call. Celle-ci lance un balayage impliquant une longue attente bloquante :

Request
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "run_sweep",
    "arguments": {
      "profile_path": "profiles/tech_writer.yaml",
      "wait_seconds": 300
    }
  }
}
Response, truncated
{
  "status": "ok",
  "sweep_status": "completed",
  "job_id": "b41e9c0d7a12",
  "discovered_count": 137,
  "new_count": 41,
  "previously_seen_count": 96,
  "active_count": 137,
  "top_match": {
    "title": "Senior Technical Writer",
    "company": "Acme",
    "match_score": 92,
    "url": "https://example.com/jobs/4412"
  },
  "reports": {
    "pdf": "C:\\Users\\Alex\\sweepy\\results\\tech_writer_mcp_2026-10-27-223115.pdf",
    "csv": "C:\\Users\\Alex\\sweepy\\results\\tech_writer_mcp_2026-10-27-223115.csv"
  },
  "card_count": 24,
  "assessment_mode": "agent",
  "assessment_required": true,
  "elapsed_seconds": 214.6,
  "message": null
}

Le contenu complet du payload indique également les valeurs top_roles, job_ids, skipped_sources et debug_log.

Outils de profil et de balayage​

create_profile​

Vérifie chaque moteur activé, puis écrit le fichier de profil YAML.

ParamètreTypeValeur par défautDescription
nameChaîne de caractèresObligatoireNom complet à inclure dans le profil.
titlesTableau de chaînes de caractèresObligatoireTitres de poste cibles, tels que ["Technical Writer", "UX Writer"].
locationChaîne de caractèresObligatoireLieu de travail cible, tels que "New York, NY".
resume_pathChaîne de caractèresObligatoireChemin vers un CV en PDF ou un CV sous forme DOCX.
resume_tracksTableau d’objetsnullUne entrée pour chaque profil de candidat ; chaque profil contient une liste name et un CV optionnel path. Sweepy évalue chaque publication en fonction du profil auquel elle est destinée.
portfoliosTableau d’objetsnullEntrées de portfolio ; chacune contient une liste track, une liste url ou path, ainsi qu’une liste pieces optionnelle.
pieces_per_cardEntier3Nombre d’éléments du portfolio affichés sur chaque carte (de 1 à 10).
remote_onlyBooleenfalseRestreint les résultats aux postes entièrement télétravaillables.
include_hybridBooleentrueInclut les postes hybrides dans les résultats.
min_salaryEntier0Salaire de base annuel minimum. Zéro signifie qu’il n’y a pas de minimum.
must_have_skillsTableau de chaînes de caractèresnullTermes de compétence qui améliorent la correspondance avec les critères de recherche.
synonymsTableau de tableauxnullGroupes de termes interchangeables, tels que [["docs-as-code", "documentation as code"]].
platformsobjectnullLes informations relatives aux changements de plateforme ont été intégrées dans le bloc platforms du profil.
sources_configObjetnullLa sélection de l’engine a été intégrée dans le bloc sources. Chaque engine est validée avant l’écriture des données.
cache_configObjetnullParamètres de cache : enabled et ttl_seconds.
orchestrator_configObjetnullParamètres de timeout et de disjoncteur de circuit.
history_configObjetnullParamètres de contrôle qui déterminent les publications à ignorer lors du processus de nettoyage („sweep“).
job_trackingbooléentrueAjoute les colonnes de suivi des tâches au fichier CSV et conserve les valeurs précédentes.
assessmentstring"agent"Fonction de contrôle des rapports : La fonction agent bloque la création d’un rapport tant qu’au moins une carte contient des mots-clés en commun avec une autre carte. La fonction keyword autorise la création de rapports contenant uniquement des mots-clés.
output_filenamechaîne de caractèresnullChemin personnalisé pour le traitement des données. La valeur par défaut est profiles/{name}_{title}.yaml ; Sweepy convertit en minuscules les deux parties du chemin et remplace tous les caractères non alphanumériques par _.

orchestrator_config Prend en entrée un objet timeout_per_source_seconds ainsi qu’un objet circuit_breaker contenant les paramètres failure_threshold et cooldown_seconds.

history_config prend en entrée enabled, retention_days, match et path. La valeur par défaut de retention_days est 4 ; match accepte les valeurs url ou url+role ; la valeur par défaut de path est ~/.sweepy/history.db.

portfolios accepte un URL en ligne, un fichier PDF local, du texte, un fichier au format Markdown, ou une liste d’éléments à inclure dans le portfolio. Nommez un dossier (track) pour conserver un portfolio distinct par projet, puis transmettez les éléments sélectionnés à submit_judgments selon la méthode indiquée (portfolio_highlight). Utilisez set_portfolio pour modifier le portfolio d’un profil existant.

Retourne profile_path, enabled_engines, engines_not_enabled, ainsi que resume_documents pour le nouveau profil. Chaque entrée de CV indique son path et les pistes (tracks) qui l’utilisent, sans le texte analysé (parsed text).

set_portfolio​

Ajoute ou remplace les portfolios soumis par un profil enregistré. Appelez cette fonction une fois que l'utilisateur a donné un nom à un portfolio.

ParamètreTypeValeur par défautDescription
profile_pathChaîne de caractèresObligatoireChemin vers un fichier de profil existant YAML.
portfoliosUne liste d’objetsnullLes éléments à ajouter. Un élément sans track s’applique à toutes les pistes. Transmettez une liste vide avec replace pour supprimer tous les portefeuilles.
replacebooléenfalseEfface les portefeuilles enregistrés avant d’ajouter les nouveaux éléments.
pieces_per_cardEntier3Les éléments du portefeuille sont listés par carte (de 1 à 10). Laissez cette valeur non définie pour conserver la valeur enregistrée.

Retourne les valeurs portfolios, pieces_per_card, track, url, path et pieces. Si le profil n’a pas de portfolio, {title, url, tags} indique ce qu’il faut demander à l’utilisateur.

Retourne profile_path, resume_tracks, portfolio_configured, portfolio_sources, portfolio_pieces_per_card et portfolio_guidance. Lorsque le profil ne possède pas de portefeuille, portfolio_guidance indique ce qu’il faut demander à l’utilisateur.

run_sweep​

Chemin vers le profil à utiliser ; si omis, Sweepy utilise le dernier profil enregistré, puis le profil le plus récent, ou le premier profil disponible sur le disque.

ParamètreTypeValeur par défautDescription
profile_pathChaîne de caractèresnullChemin vers le profil YAML. Lorsque cette information est omise, Sweepy utilise le dernier profil enregistré, puis le profil le plus récent indiqué à profiles/, et enfin le premier profil conventionnel présent sur le disque (profiles/custom_profile.yaml, profiles/paralegal_nyc.yaml ou config.sample.yaml).
deduplicatebooléentrueFusionne les URL répétées ainsi que les publications correspondantes provenant de différents forums pour cette session.
include_seenbooléenfalseAffiche les publications issues des balayages précédents et actualise leur historique.
wait_secondsEntier45Délai d’attente le plus long avant que la fonction ne retourne des informations sur son avancement. La valeur est limitée à la plage de 0 à 600.
timestampChaîne de caractèresnullL’heure locale de l’utilisateur pour les noms des rapports, selon le format YYYY-MM-DD-HHMMSS ou ISO 8601. L’assistant utilise l’heure déjà connue à partir de la conversation pour étiqueter chaque rapport avec l’heure de l’utilisateur, et non celle du serveur.

Une opération de nettoyage en temps réel dure souvent plus longtemps que le délai d’attente défini par le client. Le pipeline gère cette différence en s’exécutant sur un thread en arrière-plan. Une appel qui retourne la valeur sweep_status: "running" contient également la valeur job_id ; transmettez cette identité à la fonction get_sweep_status jusqu’à ce que l’état de l’opération soit mis à jour (indiqué par la valeur completed).

Une seconde appelation avec le même profil et les mêmes paramètres s’ajoute à la tâche en cours plutôt que de lancer une nouvelle tâche. Le processus serveur doit rester en marche. Les identifiants des tâches de nettoyage sont stockés en mémoire ; un redémarrage les efface.

La réponse contient l’un des trois types de données suivants :

  • Lancement : sweep_status, job_id, progress avec step, total et label, ainsi que elapsed_seconds, debug_log et message.
  • Achèvement des tâches : sweep_status, job_id, discovered_count, new_count, previously_seen_count, active_count, top_match, top_roles, reports, job_ids, card_count, assessed_count, assessment_mode, assessment_required, skipped_sources, elapsed_seconds, debug_log et message. La ligne top_roles contient les cinq premiers rôles.
  • Échec : status: "error", message, job_id et sweep_status: "failed".

La fonction attend la fin de l’opération de nettoyage initiée par la valeur job_id et en rapporte l’avancement.

Lorsque chaque publication découverte est une répétition, previously_seen_count affiche le total et active_count affiche zéro. Appelez run_sweep avec include_seen réglé sur true pour les examiner.

Une opération de balayage MCP (MCP sweep) écrit les mêmes noms d’artefacts que la ligne de commande, et ajoute un marqueur mcp, comme dans les fichiers results/tech_writer_mcp_2026-10-27-223115.pdf, .csv et .json correspondants. Une interface CLI ou un assistant d’utilisation écrit le nom de l’artefact sans ce marqueur, afin que le dossier indique quel chemin a généré chaque rapport. Le paramètre timestamp est utilisé pour marquer les fichiers avec la date et l’heure de l’utilisateur. En l’absence de ce paramètre, l’outil Sweepy récupère l’heure à partir de la valeur stockée dans la clé export.timezone du profil de l’utilisateur.

get_sweep_status​

Attente le résultat de la tâche déclenchée par run_sweep et en rapporte l’avancement.

ParamètreTypeValeur par défautDescription
job_idChaîne de caractèresnullIdentifiant de la tâche provenant de run_sweep. La valeur par défaut est celle de la tâche la plus récente.
wait_secondsEntier45Délai d’attente le plus long avant que la fonction ne retourne des informations sur son avancement. La valeur est limitée à la plage de 0 à 600.

Chaque réponse contient les mêmes champs que le résultat correspondant (run_sweep). L’absence ou l’inconnu de certaines informations (job_id) provoque une erreur qui renvoie à la raison de l’échec (run_sweep).

Une opération de balayage terminée charge également ses données dans la session en cours ; par conséquent, les éléments get_jobs, submit_judgments et render_report fonctionnent dès que l’état est indiqué comme « completed ».

get_jobs​

Retourne les enregistrements de cartes conservés dans la session actuelle, classés par chevauchement des mots-clés ou score de correspondance des soumissions.

ParamètreTypeValeur par défautDescription
profile_stemChaîne de caractèresnullIdentifiant de profil utilisé pour charger une session enregistrée, tel que pedro_writer.
results_dirChaîne de caractères"results"Fichier qui contient report_session.json.
limitEntiernullNombre de cartes à retourner. Omettre cette valeur pour retourner toutes les cartes. Sweepy impose un minimum d’une carte à être retournée.
needs_descriptionbooleannulltrue ne retourne que les cartes qui ne contiennent aucun corps de publication. false ne retourne que les cartes qui contiennent un corps de publication.

Retourne les valeurs count, session_count, needs_description_count, jobs, ainsi que les documents de résumé (resume) du profil actif. Pendant l’exécution d’une opération de balayage (sweep), le contenu transmis inclut également les valeurs sweep_status, running_job_id, progress et message, qui indiquent que ces informations datent d’une opération de balayage antérieure.

Documents de reprise​

resume_documents liste une entrée par fichier de CV. Chaque entrée indique path, les tracks qui utilisent ce fichier, et text, le document analysé. Les tracks qui partagent un fichier partagent une entrée, donc Sweepy ne répète jamais le texte. La charge utile indique aussi resume_default_path, resume_configured et resume_guidance.

Votre assistant évalue ce texte. Les informations contenues dans les sections must_have_skills et synonyms du profil servent uniquement à déterminer si le candidat répond aux critères requis. La note obtenue à partir de ces informations mesure la pertinence du profil, et non celle du candidat lui-même.

L’assistant lit le fichier exactement comme le ferait un recruteur : il prend en compte les compétences transférables, l’expérience, le domaine d’activité, les outils utilisés, ainsi que les résultats obtenus par le candidat. Ensuite, il attribue une note au fichier selon la manière dont le système de suivi des candidats (ATS – Applicant Tracking System) de l’entreprise l’interprète.

  • Un terme présent dans une section standard Experience ou Skills est considéré comme une preuve.
  • Le même terme situé à l’intérieur d’une table, d’un en-tête, d’un pied de page, d’une image ou d’une barre latérale à deux colonnes n’est pas pris en compte, car il est moins significatif.
  • L’assistant indique la famille du système ATS utilisé par l’entreprise (par exemple : Workday, Greenhouse, Lever, Ashby, iCIMS, Taleo, Workable, SmartRecruiters) lorsque le lien de candidature est cliqué.
  • Tout ce que le parseur omettrait d’interpréter est indiqué dans concerns sur cette carte.

Un fichier manquant ou illisible renvoie la valeur text et aucun message d’erreur n’est affiché. Le chemin du fichier est tout de même affiché, permettant ainsi à l’assistant de signaler le problème.

submit_judgments​

Intégrez l’évaluation d’un assistant dans une seule carte ou dans un lot entier de cartes. Seuls les champs non nuls sont modifiés.

ParamètreTypeValeur par défautDescription
job_idChaîne de caractèresnullIdentifiant de la carte stable provenant de run_sweep ou get_jobs. Obligatoire sauf si vous spécifiez judgments.
match_pctEntiernullPourcentage de correspondance allant de 0 à 100. Lisez d’abord la valeur de resume_documents, puis évaluez le fichier analysé selon la méthode utilisée par ATS. La fourniture de cette valeur modifie l’étiquette de la carte pour la mettre en valeur avec MATCH.
resume_trackChaîne de caractèresnullPiste de résumé à afficher sur la carte.
resume_colorChaîne de caractèresnullCouleur de l’ badge associée à cette piste.
domainChaîne de caractèresnullDomaine de rôle affiché sur la carte.
summaryChaîne de caractèresnullTexte résumant la carte.
requirementsChaîne de caractèresnullTexte des exigences.
alignmentChaine de caractèresnullIl s’agit d’un élément qui relie les preuves présentées dans le CV au poste pour lequel on postule.
concernsChaine de caractèresnullCe qui nuit au candidat : exigences non remplies, lacunes dans l’expérience professionnelle, incompatibilité avec le domaine, attentes sur place, salaire inférieur au minimum prévu, ou des informations qui ne pourraient pas être traitées par les outils d’analyse (par exemple, du contenu non structuré).
has_extended_responsebooléennullMarque un post qui nécessite des réponses écrites.
app_formatChaîne de caractèresnullFormat d’application, tel qu’un portail ou un e-mail.
compChaîne de caractèresnullLigne relative à la compensation.
benefitsChaîne de caractèresnullLigne des avantages.
page_themeChaîne de caractèresnullSurcharge du thème des cartes.
portfolio_fitEntiernullScore du portefeuille allant de 0 à 100. La carte l'affiche sous la forme de PORTFOLIO FIT.
portfolio_highlightChaîne de caractèresnullNomme les éléments à envoyer avec cette application. Une carte sans nom affiche les éléments enregistrés dans le profil.
descriptionChaîne de caractèresnullContenu du corps de la publication, lu à partir de l’URL de la carte (qui n’a pas pu être analysée par Sweepy).
judgmentsTableaunullListe d’objets de jugement, chacun comprenant un champ job_id ainsi que d’autres champs supplémentaires. Ne les combinez pas avec job_id.

Évaluez le document, pas le profil. get_jobs retourne le texte du CV analysé (parseé) dans resume_documents, tandis que must_have_skills et synonyms ne fournissent que les informations obtenues par une approche déterministe. Notez tout ce qu’un analyseur pourrait manquer de capturer, comme les compétences présentées dans un élément graphique de type sidebar (concerns).

La fonction retourne la carte fusionnée sous la forme de job. Une commande en lot retourne applied, jobs et rejected ; rejected désigne toute entrée dont l’identifiant (id) manque dans la session.

import_jobs​

Ajoutez les rôles identifiés par des recherches indépendantes et vérifiées. Sweepy ne les confirme pas par défaut.

ParamètreTypeValeur par défautDescription
jobs_jsonChaîne de caractèresObligatoireTableau contenant les enregistrements des cartes à analyser.
validatebooléenfalseExécute chaque URL via le vérificateur de liens avant l’importation.

Retournez les informations de imported et skipped. Les réponses liées aux limites de fréquence d’utilisation ou aux protections anti-bot sont considérées comme non vérifiées.

render_report​

génère les cartes sous forme de fichiers PDF pour la session en cours.

ParamètreTypeValeur par défautDescription
profile_stemChaîne de caractèresnullIdentifiant de profil utilisé pour charger une session enregistrée.
results_dirChaîne de caractères"results"Dossier contenant le résultat par défaut et la session enregistrée.
output_filenameChaîne de caractèresnullChemin vers le fichier PDF spécifique. Ce chemin doit se trouver à l’intérieur du espace de travail. Une valeur vide affiche « {profile_stem}_mcp_{YYYY-MM-DD-HHMMSS}.pdf » dans « results_dir ». Ce nom correspond aux noms des fichiers spécifiés dans la ligne de commande et inclut un marquage « mcp ».
playbookChaîne de caractères""Note de stratégie en texte brut. Les caractères « & » et les crochets angulaires sont rendus en gras (**bold**). Les sauts de ligne sont conservés lors de la conversion. La fonction « Sweepy » enregistre le texte avec la session ; une nouvelle invocation reutilise donc automatiquement le texte déjà sauvegardé. Une valeur vide entraîne la création d’un playbook prédéfini (déterministe).
timestampChaîne de caractèresnullL’heure locale de l’utilisateur pour le nom de fichier par défaut, selon la convention YYYY-MM-DD-HHMMSS ou le format ISO 8601. Cette valeur s’applique uniquement lorsque output_filename est vide.

Retournez les informations de pdf_report, pages, card_count et playbook_saved.

Les profils sont par défaut définis comme report.assessment: "agent", ce qui bloque l’affichage des informations tant qu’au moins une carte contient des mots-clés communs avec un autre profil. Les erreurs sont listées sous les codes unassessed_job_ids et unassessed_titles afin que l’assistant sache comment les gérer. Définissez report.assessment: "keyword" pour autoriser la présence de rapports mixtes, ou utilisez SWEEPY_REQUIRE_JUDGMENTS=1 pour appliquer cette règle à tous les profils, ou encore export_report pour modifier d’autres paramètres associés.

Outils de résultats et d'historique​

get_results​

Lisez les dernières données collectées depuis le disque. Les analyses et les évaluations ne sont jamais réexécutées.

ParamètreTypeValeur par défautDescription
profile_stemChaîne de caractèresnullIdentifiant de profil permettant de filtrer les fichiers de résultat. Omettre cet identifiant pour lire le fichier de résultat le plus récent.
results_dirstring"results"Répertoire contenant les fichiers de résultat.
limitEntier10Nombre de postes de haut niveau à retourner. Limité à la plage de 1 à 100.

La fonction retourne result_file, pdf_report, csv_report, total_roles et top_roles. Chaque rôle contient title, company, location, match_score, match_kind, resume_track, domain, url et playbook.

Les scores étiquetés KEYWORD OVERLAP sont des valeurs déterministes obtenues lors du premier examen des données. Utilisez get_jobs et submit_judgments avant de présenter ces résultats comme correspondances.

export_report​

Reconstruit les fichiers de rapport à partir d’une analyse préexistante (JSON).

ParamètreTypeValeur par défautDescription
json_sourcestringnullChemin vers l’analyse (JSON). Prend la priorité sur profile_stem.
profile_stemstringnullIdentifiant de profil utilisé pour trouver la dernière correspondance (JSON).
results_dirstring"results"Répertoire contenant les fichiers de résultat.
formatsstring[]["pdf"]Formats de sortie : pdf, png, csv ou json.
candidate_namestring"Job Seeker"Nom affiché dans l’en-tête du fichier PDF.
output_dirstringnullRépertoire de sortie. Par défaut, c’est le répertoire contenant le fichier source (JSON).
job_trackingbooléennullAjoutez les colonnes de suivi des tâches à l’exportation en CSV. Laissez-les non définies pour suivre la configuration spécifiée par le profil (export.tracking).

Les valeurs source_file, roles_exported, generated et errors sont retournées. L’objet generated contient les valeurs pdf, pdf_pages, png, csv, csv_rows et json lorsque la demande inclut ces formats. Une demande en format PNG affiche d’abord le fichier PDF. La sortie de la ligne JSON écrit le contenu de la variable {stem}_export.json, sans jamais écraser le fichier source qui lui sert de base.

clear_history​

Efface les données déjà analysées afin que la prochaine analyse puisse les recenser à nouveau.

ParamètreTypeValeur par défautDescription
profile_pathstringnullChemin vers le profil (YAML).
profile_stemChaîne de caractèresnullIdentifiant de profil, par exemple pedro_writer.

La fonction retourne scope, cleared et remaining. Les historiques des analyses sont liés au profil spécifié. Appeler l’outil sans paramètres après une analyse pour effacer les données de ce profil. Dans ce cas, les données sont récupérées depuis le serveur en cours d’exécution ; passez donc profile_path ou profile_stem après un redémarrage.

Outils de conversion de documents​

convert_document​

Convertit .docx, .doc, .txt, .md ou .pdf en format PDF. Les fichiers sources en format PDF ne sont pas modifiés. Les fichiers obsolètes (.doc) nécessitent Microsoft Word.

ParamètreTypeValeur par défautDescription
document_pathChaîne de caractèresObligatoireChemin du fichier à convertir.
pdf_pathChaîne de caractèresnullChemin de sortie. La valeur par défaut est le dossier source.

Retourne pdf_path et source_path.

convert_docx​

Convertit un CV représenté par le symbole DOCX en fichier PDF à l’aide des données fournies par les symboles python-docx et reportlab. Si Microsoft Word est disponible, la conversion se fait automatiquement via cette application. Dans le cas contraire, la méthode docx2pdf est utilisée.

ParamètreTypeValeur par défautDescription
docx_pathchaîne de caractèresObligatoireChemin d'accès au fichier .docx.
pdf_pathChaîne de caractèresnullChemin de sortie. Par défaut, il s’agit du dossier DOCX.

Renvoie pdf_path.

Chemins d'écriture​

Les outils qui génèrent des fichiers de sortie les stockent dans le dossier « Sweepy ». Toute tentative d’écriture en dehors de ce dossier échoue, sauf si la valeur de SWEEPY_ALLOW_EXTERNAL_WRITES est modifiée en 1. Les fichiers sources peuvent être situés sur n’importe quel chemin accessible par le processus.
