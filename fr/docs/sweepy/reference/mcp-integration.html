Lancer Sweepy depuis un assistant IA avec MCP

Un assistant IA peut lancer Sweepy à votre place. Vous décrivez le poste recherché, et l’assistant appelle Sweepy pour vous au lieu de vous demander de taper des commandes de terminal.

Cette connexion utilise le Model Context Protocol (MCP). MCP est un langage partagé qui permet à un assistant IA d’utiliser les outils installés sur votre ordinateur. Sweepy inclut un serveur MCP dans server.py. Il fonctionne sur le transport stdio, donc il parle à votre client en local et n’ouvre aucun port réseau.

Remarque

MCP est optionnel. Sweepy fonctionne entièrement depuis les commandes de terminal sans aucun assistant IA. Le serveur ajoute une couche conversationnelle au-dessus du même moteur. Il ajoute aussi le jugement et l’intelligence du modèle à la notation et au filtrage déterministes que Sweepy exécute déjà.

Avant de vous connecter​

  • Terminez Installation pour que Python et les dépendances de Sweepy soient en place. Les paquets mcp et anyio arrivent avec requirements.txt.
  • Notez le chemin absolu de server.py. Vous collez ce chemin dans la configuration de votre client.
  • Redémarrez votre client IA après avoir modifié sa configuration MCP.

Outils disponibles​

Sweepy expose douze outils à votre assistant. Chacun renvoie une charge utile JSON et déclare des indications de lecture seule, de destruction, d’idempotence et de monde ouvert.

OutilCe qu’il fait
create_profileConstruit, valide et enregistre un profil YAML à partir d’un CV PDF ou DOCX.
run_sweepLance le pipeline en cinq étapes en arrière-plan et stocke des fiches déterministes.
get_sweep_statusAttend un balayage en cours et rapporte sa progression.
get_jobsRenvoie les fiches de la session courante, classées par score.
submit_judgmentsRemplace les champs déterministes d’une fiche par l’évaluation de votre assistant.
import_jobsAjoute des postes que votre assistant a vérifiés ailleurs.
render_reportEffectue le rendu du PDF de fiches depuis la session courante.
get_resultsLit le résultat de balayage le plus récent sur le disque.
export_reportReconstruit des fichiers PDF, PNG, CSV ou JSON depuis un balayage existant.
clear_historyOublie les offres rapportées pour un profil.
convert_documentConvertit un document pris en charge en PDF.
convert_docxConvertit un CV DOCX en PDF.

La référence des outils MCP entre dans le détail. Elle liste chaque paramètre, valeur par défaut, charge utile et indication de comportement.

Choisir les moteurs de recherche d’emploi​

Quand vous omettez sources_config, create_profile active les moteurs intégrés JobSpy et ATS. Il active aussi les moteurs optionnels dont l’installation fonctionne et dont les valeurs par défaut sont valides. L’outil renvoie enabled_engines et engines_not_enabled, pour que vous voyiez quels moteurs tournent et lesquels demandent encore une configuration.

OpenRoles ne cherche que dans les sites d’entreprise que vous listez. Ajoutez des identifiants d’entreprise avant de l’activer. Apify peut entraîner des frais. Activez-le si vous le souhaitez. Sweepy n’installe pas automatiquement les paquets optionnels. Vous n’avez pas besoin de choisir des moteurs pour chaque recherche. Choisissez explicitement seulement quand un moteur exige une configuration, un accord pour un service payant ou une contrainte de recherche.

Passez sources_config quand vous choisissez des moteurs explicitement. Sweepy conserve cette sélection au lieu d’ajouter d’autres moteurs. Ce JSON sélectionne deux moteurs :

{
  "enabled": ["jobspy", "openroles"],
  "openroles": {"companies": ["figma", "stripe"]}
}

Flux d’outils simple et hybride​

Sweepy fonctionne selon deux schémas. Choisissez celui qui correspond à la part de décision que vous voulez confier à l’assistant.

Flux simple. Votre assistant configure et lance tout, et le moteur note chaque poste par chevauchement de mots-clés du CV.

create_profile -> run_sweep -> get_results -> export_report (optional)

Flux hybride avec état. Votre assistant examine chaque fiche et fournit sa propre évaluation avant le rendu du rapport.

run_sweep -> get_jobs -> submit_judgments -> render_report

Un balayage en cours peut continuer après l’expiration du délai d’un client. Quand run_sweep renvoie sweep_status: "running", appelez get_sweep_status avec le job_id renvoyé jusqu’à ce qu’il indique completed. Continuez ensuite avec get_jobs.

astuce

Vous n’avez pas besoin d’un LLM pour obtenir un rapport exploitable. L’outil run_sweep seul produit le PDF complet de fiches à partir des champs déterministes, exactement comme un balayage en terminal.

Chaque fiche affiche l’une de deux étiquettes de score :

  • NN% KEYWORD OVERLAP vient du moteur déterministe. Il compare le texte de votre CV à chaque offre.
  • NN% MATCH vient de votre assistant. Il apparaît quand vous appelez submit_judgments avec une valeur match_pct.

Vérifier et compléter les résultats du balayage​

Traitez chaque résultat de balayage comme un ensemble de départ, puis vérifiez chaque correspondance par rapport à l’offre. Après run_sweep, examinez skipped_sources et signalez les échecs de source. Examinez les postes avec get_jobs, puis comparez chaque offre à votre CV et à vos préférences déclarées avant que votre assistant soumette une évaluation LLM.

Quand votre assistant dispose d’outils web ou de recherche, demandez-lui de vérifier les postes prometteurs sur les pages carrières des employeurs ou sur leur ATS. Il peut aussi chercher des postes pertinents que Sweepy a manqués, ajouter des offres vérifiées non dupliquées via import_jobs, et inclure ces postes dans le rapport avec render_report. Votre assistant ne doit jamais inventer des offres ni combler des détails manquants par des suppositions.

Le vérificateur d’URL de Sweepy conserve certaines URL comme non vérifiées quand un hôte bloque l’accès, limite les requêtes ou dépasse le délai. Un code 403 ou 429 ne prouve pas qu’une offre a expiré. Confirmez l’annonce sur une source employeur accessible quand c’est possible, ou traitez-la comme non vérifiée. Si votre assistant n’a pas d’outil de recherche, ou si des sources restent inaccessibles, signalez que les résultats peuvent être incomplets. Évitez de répéter un balayage avec des paramètres inchangés après une erreur.

Se connecter à Antigravity ou Claude Desktop​

Ajoutez Sweepy au fichier de configuration MCP de votre client, nommé mcp_config.json ou claude_desktop_config.json selon le client :

mcp_config.json
{
  "mcpServers": {
    "sweepy": {
      "command": "python",
      "args": [
        "/path/to/sweepy/server.py"
      ]
    }
  }
}

Remplacez /path/to/sweepy par le chemin absolu de votre dossier Sweepy, puis redémarrez le client. Une fois le serveur enregistré, vous pouvez demander un travail comme ceci :

  • « Crée un profil Sweepy pour Alex qui cherche des postes de Technical Writer en télétravail à New York. Le CV se trouve dans path/to/resume.pdf. »
  • « Lance un balayage avec le profil writer et montre les 5 meilleures correspondances. »
  • « Régénère le PDF du dernier balayage pedro_writer et enregistre-le sur le Bureau. »
  • « Convertis path/to/notes.md en PDF à côté du fichier d’origine. »
Écriture hors du dossier Sweepy

Chaque outil d’écriture reste dans votre dossier Sweepy par défaut. Une demande d’enregistrement sur le Bureau échoue tant que vous ne définissez pas la variable d’environnement SWEEPY_ALLOW_EXTERNAL_WRITES à 1.

Se connecter à VS Code​

VS Code se connecte aux serveurs MCP sans extension supplémentaire :

  1. Ouvrez la palette de commandes et lancez MCP: Add Server.
  2. Choisissez Command (stdio), puis saisissez python comme commande. Ajoutez le chemin absolu de server.py comme argument.
  3. Nommez le serveur sweepy, puis choisissez la destination de la configuration.
  4. Confirmez que les outils Sweepy apparaissent dans le panneau de discussion, puis appelez-les depuis là.

Pour un fichier limité à l’espace de travail, ajoutez .vscode/mcp.json à votre projet. Le format VS Code utilise un objet servers au niveau racine :

.vscode/mcp.json
{
  "servers": {
    "sweepy": {
      "type": "stdio",
      "command": "python",
      "args": [
        "/path/to/sweepy/server.py"
      ]
    }
  }
}

Installer la compétence /sweepy​

Sweepy fournit une compétence /sweepy pour Copilot CLI, Claude Code, Antigravity et d’autres outils en ligne de commande qui lisent les compétences. Copiez le dossier fourni dans le répertoire de compétences de votre outil :

Terminal
cp -r skills/sweepy ~/.claude/skills/sweepy   # adjust to your tool's skills path

Enregistrez le serveur MCP de la section précédente, puis redémarrez votre outil. La compétence documente trois flux principaux :

  • Démarrer une nouvelle extraction en appelant create_profile, puis run_sweep.
  • Consulter les résultats d’une extraction en appelant get_results pour les meilleures correspondances et les playbooks, ou get_jobs pour l’ensemble complet des fiches.
  • Exporter les résultats vers un fichier CSV en appelant export_report avec formats=["csv"].

La compétence couvre aussi le repli pour les outils en ligne de commande sans prise en charge de MCP :

Terminal
sweepy --setup                         # interactive profile wizard
sweepy --profile profiles/your_profile.yaml
sweepy --docx resume.docx              # convert a DOCX resume to PDF
sweepy --convert notes.md              # convert any supported document to PDF

Tout configurer avec une seule invite​

Copiez cette invite et collez-la dans n’importe quelle session IA en ligne de commande ou discussion d’IDE :

Set up Sweepy on this machine. Complete these steps in order:

1. Clone or download the Sweepy repository.
2. Run `pip install -r requirements.txt` in the repository root.
3. Register `server.py` in the MCP configuration as a stdio server. Use the command `python` and args pointing at `server.py`.
4. Copy the `skills/sweepy` folder into the CLI's skills directory.

Approfondir les schémas d’invite​

Le fichier AGENTS.md du dépôt documente l’enchaînement des outils, les conseils par outil et les schémas d’invite. Lisez-le si vous voulez une automatisation plus poussée que les flux de cette page.
