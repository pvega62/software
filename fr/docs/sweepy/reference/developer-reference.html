Référence du développeur Sweepy

Sweepy s'exécute sous la forme d'un petit projet Python doté d'un moteur plat. Cette page établit une correspondance entre chaque étape du pipeline et le module qui l'exécute, afin que vous sachiez où apporter une modification.

Public visé​

Consultez cette page si vous prévoyez de modifier le code de Sweepy ou d'ajouter une source d'offres d'emploi. Les relecteurs peuvent s’en servir pour orienter une pull request. Elle ne traite que des aspects internes : modules, dépendances et versions de Python.

Ignorez cette page si vous souhaitez exécuter des balayages. Commencez par Installation.

Étapes du pipeline et modules​

swee.py exécute cinq étapes dans l’ordre. Le terminal affiche chaque étape sous la forme [1/5] à [5/5].

ÉtapeModuleFonction
1. Chargement du profilengine/config.pyCharge et valide votre profil YAML. L’assistant de ce même module en crée un.
2. Découverte des rôlesengine/discovery.pyInterroge les flux d’agrégateurs via python-jobspy et classe chaque plateforme.
2. Découverte des rôlesengine/sources/Récupère les offres d’emploi de Greenhouse, Ashby, Lever, Workable et Built In NYC à partir de points de terminaison publics.
2. Déduplicationswee.pyFusionne les résultats des agrégateurs et des sources en une seule fiche par lien d’offre d’emploi.
3. Validation des URLengine/validator.pyVérifie chaque lien à l’aide d’une requête HTTP HEAD et d’une requête GET de secours. Il élimine les offres d’emploi obsolètes.
4. Notation par rapport au CVengine/scorer.pyExtrait les termes des offres d’emploi et des CV, puis évalue le chevauchement entre les exigences et les mots-clés. Il marque les offres d’emploi qui exigent des réponses écrites.
5. Acheminement des parcours de CVengine/enrich.pySélectionne le parcours présentant le plus grand chevauchement de termes et attribue la couleur de badge correspondante.
5. Enrichissement des fichesengine/enrich.pyGénère les résumés des fiches, les lignes de rémunération et les conseils personnalisés.
5. Fichier PDF de carte par défautengine/report.pyGénère la mise en page des cartes, six cartes par page par défaut, et renvoie le nombre de pages.
5. Fichier PDF de tableau classiqueengine/pdf_builder.pyGénère la mise en page du tableau lorsque votre profil définit report.style: legacy.
5. Exportations de donnéesengine/exporter.pyÉcrit des fichiers CSV et JSON. Il rasterise les images de page au format PNG sur demande.
5. Suivi des tâchesengine/tracking.pyAjoute les colonnes de suivi et lit les exportations précédentes afin que les valeurs que vous saisissez soient conservées.

engine/session.py contient le magasin de cartes pour le flux MCP (Model Context Protocol) avec état. Il conserve les cartes dans une table (map) thread-safe indexée par un hachage stable de chaque lien de tâche.

Où apporter une modification​

Vous souhaitez modifierCommencez par
Une source de tâche ou son point de terminaisonengine/sources/, ainsi qu’une liste de graines dans data/sources/
Comment les correspondances sont notéesengine/scorer.py
Ce qu’affiche une ficheengine/enrich.py, puis engine/report.py
Comment les liens sont vérifiésengine/validator.py
Un indicateur de ligne de commandeswee.py
Un outil MCPserver.py

server.py importe les mêmes modules du moteur que l’outil en ligne de commande. Testez le chemin MCP après toute modification du moteur, car une correction affecte les deux points d’entrée.

Référence des modules​

Points d’entrée​

ModuleObjectif
swee.pyOrchestrateur principal et point d’entrée en ligne de commande argparse pour le pipeline en cinq étapes.
server.pyServeur Model Context Protocol (stdio) qui expose les outils du moteur aux assistants IA. La fonction get_jobs renvoie le texte du CV analysé afin que l’assistant évalue le document lui-même, et non la liste de mots-clés du profil.

Modules du moteur​

ModuleObjectif
engine/config.pyAssistant interactif, chargement et validation de fichiers YAML.
engine/discovery.pyOrchestration des scrapers pour python-jobspy et les sources déterministes, détection des systèmes de suivi des candidats (ATS) et déduplication.
engine/validator.pyVérification de la disponibilité des liens avec détection des erreurs 404 logiques. Les liens non vérifiables restent dans le cycle d’exécution.
engine/scorer.pyExtraction des termes du CV, calcul du pourcentage de correspondance, balisage et notation par piste.
engine/enrich.pyEnrichissement des fiches pour les résumés, la rémunération, l’acheminement vers les pistes et les conseils personnalisés.
engine/session.pyStockage des fiches thread-safe avec des identifiants stables pour le flux MCP avec état.
engine/report.pyPDF par défaut avec mise en page des fiches.
engine/pdf_builder.pyPDF au format de mise en page « tableau » hérité pour report.style: legacy.
engine/exporter.pyExportations au format CSV et JSON, ainsi que la rastérisation au format PNG des PDF de rapport.
engine/tracking.pySuivi des colonnes et lecture des données reportées des exportations précédentes.
engine/docx.pyConversion DOCX vers PDF avec python-docx et reportlab, ainsi qu’une solution de secours pour Microsoft Word.
engine/documents.pyDistribution des documents pour l’option --convert et le convertisseur MCP, prenant en charge les formats DOCX, DOC, texte, Markdown et PDF.
engine/logging.pyJournaux de débogage activables dans le répertoire logs/.
engine/cache.pyCache de scraping SQLite indexé par requête et ensemble de moteurs, avec une durée de vie d’une heure.
engine/circuit_breaker.pyCompte les erreurs source consécutives et met les appels en pause pendant un délai de refroidissement.
engine/engine_defaults.pyListes de sites par défaut et paramètres de moteur partagés, sans importation pour éviter les boucles.
engine/engines.pyRegistre des adaptateurs et programme d’installation pour les moteurs optionnels hirehunt, openroles, apify et jobdrop.
engine/history.pyEnregistrement persistant des offres d’emploi déjà signalées. Un balayage quotidien ne signale que les nouvelles offres.
engine/normalize.pyNormalise les lignes brutes du moteur pour les adapter aux colonnes partagées des offres d’emploi.
engine/salary.pyExtraction des informations salariales à partir du texte de l’offre d’emploi lorsqu’un site omet d’indiquer une rémunération structurée.
engine/sweep_config.pyApplique les valeurs par défaut partagées du moteur aux paramètres de profil.
engine/updater.pyVérification des mises à jour via Git et réinstallation des dépendances pour le checkout.

engine/sources/_common.pyAides partagées pour les en-têtes HTTP, le préfiltrage des titres et la conversion HTML-texte.
engine/sources/greenhouse.pyRécupérateur d’offres d’emploi Greenhouse.

Adaptateurs de moteur​

ModuleObjectif

engine/adapters/jobspy_adapter.pyAdaptateur d’agrégateur python-jobspy pour LinkedIn, Indeed, Glassdoor et ZipRecruiter.

Données, scripts et tests​

CheminObjectif
data/sources/*.txtListes de données de départ pour les tableaux d’offres, les entreprises, les organisations et les catégories.
scripts/make_sample.pyGénérateur du rapport d’exemple stocké dans docs/.
tests/Suite pytest comprenant un fichier par domaine : adaptateurs, configuration, documents, docx, moteurs, enrichissement, historique, journalisation et rapports. D’autres fichiers couvrent les salaires, le système de notation, le serveur, les sessions, les sources, swee, le suivi, la mise à jour et la validation.
Remarque

Ajoutez un fichier de test dédié lorsque vous modifiez discovery.py, exporter.py ou pdf_builder.py. Placez le fichier dans tests/.

Dépendances​

Les paquets d'exécution proviennent de requirements.txt. Les versions ci-dessous correspondent à ce fichier.

PaquetVersionFonction dans Sweepy
reportlab5.0.1Génère le rapport PDF mis en forme avec des liens cliquables.
pymupdf1.28.2Extrait le texte des CV au format PDF et rastérise les exportations au format PNG.
python-docx1.2.0Lit les CV au format .docx et reconstitue le texte DOCX sous forme de PDF sans Word.
requests2.32.5Accède aux points de terminaison ATS et vérifie que chaque lien vers une offre d’emploi renvoie une réponse valide.
beautifulsoup44.15.0Analyse le code HTML provenant des sources Greenhouse, Lever, Workable et Built In NYC.
pyyaml6.0.3Lit et écrit des profils YAML.
questionary2.1.1Gère les questions de l'assistant interactif.
prompt-toolkit3.0.53Gère la saisie de texte interactive de l'assistant.
python-jobspy1.2.0Récupère des données sur LinkedIn, Indeed, Glassdoor et ZipRecruiter sans identifiants API.
pandas2.2.3Structure les offres d'emploi et génère les exportations au format CSV et JSON.
mcp1.30.0Exécute le serveur Model Context Protocol.
anyio4.12.1Gère le transport asynchrone MCP.

Le fichier requirements.txt répertorie également un paquet facultatif. Décommentez docx2pdf lorsque Word doit générer le PDF.

  • docx2pdf (0.5.2, facultatif) convertit les fichiers DOCX en PDF via Microsoft Word sous Windows. Sweepy l'appelle dès que Microsoft Word est installé sur la machine.
Remarque

mcp reste volontairement en version 1.x. Le SDK 2.x ne prend en charge que la version du protocole datée du 28 juillet 2026. Un client qui interroge server/discover puis se rabat sur la procédure d’établissement de connexion initialize obtient une erreur -32022. VS Code Copilot suit cette procédure de secours.

pandas reste volontairement en version 2.x. Pandas 3.x nécessite Python 3.11 ou une version plus récente, et la matrice CI teste toujours Python 3.10.

Paquets de développement (requirements-dev.txt)​

PaquetVersionFonction
pytest9.1.1Exécute la suite de tests dans tests/.
pytest-cov7.1.0Génère un rapport de couverture pour swee.py, server.py et engine/scorer.py.
ruff0.17.0Effectue une analyse syntaxique du code et organise les importations.
tomli2.2.1Fournit tomllib pour les exécutions de tests sous Python 3.10.
Terminal
pip install -r requirements.txt
pip install -r requirements-dev.txt
ruff check .
pytest -q

Exigences et versions Python prises en charge​

ÉlémentDétails
Version minimale de PythonSweepy nécessite Python 3.10 ou une version plus récente et cible la syntaxe 3.10 dans chaque module.
Plage testéeLe workflow CI dans .github/workflows/ci.yml s'exécute sous Python 3.10, 3.11 et 3.12 sur Ubuntu.
Cible du lintpyproject.toml définit target-version = "py310" pour ruff. Une construction « newer-only » fait échouer la tâche de lint.
Longueur de ligneRuff impose une limite de 100 caractères par ligne et ignore E501.
Étapes de CILa tâche installe les deux fichiers de dépendances et exécute ruff check . avant pytest.
Remarque

pyproject.toml déclare requires-python = ">=3.10", ce qui fait que pip refuse un interpréteur plus ancien au moment de l’installation. La matrice CI et la cible ruff définissent la plage testée. Python 3.13 fonctionne dans la pratique, mais reste en dehors de cette plage.

Python 3.13

Le paquet pymupdf peut être compilé à partir du code source lorsqu’il n’existe pas de wheel précompilé. Installez les Microsoft C++ Build Tools et sélectionnez la charge de travail « Développement sur bureau avec C++ » avant d’installer les dépendances.

Structure du référentiel​

Structure du référentiel
swee.py Point d’entrée CLI et orchestrateur de balayage
server.py Serveur MCP via stdio
engine/ Modules de pipeline
engine/sources/ Récupérateurs ATS déterministes
engine/adapters/     Agrégateur et adaptateurs de moteur optionnels
data/sources/ Listes de données de départ pour chaque outil de collecte
profiles/ Profils de recherche au format YAML
results/ Fichiers PDF, CSV, JSON et PNG générés
logs/ Journaux de débogage activables
styles/ Règles de style Vale pour la documentation
tests/ Suite de tests pytest

Lorsque vous modifiez la signature d’un outil dans server.py, mettez à jour la référence des outils MCP dans le même commit.
