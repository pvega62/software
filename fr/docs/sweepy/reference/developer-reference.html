Référence pour les développeurs de Sweepy

Sweepy fonctionne comme un petit projet Python doté d’un moteur simple. Cette page met en correspondance chaque étape du pipeline avec le module qui l’exécute, afin que vous sachiez où effectuer les modifications nécessaires.

Public visé​

Lisez cette page si vous prévoyez de modifier le code de Sweepy ou d’ajouter une nouvelle source de tâches. Les réviseurs peuvent s’en servir pour se familiariser avec les fonctionnalités du système. Cette page ne couvre que les aspects internes : modules, dépendances et versions de Python.

astuce

Sautez cette page si vous souhaitez simplement exécuter des tâches de nettoyage (sweeps). Commencez par la section Installation.

Étapes et modules du pipeline​

swee.py exécute cinq étapes dans l’ordre. Le terminal affiche chaque étape sous la forme de [1/5] à [5/5].

ÉtapeModuleCe qu’il fait
1. Chargement du profilengine/config.pyCharge et valide votre profil. L’assistant présent dans le même module s’occupe de l’établissement de ce profil.
2. Découverte des rôlesengine/discovery.pyLes flux d’agrégation de requêtes sont analysés par python-jobspy et chaque plateforme est classée en fonction de ses caractéristiques.
2. Découverte des offres d’emploiengine/sources/Récupère les informations concernant les offres Greenhouse, Ashby, Lever, Workable et Built In NYC depuis des points de terminaison publics.
2. Déduplication des donnéesswee.pyFusionne les résultats provenant de l’agrégateur et de la source en une seule carte par lien d’offre d’emploi.
3. Validation des URLengine/validator.pyVérifie chaque lien à l'aide d'une requête HTTP HEAD et d'une requête GET de secours. Il supprime les publications obsolètes.
4. Évaluation des offres en fonction du CVengine/scorer.pyExtrait les termes présents dans l’annonce et le CV, puis évalue leur correspondance en termes de besoins et de mots-clés. Marque les annonces qui nécessitent des réponses écrites.
5. Attribution d’une couleur de badge en fonction des correspondancesengine/enrich.pyChoisi le parcours d’emploi présentant le plus de correspondances entre les termes et attribue la couleur de badge appropriée.
5. enrichissement des cartes d’informationengine/enrich.pyCrée des résumés pour chaque carte, ainsi que des informations sur la rémunération et des conseils personnalisés.
5. Format PDF par défautengine/report.pyAffiche par défaut six cartes par page et retourne le nombre total de pages.
Tableau PDF obsolèteengine/pdf_builder.pyAffiche le formatage du tableau lorsque votre profil est configuré comme indiqué (report.style: legacy).
5. Exportation des donnéesengine/exporter.pyCrée des fichiers CSV et JSON. Rasterise les images des pages sous format PNG sur demande.
5. Suivi des offres d’emploiengine/tracking.pyAjoute des colonnes permettant de suivre l’avancement des candidatures et récupère les données exportées précédemment.

engine/session.py Stocke les informations des cartes dans un système sécurisé (Model Context Protocol – MCP). Les cartes sont mémorisées dans un dictionnaire indexé par un hash unique de chaque lien d’offre d’emploi.

Où effectuer une modification​

Vous souhaitez modifierCommencer par
Une source d’offres d’emploi ou son point de terminaisonengine/sources/, ainsi qu’une liste de références dans data/sources/
Comment les matchs sont notésengine/scorer.py
Ce que montre la carteengine/enrich.py, puis engine/report.py
Paramètre de ligne de commandeengine/validator.py
Un argument de ligne de commandeswee.py
Un outil MCPserver.py
astuce

server.py importe les mêmes modules moteur que l’outil ligne de commande. Vérifiez le chemin MCP après tout changement de moteur, car une correction peut affecter les deux points d’entrée.

Référence des modules​

Points d'entrée​

ModulePurpose
swee.pyPrincipal orchestrateur et point d’entrée en ligne de commande (command-line) pour le pipeline à cinq étapes, représenté par la commande argparse.
server.pyLe protocole Model Context Protocol (stdio) permet aux serveurs d’exposer les outils du moteur de traitement de données aux assistants intelligents. La fonction get_jobs retourne le texte du CV analysé, afin que l’assistant puisse évaluer le document, et non simplement la liste des mots-clés du profil de la personne concernée.

Modules du moteur​

ModulePurpose
engine/config.pyGuide interactif, ainsi que fonctionnalités de chargement et de validation des données.
engine/discovery.pyOrchestration des outils de scraping pour la récupération des données de python-jobspy, ainsi que pour la détection des systèmes de suivi des candidats (Applicant Tracking Systems – ATS) et l’élimination des doublons.
engine/validator.pyVérification de la disponibilité des liens, avec détection des erreurs 404. Les liens non vérifiables sont conservés lors de l’exécution du processus.
engine/scorer.pyExtraction des informations du CV, correspondance par pourcentage, étiquetage des éléments, et notation de chaque section du CV.
engine/enrich.pyEnrichissement des informations présentées dans les cartes visuelles, calcul des compensations, routage des données vers les bonnes sections, et fourniture de conseils personnalisés.
engine/session.pyStockage des données dans un format sécurisé, permettant une gestion fiable des flux de données dynamiques (MCP – Managed Content Process).
engine/report.pyFormat PDF par défaut pour l'affichage des informations dans les cartes visuelles.
engine/pdf_builder.pyPDF de mise en page de tableur obsolète pour report.style: legacy.
engine/exporter.pyExportation des données sous formats CSV et JSON, ainsi que conversion des rapports PDF en images bitmap (PNG).
engine/tracking.pyColonnes de suivi et données issues des exportations précédentes.
engine/docx.pyConversion en PDF avec les fichiers python-docx et reportlab, avec une option de repli vers Microsoft Word.
engine/documents.pyEnvoi des documents à l’outil --convert ainsi qu’au convertisseur MCP, couvrant les formats DOC, texte, Markdown et PDF.
engine/logging.pyJournalisation des informations de débogage pour logs/.
engine/cache.pyCache de données extraites de la base SQLite, organisée par requête et paramètres de l’engine, avec une durée de validité d’une heure.
engine/circuit_breaker.pyComptage des erreurs successives et des interruptions des opérations pendant la période de refroidissement (cooldown).
engine/engine_defaults.pyListes de sites et paramètres d’engine partagés, maintenus sans nécessité d’importation pour éviter les boucles de traitement.
engine/engines.pyRegistre d’adaptateurs et outils d’installation pour les engines optionnels tels que hirehunt, openroles, apify et jobdrop.
engine/history.pyEnregistrement permanent des annonces déjà signalées ; un balayage quotidien ne révèle que les annonces nouvelles.
engine/normalize.pyNormalisation des données brutes provenant des engines dans les colonnes de publication partagées.
engine/salary.pyExtraction des informations salariales du texte des annonces lorsque celles-ci ne sont pas structurées.
engine/sweep_config.pyApplication des paramètres par défaut de l’engine aux réglages des profils utilisateurs.
engine/updater.pyVérification des mises à jour basées sur Git et réinstallation des dépendances pour le processus de récupération des données („checkout“).

engine/sources/_common.pyFonctions d’aide communes pour les en-têtes des données, préfiltrage des titres, et conversion des données en texte depuis HTML.
engine/sources/greenhouse.pyExtracteur d’offres d’emploi depuis le site „Greenhouse“.
engine/sources/ashby.pyExtracteur d’offres d’emploi depuis le site „Ashby“.
engine/sources/lever.pyExtracteur d’annonces depuis le site „Lever“.
engine/sources/workable.pyExtracteur d’API pour les widgets fonctionnels.

Adaptateurs de moteur​

ModulePurpose

engine/adapters/base.pyLa classe de base ScraperAdapter, le fichier d’en-tête commun User-Agent, et les outils pour la gestion de la forme du résultat.
engine/adapters/jobspy_adapter.pypython-jobspy Adaptateur d’agrégateurs de données pour LinkedIn, Indeed, Glassdoor et ZipRecruiter.
engine/adapters/ats_adapter.pyAdapter les mécanismes de récupération des données (fetchers) utilisés dans engine/sources/ par rapport à ceux basés sur des approches déterministes.
engine/adapters/hirehunt_adapter.pyUn adaptateur optionnel pour le moteur Hirehunt.
engine/adapters/openroles_adapter.pyUn adaptateur optionnel pour le moteur Openroles.

engine/adapters/jobdrop_adapter.pyUn adaptateur optionnel pour le moteur Jobdrop.

Données, scripts et tests​

PathPurpose
data/sources/*.txtDes listes de référence pour les panneaux d’information, les entreprises, les organisations et les catégories.
scripts/make_sample.pyUn outil permettant de créer les rapports d’exemple stockés dans docs/.
tests/Suite pytest comprenant un fichier par domaine : adaptateurs, configuration, documents, docx, moteurs, enrichissement, historique, journalisation et rapport. D'autres fichiers concernent les salaires, le système de notation, le serveur, les sessions, les sources, swee, le suivi, la mise à jour et la validation.
Remarque

Ajoutez un fichier de test spécifique lorsque vous modifiez les éléments indiqués par discovery.py, exporter.py ou pdf_builder.py. Placez ce fichier dans la section tests/.

Exigences et versions Python prises en charge​

ÉlémentDétails
Version minimale de PythonSweepy nécessite Python 3.10 ou une version ultérieure ; tous les modules utilisent la syntaxe de Python 3.10.
Plage de valeurs testéesLe flux de travail de CI présenté dans .github/workflows/ci.yml exécute Python 3.10, 3.11 et 3.12 sur Ubuntu.
Cible de vérification du code (Lint)pyproject.toml définit les règles de validation (target-version = "py310"). Une construction réservée aux versions plus récentes échoue à la vérification du code.
Longueur des lignesLe système ruff impose une limite de 100 caractères par ligne et ignore les spécifications de E501.
CI stepsL’application installe les deux fichiers requis et exécute ruff check . avant d’exécuter pytest.
Remarque

pyproject.toml déclare l’utilisation de requires-python = ">=3.10" ; par conséquent, pip refuse tout interpréteur plus ancien lors de l’installation. La matrice de contrôle continu (CI – Continuous Integration) et le critère de testation définissent la plage de versions valides. Python 3.13 fonctionne bien en pratique, mais reste en dehors de cette plage.

Python 3.13

Le paquet pymupdf peut être compilé à partir du code source lorsqu’aucun fichier pré-compilé n’est disponible. Installez les Outils de compilation C++ de Microsoft et sélectionnez la tâche de travail “Développement desktop avec C++” avant d’installer les dépendances.

Structure du dépôt​

Repository layout
swee.py              CLI entry point and sweep orchestrator
server.py            MCP server over stdio
engine/              Pipeline modules
engine/sources/      Deterministic ATS fetchers
engine/adapters/     Aggregator and optional engine adapters
data/sources/        Seed lists for each fetcher
profiles/            YAML search profiles
results/             Generated PDF, CSV, JSON, and PNG files
logs/                Opt-in debug logs
styles/              Vale style rules for the docs
tests/               pytest suite

Lorsque vous modifiez une spécification d’outil dans server.py, mettez à jour la référence de cet outil (MCP tool reference) dans le même commit.
