Introduction

Bienvenue dans mon portefeuille d’écriture technique​

Ce site rassemble des exemples de documentation logicielle issus de mon portefeuille d’écriture technique. Docusaurus génère chaque page à partir de fichiers sources en Markdown et MDX. Ce recueil couvre des guides pour les développeurs, des références aux API basées sur des contrats, ainsi que de la documentation de produits. Chaque exemple montre également le processus de création de ces documents.

Navigation dans le portefeuille​

Parcourez les exemples par type de document et domaine :

Guides pour les développeurs et les systèmes​

  • Installer et appliquer un thème à Google Chrome. Une étape par étape pour personnaliser votre navigateur, avec des onglets interactifs et un layout adaptatif.
  • Processus de travail entre Microsoft Word et GitHub Wiki avec Writage. Un guide pour écrire du Markdown dans Word, puis mettre en ligne les modifications via GitHub Desktop.
  • Utiliser Postman pour se connecter à l’API de Stripe. Un guide pour authentifier les utilisateurs et effectuer des demandes API avec Postman.
  • Créer un serveur de simulation (mock server) avec Postman. Un tutoriel pratique pour configurer des serveurs de simulation afin de tester des intégrations webhook et des schémas API.
  • L’application permet d’envoyer les journaux de trace des applications cloud dans un pipeline. Une procédure opérationnelle pour l’ingestion et le filtrage des données de télémesure provenant des applications cloud.
  • Comment récupérer des données d’objet. Un tutoriel expliquant comment effectuer des requêtes de lecture à l’aide du SDK Sui TypeScript.
  • Utilisation de l’opération d’écriture pour envoyer une transaction. Un guide pour les développeurs sur la signature et la diffusion de transactions programmables.

Documentation sur Sweepy pour la recherche d’emploi​

Sweepy parcourt les systèmes de suivi des candidats et les plateformes d’offres d’emploi, puis évalue chaque annonce en fonction du CV. Cet outil Python est open source et inclut un ensemble de documents de 14 pages couvrant l’installation, la configuration des profils ainsi que l’exportation des données sous format PDF ou CSV. Il décrit également un serveur utilisant le protocole Model Context Protocol (MCP) pour gérer les recherches depuis un assistant intelligent.

Débuter​

  • Découvrez Sweepy. Explication de la fonctionnalité de Sweepy, des cinq étapes du processus de recherche et de la manière dont l’outil évalue les CV.
  • Installer Sweepy. Guide pas à pas pour installer Sweepy sur Windows, macOS et Linux, en utilisant Python et Git.
  • Configurer Sweepy. Création d’un profil de recherche à l’aide de l’assistant de configuration ou d’un fichier YAML.
  • Exécuter votre première recherche. Guide pour effectuer votre première recherche, de la création du profil à la visualisation des résultats.

Lire les résultats​

  • Comprendre vos résultats. Explication de la structure des fichiers PDF, des pourcentages de correspondance, des indicateurs liés aux applications et des colonnes de suivi dans les fichiers CSV.
  • Résumés et résultats de comparaison : Présente la mise en forme des résumés pour le logiciel de traitement, ainsi que le processus de calcul du pourcentage de correspondance entre les données du résumé et celles des offres d’emploi.
  • Comment Sweepy évalue un résumé : Explique le système de comparaison des mots utilisés dans le résumé et ce que le score obtenu ne peut pas mesurer.

Références et intégrations​

  • Référence des commandes et des paramètres de configuration de Sweepy : Liste toutes les commandes disponibles, les paramètres de configuration, ainsi que les sources d’offres d’emploi prises en charge par le logiciel.
  • Intégration de Sweepy avec MCP : Permet de connecter le serveur intégré de Sweepy à des outils tels qu’Antigravity, Claude Desktop ou VS Code.
  • Référence des outils utilisés avec Sweepy MCP : Documente les treize outils compatibles, leurs paramètres et les données qu’ils retournent.

L’index de la documentation de Sweepy rassemble toutes les pages de documentation, y compris les instructions d’installation, des notes pour les développeurs, ainsi qu’un étude de cas sur l’expérience utilisateur.

Références API​

  • API de Stripe : Documentation détaillée sur l’infrastructure de paiement ; une page pour chaque point de terminaison API, avec des sections distinctes sur les concepts et les démarrages rapides.
    • APIs de gestion du solde
    • APIs relatives aux intentions de paiement
    • APIs de remboursement
  • API Blüdhaven Pets : Gestion des animaux de compagnie d’entreprise, licences municipales et inventaire de vente au détail, documentée selon les spécifications d’un contrat OpenAPI 3.1.
    • Référence interactive de l’API
    • Modèle de domaine
    • Authentification et autorisations
    • Erreurs et détails des problèmes
    • Pagination
    • Limites de fréquentation et mécanismes de redémarrage automatique
    • Gestion des versions et politique de modification
    • Webhooks et signatures
    • Demandes de test
    • Dépannage
    • Retention des animaux en attente d’adoption et gestion de la concurrence
    • Frais et remboursements
    • Conformité et licences
  • API d’ingestion des logs de Datadog : Référence pour l’envoi de données de télémesure par lots.
  • Référence du SDK Sui TypeScript :
    • SuiClient.getObject
    • SuiClient.multiGetObjects
    • SuiClient.getOwnedObjects

Documentation architecturale et conceptuelle​

  • Flux d’événements et pipelines d’observabilité : Aperçu architectural du traitement des données en flux, de l’acheminement des requêtes et de la transformation des informations.
  • Concepts de l’API Stripe : La manière dont l’argent s’écoule via Stripe, ainsi que le comportement commun de chaque point de terminaison (endpoint) : authentification, idempotence, erreurs, pagination, gestion des versions et mode de test.
  • Guide de démarrage rapide pour l’API Stripe : Des guides pas à pas qui permettent d’accepter des paiements par carte et d’exécuter l’ordre depuis un webhook vérifié.
  • Flux d’événements et pipelines d’observabilité : Aperçu architectural du traitement des flux de données, de l’acheminement des données aux périphériques (edge routing) et de la transformation des données.
  • Observabilité parallèle pour le cloud et l’IA : Guide architectural comparant les modèles de routage des journaux d’activité pour les systèmes d’entreprise.
  • Le SuiClient : Explication du fonctionnement des clients RPC distribués pour la gestion des requêtes d’état.

Messages de commit et demandes de pull​

  • Correction des problèmes liés aux transferts de données via le protocole protobuf pour les arrays organisés selon un ordre spécifique : Message de commit et description de la demande de pull issues d’un exercice écrit, avec le patch fourni pour contextualiser les modifications.
  • Rendre ak.mean différentiable sous JAX. Message de commit et description de la demande de pull (pull request) provenant d’un exercice d’écriture à réaliser à domicile ; le patch fourni est reproduit pour contextualiser.

Cas d’étude​

  • Conception d’Artie, un assistant de documentation basé sur l’IA : Étude d’ingénierie analysant les aspects liés à la conception des prompts, à la sécurité des modèles d’apprentissage automatique (LLM) et à l’architecture de récupération d’informations (RAG).
  • Quand 92 % signifie des choses différentes : Étude d’UX concernant l’utilisation des étiquettes de scores, des lignes d’état et des indications dans l’interface de terminal de Sweepy.

Pour consulter les sources Markdown brutes de ces documents, consultez le répertoire GitHub.

Processus de création de documentation en tant que code​

  • Rédaction en Markdown et MDX à l’aide de VS Code et d’Antigravity.
  • Vérification de la qualité du texte et de son style à l’aide de Vale.
  • Internationalisation et traduction à l’aide de DeepL et Lara.
  • Diagrammation de l’architecture du système à l’aide de Mermaid.
  • Rédaction de la documentation produit pour un outil en ligne de commande et son serveur MCP à chaque version.
  • Gestion du contrôle de version et révision collaborative du code avec Git et GitHub.
  • Exploration et validation des API avec Postman et Swagger/OpenAPI.
  • Édition des contrats OpenAPI 3.1 à l’aide de schémas partagés et de la technologie Scalar.
  • Déploiement continu avec Docusaurus.

Stack technique​

  • Docusaurus. Génère des sites statiques, des barres de navigation et des versions localisées.
  • VS Code : C’est l’outil principal pour la rédaction de documents Markdown et MDX.
  • Postman. Vérifie la validité des points de terminaison d’API et génère des exemples de demandes/réponses.
  • OpenAPI 3.1 et Scalar : Définit le contrat de Blüdhaven Pets et le présente sous forme de référence interactive à trois panneaux.
  • Vale. Vérifie la qualité de la prose technique pour respecter les directives de la documentation des développeurs de Google.
  • Git et GitHub. Suivi des modifications effectuées sur les branches et déploiement du site.
  • Mermaid. Affiche des diagrammes de flux et des schémas de pipelines de données.
  • Python et MCP. Exécute l’engine Sweepy ainsi que le serveur d’outils qui le relie aux assistants intelligents.
  • DeepL et Lara. Automatise la traduction de la documentation dans d’autres langues.
