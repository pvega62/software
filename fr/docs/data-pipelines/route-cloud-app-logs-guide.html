Acheminer les logs des applications cloud vers un pipeline

Ce guide envoie un log JSON depuis une application cloud vers l'API d'ingestion de logs Datadog. Vous suivez ensuite l'événement dans Log Explorer et vous l'acheminez vers une destination.

Vérifier l'ingestion avant le routage​

Vérifiez d'abord le chemin d'ingestion. Créez des règles d'analyse ou acheminez les données vers des outils coûteux de gestion des informations et des événements de sécurité (SIEM) après avoir confirmé que les événements arrivent. Ce workflow confirme trois points :

  1. Votre clé API Datadog s'authentifie.
  2. L'API d'ingestion de logs accepte votre tableau JSON.
  3. L'événement apparaît dans Log Explorer.

Avant de commencer​

Vérifiez que vous disposez de :

  • Une clé API Datadog avec les autorisations d'ingestion de logs. Trouvez-la dans Paramètres de l'organisation → Clés API.
  • L'adresse de votre site Datadog, par exemple datadoghq.com ou ap2.datadoghq.com.
  • Un accès au terminal pour exécuter curl, ou Postman.

1. Créer ou sélectionner un index​

  1. Accédez à Logs > Configuration > Index.
  2. Sélectionnez Ajouter un index, ou sélectionnez l'index qui stocke les logs de votre application cloud.
  3. Nommez l'index app-logs.
  4. Définissez la période de conservation exigée par votre politique de conformité.

2. Créer un exemple d'événement de log​

Simulez un log d'application cloud en enregistrant le tableau suivant sous le nom app-log.json.

app-log.json
[
  {
    "message": "Transaction failed: Gateway timeout",
    "ddsource": "java",
    "ddtags": "env:prod,region:us-east-1",
    "hostname": "payments-host-01",
    "service": "payment-gateway",
    "status": "ERROR",
    "timestamp": "2025-11-15T08:30:00Z",
    "transaction_id": "txn_998877",
    "customer_id": "cus_554433"
  }
]
Remarque

Utilisez le format ISO 8601 (Organisation internationale de normalisation) en temps universel coordonné (UTC) pour timestamp. Datadog aligne la chronologie des logs dans Log Explorer sur cette valeur. Un log sans horodatage utilise l'heure d'ingestion.

3. Envoyer l'événement de log​

Utilisez curl pour envoyer le log comme le fait l'application.

cURL
export DD_API_KEY="your_datadog_api_key_here"
export DD_SITE="datadoghq.com"

curl -X POST "https://http-intake.logs.$DD_SITE/api/v2/logs" \
  -H "DD-API-KEY: $DD_API_KEY" \
  -H "Content-Type: application/json" \
  -d @app-log.json

Réponse attendue​

Response
{}

Une réponse 202 Accepted avec un corps JSON vide signifie que l'API d'ingestion de logs a accepté la charge utile.

4. Vérifier votre log dans Log Explorer​

  1. Ouvrez Log Explorer.
  2. Filtrez sur service:payment-gateway.
  3. Sélectionnez Live Tail.

L'événement apparaît en quelques secondes :

Live tail output
[ERROR] 2025-11-15T08:30:00Z service=payment-gateway msg="Transaction failed..."

5. Acheminer les logs vers une destination​

Créez un pipeline qui correspond aux événements d'erreur :

  1. Accédez à Logs > Configuration > Pipelines.
  2. Sélectionnez Nouveau pipeline.
  3. Définissez la requête de filtre sur status:ERROR.
  4. Nommez le pipeline error-routing.
  5. Sélectionnez Enregistrer.

Renvoyez la même requête. Le pipeline correspond à l'événement, vous pouvez donc agir dessus.

  • Archivez les logs correspondants en ouvrant Logs > Configuration > Archives et en créant une archive s3-archive qui cible votre compartiment S3.
  • Alertez sur les logs correspondants en créant un moniteur de logs avec la requête status:ERROR, puis acheminez les notifications vers un canal Slack.

6. Améliorer le pipeline​

Ajoutez des processeurs au pipeline une fois le flux fonctionnel :

  • Remapper déplace customer_id vers un attribut qui se prête proprement aux facettes et au filtrage.
  • Grok Parser extrait les codes d'erreur ou les ID de transaction des chaînes message brutes.
  • Lookup Processor ajoute une balise team_owner à partir du nom service.
  • Sensitive Data Scanner masque customer_id lorsque ce champ contient des informations personnelles identifiables (PII).

Dépannage​

Problème / Code d'étatCause possible / Résolution
401 UnauthorizedAjoutez l'en-tête DD-API-KEY.
403 ForbiddenVérifiez que la clé API dispose des autorisations d'ingestion de logs.
400 Bad RequestVérifiez la syntaxe JSON et envoyez la charge utile sous forme de tableau JSON.
413 Payload Too LargeFractionnez le lot ou compressez la charge utile avec Content-Encoding: gzip.
Log absent de Log ExplorerVérifiez qu'aucun filtre de pipeline n'exclut l'événement, puis contrôlez le filtre de l'index.
Horodatage dans le désordreEnvoyez des horodatages ISO 8601 UTC, comme 2025-11-15T08:30:00Z, dans les 18 heures suivant l'événement.
