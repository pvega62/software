Accepter un paiement par carte

  • Public cible : Développeurs effectuant un premier paiement via l’API Stripe.
  • Prérequis : Un compte Stripe en mode de test, une clé secrète dans l’environnement, et Node.js 18 ou une version ultérieure.
  • Objectif : Recevoir le paiement par carte, consulter son état, et exécuter la commande uniquement après confirmation du serveur.

À la fin, vous aurez un point de terminaison de serveur (server endpoint) qui crée un objet de type PaymentIntent, ainsi qu’un client qui confirme cette création. Tous les résultats proviennent du mode de test (test mode). L’exécution de ce processus ne coûte rien.

Déroulement de la requête​

Un paiement par carte est réparti entre votre serveur, votre client et Stripe. Le serveur stocke la clé secrète. Le client recueille les données de la carte et confirme l'intention de paiement. Stripe communique le résultat à deux reprises : une fois au client et une fois à un webhook.

Chaque étape se déroule à un seul endroit, et le type de clé dépend de ce lieu.

ÉtapeFonctionne surCredentiel
Créer l’objet PaymentIntentVotre serveurClé secrète
Collecter les détails de la carteClientClé publiable
Confirmer le paiementClientclient_secret
Rendre compte du résultatStripeSignature du webhook

Gérer les webhooks de paiement couvre la dernière étape du processus ; cette page s’arrête à l’état de validation du paiement.

1. Créer le PaymentIntent​

Créez un objet PaymentIntent pour chaque commande sur le serveur ; la réponse inclut une clé (client_secret) que le client utilise pour confirmer le paiement.

server.js
import express from "express";

const app = express();
app.use(express.json());

app.post("/create-payment-intent", async (req, res) => {
  const orderId = req.body.orderId;

  if (!orderId) {
    return res.status(400).json({ error: "orderId is required" });
  }

  const params = new URLSearchParams({
    amount: "2120",
    currency: "usd",
    "automatic_payment_methods[enabled]": "true",
    "metadata[order_id]": orderId,
  });

  const response = await fetch("https://api.stripe.com/v1/payment_intents", {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.STRIPE_SECRET_KEY}`,
      "Content-Type": "application/x-www-form-urlencoded",
      "Idempotency-Key": `order-${orderId}`,
    },
    body: params,
  });

  if (!response.ok) {
    const failure = await response.json();
    return res.status(response.status).json({ error: failure.error.message });
  }

  const intent = await response.json();
  res.json({ clientSecret: intent.client_secret });
});

app.listen(4242, () => console.log("Listening on port 4242"));
  • amount utilise l’unité monétaire la plus petite. 2120 facture 21,20 $, et non 2 120 $.
  • Idempotency-Key réutilise l’identifiant de la demande. Une demande réessayée renvoie l’intention originale au lieu de créer une seconde demande.
  • La clé metadata[order_id] est liée à la commande correspondante. Le gestionnaire du webhook le lit directement sans recourir à une base de données.
avertissement

Chaque clé client_secret est unique pour une commande ; ne l’enregistrez pas et ne la réutilisez pas pour plusieurs clients.

Vérifiez bien que l’endpoint répond correctement avant de coder le côté client.

curl -X POST http://localhost:4242/create-payment-intent \
  -H "Content-Type: application/json" \
  -d '{"orderId":"ord_8842"}'

La réponse inclut une valeur de type clientSecret qui commence par pi_ et contient des informations sur le paiement (_secret_).

2. Validez le paiement côté client​

Chargez Stripe.js et confirmez l’intention de paiement avec la carte du client. Stripe gère l’entrée des données de la carte ; ainsi, le numéro de la carte n’atteint jamais votre serveur.

checkout.html
<div id="card-element"></div>
<script src="https://js.stripe.com/v3/"></script>
<script>
  const stripe = Stripe("pk_test_REPLACE_WITH_YOUR_KEY");
  const elements = stripe.elements();
  const cardElement = elements.create("card");
  cardElement.mount("#card-element");

  async function pay() {
    const response = await fetch("/create-payment-intent", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ orderId: "ord_8842" }),
    });

    const { clientSecret } = await response.json();

    const result = await stripe.confirmCardPayment(clientSecret, {
      payment_method: { card: cardElement },
    });

    if (result.error) {
      showDecline(result.error.message, result.error.decline_code);
      return;
    }

    if (result.paymentIntent.status === "succeeded") {
      showConfirmation();
    } else {
      showPending();
    }
  }
</script>

Le champ status détermine le cours des opérations de paiement : un statut succeeded indique que l’émetteur de la carte a approuvé le paiement ; un statut requires_action signifie que le client doit encore compléter une étape supplémentaire avant que le paiement ne soit finalisé (et que Stripe.js lance cette étape pendant la phase confirmCardPayment).

3. Vérifiez le statut sur le serveur​

Le client vous communique le résultat du paiement, mais le navigateur peut mentir (il est possible qu’il affiche un état faux). Lisez d’abord les informations fournies par Stripe avant d’envoyer les produits.

server.js
app.get("/orders/:orderId/status", async (req, res) => {
  const intentId = await lookupIntentId(req.params.orderId);

  const response = await fetch(
    `https://api.stripe.com/v1/payment_intents/${intentId}`,
    { headers: { Authorization: `Bearer ${process.env.STRIPE_SECRET_KEY}` } }
  );

  const intent = await response.json();

  res.json({
    fulfilled: intent.status === "succeeded",
    status: intent.status,
    amountReceived: intent.amount_received,
  });
});

Comparez également amount_received avec amount. Une capture partielle laisse amount_received en dessous de amount. La différence indique le montant à rembourser ou à libérer.

astuce

Mettez en cache le résultat du paiement pendant quelques secondes pour chaque commande. Sinon, une demande à l’API pourrait être effectuée trop souvent (par exemple, une fois par seconde sur une page de paiement rapide).

4. N’effectuez l’exécution qu’une fois le statut confirmé​

Le webhook associé à payment_intent.succeeded offre un mécanisme de traitement des paiements plus fiable que celui utilisé par le navigateur : il est envoyé une seule fois, même lorsque le client ferme la fenêtre de navigation, et contient une signature vérifiable.

fulfillment.js
async function handleSucceeded(intent) {
  const orderId = intent.metadata.order_id;

  if (!orderId) {
    console.warn("No order_id on intent", intent.id);
    return;
  }

  if (intent.amount_received < intent.amount) {
    console.warn("Underpaid intent", intent.id);
    return;
  }

  await markOrderPaid(orderId, intent.id);
}

L’ID de la commande provient des métadonnées que vous avez définies à l’étape 1 ; cet identifiant permet d’éviter de devoir rechercher les informations relatives au paiement ultérieurement.

Gérer le cas de refus​

En cas de refus de paiement par la carte, l’objet PaymentIntent reste dans l’état initial (requires_payment_method) ; le montant et les informations du client sont conservés, permettant au client de tenter à nouveau le paiement avec une autre carte.

client.js
function showDecline(message, code) {
  const copy = {
    insufficient_funds: "That card can't cover this order. Try another card.",
    expired_card: "That card has expired. Add a new one.",
    incorrect_cvc: "The security code doesn't match. Check it and try again.",
  };

  showMessage(copy[code] ?? "That card was declined. Try another payment method.");
}

Remplacez la valeur decline_code par votre propre information, au lieu de présenter le texte brut message. Ce texte brut indique l’émetteur de la carte de crédit et ne convient pas du tout à un formulaire de paiement.

Testez les quatre cas de figure​

Exécutez chaque numéro de carte depuis la section Mode de test et confirmez le comportement du système.

CarteRésultat attenduÀ vérifier
4242 4242 4242 4242Le paiement est réussi.L’état de la commande est indiqué comme « succeeded », et la commande passe en état « payée ».
4000 0000 0000 9995Refus dû à un manque de fonds.Le message de refus s’affiche, et l’intention d’achat reste valable.
4000 0025 0000 3155Authentification requise.Une étape de vérification est lancée, et le processus se poursuit après cela.
4000 0000 0000 0002Refus générique.Le message de remplacement s’affiche, et la commande reste non payée.

Rejouez ensuite l’appel de confirmation avec le même clé d’idempotence. Stripe restitue l’intention initiale, ce qui maintient l’ordre des opérations en une seule facture.

Mise en production​

Passer du mode de test au mode en ligne d’un seul coup.

  1. Remplacer la paire de clés de test par les clés réelles dans le magasin de secrets de production.
  2. Enregistrez l’adresse URL de l’endpoint webhook de production et conservez le secret de signature associé.
  3. Envoyez une transaction à faible valeur puis effectuez son remboursement.
  4. Confirmez le calendrier des paiements ainsi que le compte bancaire utilisé.
  5. Activez les alertes pour les réponses de type 5xx et les échecs des webhooks.

Étapes suivantes​

  • Gérer les webhook de paiement pour exécuter les commandes provenant d’événements vérifiés.
  • Les requêtes idempotentes sont utilisées pour les règles de réessaye associées à ce paramètre clé.
  • Erreurs et tentatives de réémission pour les codes de refus ainsi que la politique de retrait (backoff policy).
  • Créer une intention de paiement en utilisant la liste complète des paramètres.
