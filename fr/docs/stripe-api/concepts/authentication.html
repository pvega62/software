Authentification et gestion des clés

Les demandes adressées à Stripe incluent une clé API dans l’en-tête Authorization. Cette clé identifie votre compte et hérite des autorisations du rôle qui l’a créée. La divulgation d’une clé secrète expose toutes les transactions, les clients et les paiements effectués par ce compte.

Types de clés​

Chaque compte dispose de trois types de clés ; seule une d’entre elles doit être stockée sur le serveur.

CléPréfixeUtilisable depuis un navigateurDestinataire
Publiablepk_test_, pk_live_OuiTokenisation du côté client et utilisation de Stripe.js. Cela n’accorde pas d’accès à l’API.
Secretsk_test_, sk_live_NonAppels API du côté serveur. Permissions complètes sur le compte.
Restreintrk_test_, rk_live_NonLes appels du côté du serveur sont limités aux ressources et opérations nommées.

Une clé secrète permet de lire et d’écrire toutes les données appartenant au compte. Les clés restreintes limitent l’accès aux ressources spécifiques, par exemple à des opérations de lecture seule. Utilisez une clé restreinte chaque fois que l’intégration n’a pas besoin de l’ensemble des fonctionnalités du compte.

danger

Il est interdit de placer une clé secrète ou restreinte dans le code client, un fichier exécutable pour appareil mobile, un répertoire public, ou un ticket d’assistance. Toute personne détenant cette clé peut effectuer des transferts d’argent.

Envoyer la clé​

curl https://api.stripe.com/v1/balance \
  -u "$STRIPE_SECRET_KEY:"
Node.js
const response = await fetch("https://api.stripe.com/v1/balance", {
  headers: { Authorization: `Bearer ${process.env.STRIPE_SECRET_KEY}` },
});
Python
import os, requests

response = requests.get(
    "https://api.stripe.com/v1/balance",
    auth=(os.environ["STRIPE_SECRET_KEY"], ""),
)

Stocker la clé​

Exemples de permissions suggérées pour certaines intégrations :

.env
STRIPE_SECRET_KEY=sk_test_51N...
server.js
if (!process.env.STRIPE_SECRET_KEY) {
  throw new Error("STRIPE_SECRET_KEY is not set");
}

Ajoutez le fichier d’environnement dans .gitignore. Les plateformes hébergeantes conservent cette valeur dans un stockage sécurisé et l’injectent dans l’environnement de l’exécution du programme. Cela permet de préserver le secret de la clé et d’éviter qu’elle ne soit incluse dans le répertoire source ou les journaux de compilation.

Vérifier la connexion​

Envoyer une demande de lecture ; une réponse de type 200 contenant un objet décrivant le solde, l’adresse de base et le chemin réseau confirme l’authentification.

curl -s https://api.stripe.com/v1/balance -u "$STRIPE_SECRET_KEY:" | jq '.object, .livemode'

Les valeurs « "balance" » et « false » correspondent à des clés de test. La valeur « 401 » indique que la clé est incorrecte pour cet compte, a été révoquée ou est manquante. La valeur « 403 » signifie qu’une clé restreinte ne dispose pas des autorisations nécessaires pour accéder à la ressource.

Limiter les droits d’une clé restreinte​

Une clé restreinte définit les autorisations pour chaque ressource. Accordez uniquement l’ensemble d’autorisations le plus restreint nécessaire à l’intégration.

IntégrationPermissions recommandées
Tâche de rapportageLecture des frais, des transactions et des paiements.
Serveur de règlementGère les intentions de paiement et les remboursements. Informe les clients.
Vérificateur de webhookLit les événements. Aucun droit d’écriture.

Donnez à chaque clé le nom du service qui l’utilise. Un nom comme checkout-api-prod facilite l’analyse des incidents, car le journal d’audit indique quelle clé a été utilisée.

Rotation des clés​

Procédures pour la rotation :

  1. Créer une clé de remplacement avec les mêmes autorisations.
  2. Ajoutez-le à la boutique secrète sous un nouveau nom.
  3. Déployez le service qui lit le nouveau nom.
  4. Vérifier que le trafic fonctionne correctement avec la nouvelle clé.
  5. Révoquer la clé ancienne depuis le tableau de bord.
  6. Vérifiez le journal des demandes (request log) pour détecter les appels provenant de l’ancien identifiant (key) après le déploiement.
avertissement

La révocation de la clé actuelle interrompt la production. Déployez la nouvelle clé avant de révoquer l’ancienne, et observez le taux d’erreurs entre les deux étapes.

Réagir à une fuite de données​

Considérez toute clé secrète présente dans un répertoire, un journal d’activité ou un message de chat comme compromise.

  1. Révoguez la clé dans le Panneau de contrôle, sous Développeurs → Clés API.
  2. Créez une clé de remplacement et déployez-la.
  3. Examinez le journal des demandes pour détecter d’éventuelles adresses IP inconnues ou des points de terminaison inhabituels.
  4. Vérifiez le solde et l’historique des paiements pour détecter toute activité non initiée par vous.
  5. Contactez le support de Stripe en cas d’activité non autorisée.

La révocation prend effet immédiatement ; une clé révoquée échouera à toutes ses futures demandes.

Erreurs courantes​

SymptômeCauseSolution
401 Invalid API Key providedLa clé est incomplète, révoquée, ou appartient à un autre compte.Copiez à nouveau la clé depuis le Panneau de contrôle.
403 sur une ressourceUne clé restreinte manque de permissions.Ajoutez les permissions ou utilisez une clé à plus large portée.
401 uniquement en productionLa variable d’environnement est vide dans cette déploiement.Vérifiez le stockage des secrets pour l’environnement de production.
La demande s’arrête, puis échoueUn proxy bloque les communications sortantes de HTTPS vers api.stripe.com.Autorisez l’hôte sur le port 443.
