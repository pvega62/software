Pagination et points de terminaison de liste

Un point de terminaison de liste renvoie une page de résultats et un indicateur pointant vers la page suivante. Votre client suit cet indicateur jusqu'à ce que has_more prenne la valeur « false ».

Définition de la taille de la page​

{
  "object": "list",
  "url": "/v1/charges",
  "has_more": true,
  "data": [
    { "id": "ch_3Rsx4dDtWMrPDtgt1", "object": "charge", "amount": 2120 }
  ]
}
ChampsSignification
dataLes objets sur cette page.
has_moreAfficher « true » lorsque une autre page existe.
urlLe chemin de l’extrémité de pointe (endpoint) qui a généré cette page.

L’objet le plus récent apparaît en premier, et l’ordre ne change pas d’une page à l’autre, car le curseur pointe vers un objet et non vers un indice numérique.

Définir la taille de la page​

limit permet de contrôler la taille de la page et accepte les valeurs de 1 à 100. La valeur par défaut est 10, qui convient à un tableau de bord interactif et évite les allers-retours inutiles dans un job en lot.

curl -s -G https://api.stripe.com/v1/charges \
  -u "$STRIPE_SECRET_KEY:" \
  -d limit=100 | jq '.data | length, .has_more'

Une page plus grande réduit le nombre de demandes et la latence totale. Cependant, elle augmente également le coût en mémoire ainsi que l’impact d’une demande échouée ; donc, 100 éléments suffisent pour la plupart des tâches de synchronisation.

Suivez le curseur​

Lisez la valeur de id de l’ dernier objet sur la page et passez-la en tant que starting_after. Répétez l’opération jusqu’à ce que la condition has_more devienne fausse.

curl -s -G https://api.stripe.com/v1/charges \
  -u "$STRIPE_SECRET_KEY:" \
  -d limit=100 \
  -d starting_after=ch_3Rsx4dDtWMrPDtgt1
Node.js
async function listAllCharges() {
  const charges = [];
  let startingAfter;

  while (true) {
    const url = new URL("https://api.stripe.com/v1/charges");
    url.searchParams.set("limit", "100");
    if (startingAfter) url.searchParams.set("starting_after", startingAfter);

    const response = await fetch(url, {
      headers: { Authorization: `Bearer ${process.env.STRIPE_SECRET_KEY}` },
    });

    if (!response.ok) throw new Error(`Stripe returned ${response.status}`);

    const page = await response.json();
    charges.push(...page.data);

    if (!page.has_more) break;
    startingAfter = page.data.at(-1).id;
  }

  return charges;
}
astuce

Les bibliothèques officielles s’occupent de la pagination à votre place : dans Node.js, itérez sur les éléments de la liste avec stripe.charges.list({ limit: 100 }) et for await ; en Python, appelez la fonction .auto_paging_iter() sur la liste retournée ; en Java, appelez la fonction autoPagingIterable() sur la liste StripeCollection. Vérifiez la signature de la fonction avec la version de l’SDK que vous avez installée avant de l’utiliser.

Filtrez les données sur le serveur​

Un filtre réduit l’ensemble des résultats avant que Stripe ne les affiche sous forme de pages. Si le filtrage est effectué sur le client après la récupération des données, vous êtes obligé de lire toute la collection.

FiltreExempleChamp d’application
Plage horairecreated[gte]=1735689600&created[lt]=1738368000Débits, remboursements, transactions
Étatstatus=availableTransactions
Clientcustomer=cus_QyJ8...Débits, intentions de paiement, factures
Paiementpayout=po_1N...Transactions réunies dans un seul paiement

Combinez plusieurs filtres pour que toutes les informations nécessaires à une tâche de rapprochement soient affichées sur une seule page. Par exemple, une tâche quotidienne qui lit les débits d’hier peut être gérée facilement avec une plage horaire définie par created.

Les points de terminaison de recherche fonctionnent différemment​

Ce design a deux conséquences pour votre client :

  • Aucun numéro de page. Un point de terminaison de liste standard ne contient ni page=2 ni total_count. Si vous avez besoin du nombre total de résultats, comptez-les vous-même dans votre système. Les points de terminaison de recherche diffèrent, comme le montre la section suivante.
  • Pas d’accès aléatoire aux pages. Avancez à la page suivante avec starting_after et revenez en arrière avec ending_before. Ces commandes ne vous permettent pas d’accéder à la page 40 sur un total de 200 pages.

Les points de terminaison de recherche sont paginés différemment​

Les points de terminaison de recherche acceptent une chaîne de requête et retournent un jeton next_page à la place d’un curseur d’objet.

La pagination décalée demande la page 2 à la ligne 100. La base de données se décale lorsqu'une nouvelle transaction arrive entre deux requêtes ; ainsi, la ligne 100 devient la ligne 101 et un enregistrement apparaît deux fois. Un curseur pointe vers le dernier objet que vous avez consulté. Les nouvelles transactions apparaissent alors en amont du curseur et ne perturbent jamais le parcours.

curl -s -G https://api.stripe.com/v1/charges/search \
  -u "$STRIPE_SECRET_KEY:" \
  -d query="amount>1000 AND status:'succeeded'" | jq '.next_page'

Renvoyez le token sous la forme de page pour lire la page suivante. Une réponse contenant next_page: null marque la fin de la consultation. La fonction de recherche ne contient pas de valeur starting_after ; veillez donc à distinguer clairement les deux modèles de pagination dans votre client.

Type d’extrémité (Endpoint)Paramètre du curseur (Cursor Parameter)Signal de fin (End Signal)
Liste standardstarting_afterhas_more: false
Recherchepagenext_page: null

Conserver les lectures de données en masse dans les limites de vitesse préétablies​

Un rattrapage des frais accumulés sur une période d’un an peut générer des milliers de demandes. Répartissez la charge et arrêtez temporairement les opérations lorsque Stripe limite le nombre de requêtes simultanées.

  • Lisez une seule page à la fois. Les opérations sur la même collection peuvent dépasser la limite de concurrence si elles sont effectuées en parallèle.
  • Respectez l’en-tête Retry-After présent dans un fichier 429. Voir la section Erreurs et tentatives de réémission.
  • Cachez la position actuelle du curseur dans un stockage fiable afin que le programme puisse reprendre là où il s’est arrêté en cas de redémarrage.
  • Préférez une plage de valeurs pour created plus restreinte à une visualisation complète de la collection.

Prochaines étapes​

  • Étendre les objets imbriqués pour enrichir la page sans effectuer de nouvelles demandes.
  • Erreurs et tentatives de réémission : comprendre le fonctionnement de la politique de récupération en cas d’échec.
  • Récupérer les informations relatives aux transactions financières pour chaque ligne de données.
