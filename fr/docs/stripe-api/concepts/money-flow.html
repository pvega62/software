Comment l’argent circule via Stripe

Un paiement passe par cinq éléments avant d’être crédité sur votre compte bancaire. Chacun de ces éléments enregistre une étape du processus ; en les lisant dans l’ordre, vous pouvez reconstituer l’intégralité du parcours du paiement, de sa première tentative à son règlement final.

Étapes d'un paiement​

ÉtapeObjetCe qu’il enregistre
1PaymentIntentLe montant que le client a essayé de payer, et si la tentative a été réussie.
2ChargeLa méthode de paiement qui a effectué le transfert d’argent, ainsi que le montant capturé.
3BalanceTransactionLa frais de transfert, ainsi que le montant net qui est apparu sur le solde du compte.
4BalanceLe montant que le compte peut débiter actuellement.
5PayoutQu’est-ce qui est resté sur le compte pour la banque, et quand ?

Les étapes se déroulent dans l’ordre. Les objets sont reliés entre eux, vous pouvez donc ouvrir n’importe quelle étape ultérieurement et revenir à l’intention initiale.

Étape 1 : L’intention enregistrée reflète l’essai effectué par le client pour effectuer un paiement​

Une valeur représentée par PaymentIntent contient le montant du paiement, la monnaie utilisée et l’état de l’opération. Cette information est conservée même en cas d’échec, permettant au client de réessayer avec une autre carte pour la même transaction.

ÉtatSignificationProchain pas
requires_payment_methodAucun moyen de paiement utilisable pour l’instant.Joignez un moyen de paiement et confirmez.
requires_confirmationPrêt à confirmer.Confirmez votre intention.
requires_actionL’émetteur nécessite que le client s’authentifie.Completez la tâche dans le client.
processingLe réseau fonctionne toujours.Attendez un webhook.
requires_captureAutorisé mais pas capturé.Effectuer la capture dans la fenêtre d’autorisation.
succeededL’argent a été transféré.Exécutez la commande.
canceledLe paiement a échoué de manière permanente.Créez une nouvelle tentative de paiement.
avertissement

Le client fournit un résultat, mais c’est le serveur qui prend la décision finale. Traitez la valeur succeeded transmise par le client comme une suggestion. Confirmez l’état de la transaction via un webhook ou une demande d’obtention des données (retrieve call) avant de valider la commande.

Étape 2 : Le transfert des fonds est effectué par le serveur​

La confirmation génère un objet Charge. L’enregistrement de la transaction indique le mode de paiement utilisé, le montant prélevé et le résultat obtenu auprès du réseau de cartes de crédit. Une seule tentative de paiement réussie entraîne une seule transaction de paiement. Le montant prélevé ne peut pas être modifié après que la transaction a été finalisée.

Vous pouvez autoriser le prélèvement et effectuer le paiement en même temps, ou séparément. Vous pouvez également définir l’objet capture_method comme étant de type manual pour bloquer les fonds immédiatement et effectuer le paiement ultérieurement. Les plateformes d’e-commerce qui expédient les produits avant de prélever les frais nécessitent cette séparation des opérations. Les blocages des fonds ont une durée limitée ; il est donc essentiel de procéder au prélèvement avant que la période autorisée ne se termine.

Étape 3 : L’enregistrement du solde reflète le montant total des fonds disponibles​

Chaque mouvement financier génère un nouvel objet BalanceTransaction. Cet enregistrement contient trois informations :

  • Un remboursement crée une nouvelle transaction de solde avec un montant négatif. Les paiements effectués par le vendeur génèrent également un objet amount. Il est nécessaire de concilier ces données avec le livre comptable pour garantir l’exactitude des comptes.

  • Étape 4 : Les fonds bloqués sont désormais disponibles pour le paiement ou le transfert. L’objet fee contient deux listes :​

  • net. La somme qui modifie réellement le solde.

Un remboursement génère une deuxième transaction de solde présentant un montant négatif. Les paiements effectués par les utilisateurs créent également une telle transaction. Il convient de concilier ces données avec le livre comptable. Aucun autre enregistrement ne reflète les frais afférents à ces opérations.

Étape 4 : Les fonds déposés sont définitivement bloqués​

L’objet Balance divise les fonds en deux tableaux (arrays).

ArraySignification
availableFonds que vous pouvez retirer ou transférer maintenant.
pendingLes fonds provenant des frais qui n’ont pas encore été réglés.

Un troisième champ, refund_and_dispute_prefunding, conserve de l’argent réservé pour les remboursements futurs, les litiges ou un solde négatif. Chaque tableau liste une entrée par monnaie.

Remarque

Le solde indique ce que vous pouvez débourser ; il ne reflète pas vos revenus. Pour le suivi des revenus, additionnez les valeurs de net issues des transactions de solde sur la période considérée.

Étape 5 : Le virement est effectué depuis le compte​

Un Payout transfère les fonds disponibles sur le compte bancaire enregistré.Votre calendrier de virement définit le rythme : quotidien, hebdomadaire, mensuel ou manuel. Les retards de règlement varient selon le pays et la méthode de paiement utilisée.

Un virement couvre plusieurs frais en même temps. Pour associer un virement à ses frais sources, utilisez les transactions de solde filtrées par payout={payout_id}.

Exemple pratique​

Un client achète un forfait mensuel pour 21,20 $ ; la plateforme applique un taux de 2,9 % plus 0,30 $.

ÉtapeObjetMontantNotes
1PaymentIntent pi_...2120Créé avec amount=2120, currency=usd.
2Débit ch_...2120L’émetteur approuve le débit.
3BalanceTransaction txn_...amount: 2120fee: 91, net: 2029, type: charge.
4Soldeavailable: 2029Les fonds apparaissent après le délai de règlement.
5Paiement po_...2029Paiement effectué avec d’autres frais déjà réglés.

La commission est de 91 cents : un taux de 2,9 % représente 61,48 cents ; la commission fixe s’ajoute pour atteindre un total de 91 cents. Le compte gagne 20,29 $, et non 21,20 $.

Ce qui modifie le parcours du processus…​

Un paiement rejeté…​

Un rejet met fin à l’essai de paiement sans qu’aucun frais ne soit débité. L’intention de paiement est conservée (état requires_payment_method) et son montant est maintenu. Une nouvelle tentative avec la même intention évite une commande dupliquée.

Les rejets sont classés en fonction de leur probabilité de succès :

  • Refus catégoriques. L’émetteur rejette la carte de manière définitive, par exemple… lost_card or stolen_cardNe pas réessayer.
  • Refus doux. L’émetteur rejette cette tentative. 0Une nouvelle tentative ultérieure peut réussir.

Un remboursement…​

Un remboursement crée un nouvel objet Refund ainsi qu’une seconde transaction de solde avec un montant négatif. Le remboursement ne compense pas la commission initiale de traitement.

Type de remboursementTransaction de soldeEffet sur le solde
Remboursement completamount: -2120, fee: 0, net: -2120Retire l’intégralité du montant facturé.
Remboursement partielamount: -1000, fee: 0, net: -1000Retire une partie du montant facturé.
Deux ou plusieurs remboursements partielsUne seule transaction par remboursementChaque remboursement est enregistré séparément dans le compte.

Le compte doit toujours payer la frais initial de 91 cents. Un remboursement complet coûte 21,20 $, soit le montant restitué plus ce frais.

Litige​

Un remboursement (chargeback) annule le paiement effectué et ajoute une frais de contestation. Stripe retire le montant contesté du compte de l’acheteur. available Lorsque l’émetteur ouvre le dossier, il percevra alors une frais de contestation fixe de 15 $ aux États-Unis.

Un litige peut entraîner trois transactions dans le compte du client : la première retire le montant contesté, la seconde facture le frais de litige, et la troisième restitue le montant si la banque tranche en faveur du client. Suivez l’avancement du litige à travers l’objet Dispute plutôt que simplement à travers les mouvements de solde.

Prélèvement manuel​

Une capture manuelle peut consommer moins de la quantité autorisée. Un blocage d’une valeur de 50 $, effectué alors que la quantité réelle est de 40 $, entraîne une facture pour la différence. 4000 Le système rembourse les 10 $ restants au client. Une seule transaction de solde enregistre le montant de 40 $.

Prochaines étapes​

  • Authentification et gestion des clés pour envoyer la première demande de remboursement.
  • Demandes idempotentes pour tenter à nouveau le prélèvement sans le dupliquer.
  • Erreurs et tentatives de réémission pour gérer les refus, les limites de fréquence d’utilisation et les pannes.
  • Récupérer une transaction de solde afin d’obtenir la liste complète des attributs.
