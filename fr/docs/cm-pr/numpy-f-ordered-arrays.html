« Correction des problèmes liés à l’encodage/décodage des tableaux organisés selon un ordre spécifique avec Protobuf »

Contexte de l’échantillon

La patch, le exemple de reproduction ainsi que le titre de l’issue citée ci-dessous proviennent d’un exercice donné à moi. Le message de commit et la description de la demande de pull request sont de ma création.

Message de commit​

Fix encoding/decoding of F-ordered NumPy arrays

`bytes(arr.data)` materializes the buffer contents in C order, so encoding a
Fortran-ordered array pairs C-ordered bytes with Fortran strides. Decoding
then reads those bytes with the wrong strides and returns a scrambled array.

Record the memory order in a new `order` field of the `Ndarray` message, and
let `ndarray_to_numpy` transpose and reshape when that field reports "F".
Buffers encoded before 0.2.4 have an empty `order` field, so decoding them
yields C-ordered arrays.

Closes #63

Demande de pull​

Résumé​

Le protocole Protobuf altère la structure des tableaux NumPy qui utilisent un ordre de données conforme à celui du langage Fortran. Un tableau organisé selon le format Fortran est décodé avec ses valeurs dans les mauvaises positions ; le décodeur ne signale aucun problème, et l’utilisateur accepte ainsi un tableau déformé.

Round-trip test
arrF = numpy.array([[1, 2, 3], [4, 5, 6]], order="F")
numpy.testing.assert_array_equal(
    arrF,
    ndarray_to_numpy(ndarray_from_numpy(arrF)),  # returns [[1, 3, 5], [2, 4, 6]] without the fix
)

Cause principale​

La variable ndarray_from_numpy stocke le contenu brut du buffer à côté des informations relatives à l’organisation de la mémoire (les “strides” du tableau). Ces deux informations décrivent en fait deux structures de mémoire différentes :

  1. Encodage : bytes(arr.data) convertit les données selon l’ordre du langage C, ce qui produit des octets organisés selon cet ordre.
  2. Strides : ndarray_from_numpy copie strides sans modification ; elles décrivent donc toujours le formatage utilisé en Fortran.
  3. Décodage : numpy.ndarray(buffer=..., strides=...) applique les informations de “strides” provenant du format Fortran aux octets organisés selon C, ce qui entraîne l’accès aux mauvaises cellules et donc la restitution de valeurs incorrectes.

Correction​

Enregistrer l’ordre des données dans la mémoire lors de l’encodage, puis le réutiliser lors du décodage.

  • protobufs/npproto/ndarray.proto Et le contenu généré… mcbackend/npproto/__init__.py Acquérir une certaine compétence ou un avantage. order Champs de type chaîne de caractères (étiquette 5) sur le… Ndarray message.
  • mcbackend/npproto/utils.py writes order="CF"[arr.flags.f_contiguous] Pendant l’encodage, un tableau organisé selon le format Fortran stocke… "F"Lors du décodage… ndarray_to_numpy Transpose et redessine lorsque… nda.order == "F"Cette étape rétablit la structure du code Fortran à partir des octets classés selon l’ordre C.
  • mcbackend/test_npproto.py ajoute la valeur test_byteorders, qui sert à paramétrer les opérations sur shape et order.*

Tests​

  • TestUtils.test_byteorders paramètre simultanément les valeurs shape et order. Chacun des éléments des tableaux (5,), (2, 3), (2, 3, 5) et (5, 2, 1, 7) est exécuté deux fois, une fois pour chaque ordre de mémoire possible. Chaque cas vérifie que les résultats correspondent correctement (nda.order correspond à arr.flags.f_contiguous), puis le tableau est soumis à des opérations d’encodage et de décodage.

  • TestUtils.test_conversion prend en charge les types de données suivants : entier, flottant, scalaire, chaîne de caractères, objet, et date/heure.*

Notes​

  • La version du logiciel est mise à jour à 0.2.4.
  • ndarray_to_numpy conserve l’opération de transposition ainsi que la gestion des buffers et des types de données existants.
  • Les buffers encodés avant l’application de la fonction *0.2.4 contiennent un champ order vide ; leur décodage produit un tableau organisé selon l’ordre C.
