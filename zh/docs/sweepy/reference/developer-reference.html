Sweepy 开发者参考

Sweepy 是一个基于 Python 的小型项目，采用扁平化的架构。此页面将每个流程阶段与其对应的执行模块进行关联，以便您知道在哪里进行修改。

适用对象​

如果您计划修改 Sweepy 的代码或添加新的任务来源，请阅读此页面。审阅者可以借助该文档来了解如何处理拉取请求（pull request）。该文档仅涵盖内部实现细节，包括模块、依赖关系以及所使用的 Python 版本。

提示

如果您想执行数据扫描操作，请跳过此页面。请从安装指南开始操作。

管道阶段和模块​

swee.py 会按顺序执行五个阶段。终端会依次显示每个阶段的输出，其编号分别为 [1/5] 到 [5/5]。

阶段模块功能/作用
1. 加载个人资料engine/config.py此操作会加载并验证您的个人资料。该模块中的向导会帮助您完成个人资料的填写与保存。
2. 角色发现engine/discovery.py查询聚合器会遍历python-jobspy中的数据，并对每个平台进行分类。
2. 角色探索engine/sources/从公共端点获取 Greenhouse、Ashby、Lever、Workable 以及 Built In NYC 等相关信息。
2. 去重处理swee.py将聚合器的结果与源数据的结果合并，为每个作业链接生成一张卡片。
3. 验证 URLengine/validator.py使用HTTPHEAD请求检查每个链接，并提供GET备用方案；同时会删除失效的帖子。
4. 根据简历进行评分engine/scorer.py从招聘信息中提取关键词和简历中的相关内容，然后对比两者在要求和关键词上的匹配程度。对于需要书面回答的职位，会对其进行标记。
5. 路由简历信息engine/enrich.py选择匹配度最高的简历，并为其分配相应的徽标颜色。
5. 丰富卡片内容engine/enrich.py用于生成卡片摘要、薪酬信息以及定制的提示文本。
5. 默认卡片PDF格式engine/report.py以每页显示六张卡片的方式渲染卡片布局，并返回总页数。
5. 遗传表格PDF文件（Legacy Table PDF）engine/pdf_builder.py当您的个人资料设置启用report.style: legacy时，该文件会显示表格的布局。
5. 数据导出功能engine/exporter.py可生成 CSV 和 JSON 格式的文件；根据需求可将 PNG 图片转换为栅格格式。
5. 工作任务跟踪engine/tracking.py添加了用于跟踪任务的列，并能够读取之前的数据导出结果，以确保您输入的值能够被正确处理。

engine/session.py 用于存储基于 Stateful Model Context Protocol (MCP) 流式的卡片数据。这些卡片被保存在一个线程安全的映射结构中，每个卡片的索引是由相应作业链接的哈希值生成的。

在哪里进行修改​

您想要更改从这里开始
求职信息的来源或其终点engine/sources/，以及data/sources/中的种子列表（用于数据匹配）。
系统如何对招聘信息进行匹配和评分engine/scorer.py
卡片上显示的内容engine/enrich.py，接着是engine/report.py中的详细信息。
系统如何检查链接的有效性engine/validator.py
命令行工具使用的参数标志swee.py
一种名为MCP的工具server.py
提示

server.py 会导入与命令行工具相同的引擎模块。在修改任何引擎后，请务必测试 MCP 路径，因为一次修改可能会同时影响到这两个使用入口。

模块参考​

入口点​

模块功能说明
swee.py作为五阶段处理流程的主要协调者；argparse则是该流程的命令行入口点。
server.pyModel Context Protocol（stdio）服务器：将工具接口提供给AI助手使用；get_jobs负责解析简历内容，以便助手评估简历的质量（而非仅依赖关键词列表）。

引擎模块​

模块功能说明
engine/config.py优化招聘信息卡片的展示内容，包括摘要、薪资信息、职位分配建议等个性化提示。
engine/discovery.py用于python-jobspy的抓取工具编排，以及申请跟踪系统（ATS）的检测和去重功能。
engine/validator.py用于生成默认格式的PDF卡片。
engine/scorer.py为旧版系统生成的表格格式PDF文件。
engine/enrich.py支持CSV和JSON格式的数据输出，以及报告PDF文件的PNG图像化处理。
engine/session.py包含用于追踪招聘流程的列信息，以及之前输出的数据的延续性处理。
engine/report.py默认卡片布局的 PDF 文件。
engine/pdf_builder.py适用于 report.style: legacy 的旧版表格布局 PDF 文件。
engine/exporter.py支持CSV和JSON格式的数据导出；同时支持PDF报告的栅格化处理。
engine/tracking.py跟踪列以及之前导出的数据延续性（即这些数据如何被后续处理或使用）。
engine/docx.py使用python-docx和reportlab将数据转换为PDF格式；同时提供Microsoft Word格式的备用选项。
engine/documents.py用于--convert和MCP转换器的文档分发功能，支持DOC、文本、Markdown及PDF格式。
engine/logging.py在logs/下启用调试日志记录功能（需用户选择）。
engine/cache.py基于SQLite的缓存系统，根据查询条件和引擎设置进行数据抓取，缓存有效期为1小时。
engine/circuit_breaker.py计录连续出现的源错误，并在冷却期间暂停相关操作。
engine/engine_defaults.py共享默认的站点列表和引擎设置，确保数据导入不会引发循环问题。
engine/engines.py提供适配器注册表及安装工具，用于hirehunt、openroles、apify和jobdrop等引擎的集成。
engine/history.py记录已报告的职位信息；每日更新仅显示新发布的职位。
engine/normalize.py将原始引擎数据格式化为统一的共享发布格式。
engine/salary.py当职位信息中未包含薪资结构时，从文本中提取薪资信息。
engine/sweep_config.py将共享的引擎默认设置应用到用户配置中。
engine/updater.py基于Git的检查机制，用于确认更新需求并重新安装依赖项。

确定性源​

模块功能说明
engine/sources/__init__.py从data/sources/获取数据并加载种子列表。
engine/sources/_common.py提供通用辅助函数，用于处理HTTP的头部信息、标题预过滤以及HTML格式的文本转换。
engine/sources/greenhouse.py用于抓取Greenhouse招聘网站的接口。
engine/sources/ashby.py用于抓取Ashby招聘网站的接口。
engine/sources/lever.py用于抓取Lever招聘网站的接口。
engine/sources/workable.py用于获取Workable插件所需数据的接口。
engine/sources/builtinnyc.py用于抓取Built In NYC招聘网站数据的工具。

引擎适配器​

模块功能说明
engine/adapters/__init__.py将引擎名称与对应的适配器进行映射的注册表。
engine/adapters/base.py提供ScraperAdapter的基础类、通用的User-Agent头部信息处理程序以及结果格式化工具。
engine/adapters/jobspy_adapter.py适用于 LinkedIn、Indeed、Glassdoor 和 ZipRecruiter 的 python-jobspy 聚合适配器。
engine/adapters/ats_adapter.py用于替代 engine/sources/ 中的确定性 ATS（Application Tracking System）数据获取器的适配器。
engine/adapters/hirehunt_adapter.py可选的招聘信息搜索引擎适配器。
engine/adapters/openroles_adapter.py可选的 openroles 数据库适配器。
engine/adapters/apify_adapter.py可选的 Apify 框架适配器。
engine/adapters/jobdrop_adapter.py可选的 jobdrop 数据库适配器。

数据、脚本和测试​

路径用途
data/sources/*.txt用于生成职位列表、公司信息、组织列表及分类信息的种子数据。
scripts/make_sample.py用于生成存储在 docs/ 中的示例报告的工具。
tests/包含多个测试用例的 pytest 套件，每个测试用例对应一个文件夹：适配器、配置文件、文档、PDF 文件、相关引擎、数据处理逻辑、日志记录以及报告文件；其他文件夹分别包含薪资信息处理、评分系统、服务器相关代码、会话管理、数据来源处理、跟踪功能、更新逻辑及验证工具等。
备注

当您修改 discovery.py、exporter.py 或 pdf_builder.py 时，请添加相应的测试文件，并将其放入 tests/ 目录中。

依赖项​

运行时所需的软件包（runtime packages）来自文件 requirements.txt。该文件中列出的版本即为这些软件包的当前版本。

包名版本在 Sweepy 中的作用
reportlab5.0.1生成带有可点击链接的格式化 PDF 报告。
pymupdf1.28.2从简历 PDF 文件中提取文本并转换为 PNG 格式。
python-docx1.2.0读取 .docx 中的简历内容，并将其重新生成为 PDF 格式（无需使用 Word 工具）。
requests2.32.5连接 ATS 端点，检查每个职位链接是否返回实时响应。
beautifulsoup44.15.0从 Greenhouse、Lever、Workable 以及 Built In NYC 等来源解析数据。
pyyaml6.0.3读写 YAML 中的候选人信息。
questionary2.1.1驱动交互式向导的运行。
prompt-toolkit3.0.53驱动向导中的交互式文本输入功能。
python-jobspy1.2.0无需 API 凭据即可抓取 LinkedIn、Indeed、Glassdoor 和 ZipRecruiter 上的职位信息。
pandas2.2.3对招聘信息进行结构化处理，并生成 CSV 和 JSON 格式的输出文件。
mcp1.30.0运行 Model Context Protocol 服务器。
anyio4.12.1负责运行异步的 MCP 数据传输任务。
tzdata2026.5在 Windows 系统上提供 IANA 区域数据库的支持，因此 export.timezone 可以使用如 America/New_York 这样的名称进行标识。

requirements.txt 还列出了一个可选的软件包；当需要使用 Word 生成 PDF 时，请取消注释 docx2pdf。

  • docx2pdf (0.5.2，可选)：通过 Windows 上的 Microsoft Word 将 DOCX 文件转换为 PDF 格式；Sweepy 会在系统安装了 Microsoft Word 的情况下自动调用该功能。
备注

mcp 被故意维持在 1.x 版本。2.x SDK 仅适用于 2026-07-28 协议版本。如果客户端尝试连接 server/discover 协议但无法连接，会自动回退到 initialize 协议；此时会收到 -32022 错误提示。VS Code 的 Copilot 功能也会遵循这一回退机制。

提示

pandas 同样故意保持版本号为 2.x；Pandas 3.x 需要 Python 3.11 或更高版本，而持续集成（CI）流程仍使用 Python 3.10 进行测试。

软件包版本功能说明

依赖项和支持的 Python 版本​

项目要求详细说明
Python 最低版本Sweepy 要求 Python 3.10 或更高版本，并且所有模块都必须遵循 3.10 的语法规范。
测试范围在.github/workflows/ci.yml中定义的持续集成（CI）工作流程可在Ubuntu系统上运行Python 3.10、3.11和3.12版本。
编译检查目标（Lint target）pyproject.toml
行长度Ruff 规定每行最多只能包含 100 个字符，并会忽略占位符 E501。
构建（CI）步骤该流程会先安装所有所需的文件，然后执行 ruff check .，之后再执行 pytest。
备注

pyproject.toml 声明了 requires-python = ">=3.10"，因此 pip 会在安装时拒绝更低版本的解释器。CI 矩阵和 ruff 目标定义了经过测试的版本范围。Python 3.13 在实践中可以运行，但不在官方测试范围之内。

Python 3.13

如果没有现成的 wheel 包，可能需要从源代码编译 pymupdf 包。在安装依赖项之前，请先安装 Microsoft C++ 构建工具，并选择 “使用 C++ 进行桌面开发” 工作负载。

代码库结构​

Repository layout
swee.py              CLI entry point and sweep orchestrator
server.py            MCP server over stdio
engine/              Pipeline modules
engine/sources/      Deterministic ATS fetchers
engine/adapters/     Aggregator and optional engine adapters
data/sources/        Seed lists for each fetcher
profiles/            YAML search profiles
results/             Generated PDF, CSV, JSON, and PNG files
logs/                Opt-in debug logs
styles/              Vale style rules for the docs
tests/               pytest suite

当修改 server.py 中的工具配置时，请在同一提交中更新 MCP 工具参考文档。
