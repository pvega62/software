Sweepy 开发者参考

Sweepy 作为一个采用扁平化架构的小型 Python 项目运行。本页面将每个管道阶段与其对应的执行模块进行映射，以便您了解应在何处进行修改。

目标读者​

如果您计划修改 Sweepy 的代码或添加职位来源，请阅读本页面。 审核人员可利用本页指导拉取请求。本页仅涵盖内部实现：模块、依赖项和 Python 版本。

:::提示 若您只想运行扫描任务，请跳过本页。请从 安装 开始。 :::

管道阶段与模块​

swee.py 按顺序运行五个阶段。终端会以 [1/5] 到 [5/5] 的形式显示每个阶段。

阶段模块功能
1. 加载配置文件engine/config.py加载并验证您的 YAML 配置文件。同一模块中的向导会生成该文件。
2. 发现角色engine/discovery.py通过 python-jobspy 查询聚合器数据源，并对每个平台进行分类。
2. 发现职位engine/sources/从公共端点获取 Greenhouse、Ashby、Lever、Workable 和 Built In NYC 的职位板。
2. 去重swee.py将聚合器和来源的结果合并，每个职位链接生成一张卡片。
3. 验证 URLengine/validator.py通过 HTTP HEAD 请求（并以 GET 请求作为备用方案）检查每个链接，剔除失效的职位发布。
4. 基于简历进行评分engine/scorer.py提取职位发布和简历中的术语，然后对职位要求与关键词的重叠度进行评分。它会为要求书面回答的职位发布添加标签。
5. 简历路径路由engine/enrich.py选择术语重合度最高的路径，并分配相应的徽章颜色。
5. 卡片内容丰富化engine/enrich.py生成卡片摘要、薪酬信息及定制化提示文本。
5. 默认卡片 PDFengine/report.py渲染卡片布局（默认每页六张卡片），并返回页数。
5. 传统表格 PDFengine/pdf_builder.py当个人资料设置 report.style: legacy 时，渲染表格布局。
5. 数据导出engine/exporter.py生成 CSV 和 JSON 文件。根据请求将页面图像栅格化为 PNG 格式。
5. 任务跟踪engine/tracking.py添加跟踪字段，并读取之前的导出数据，确保您输入的值能够被保留。

engine/session.py 存储了具有状态的模型上下文协议（MCP）流程的卡片存储。它将卡片保存在一个线程安全的映射中，该映射以每个任务链接的稳定哈希值作为索引。

修改位置​

您想修改的内容请从这里开始
任务源或其端点engine/sources/，以及 data/sources/ 中的种子列表
匹配评分规则engine/scorer.py
卡片显示内容engine/enrich.py，然后是 engine/report.py
链接验证方式engine/validator.py
命令行参数swee.py
MCP 工具server.py

:::提示 server.py 导入的引擎模块与命令行工具相同。每次修改引擎后，请测试 MCP 路径，因为一个修复会同时影响这两个入口点。 :::

模块参考​

入口点​

模块用途
swee.py五阶段管道的主要协调器及 argparse 命令行入口点。
server.py模型上下文协议 （stdio）服务器，向 AI 助手暴露引擎工具。get_jobs 返回已解析的简历文本，以便助手根据文档内容而非个人资料关键词列表进行判断。

引擎模块​

模块用途
engine/config.py交互式向导，以及 YAML 加载和验证。
engine/discovery.py负责 python-jobspy 及确定性数据源的爬虫协调、求职者跟踪系统 (ATS) 检测以及去重。
engine/validator.py链接可用性检查及软404检测。无法验证的链接仍保留在处理流程中。
engine/scorer.py简历术语提取、匹配度百分比计算、标签分配及各职业路径的评分。
engine/enrich.py用于摘要、薪酬、职位路径和个性化建议的卡片信息丰富化。
engine/session.py具有稳定 ID 的线程安全卡片存储，用于带状态的 MCP 流程。
engine/report.py默认卡片布局的 PDF。
engine/pdf_builder.py用于 report.style: legacy 的传统表格布局 PDF。
engine/exporter.pyCSV 和 JSON 导出，以及报告 PDF 的 PNG 栅格化。
engine/tracking.py跟踪列以及对先前导出内容的延续读取。
engine/docx.py使用 python-docx 和 reportlab 进行 DOCX 到 PDF 的转换，并提供 Microsoft Word 备用方案。
engine/documents.py处理 --convert 选项和 MCP 转换器的文档分发，涵盖 DOCX、DOC、文本、Markdown 和 PDF 格式。
engine/logging.py在 logs/ 目录下生成可选的调试日志。
engine/cache.py以查询和引擎集为键的 SQLite 抓取缓存，有效期为一小时。
engine/circuit_breaker.py统计连续源错误次数，并在冷却期间暂停调用。
engine/engine_defaults.py共享的默认站点列表和引擎设置，采用无导入设计以避免循环引用。
engine/engines.py可选引擎（hirehunt、openroles、apify 和 jobdrop）的适配器注册表和安装程序。
engine/history.py已上报职位的持久化记录。每日清理操作仅上报新职位。
engine/normalize.py将引擎的原始数据行规范化为共享的职位发布字段。
engine/salary.py当招聘平台未提供结构化薪资信息时，从职位描述文本中提取薪资数据。
engine/sweep_config.py将共享引擎默认值应用到配置文件设置中。
engine/updater.py基于 Git 的更新检查以及对检出代码的依赖项重新安装。

确定性数据源​

模块用途
engine/sources/__init__.py从 data/sources/ 加载数据提取器导出项和种子列表。
engine/sources/_common.py用于 HTTP 头部处理、标题预过滤以及 HTML 转文本的共享辅助函数。
engine/sources/greenhouse.pyGreenhouse 招聘网站抓取器。
engine/sources/ashby.pyAshby 招聘网站抓取器。
engine/sources/lever.pyLever 职位发布抓取器。
engine/sources/workable.pyWorkable 小部件 API 抓取器。
engine/sources/builtinnyc.pyBuilt In NYC 分类抓取器。

引擎适配器​

模块用途
engine/adapters/__init__.py将每个引擎名称与其适配器进行映射的注册表。
engine/adapters/base.pyScraperAdapter 基类、共享的 User-Agent 头部以及结果格式辅助函数。
engine/adapters/jobspy_adapter.py用于 LinkedIn、Indeed、Glassdoor 和 ZipRecruiter 的 python-jobspy 聚合适配器。
engine/adapters/ats_adapter.py基于 engine/sources/ 目录中确定性 ATS 抓取器的适配器。
engine/adapters/hirehunt_adapter.py可选的 hirehunt 引擎适配器。
engine/adapters/openroles_adapter.py可选的 openroles 引擎适配器。
engine/adapters/apify_adapter.py可选的 Apify 执行器适配器。
engine/adapters/jobdrop_adapter.py可选的 jobdrop 引擎适配器。

数据、脚本和测试​

路径用途
data/sources/*.txt职位板、公司、组织和类别的种子列表。
scripts/make_sample.py用于生成存储在 docs/ 目录中的示例报告的构建脚本。
tests/pytest 测试套件，每个领域对应一个文件：适配器、配置、文档、docx、引擎、数据增强、历史、日志记录和报告。其他文件涵盖薪资、评分器、服务器、会话、数据源、swee、跟踪、更新器和验证器。

:::注 修改 discovery.py、exporter.py 或 pdf_builder.py 时，请添加一个专门的测试文件。将该文件放置在 tests/ 目录下。 :::

依赖项​

运行时包来自 requirements.txt。以下版本与该文件中的版本一致。

包版本在 Sweepy 中的作用
reportlab5.0.1生成带有可点击链接的样式化 PDF 报告。
pymupdf1.28.2从简历 PDF 中提取文本，并将 PNG 导出文件栅格化。
python-docx1.2.0读取 .docx 格式的简历，并在不使用 Word 的情况下将 DOCX 文本重建为 PDF。
requests2.32.5访问 ATS 端点，并检查每个职位链接是否能返回有效响应。
beautifulsoup44.15.0解析来自 Greenhouse、Lever、Workable 和 Built In NYC 源的 HTML 内容。
pyyaml6.0.3读写 YAML 配置文件。
questionary2.1.1驱动交互式向导问题。
prompt-toolkit3.0.53驱动向导的交互式文本输入。
python-jobspy1.2.0无需 API 凭据即可抓取 LinkedIn、Indeed、Glassdoor 和 ZipRecruiter 上的职位信息。
pandas2.2.3对职位信息进行结构化处理，并生成 CSV 和 JSON 导出文件。
mcp1.30.0运行模型上下文协议（MCP）服务器。
anyio4.12.1运行异步 MCP 传输。

requirements.txt 中还列出了一个可选包。当需要通过 Word 生成 PDF 时，请取消注释 docx2pdf。

  • docx2pdf (0.5.2，可选) 通过 Windows 上的 Microsoft Word 将 DOCX 渲染为 PDF。只要机器上安装了 Microsoft Word，Sweepy 就会调用它。

:::注 mcp 特意保持在 1.x 版本。2.x SDK 仅支持 2026-07-28 协议时代。 若客户端先探测 server/discover，随后回退到 initialize 握手流程，将收到 -32022 错误。VS Code Copilot 会遵循该回退机制。 :::

:::提示 pandas 特意保持在 2.x 版本。Pandas 3.x 需要 Python 3.11 或更高版本，而 CI 测试矩阵目前仍仅测试 Python 3.10。 :::

开发包（requirements-dev.txt）​

包名版本功能说明
pytest9.1.1运行 tests/ 目录中的测试套件。
pytest-cov7.1.0报告 swee.py、server.py 和 engine/scorer.py 的代码覆盖率。
ruff0.17.0检查代码规范并整理导入语句。
tomli2.2.1为 Python 3.10 测试运行提供 tomllib。
终端
pip install -r requirements.txt
pip install -r requirements-dev.txt
ruff check .
pytest -q

依赖项和支持的 Python 版本​

项目详情
Python 最低版本Sweepy 要求 Python 3.10 或更高版本，且每个模块均采用 3.10 语法。
测试范围.github/workflows/ci.yml 中的 CI 工作流在 Ubuntu 上运行 Python 3.10、3.11 和 3.12。
代码检查目标pyproject.toml 将 ruff 的 target-version 设置为 "py310"。若使用仅支持新版本的语法结构，代码检查任务将失败。
行长限制Ruff 强制执行 100 个字符的行长限制，并忽略 E501 错误。
CI 步骤该任务会同时安装两个依赖文件，并在运行 pytest 之前执行 ruff check .。
备注

pyproject.toml 声明了 requires-python = ">=3.10"，因此 pip 在安装时会拒绝较旧的解释器。 CI 矩阵和 ruff 目标定义了测试范围。Python 3.13 虽然实际可用，但超出了该范围。

Python 3.13

若不存在预编译的 wheel 包，pymupdf 包可能会从源代码编译。 在安装依赖项之前，请安装 Microsoft C++ 构建工具，并选择 “使用 C++ 进行桌面开发” 工作负载。

代码库结构​

仓库结构
swee.py CLI 入口点和扫描协调器
server.py 通过 stdio 运行的 MCP 服务器
engine/ 管道模块
engine/sources/ 确定性 ATS 获取器
engine/adapters/     聚合器及可选引擎适配器
data/sources/ 各获取器的种子列表
profiles/ YAML 搜索配置文件
results/ 生成的 PDF、CSV、JSON 和 PNG 文件
logs/ 可选的调试日志
styles/ 文档的 Vale 样式规则
tests/ pytest 测试套件
