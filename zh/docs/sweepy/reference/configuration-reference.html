配置文件参考

本页面列出了Sweepy配置文件支持的所有设置。在编辑个人资料时请保持此页面打开状态；如需详细操作指南，请参阅设置Sweepy。

配置文件的存储位置​

Sweepy从您Sweepy目录下的profiles/文件夹中读取配置文件。每个配置文件采用YAML格式编写（纯文本，通过缩进和冒号进行组织）。您可以使用记事本、VS Code或任何现有的文本编辑器来打开这些文件。

从config.sample.yaml文件或预设模板（如profiles/paralegal_nyc.yaml）开始，复制模板并修改其中的数值即可。

Terminal
copy config.sample.yaml profiles\my_search.yaml
notepad profiles\my_search.yaml

然后使用Sweepy工具来应用这些配置文件。

Terminal
sweepy --profile profiles/my_search.yaml
备注

您可以创建任意数量的配置文件（例如：按城市或职位类型分类）。Sweepy会将配置信息存储在缓存文件、历史记录数据库以及logs/和results/文件夹中。

警告

使用空格进行缩进，切勿使用制表符；YAML文件不支持制表符，一个错误的制表符可能会导致整个配置文件无法正常读取。

完整的配置文件示例​

下面的示例展示了Alex的完整配置文件。以#开头的行属于注释内容，Sweepy会忽略这些注释。

profiles/paralegal_nyc.yaml
# ─────────────────────────────────────────────────
# Sweepy — Alex's Paralegal Profile (New York City)
# ─────────────────────────────────────────────────

# Your name. It appears in the PDF report header.
name: "Alex Rivera"

# Set true to write rotating debug logs under logs/.
debug: false

# ─── Job search ───────────────────────────────────
search:
  # Every title Sweepy searches at the same time.
  titles:
    - "Paralegal"
    - "Legal Assistant"
    - "Litigation Support Specialist"
    - "Legal Secretary"

  # Your target market.
  location: "New York, NY"

  # true keeps remote roles only. false keeps remote, hybrid, and on-site roles.
  remote_only: false

  # false removes hybrid roles from every report.
  include_hybrid: true

  # Annual salary floor. Use 0 to skip salary filtering.
  min_salary: 65000

  # true reads pay from the posting text when a board omits structured pay.
  salary_from_description: true

# ─── Resume ───────────────────────────────────────
resume:
  # Path to a PDF or DOCX resume. Forward slashes work on Windows.
  path: "Alex_Rivera_Resume.pdf"

  # Terms that carry the most weight when Sweepy scores a posting.
  must_have_skills:
    - "Westlaw"
    - "LexisNexis"
    - "e-discovery"
    - "Contract Review"
    - "Legal Research"

  # 1.0 is standard. Raise it to reward exact skill matches.
  keywords_weight: 1.5

  # Interchangeable terms. Sweepy matches every member of a group either way.
  synonyms:
    - ["e-discovery", "ediscovery", "electronic discovery"]
    - ["legal research", "case law research"]
    - ["docketing", "case calendaring"]
    - ["legal assistant", "legal secretary"]
    - ["contract review", "contract analysis", "agreement review"]

  # Optional: one resume per role family. Sweepy picks the best fit for each posting.
  tracks:
    - name: "Paralegal Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Paralegal.pdf"
      color: "#1D4ED8"
      route_keywords: ["paralegal", "litigation", "e-discovery"]
    - name: "Legal Assistant Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Legal_Assistant.pdf"
      color: "#7E22CE"
      route_keywords: ["legal assistant", "legal secretary", "scheduling"]

# ─── Platforms ────────────────────────────────────
platforms:
  greenhouse: true
  ashby: true
  lever: true
  workable: true
  aggregators: false

  # Extra ATS domains. Sweepy labels matching postings with this name.
  custom:
    - name: "SmartRecruiters"
      domain: "smartrecruiters.com"
      enabled: true
    - name: "Breezy HR"
      domain: "breezy.hr"
      enabled: true

# ─── Sources ──────────────────────────────────────
sources:
  jobspy:
    linkedin: true
    indeed: true
    glassdoor: true
    zip_recruiter: true

  # Leave a list empty to fall back to the seed lists in data/sources/.
  ashby:
    orgs:
      - "crosby"
      - "normlaw"
      - "hargrove-firm"
      - "lawhive"
  workable:
    slugs:
      - "shegerianand-associates-1"
      - "harper-james"
      - "legalvision"
  builtinnyc:
    enabled: true
    categories:
      - "jobs/legal"
      - "jobs/legal/search/paralegal"

# ─── Cache and history ────────────────────────────
cache:
  enabled: true
  ttl_seconds: 3600       # reuse discovery results for an hour

history:
  enabled: true
  retention_days: 4       # hide a reported posting for four days
  match: "url+role"       # "url" matches only an identical posting address
  path: null              # null uses ~/.sweepy/history.db

orchestrator:
  timeout_per_source_seconds: 180
  circuit_breaker:
    failure_threshold: 5
    cooldown_seconds: 30

# ─── Report layout ────────────────────────────────
report:
  style: "cards"          # "cards" (default) or "legacy"
  cards_per_page: 6       # cards on each PDF page
  max_cards: 24           # 0 or less shows every match
  destinations: []        # extra folders for a copy of the PDF
  assessment: "agent"     # "keyword" accepts reports without agent judgments

# ─── Exports ──────────────────────────────────────
export:
  format: "pdf,csv,json"  # add "png" for page images
  output_dir: "results"
  tracking: true          # job-tracking columns in the CSV
  description_chars: 1000 # posting excerpt length in the CSV and JSON
  timezone: "local"       # clock behind the report filename stamp

简历跟踪（Resume Tracking）​

“轨道”即为命名后的简历。当您针对两个不同的职位/头衔，且希望每个职位发布都能根据相应的简历进行评分时，请使用“轨道”。

profiles/paralegal_nyc.yaml
resume:
  tracks:
    - name: "Paralegal Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Paralegal.pdf"
      color: "#1D4ED8"
      route_keywords: ["paralegal", "litigation", "e-discovery"]
    - name: "Legal Assistant Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Legal_Assistant.pdf"
      color: "#7E22CE"
      route_keywords: ["legal assistant", "legal secretary", "scheduling"]
  • name 用于标记该条目。报告卡上会显示这个标签，请写上一两个描述性的词语来说明它的含义。
  • path 指向该职位的简历 PDF 文件；DOCX 指向相应的文件。
  • color 用于设置徽章的颜色。可以使用十六进制代码（如 #1D4ED8）或颜色名称（如 navy）来指定颜色。
  • route_keywords：决定 Sweepy 应将哪些帖子分配到这个分类中。

Sweepy 根据关键词的匹配程度来分配帖子到相应的曲目中。它会比较帖子的标题和描述与每首曲目的 route_keywords（关键词）之间的全词匹配情况，并将帖子分配给匹配次数最多的曲目。如果有多首曲目的匹配次数相同，Sweepy 会优先选择列表中的第一首曲目。

每个条目包含四个字段：

提示

使用 route_keywords 将求职信息发布到招聘平台上，但招聘平台永远不会更改职位匹配的百分比（即职位匹配的准确性）。请在发布信息时添加每个职位类别实际使用的具体表述。

省略 tracks；Sweepy 将 resume.path 视为一个隐含的跟踪（track）选项。

求职简历的同义词​

resume.synonyms 用于表示意思相同的词语组。在 Sweepy 中，这些词语中的每一个都被视为等同的；因此匹配操作可以双向进行（即可以从任意一个词语开始进行匹配）。有关更详细的格式要求，请参阅 添加行业特定术语。

profiles/paralegal_nyc.yaml
resume:
  synonyms:
    - ["e-discovery", "ediscovery", "electronic discovery"]
    - ["legal research", "case law research"]
    - ["docketing", "case calendaring"]
    - ["legal assistant", "legal secretary"]
    - ["contract review", "contract analysis", "agreement review"]

一个组至少需要包含两个术语，否则 Sweepy 会忽略该组。匹配过程不区分大小写，并能处理单数和复数形式。该引擎仍能匹配完整的短语；因此，当您希望同时计算 legal research 和 legal researcher 时，请将它们作为独立的术语列出。

亚历克斯在简历中写下了“e-discovery”这个关键词。现在有一则招聘信息也使用了“electronic discovery”这个关键词，因为这两个词属于同一类别（即都属于描述职位或技能的标签）。

提示

每遇到重复出现的错误（即某个术语被错误地使用了两次），就创建一个新的分组，并将该错误内容（包括其原始表述）复制到新分组中。

常见的格式错误​

大多数出现问题的配置文件问题都可以归结为几个常见的错误。

Windows路径必须使用正斜杠（/）或双反斜杠（\）。 反斜杠（\）在Windows系统中被视为转义字符，因此会导致文件路径解析错误。例如，路径 C:\Users\Alex 会导致程序无法正确识别文件位置。

profiles/paralegal_nyc.yaml
resume:
  path: "C:/Users/Alex/Documents/Alex_Rivera_Resume.pdf"     # ✅ works
  # path: "C:\\Users\\Alex\\Documents\\Alex_Rivera_Resume.pdf"  # ✅ also works
  # path: "C:\Users\Alex\Documents\Alex_Rivera_Resume.pdf"      # ❌ breaks YAML
警告

路径中如果包含一个反斜杠（\），Sweepy 就无法读取您的个人资料。设置向导会自动将路径中的反斜杠替换为正斜杠（/），因此您在手动编辑时也需要保持这种格式。

注释以 # 开头。 Sweepy 会忽略该行中 # 之后的所有内容。请使用注释来说明某个值的重要性（例如示例配置文件中所做的那样）。

缩进决定了代码的结构。 每一层代码都需要向前缩进两个空格；在文件中的任何位置使用制表符（tab）都会导致YAML标记的失效（即该标记不再被识别）。
