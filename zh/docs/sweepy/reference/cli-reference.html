命令行参考

Sweepy 可以通过一个命令进行安装（sweepy），输入该命令后按 Enter 键即可。当需要使用非默认设置时，可添加相应的参数。所有配置文件、扫描操作和报告都从这里开始。

Terminal
sweepy

Alex 每天早上会使用这两个命令：首先使用 --run 使用上次保存的配置文件进行扫描；然后使用 --logs 查看扫描过程中出现的错误信息。

备注

所有命令都需要在 sweepy 文件夹内执行。如果上次操作后关闭了终端，请重新打开终端后再运行 cd sweepy。

命令参考​

不加任何参数运行 sweepy 可以打开 Sweepy 的控制面板。下表将各种参数按照其对应的功能进行了分类。

命令形式

在 sweepy 文件夹中运行 pip install -e . 时，系统会显示简化的命令形式；如果您的 Shell 系统找不到 sweepy，请重新打开终端或尝试运行 python swee.py。

扫描与配置文件​

标志功能说明
--run使用您上次保存的配置文件来执行扫描操作。
--profile <path>从 YAML 配置文件中执行扫描操作。
--setup打开搜索启动界面，用于执行搜索或设置个人资料。
--non-interactive根据用户设置的标志（flags）来构建或更新个人资料，而非通过提示进行操作。请将其与 --setup 配合使用。

单次运行覆盖（One-run overrides）​

标志功能说明
--no-dedupe将来自不同板块的重复帖子合并到一起进行处理。
--include-seen该报告还包含了之前一次数据扫描的结果。
--reset-history会忽略该用户资料中已报告的帖子。

文档​

标志功能说明
--docx <path>将 DOCX 格式的文件转换为 PDF 格式，然后程序结束。
--convert <path>将支持的文档转换为PDF格式，并将其保存在源文件旁边，之后程序退出。

求职搜索引擎​

标志功能说明
--list-engines列出所有可用的引擎、它们所读取的数据源以及它们的安装状态。
--install-engines [names]下载所有可选的引擎，或仅下载您指定的引擎。
--allow-engine-conflicts安装与已安装引擎存在冲突的引擎（忽略该引擎），并配合使用 --install-engines 进行后续处理。

更新与版本管理​

标志功能说明
--update下载最新的 Sweepy 代码并重新安装相关依赖项。
--check-update检查是否存在更新的 Sweepy 版本。
--version显示引擎的版本及其依赖关系。

日志记录​

标志功能说明
--debug在启用 logs/ 后开启调试日志记录功能。
--log-dir <dir>移动调试日志文件的位置。
--logs打印最新的调试日志内容。

无头模式配置​

当您使用 --setup 时，这些标志会用于生成配置文件。每个配置值都需要对应的标志；除非配置文件中已经提供了这些值，否则 --name、--titles、--location 和 --resume 是必需的。

标志功能说明
--sources <names>启用这些引擎（以逗号分隔）。
--jobspy-sites <sites>设置 JobSpy 的数据源（以逗号分隔）。
--hirehunt-sources <sources>设置 HireHunt 的数据源（以逗号分隔）。
--jobdrop-sites <sites>设置 JobDrop 的数据源（以逗号分隔）。
--openroles-companies <slugs>设置 OpenRoles 的相关域名（以逗号分隔）。
--apify-actor <actor>设置 Apify 的代理 ID。
--timeout <seconds>设置每个数据源的请求超时时间。
--cache-ttl <seconds>设置日志缓存的有效期。
--no-cache禁用发现缓存。
--history-days <days>设置某条帖子再次显示所需等待的天数。
--no-history每次运行时都会报告所有帖子的状态。
--job-tracking / --no-job-tracking开启或关闭 CSV 文件中的任务跟踪功能。
--name <name>设置个人资料的名称。
--titles <titles>以逗号分隔的形式设置目标标题。
--location <location>设置目标位置。
--resume <path>设置简历文件的路径。
--portfolio <value>用于为“sweep”功能添加一个资源库（portfolio），以便从中选取内容。支持输入URL、本地PDF文件、Markdown格式的文本文件或HTML类型的文件。若需添加更多资源来源，可重复使用该选项；若要将某个资源关联到某份简历中，请在资源名称前加上TRACK=前缀。
--portfolio-track <track>为没有 TRACK= 前缀的 --portfolio 值设置简历跟踪信息。

Sweepy 会先处理参数 --logs、--version、--update、--check-update 和 --list-engines、--install-engines，然后再转换文档内容；参数 --setup 会在最后执行；每个命令仅运行一次任务。

使用 --run 运行最后一个保存的个人资料。​

保存一次配置文件后，只需通过一条简短的命令即可完成整个扫描过程；Sweepy 会自动使用您上次保存的配置文件（profiles/.last_profile）。

Terminal
sweepy --run

Sweepy 会按以下顺序查找个人资料：

  1. 使用 profiles/.last_profile 创建个人资料：​

  2. 最新的个人资料信息位于 profiles/ 中。
  3. 先执行 3. profiles/custom_profile.yaml，然后执行 profiles/paralegal_nyc.yaml，最后执行 config.sample.yaml。

如果这些资源（或工具）中任何一个都不存在，Sweepy 会报告一个错误，并提示您参考 --setup。

使用 --setup 创建个人资料​

向导会打开搜索启动界面，并为您创建一个名为YAML的配置文件。

Terminal
sweepy --setup
启动板磁贴它的功能是
开始扫描使用您打开的配置文件进行扫描。状态栏会持续显示警告信息，直到您再次打开另一个配置文件为止。
加载配置文件允许您选择已保存的配置文件，以便在下一次扫描时使用。
Sweepy的工具箱打开下面列出的工具箱条目。
创建个人资料以简单的英语形式提问，随后会保存一个新的个人资料。
扫描设置可更改关键词的权重、卡片显示的限制、报告格式、历史记录的显示方式，以及 CSV 文件中的任务跟踪列内容。
退出 Sweepy保存您的更改并返回到命令行界面。

Sweepy's Toolbox中包含以下功能：

工具箱条目其功能
编辑现有资料从 profiles/ 加载个人资料并允许您进行修改，其中包括切换工作跟踪列的功能。
管理作业引擎可以开启或关闭作业引擎，并编辑它们的配置。
下载作业引擎在您确认后，可以选择安装所需的引擎。
添加或编辑聚合器可切换数据源并管理自定义聚合器。
切换调试日志功能用于切换配置文件中 debug 的值。
显示帮助为向导提供使用指南。
显示最近日志打印最新的调试日志条目。
将文档转换为PDF格式（可选）可将DOCX、DOC、TXT、MD或PDF格式的文件转换为PDF格式，并将其返回到工具箱中。
更新 Sweepy下载最新代码并重新安装依赖项。
退出用于关闭工具箱中的向导界面。

您可以随时重新运行向导来创建新的配置文件或编辑现有的配置文件。系统不会删除您之前的配置文件。设置 Sweepy 页面会逐步引导您完成所有设置步骤。

将文档转换为PDF（附加功能）：即使没有配置文件，也可以使用此功能。选择“将文档转换为PDF”，然后提供文档路径。​

直接打开配置文件进行编辑：无需通过向导，可以直接通过指定路径打开配置文件进行编辑。

输入Sweepy 的功能是什么
.docx使用python-docx和reportlab重新生成文本文件，必要时也会使用Microsoft Word。
.doc通过Microsoft Word渲染文档内容（需要docx2pdf文件作为输入）。
.txt、.md生成包含标题和项目符号的文档。
.pdf将文件传递给指定的输出路径，或将其复制到该路径。

当输入的路径无效时，Sweepy会显示一条警告信息，并重新打开命令提示符；如果输入有拼写错误，系统会将用户返回到初始的向导界面。

直接跳转到个人资料页面​

添加 --profile 以在不使用启动平台（launchpad）的情况下打开一个配置文件进行编辑。

Terminal
sweepy --setup --profile profiles/paralegal_nyc.yaml

向审核界面加载该文件的当前设置值。

无需提示即可创建个人资料。​

当需要在所有机器上使用相同的配置时，可以通过脚本自动生成个人资料；此时需要添加 --setup --non-interactive 并将每个配置项作为参数传递。

Terminal
sweepy --setup --non-interactive `
  --name "Alex Rivera" `
  --titles "Technical Writer,UX Writer" `
  --location "New York, NY" `
  --resume C:\Users\Alex\sweepy\resume.pdf `
  --sources jobspy,openroles `
  --openroles-companies figma,stripe,notion `
  --timeout 120 --no-cache

Sweepy 在写入文件之前会检查所有已启用的工具；如果缺少某个配置项（例如 OpenRoles 公司名称），它会输出 Error: 并以代码 1 结束执行。如果没有 --profile，Sweepy 会使用用户的名字和职位名称来生成文件名（例如：Alex 的个人资料会被保存到 profiles/alex_rivera_technical_writer.yaml）。若需更新现有文件，请添加 --profile <path> 参数。

Sweepy 的更新流程：​

在 Sweepy 的工具箱 中执行 “更新 Sweepy” 命令即可完成相同更新操作。

Terminal
sweepy --update

Sweepy 会从远程服务器获取数据（origin），快速推进当前开发分支的进度，并执行python -m pip install -r requirements.txt命令；如果被跟踪的文件包含未提交的更改，它将拒绝执行操作，因此不会覆盖本地编辑的内容。建议使用只读模式来检查是否有更新。

Terminal
sweepy --check-update

“Sweepy” 在 “Sweepy 的工具箱” 中运行的是相同的更新。

覆盖特定命令的执行结果：​

列出所有引擎、它们读取的板卡以及安装状态：

Terminal
sweepy --list-engines

下载可选引擎：

Terminal
sweepy --install-engines all

当 JobSpy 持有冲突的配置时，all 配置会跳过 JobDrop 功能；需要单独通过--allow-engine-conflicts命令安装 JobDrop。

Terminal
sweepy --install-engines jobdrop --allow-engine-conflicts

安装某个引擎后，该引擎会处于关闭状态。您可以在配置文件中的 sources.enabled 处将其启用，或者在无头（headless）设置过程中通过 --sources 参数来激活它。如果安装失败，命令会以代码 1 退出。可选的引擎列表 中列出了所有可用的引擎。

使用 --profile 运行一次扫描操作。​

为每个城市或角色类型创建一个独立的个人资料（profile），然后用 --profile 指向您想要查看的个人资料。其余的工作由 Sweepy 完成。

Terminal
sweepy --profile profiles/paralegal_nyc.yaml

请替换为您自己的文件名。当您希望 Sweepy 重用上次保存的配置文件时，请使用 --run。

提示

为每个城市或角色类型存储一个配置文件（profile）。通过更改文件名来切换不同的搜索条件。

覆盖某次运行结果​

--run 和 --profile 允许设置三个覆盖选项（overrides）。每个覆盖选项仅适用于相应的命令，且不会影响其他配置项或配置文件的整体结构。

Terminal
sweepy --run --no-dedupe
sweepy --run --include-seen
sweepy --run --reset-history

当两个板块发布相同的内容时，--no-dedupe会保留这两个板块的列表信息；“sweep”功能仅会报告新的帖子；而个人资料中的history.retention_days设置默认显示期限为四天。--include-seen功能还会显示被隐藏的帖子。单独运行--reset-history可以清除这些历史记录并直接退出程序，无需执行“sweep”操作。

扫描过程中会发生什么​

每次扫描都遵循相同的五个步骤。

阶段发生的事情
1. 配置文件加载读取您的YAML文件并检查其中的设置。
2. 发现功能该功能会在您启用的平台上运行数据抓取工具（scrapers），并收集相关内容。
3. 验证删除无效链接并检测“软404”重定向。无法被验证的文件会继续留在处理流程中。
4. 分析解析您的简历PDF或DOCX文件，检查其中是否存在重复的术语，然后为每个职位生成相应的应用提示。
5. 生成生成带有日期戳的PDF、CSV和JSON文件；将png文件添加到输出格式中（用于页面图片）。

在执行过程中，终端会依次显示每个处理阶段的进度（从[1/5]到[5/5]）。首次运行时会显示全部输出结果。

将DOCX文件转换为PDF格式（使用--docx）​

将--docx文件导入Sweepy程序，程序会将其转换为PDF格式并保存后退出。

Terminal
sweepy --docx path/to/resume.docx

接着Sweepy会询问您希望将PDF文件保存到哪里。

Terminal output
Where should the PDF go? (leave blank to save next to the DOCX):

如果答案为空，请按 Enter 键，PDF 文件将保存到 DOCX 文件旁边，且文件名与 DOCX 文件名相同。若要将其保存到其他位置，请输入完整路径。无论采用哪种方式，Sweepy 都会显示 PDF saved: 以及最终保存位置。

备注

如果您的电脑安装了Microsoft Word，Sweepy会优先使用docx2pdf文件来生成PDF；否则会使用DOCX文件。

使用--convert转换任何文档​

--convert会自动运行并生成新的PDF文件（该文件会保存在原始文件旁边）。只需指定.docx、.doc、.txt、.md或.pdf文件作为输入即可。

Terminal
sweepy --convert path/to/resume.docx
Terminal output
PDF saved: C:\Users\Alex\sweepy\resume.pdf

输出文件会保留原始文件名，但扩展名会被替换；notes.md文件会被保存在与notes.pdf相同的文件夹中。如果.pdf文件已经存在，Sweepy会生成This file is already a PDF:文件并保持原文件不变。

输入Sweepy 的功能是什么
.docx使用python-docx和reportlab重新生成文本文件，必要时也会使用Microsoft Word。
.doc通过Microsoft Word渲染文档内容（需要docx2pdf文件作为输入）。
.txt、.md生成包含标题和项目符号的文档。
.pdf生成后的文件不会被修改，程序会仅输出其保存路径。

如果某个文件缺失或不被支持，程序会输出 “Error:” 并以代码 “1” 退出。这样一来，该命令就可以安全地用于脚本和定时任务中。

生成PDF文件后，只需在个人资料中指定resume.path文件的路径，然后运行sweep命令即可。

使用--version检查版本信息​

通过此命令确认引擎及其依赖库是否已正确安装。

Terminal
sweepy --version
Terminal output
Sweepy v3.1.0
Python 3.13.1 | pymupdf 1.28.2 | reportlab 5.0.1
Ready to sweep.

如果pymupdf或reportlab文件无法正常读取MISSING文件，请重新安装相关依赖库。安装指南中有详细步骤。

启用调试日志​

调试日志会记录引擎的运行过程（逐步显示）。可以通过标志、配置设置或环境变量来启用调试日志。

方法设置位置日志保留时间
--debug flag将其添加到您的终端命令中。该设置仅对当前运行有效（即仅在当前命令执行期间生效）。
debug: true将它添加到您的 YAML 个人资料中。每次运行时都会显示该内容，直到您将其删除为止。
将其设置为环境变量（SWEEPY_DEBUG=1）。该设置会在每次终端运行期间持续生效，直到您关闭终端为止。

可以将此标志添加到任何扫描任务中；

Terminal
sweepy --debug --profile profiles/paralegal_nyc.yaml

或者在您的个人资料中永久启用日志记录功能：

profiles/paralegal_nyc.yaml
# Write a rotating debug log under logs/ on every run.
debug: true

或者，您也可以通过设置环境变量来实现相同的功能。

Terminal
$env:SWEEPY_DEBUG = "1"
sweepy --profile profiles/paralegal_nyc.yaml

在 macOS 或 Linux 系统中，将第一行替换为 export SWEEPY_DEBUG=1。

Sweepy 将日志文件写入位于应用文件夹内的 logs/ 文件中；需要将这些日志发送到其他位置时，可以使用 --log-dir 来完成传输。

Terminal
sweepy --debug --log-dir C:\Users\Alex\sweepy-logs --profile profiles/paralegal_nyc.yaml

要在不打开文件的情况下阅读最新的条目，请运行：

Terminal
sweepy --logs
备注

--logs 命令会持续输出 No debug logs found. Run Sweepy with --debug to enable logging.，直到生成调试日志为止。

安排每日运行任务​

招聘团队整周都在发布新的职位信息。每天早上运行相同的命令，您就能尽早获取到这些招聘信息。

Terminal
sweepy --profile profiles/paralegal_nyc.yaml

当系统检测到新的帖子时，Sweepy会生成相应的报告文件。这些报告文件的名称中会包含用户信息、日期和时间，例如paralegal_nyc_2026-10-08-081500.pdf和paralegal_nyc_2026-10-08-081500.csv所示。当Sweepy通过MCP（一种数据处理工具）执行扫描任务时，它会在文件名中添加额外的标识符mcp（如paralegal_nyc_mcp_2026-10-08-081500.pdf所示），以便区分不同的报告文件。报告中的日期和时间来自export.timezone中的时钟系统；该时钟系统的默认设置是local。您也可以将日期和时间设置为UTC所示的值，或者使用IANA中的命名规则（例如America/New_York），或者通过-05:00指定时区差来为文件添加时间戳。这样的时间戳机制可以防止同一次搜索产生的文件相互覆盖，从而确保results中保存了完整的搜索历史记录。

“Sweeps”仅扫描新的帖子；默认情况下，它会将扫描到的每个帖子记录在系统中四天。如果某天早上没有发现新帖子，“Sweeps”会输出No new postings since your last sweep并停止生成报告文件；同样地，当所有被检测到的链接都已失效时，它也会停止生成报告文件。

在 Windows 上安排任务（或日程）​

  1. 从“开始”菜单中打开任务计划程序。
  2. 选择 创建基本任务，并将其命名为 Sweepy morning sweep 之类的名称。
  3. 选择“每日”，然后选择一个开始时间，例如上午8:00。
  4. 对于该操作，请选择“启动一个程序”。
  5. 将 Program/script 设置为您的 Python 可执行文件。在 PowerShell 中运行 (Get-Command python).Source，以打印该文件的路径。
  6. 将 添加参数 设置为 swee.py 的完整路径加上配置文件："C:\Users\Alex\sweepy\swee.py" --profile profiles\paralegal_nyc.yaml。
  7. 将 Start in 设置为您的 sweepy 文件夹。引擎会从该文件夹中查找 profiles 并写入 results。

在 macOS 和 Linux 上安排任务（或日程）​

  1. 使用 crontab -e 打开您的 crontab 文件。
  2. 每天早上8:00（根据您机器所使用的时区），会自动运行一次清理任务。
Terminal
0 8 * * * cd /path/to/sweepy && python3 swee.py --profile profiles/paralegal_nyc.yaml

cd 这个部分非常重要：该工具会根据您启动它的文件夹位置来读取 profiles 并写入 results。请使用安装了 Sweepy 包的 python3 环境进行操作。用 python3 -c "import swee" 来测试它的功能。

警告

定时任务会在没有终端窗口的情况下自动运行，因此之前会话中的 Shell 配置不会被继承。请先手动运行一次命令，确认其正常工作后再设置定时任务。
