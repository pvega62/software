Sweepy MCP 工具参考

在 server.py 中，MCP 服务器提供了这十三个工具的接口；MCP 集成 页面介绍了注册流程和常见工作流程。本页面列出了所有工具的调用签名（signature），因此您可以在助手执行操作前预测其具体效果。

返回的数据结构​

每个工具都会在文本块中返回一个 JSON 格式的字符串：成功的结果以 "status": "ok" 开头，失败的结果以 "status": "error" 开头，并包含 message 用于说明失败原因；失败的操作还会报告 job_id 和 sweep_status: "failed" 的详细信息。

助手通过发送 tools/call 请求来调用这些工具；某些工具在执行时会长时间阻塞系统。

Request
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "run_sweep",
    "arguments": {
      "profile_path": "profiles/tech_writer.yaml",
      "wait_seconds": 300
    }
  }
}
Response, truncated
{
  "status": "ok",
  "sweep_status": "completed",
  "job_id": "b41e9c0d7a12",
  "discovered_count": 137,
  "new_count": 41,
  "previously_seen_count": 96,
  "active_count": 137,
  "top_match": {
    "title": "Senior Technical Writer",
    "company": "Acme",
    "match_score": 92,
    "url": "https://example.com/jobs/4412"
  },
  "reports": {
    "pdf": "C:\\Users\\Alex\\sweepy\\results\\tech_writer_mcp_2026-10-27-223115.pdf",
    "csv": "C:\\Users\\Alex\\sweepy\\results\\tech_writer_mcp_2026-10-27-223115.csv"
  },
  "card_count": 24,
  "assessment_mode": "agent",
  "assessment_required": true,
  "elapsed_seconds": 214.6,
  "message": null
}

完整的返回数据会包含 top_roles、job_ids、skipped_sources 和 debug_log 等字段。

个人资料与求职工具​

create_profile​

验证所有启用的求职引擎，然后生成个人资料文件。

参数类型默认值说明
name字符串必填用于填写个人资料的完整姓名。
titles字符串数组必填目标职位名称（例如 ["Technical Writer", "UX Writer"]）。
location字符串必填目标工作地点（例如 "New York, NY"）。
resume_path字符串必填PDF 文件或 DOCX 格式简历的路径。
resume_tracks对象数组null每份简历对应一个条目，包含 name 和可选的 path；Sweepy 会根据目标职位对简历进行评分。
portfolios对象数组null作品集条目，每个条目可包含 track、url 或 path、pieces 等信息。
pieces_per_card整数3每张作品集卡片上展示的作品数量（1 至 10 件）。
remote_only布尔值false仅显示完全远程工作的职位。
include_hybrid布尔值true在结果中保留混合办公模式的职位。
min_salary整数0最低年薪要求；0 表示无最低要求。
must_have_skills字符串数组null有助于提高匹配度的技能关键词。
synonyms数组数组null可互换的技能分类（例如 [["docs-as-code", "documentation as code"]]）。
platforms对象null平台信息会合并到个人资料的 platforms 部分。
sources_config对象null选择的求职引擎信息会合并到个人资料的 sources 部分；所有引擎在写入前都会被验证。
cache_config对象null缓存设置（enabled 和 ttl_seconds）。
orchestrator_config对象null超时和断路器设置。
history_config对象null控制哪些职位会被跳过的规则设置。
job_tracking布尔值true将工作跟踪信息添加到 CSV 文件中，并保留之前的数据。
assessment字符串"agent"报告生成规则：当任何卡片中的关键词存在重复时，阻止报告生成（agent）；仅允许基于关键词的报告（keyword）。
output_filename字符串null自定义路径（YAML）；默认使用 profiles/{name}_{title}.yaml；Sweepy 会将路径中的所有非字母数字字符替换为 _。

orchestrator_config 接收一个包含 timeout_per_source_seconds 和带有 failure_threshold 与 cooldown_seconds 的对象的 circuit_breaker。

history_config 接受 enabled、retention_days、match 和 path 作为参数；retention_days 默认值为 4；match 允许使用 url 或 url+role；path 默认值为 ~/.sweepy/history.db。

portfolios 可以是在线 URL、本地 PDF 文件、Markdown 文本、文本文件或文件列表；为每个项目指定一个名称（track），以便为每个项目创建单独的作品集，并将选定的内容传递给 submit_judgments（作为 portfolio_highlight）；使用 set_portfolio 修改已存在的作品集。

返回 profile_path、enabled_engines、engines_not_enabled 以及新作品集的详细信息（resume_documents）；每份简历都会显示其对应的作品集及其使用情况（path），但不包括解析后的文本内容。

set_portfolio​

当用户为作品集命名后，该函数会更新或替换已保存的作品集。

参数类型默认值说明
profile_path字符串必填现有作品集文件的路径（YAML）。
portfolios对象数组null需要添加的条目。如果没有 track，则该条目适用于所有项目/轨道（track）。使用空列表（通过 replace 传递）可以删除所有项目/轨道的信息。
replace布尔值false在添加新项目之前是否删除已保存的作品集；false 会保留新项目中未提及的所有旧项目。
pieces_per_card整数3每张卡片上显示的 portfolio 作品数量（1 至 10 件）。若未设置，则保留默认值。

传递 portfolios、pieces_per_card 或两者。一个条目可以包含可选的 track、url 或 path，以及一个可选的 pieces 列表（其中包含 {title, url, tags}）。

返回 profile_path、resume_tracks、portfolio_configured、portfolio_sources、portfolio_pieces_per_card 和 portfolio_guidance；如果用户没有作品集，portfolio_guidance 会提示用户进行相应操作。

run_sweep​

启动五阶段处理流程并返回关键词重复度的评分结果（不依赖大型语言模型）。

参数类型默认值说明
profile_path字符串null配置文件（profile）的路径 YAML。如果该路径被省略，Sweepy会使用最近保存的配置文件；如果没有最近保存的文件，则会依次使用 profiles/ 中指定的配置文件、磁盘上的第一个常规配置文件（profiles/custom_profile.yaml、profiles/paralegal_nyc.yaml 或 config.sample.yaml）。
deduplicate布尔值true本次操作会合并来自不同板块的重复 URL 和匹配的帖子内容。
include_seen布尔值false用于报告之前进行的扫描结果，并更新相关历史记录。
wait_seconds整数45调用返回结果之前最长的阻塞等待时间。该值的范围限制在 0 到 600 之间。
timestamp字符串null报告文件名的用户本地时间，格式为 YYYY-MM-DD-HHMMSS 或 ISO 8601 格式。助手会使用自己已知的用户时间来标记每个报告文件的时间戳，而不是服务器的时间。

实时扫描（live sweep）的运行时间通常会超过客户端的超时时间。为了解决这个问题，该流程会在后台线程中继续执行。当某个操作返回 sweep_status: "running" 时，会同时生成一个 job_id；将这个 ID 传递给 get_sweep_status，直到其状态变为 completed。

当使用相同的配置文件和参数再次调用该函数时，系统会继续执行正在运行的任务，而不会启动新的任务。服务器进程必须保持运行状态；所有任务的ID都会保存在内存中，重启会清除这些ID。

函数返回以下三种类型的响应数据：

  • 运行中：包含sweep_status、job_id、progress，以及step、total、label、elapsed_seconds、debug_log和message。
  • 已完成的任务编号为：sweep_status、job_id、discovered_count、new_count、previously_seen_count、active_count、top_match、top_roles、reports、job_ids、card_count、assessed_count、assessment_mode、assessment_required、skipped_sources、elapsed_seconds、debug_log 和 message。其中，top_roles 对应前五个任务。
  • 失败：status: "error"、message、job_id 和 sweep_status: "failed"。

如果缺少或无法读取用户的个人资料路径，任务将无法启动；此类错误没有对应的编号（job_id）。

当所有发现的帖子都是重复内容时，previously_seen_count会显示总数，而active_count会显示“0”。此时应调用run_sweep，并将include_seen设置为true以对这些重复帖子进行审核。

当使用 MCP 工具进行数据清理时，生成的文件名会与命令行中指定的名称完全相同，并会在文件名前添加一个 mcp 标记（例如：results/tech_writer_mcp_2026-10-27-223115.pdf、.csv 和 .json）。而通过 CLI 或向导工具生成的文件名则不会包含该标记，这样文件夹就能清晰地显示每个报告是由哪个路径生成的。可以使用 timestamp 参数为文件添加用户的自定义日期和时间戳；如果没有这个参数，Sweepy 会从用户配置文件中的 export.timezone 获取当前时间。

get_sweep_status​

等待由 run_sweep 启动的扫描任务完成，并报告其进度。

参数类型默认值说明
job_id字符串null从 run_sweep 中获取扫描任务ID。默认使用最近一次执行的扫描任务的ID。
wait_seconds整数45调用返回结果之前最长的阻塞等待时间。该值的范围限制在 0 到 600 之间。

每个响应都会返回与对应的run_sweep结果相同的字段。如果某个job_id字段缺失或未知，系统会返回一个错误信息，并指向run_sweep（即相关的错误处理逻辑）。

完成一次数据清理（sweep）操作后，相关数据也会被加载到实时处理系统中；因此，当状态显示为 completed 时，get_jobs、submit_judgments 和 render_report 这些操作就会生效。

get_jobs​

返回当前会话中保存的卡片记录，这些记录按照关键词的重叠程度或提交的匹配分数进行排序。

参数类型默认值说明
profile_stem字符串null用于加载已保存会话的标识符，例如 pedro_writer。
results_dir字符串"results"包含 report_session.json 的文件夹。
limit整数null需要返回的卡片数量。若省略该参数，则返回所有卡片；Sweepy 规定至少需要返回一张卡片。
0 `boolean` 12 仅返回没有发布内容的卡片。 3 仅返回有发布内容的卡片。

返回当前活跃用户的信息（包含 count、session_count、needs_description_count、jobs），以及该用户的简历文件。在数据扫描过程中，系统会添加 sweep_status、running_job_id、progress 和 message；这些信息用于提示用户某些卡片的数据早于此次扫描的时间。

简历文件​

resume_documents会为每个简历文件列出一条记录，每条记录包含使用该文件的用户名（path）、使用该文件的系统（tracks）以及解析后的文档内容（text）。如果多个系统共享同一份文件，则只记录一条记录，以避免重复显示相同内容。此外，系统还会报告resume_default_path、resume_configured和resume_guidance的相关信息。

该系统的辅助判断功能仅依据求职者资料中的must_have_skills和synonyms部分来评估其是否符合招聘要求。评分结果实际上反映的是这些信息的有效性，而非求职者的整体能力。

辅助系统会以招聘人员的视角来读取求职者的文件内容，重点考察可转移技能、工作经验范围、职位层级、使用过的工具以及工作成果。随后，系统会根据招聘广告中使用的申请跟踪系统（ATS）的解析规则对文件进行评分。

  • 出现在标准Experience或Skills部分的任何信息都会被视为有效的评估依据。
  • 如果某个术语同时出现在表格、页眉、页脚、图片或双栏侧边栏中，那么它的权重会降低（即对评分的影响较小）。
  • 当申请链接显示具体的ATS系统名称时（如Workday、Greenhouse、Lever、iCIMS、Taleo、Workable或SmartRecruiters等），辅助系统会明确指出所使用的ATS系统类型。
  • 所有未被系统识别或无法读取的文件会导致concerns部分显示为空内容，但系统仍会记录文件路径以便后续排查问题。

submit_judgments​

将助手的评估结果合并到一张卡片中，或一次性合并到整批卡片中；只有非空字段才会被更新。

参数类型默认值说明
job_id字符串null来自 run_sweep 或 get_jobs 的稳定卡片 ID。除非指定了 judgments，否则此字段为必填项。
match_pct整数null匹配百分比（范围：0–100）。请先读取 resume_documents，然后按照帖子中的 ATS（Application Tracking System）解析方式对文件进行评分。提供该评分后，卡片标签会更新为 MATCH。
resume_track字符串null用于在卡片上显示的简历信息。
resume_color字符串null该曲目的徽章颜色。
domain字符串null卡片上显示的角色领域。
summary字符串null卡片摘要文本。
requirements字符串null需求说明文本。
alignment字符串null用于将简历中的相关内容与所申请职位关联起来。
concerns字符串null会对候选人产生不利影响的因素：未满足的职位要求、工作经验空白期、专业领域不匹配、对工作环境的期望与实际情况不符、薪资低于最低标准，或者某些内容会被解析工具忽略。
has_extended_response布尔值null标记需要书面回复的帖子。
app_format字符串null应用程序的格式，例如门户网站或电子邮件。
comp字符串null补偿信息行。
benefits字符串null“优势”部分。
page_theme字符串null卡片主题的覆盖设置。
portfolio_fit整数null项目组合的评分（范围：0–100分）。该卡片会以 PORTFOLIO FIT 的形式显示该评分。
portfolio_highlight字符串null用于指定随应用程序一起发送的文件/信息。如果没有指定，系统会使用用户资料中保存的文件。
description字符串null从卡片URL中读取的内容（适用于那些无法被Sweepy解析的卡片）。
judgments数组null包含“判断对象”的列表；每个对象前面都带有job_id标识符以及其他相关字段。请勿将此数组与job_id数组合并。

评估的是文档本身，而非个人资料。get_jobs 返回的是解析后的简历文本（存储在 resume_documents 中），而 must_have_skills 和 synonyms 仅负责执行简单的处理流程（即“确定性处理”）。请记录下解析器可能遗漏的信息，例如侧边栏图形中显示的技能列表（这些信息存储在 concerns 中）。

最终生成的卡片内容以job格式返回；批量处理时，会同时返回applied、jobs和rejected三个数组；其中rejected数组会标记出那些在当前会话中缺失的条目。

import_jobs​

该功能会添加通过独立研究验证过的角色信息；Sweepy默认不会对这些角色进行确认。

参数类型默认值说明
jobs_json字符串必填包含卡片记录的数组。
validate布尔值false在导入之前，会先对每个 URL 进行链接检测。

最终返回imported和skipped两个数组；如果返回的是速率限制或机器人防护相关的响应，则表示该卡片未通过验证。

render_report​

从当前会话中生成卡片的PDF版本。

参数类型默认值说明
profile_stem字符串null用于加载已保存会话的配置标识符。
results_dir字符串"results"用于存放默认输出结果和已保存会话数据的文件夹。
output_filename字符串null明确的 PDF 路径。该路径必须位于工作区内；如果路径为空，系统会将 {profile_stem}_mcp_{YYYY-MM-DD-HHMMSS}.pdf 写入 results_dir 中。该路径名称需与命令行中的日期格式相匹配，并会添加一个 mcp 标记。
playbook字符串""纯文本策略说明。Sweepy 会转义 & 和尖括号（< >），并将 **bold** 显示为粗体；换行符会被保留为实际的换行。Sweepy 会将文本保存在会话中，因此后续调用时可以直接使用已保存的文本。如果未保存任何文本，则生成的 Playbook 为空。
timestamp字符串null用户用于指定默认文件名的本地时间，格式为 YYYY-MM-DD-HHMMSS 或 ISO 8601 格式。该参数仅在 output_filename 为空时生效。

最终返回pdf_report、pages、card_count和playbook_saved三个数组。

默认情况下，所有个人资料的显示状态为 report.assessment: "agent"（即这些资料在页面上不会被展示），除非某张卡片中的关键词与其他资料有重叠。系统会列出导致错误的个人资料编号（unassessed_job_ids 和 unassessed_titles），以便助手判断如何处理这些情况。您可以将 report.assessment: "keyword" 设置为允许混合类型的报告显示；或者将 SWEEPY_REQUIRE_JUDGMENTS=1 设置为对所有个人资料都应用相同的筛选规则；也可以将 export_report 设置为对特定个人资料应用特定的筛选条件。

结果与历史记录工具​

get_results​

从磁盘读取最新的卡片数据（无需重新执行发现或评分流程）。

参数类型默认值说明
profile_stem字符串null用于过滤结果文件的标识符；省略该标识符可读取最新的结果文件。
results_dir字符串"results"用于存放结果文件的文件夹。
limit整数10需要返回的顶级职位数量。该数值的范围限制在 1 到 100 之间。

函数返回 result_file, pdf_report, csv_report, total_roles, 和 top_roles；每个角色对象包含 title, company, location, match_score, match_kind, resume_track, domain, url, 和 playbook。

标有 KEYWORD OVERLAP 的分数是经过初步计算得出的固定值；在将这些结果视为匹配项之前，请先使用 get_jobs 和 submit_judgments 进行进一步处理。

export_report​

参数 类型 默认值 描述

参数类型默认值说明
json_source字符串null清扫任务的路径（JSON）。该路径的优先级高于profile_stem。
profile_stem字符串null用于查找最新匹配项的配置标识符。
results_dir字符串"results"用于存放结果文件的文件夹。
formats字符串数组["pdf"]输出格式：pdf、png、csv 或 json。
candidate_name字符串"Job Seeker"PDF页眉中的名称。
output_dir字符串null输出文件夹。默认为包含源代码文件的文件夹。
job_tracking布尔值null将工作跟踪信息添加到 CSV 导出文件中；若未设置，则遵循该用户配置文件中的 export.tracking 设置。

该函数返回source_file、roles_exported、generated和errors这三个值。当请求包含这些格式时，generated对象会包含pdf、pdf_pages、png、csv、csv_rows和json这些数据。如果请求类型为PNG，系统会优先生成PDF文件。JSON的输出内容会被写入{stem}_export.json文件中，但不会覆盖作为输入的原始数据文件（即用于生成PDF文件的文件）。

clear_history​

该系统会“忘记”之前已报告的帖子，以便下一次扫描时能够再次检测到这些帖子。

参数类型默认值说明
profile_path字符串null个人资料文件的路径 YAML。
profile_stem字符串null个人资料标识符（例如 pedro_writer）。

该工具会返回 scope、cleared 和 remaining 这三个值。每个用户的操作历史记录都是单独存储的（即每个用户都有自己的历史记录）。在完成数据清理操作后（即执行“sweep”命令后），如果未传递任何参数，则该工具会自动清除该用户的历史记录；此时系统会从正在运行的服务器中读取该用户的历史记录。因此，在重启系统后，需要传递 profile_path 或 profile_stem 参数来重新加载该用户的历史记录。

文档转换工具​

convert_document​

将 .docx、.doc、.txt、.md 或 .pdf 格式的内容转换为 PDF 格式；PDF 源文件在转换过程中保持不变。对于旧版本的 .doc 文件，则需要使用 Microsoft Word 进行处理。

参数类型默认值说明
document_path字符串必填需要转换的文件路径。
pdf_path字符串null输出路径。默认为源文件夹。

返回 pdf_path 和 source_path。

convert_docx​

使用python-docx和reportlab将解析后的简历转换为PDF格式；如果系统支持Microsoft Word，则会优先使用docx2pdf进行转换。

参数类型默认值说明
docx_path字符串必填需要处理的文件路径（即 .docx 文件的路径）。
pdf_path字符串null输出路径。默认为 DOCX 文件夹。

返回 pdf_path。

路径设置​

这些工具会将生成的输出文件保存在名为 “Sweepy” 的文件夹中；如果目标文件位于该文件夹之外，程序将无法正常运行，直到您将参数 SWEEPY_ALLOW_EXTERNAL_WRITES 设置为 1 为止。输入文件可以是程序能够打开的任何路径。
