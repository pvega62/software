让匹配更精准的简历格式

Sweepy 为简历文件中的文字评分。打开文件时，它提取文本并与职位比对。格式决定引擎能读到多少文本。

第二栏、文本框或扫描页都可能让整个技能列表对引擎不可见。只调整一处格式，往往就能提高匹配度，而无需改动任何一句经历描述。

备注

本页介绍 Sweepy 如何读取简历。评分公式和报告版式参见理解结果。

Sweepy 能读取的内容​

Sweepy 读取 resume.path 指向的 PDF 和 Word 文件。让路径指向 .docx，Sweepy 会直接读取其中的段落和表格。你无需预先转换 Word 简历。编辑器同时提供两种格式时，请保留 .docx。第三方转换器可能以不同顺序重建页面，Sweepy 就会读到改变后的顺序。

需要 PDF 副本时，请使用 Sweepy 自带的转换器。它用同样的段落和表格重建干净的单栏 PDF。两种文件提取出的文字相同。参见用 --convert 转换任意文档。

以下问题会阻碍文本提取：

  • 非 PDF、非 DOCX 文件。 只有 PDF 或 DOCX 能产生可评分的文本。.pages、.odt、.doc 或 .txt 文件无法提供任何内容。Sweepy 的转换器可处理 .txt 和 .md 文件，并通过 Microsoft Word 处理 .doc 文件。.pages 或 .odt 文件需先在各自应用中导出。
  • 无文本层的扫描页。 扫描件给 Sweepy 的是文字图片，而非文字本身。Sweepy 找不到文本层，评分便回退为只用 must_have_skills。
  • 受密码保护的 PDF。 Sweepy 无法打开加密文件。保存文件前请先移除密码。
  • 文件缺失或损坏。 路径错误会记录警告并跳过提取。此时只有 must_have_skills 决定分数。
警告

当 Sweepy 无法读取简历且 must_have_skills 为空时，每个职位都得 75%。该数值无法体现排序，因为报告中每个职位都是同一分数。

提示

让 Sweepy 处理扫描件之前，先运行光学字符识别（OCR）。OCR 会添加真正的文本层，引擎才能读到你的文字。多数扫描仪应用和 PDF 编辑器都提供 OCR 选项。

做一次复制粘贴测试​

打开简历，全选文字，粘贴到纯文本编辑器中。纯文本会显示提取顺序，带格式的视图则会掩盖这一点。

各平台的复制快捷键
  • 在 Windows 上，用 Edge、Chrome 或 Acrobat 打开 PDF。按 Ctrl+A 和 Ctrl+C，然后粘贴到记事本。
  • 在 macOS 上，用 Preview 打开 PDF，按 ⌘+A，再按 ⌘+C。粘贴前用 ⇧+⌘+T 把 TextEdit 切换为纯文本。
  • 在 Linux 上，用 Evince 或 Okular 打开 PDF，按 Ctrl+A，再按 Ctrl+C。将文本粘贴到 gedit 或 Kate 等编辑器。

在 macOS 键盘上，⌘ 是 Command 键，⇧ 是 Shift 键。

如果粘贴结果混乱、空白或顺序错乱，Sweepy 读到的也是同样的内容。运行扫描前请先修正文件。

会破坏扫描的格式​

文本提取器沿页面横向读取。版式会改变返回文本的顺序。申请人跟踪系统采用同类提取方式。

格式Sweepy 读到的内容
两栏或更多栏各栏内容交错混杂，因为提取器沿页面横向读取。
表格、文本框和侧边栏内容可能错位，或与相邻内容合并。
图片、图标和图表提取会跳过一切以图片形式绘制的内容，包括技能条和徽标。
页眉和页脚许多解析器会跳过该区域。请把姓名和联系方式放在正文中。
连字符换行词条被拆到两行（先是 e-，后是 discovery）会破坏整词匹配。
连字和装饰性字体fi 和 fl 连字及特殊字形可能提取为乱码。
表情符号和自定义项目符号这些内容会丢失或乱码。请使用普通连字符或圆点项目符号。

申请人跟踪系统的偏好​

申请人跟踪系统（ATS）用与 Sweepy 相同的提取方式解析大量简历。请为它们提供一栏干净的真实文本。

  • 单栏，自上而下。 不要使用带侧边栏的双栏设计。
  • 朴素的章节标题。 使用 Experience、Education 和 Skills。标题中避免表格和图标。
  • 只用真实文本。 不要使用图片式标题、徽标或技能条。
  • 标准字体。 Arial、Calibri、Helvetica 或 Times New Roman，字号 10-12pt。
  • 普通项目符号和统一日期。 全文使用同一种日期格式，例如 Jan 2024 – Present。
  • 倒序排列。 多数招聘人员和解析器都期望如此。
  • 联系方式放在正文。 ATS 解析器常会剥离页眉和页脚。
  • 从文字处理软件导出。 从编辑器保存 PDF，并保留 .docx 以备门户网站要求。
  • 沿用职位措辞。 若职位写的是 e-discovery 或 docs-as-code，请使用同样的词条，匹配才能命中。
提示

多数申请只需一份干净简历。Sweepy 可按轨道发送不同文件，因为 tracks[].route_keywords 决定附加哪份简历。该设置从不影响匹配度。

关键词来自 must_have_skills​

Sweepy 按两项重合度指标为每个职位评分：

重合度权重衡量的内容
任职要求重合度60%职位要求中你的简历已体现的比例
关键词重合度40%职位中重复出现的简历词汇比例

职位决定了匹配的含义，因此任职要求重合度占总分的 60%。必需资质的权重是未标注词条的两倍，优选资质为一半。

你的词条列表由 must_have_skills 与一份简短的内置常见技术和法律词条表组合而成。Alex 的配置文件列出了同样的技能：

profiles/paralegal_nyc.yaml
resume:
  path: "Alex_Rivera_Resume.pdf"
  must_have_skills:
    - "Westlaw"
    - "LexisNexis"
    - "e-discovery"
    - "Contract Review"
    - "Legal Research"

内置列表词条有限，因此 Sweepy 还会直接读取你的简历。它把词条分为四个层级，按强度排序：

  1. 你的技能章节。
  2. 内置列表。
  3. 你使用频率最高的非停用词。
  4. 更高层级中已包含的首字母大写短语。

按该顺序保留最强的 60 个词条。职位词条遵循同样规则，上限为 25 个，并在职位标注要求或资质区块时从中提取。

提示

把 must_have_skills 当作你的正式词条列表。请添加：

  • 简历中提到的每项技能、工具和平台，例如 Westlaw、Relativity 或 case management。
  • 你所在行业使用的词条，即使简历措辞不同，例如 e-discovery 或 litigation support。
  • 目标职位中的原样短语。Sweepy 按整词匹配，因此在关键处以职位措辞为准。
警告

每个词条都计入关键词重合度的分母。列表过长会压低那些缺失大部分词条的职位的分数，因此只保留你真正具备的词条。

添加行业专用词条​

匹配不区分大小写，并能处理复数形式。Sweepy 为常见技术缩写内置别名表，包括：

  • API / application programming interface
  • UX / user experience
  • WCAG / web content accessibility guidelines

添加 resume.synonyms 以覆盖你所在领域的其余词汇：

profiles/paralegal_nyc.yaml
resume:
  synonyms:
    - ["e-discovery", "ediscovery", "electronic discovery"]
    - ["legal research", "case law research"]
    - ["docketing", "case calendaring"]
    - ["legal assistant", "legal secretary"]
    - ["contract review", "contract analysis", "agreement review"]

Sweepy 将同一组内的每个词条视为可互换。职位写 electronic discovery 时能匹配写 e-discovery 的简历，反之亦然。

  • 一组至少需要两个词条。只有一个词条的组会被 Sweepy 忽略。
  • 匹配仍要求完整短语。若希望 legal research 和 legal researcher 都计入，请将它们列为独立词条。

配置参考 逐字段说明该设置。

排序的工作方式​

匹配度衡量的是词汇重合。契合上下文但用词不同的职位仍可能得分偏低。高重合度只是提示该职位值得细看。是否投递由你决定。

将 Sweepy 连接到 AI

Sweepy 只比对词条，从不猜测意图。若希望结果运用上下文和更深层的推理，请通过模型上下文协议（MCP）连接大语言模型（LLM）。
