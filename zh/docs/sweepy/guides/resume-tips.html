优化简历格式以提高匹配成功率

Sweepy会分析简历文件中的文字内容，并将其与职位要求进行比对；您的格式设置会影响系统能读取多少信息。

通过添加额外的文本框或扫描页面，可以隐藏部分技能信息，从而提升匹配分数（无需修改任何工作经历内容）。

备注

本页面介绍了Sweepy如何解析简历的机制；具体评分规则和报告格式详见“了解您的匹配结果”。

Sweepy 支持读取的文件格式​

Sweepy 可以在 resume.path 处读取 PDF 和 Word 文件。只需将文件路径指向 .docx，Sweepy 便会直接读取其中的段落和表格内容。无需先转换 Word 格式的简历文件。当编辑器同时支持两种格式时，请保留 .docx 的设置；第三方转换工具可能会重新排列文件内容，之后 Sweepy 会按照新的顺序进行读取。

当您需要PDF格式的文件时，请使用Sweepy自带的转换工具。该工具会从原始的段落和表格中重新生成一份结构清晰的单栏PDF文件。无论使用哪种文件，提取出的内容都是相同的。详情请参阅使用--convert转换任何文档。

以下问题阻碍了提取：

  • 非PDF文件、非DOCX格式的文件：只有PDF或DOCX格式的文件才能被Sweepy识别并处理。.pages、.odt、.doc、.txt格式的文件对Sweepy来说毫无用处。Sweepy的转换器可以处理.txt和.md格式的文件，也可以通过Microsoft Word处理.doc格式的文件。如果需要处理.pages或.odt格式的文件，请先使用其内置应用程序进行导出。
  • 扫描后的页面中不存在文本层。 扫描结果只是图片中的文字片段，而非完整的文本内容。由于Sweepy无法识别这些文字，因此评分结果只能为must_have_skills。
  • 受密码保护的 PDF 文件。 Sweepy 无法打开加密文件。请在保存文件前先移除密码。
  • 文件缺失或损坏。 如果路径错误，系统会记录警告并跳过文件提取过程。此时，只有 must_have_skills 文件会被用于计算得分。
警告

当 Sweepy 无法读取您的简历时（即您将 must_have_skills 留空），所有职位的评分都会被标记为 75%。不过这个评分实际上没有任何实际意义，因为它适用于报告中的所有招聘信息。

提示

在使用 Sweepy 扫描文件之前，先对其进行光学字符识别（OCR）处理。OCR 会为扫描内容添加一个可读的文本层，之后 Sweepy 才能识别这些文字。大多数扫描应用程序和 PDF 编辑器都提供了 OCR 功能。

运行复制粘贴测试​

打开您的简历，选中所有文本，然后将其粘贴到一个纯文本编辑器中。纯文本会显示文本的提取顺序，而富文本编辑器可能会隐藏这一信息。

各平台的复制快捷键
  • 在 Windows 系统上，使用 Edge、Chrome 或 Acrobat 打开 PDF 文件。按 Ctrl+A 和 Ctrl+C 复制文件内容，然后将其粘贴到记事本（Notepad）中。
  • 在 macOS 上，在“预览”中打开 PDF 文件，按 ⌘+A，然后按 ⌘+C。粘贴前，请先按 ⇧+⌘+T 将“文本编辑”切换为纯文本模式。
  • 在 Linux 上，用 Evince 或 Okular 打开 PDF 文件，然后按 Ctrl+A，接着按 Ctrl+C。将文本粘贴到 gedit 或 Kate 等编辑器中。

在 macOS 键盘上，⌘ 是 Command 键，⇧ 是 Shift 键。

如果粘贴的内容看起来混乱、为空或顺序错误，Sweepy 仍然会将其视为有效数据。请在运行扫描任务之前先修复文件内容。

导致连续读取中断的格式设置​

文本提取工具会直接从页面上读取所有内容；页面布局的变更会影响这些工具返回文本的顺序。求职者跟踪系统（applicant tracking systems）也使用类似的文本提取方式。

格式说明Sweepy 的读取方式
两列或更多列当页面中包含两列或更多列时，这些列会交错排列并打乱文本的顺序；因为提取工具会从页面的左侧开始逐行读取内容。
表格、文本框和侧边栏这些元素的内容可能会被打乱顺序或与相邻内容合并。
图片、图标和图表所有被标记为图片的元素（包括技能条和徽标）都会被忽略。
页眉和页脚许多解析器会忽略这些区域；请将您的名称和联系方式放在正文部分。
跨行的内容如果某个术语分布在两行上（例如 e- 和 discovery），系统将无法正确匹配该术语。
连字和特殊字体在 fi 和 fl 中出现的连字或特殊字符可能会被错误地提取出来。
表情符号与自定义项目符号这些符号在显示时可能会出现乱码或显示不正常的情况。建议使用普通的连字符（-）或圆形项目符号（·）。

求职者跟踪系统更青睐的内容​

招聘跟踪系统（ATS）会使用与 Sweepy 相同的算法来解析数百份简历，并从中提取关键信息，最终生成一列格式整齐的纯文本数据。

  • 单列布局，从上到下。 请不要使用带有侧边栏的双列设计。
  • 普通章节标题。 使用 Experience、Education 和 Skills 来标记章节标题。避免在标题中使用表格或图标。
  • 仅限纯文本。 不得使用基于图像的标题、徽标或技能条。
  • 标准字体： 使用Arial、Calibri、Helvetica或Times New Roman字体，字号设置为10-12磅。
  • 使用纯文本列表项（无格式化符号）并保持日期格式一致。 全文应统一使用某种日期格式，例如 Jan 2024 – Present。
  • 按倒序排列。 大多数招聘人员和解析工具都期望文档按照这种顺序呈现。
  • 联系信息需放在正文部分。 自动化测试工具（ATS）的解析器通常会删除文档的页眉和页脚内容，因此联系信息必须直接放在文档的正文中。
  • 从您的文字处理软件中导出文件。 将文件保存为 PDF 格式，并保留其中的 .docx 标记，以防某些系统或平台需要该标记。
  • 严格遵循职位描述的表述。 如果招聘信息中使用了 e-discovery 或 docs-as-code 这样的术语，必须原样使用，以确保匹配准确。
提示

对于大多数求职申请，只需准备一份简洁的简历即可。Sweepy 可以根据不同的职位要求发送不同的简历文件（由 tracks[].route_keywords 来决定应附上的简历文件），但这种设置不会影响求职者的匹配评分（即求职者与职位的匹配程度）。

基于提取文本的模型评分​

通过模型上下文协议（Model Context Protocol，简称MCP），您的助手会获取resume_documents中每份简历对应部分的文本内容。该助手会根据招聘系统（ATS）的解析规则对这些文本进行评分。表格、页眉、页脚、图片或侧边栏中的术语，其评分权重低于Experience或Skills部分中相同术语的评分权重。

模型也可以记录错误信息。当布局隐藏某些内容时，系统可能会输出类似 “concerns” 的提示信息（例如 “侧边栏中的技能信息可能无法被解析”）。对于格式化后的表格名称，同样需要采用相同的修复方法：仅保留一列实际文本即可。

关键词来自 must_have_skills​

Sweepy 会根据两个评估标准来对每篇帖子进行评分：

重叠项权重所测量的内容
职位要求与简历要求的重叠程度60%简历中已体现的职位要求的占比
关键词与简历词汇的重叠程度40%简历中出现的词汇与职位描述中重复的词汇占比

职位描述定义了“匹配”的具体标准：因此，职位要求与简历要求的重叠程度占评分的60%。必备资格条件的权重是未标记术语的两倍；优先考虑的资格条件权重则减半。

您的术语列表包含了must_have_skills以及一些常见的技术和法律术语。Alex的个人资料中也列出了相同的技能。

profiles/paralegal_nyc.yaml
resume:
  path: "Alex_Rivera_Resume.pdf"
  must_have_skills:
    - "Westlaw"
    - "LexisNexis"
    - "e-discovery"
    - "Contract Review"
    - "Legal Research"

Sweepy根据您的必备技能和简历内容生成该列表，并按重要性进行排序（从高到低）：

  1. 您的 must_have_skills 列表。

  2. 添加行业特定术语​

  3. 内置列表，用于显示您的简历中还包含的条目。
  4. 您最常出现的非停用词。
  5. 一个组至少需要包含两个术语；否则该组将被忽略。

最强的 60 个术语会保留下来，顺序不变。新增的术语同样需要遵循相关规则（每个术语最多 25 个字符），其内容应来源于帖子的要求或资格说明部分（即当帖子对这些术语进行了特别标注时）。

提示

将 must_have_skills 视为您的实际术语列表。请添加以下内容：

  • 您在简历中提到的每一项技能、工具和平台（例如 Westlaw、Relativity 或 case management），都需要列出。
  • 请使用您所在行业通用的术语，即使您的简历中使用了其他表达方式（例如 e-discovery 或 litigation support）。
  • 请直接复制您需要的帖子中的确切短语。Sweepy能够匹配完整的单词，因此在需要保留原文表述时，请完整复制帖子的内容。
警告

每个术语都会被计入关键词重叠的分母中。即使列表很长，但如果某个角色缺少大部分关键词，其得分仍然会降低；因此请仅列出该角色实际拥有的关键词。

添加行业专用术语​

匹配过程不区分大小写，并能处理复数形式。Sweepy 提供了一个内置的别名列表，用于处理常见的技术缩写词，其中包括：

  • API / application programming interface
  • UX / user experience
  • WCAG / web content accessibility guidelines

添加 resume.synonyms 以涵盖该字段中剩余的所有词汇。

profiles/paralegal_nyc.yaml
resume:
  synonyms:
    - ["e-discovery", "ediscovery", "electronic discovery"]
    - ["legal research", "case law research"]
    - ["docketing", "case calendaring"]
    - ["legal assistant", "legal secretary"]
    - ["contract review", "contract analysis", "agreement review"]

Sweepy将同一组中的所有术语视为可互换的。使用electronic discovery撰写的帖子与使用e-discovery撰写的简历是等效的，反之亦然。

  • 一个组至少需要包含两个术语；Sweepy会忽略只包含一个术语的组。
  • 匹配时仍需要使用完整的短语。当您希望同时统计legal research和legal researcher这两个术语时，应将其作为独立的条目列出。

配置参考文档逐个字段地描述了这些设置选项。

排名机制​

匹配百分比用于衡量两个文本之间的词汇重叠程度。即使某个词在上下文中能够匹配，其得分也可能较低；较高的词汇重叠率会提示用户需要进一步查看相关内容。是否应用该排名规则由您决定。

将 Sweepy 连接到 AI

Sweepy会自动比较文本中的术语，但不会猜测用户的意图。如果您希望Sweepy在分析结果时利用上下文和高级推理能力，可以通过模型上下文协议（Model Context Protocol, MCP）连接大型语言模型（LLM）。
