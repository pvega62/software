优化简历格式以获得更精准的匹配

Sweepy 会对您简历文件中的词汇进行评分。 当它打开文件时，会提取文本内容并与职位招聘信息进行比对。您的排版方式决定了引擎能读取多少文本内容。

第二列、文本框或扫描页面可能会导致您的全部技能列表被引擎忽略。通常只需调整一下排版，无需修改任何工作经历内容，就能提升您的匹配分数。

备注

本页面介绍 Sweepy 如何读取您的简历。有关评分公式和报告布局，请参阅 了解您的结果。

Sweepy 能读取的内容​

Sweepy 会读取位于 resume.path 路径下的 PDF 和 Word 文件。若路径指向 .docx 文件，Sweepy 将直接读取其中的段落和表格。您无需事先将 Word 简历进行转换。当您的编辑器同时提供两种格式时，请保留 .docx 格式。 第三方转换器可能会以不同的顺序重建页面，而 Sweepy 随后会读取这种已更改的顺序。

当您需要 PDF 版本时，请运行 Sweepy 自带的转换器。它会根据相同的段落和表格重建一个整洁的单栏 PDF。无论从哪种文件提取，结果返回的词汇都是一致的。 请参阅 使用 --convert 转换任何文档。

以下问题会导致提取失败：

  • 非 PDF、非 DOCX 文件。 只有 PDF 或 DOCX 文件才能生成 Sweepy 可评分的文本。.pages、.odt、.doc 或 .txt 文件无法为引擎提供任何内容。Sweepy 的转换器支持处理 .txt 和 .md 文件，并通过 Microsoft Word 处理 .doc 文件。 请先从原生应用中导出 .pages 或 .odt 文件。
  • 没有文本层的扫描页面。 扫描结果向 Sweepy 提供的只是文字的图片，而非文字本身。由于 Sweepy 无法找到文本层，因此评分将仅依赖 must_have_skills 进行。
  • 受密码保护的 PDF 文件。 Sweepy 无法打开加密文件。请在保存文件前移除密码。
  • 文件缺失或损坏。 路径错误会触发警告并跳过提取。此时，评分仅由 must_have_skills 决定。
警告

当 Sweepy 无法读取您的简历，且您未填写 must_have_skills 字段时，每个职位的评分均为 75%。该数值无法用于排名，因为它适用于报告中的每个职位发布。

提示

在将扫描件提交给 Sweepy 之前，请先对其进行光学字符识别（OCR）。OCR 会添加一个真正的文本层，这样引擎才能读取您的文字。大多数扫描应用和 PDF 编辑器都包含 OCR 选项。

进行复制粘贴测试​

打开您的简历，全选文本，然后将其粘贴到纯文本编辑器中。纯文本会显示数据提取的顺序，而富文本编辑器可能会隐藏这一顺序。

:::提示[各平台复制快捷键]

  • 在 Windows 上，使用 Edge、Chrome 或 Acrobat 打开 PDF。 按下 Ctrl+A 和 Ctrl+C，然后粘贴到记事本中。
  • 在 macOS 上，在“预览”中打开 PDF，按下 ⌘+A，然后按下 ⌘+C。 粘贴前，请使用 ⇧+⌘+T 将 TextEdit 切换为纯文本模式。
  • 在 Linux 上，在 Evince 或 Okular 中打开 PDF，然后按 Ctrl+A 接着按 Ctrl+C。将文本粘贴到 gedit 或 Kate 等编辑器中。

在 macOS 键盘上，⌘ 是 Command 键，⇧ 是 Shift 键。 :::

如果粘贴后的内容显示混乱、空白或顺序错乱，Sweepy 读取的结果也是如此。请在运行扫描前修复文件。

导致扫描失败的格式​

文本提取器会沿页面水平方向逐行读取。版式会改变其返回文本的顺序。求职者跟踪系统采用的也是同一种提取方式。

格式Sweepy 读取的结果
两栏或多栏排版由于提取器是沿页面水平方向读取的，多栏排版会导致文本交错并混乱。
表格、文本框和侧边栏内容可能出现顺序错乱或与相邻内容合并。
图片、图标和图表提取过程会跳过所有以图片形式呈现的内容，包括技能条和徽标。
页眉和页脚许多解析器会跳过该区域。请将您的姓名和联系方式放在正文中。
带连字符的换行跨两行的术语（如 e- 接着 discovery）会导致整个术语无法匹配。
连字和装饰性字体fi 和 fl 连字以及不寻常的字形可能会被提取为乱码。
表情符号和自定义项目符号图标这些内容会被遗漏或显示混乱。请使用普通连字符或圆形项目符号。

求职者跟踪系统（ATS）的偏好​

求职者跟踪系统（ATS）会采用与 Sweepy 相同的提取方式来解析数百份简历。 请提供一列干净的纯文本内容。

  • 单栏布局，自上而下。 避免使用带有侧边栏的双栏设计。
  • 简洁的章节标题。 使用 工作经历、教育背景 和 技能 等标题。标题中避免使用表格和图标。
  • 仅限纯文本。 不要使用基于图片的标题、徽标或技能条。
  • 标准字体。 使用 10-12pt 的 Arial、Calibri、Helvetica 或 Times New Roman 字体。
  • 简洁的项目符号和统一的日期格式。 全文统一使用一种日期格式，例如 2024年1月 – 至今。
  • 倒叙时间顺序。 大多数招聘人员和简历解析器都期望这种格式。
  • 联系信息置于正文中。 ATS 解析器通常会过滤掉页眉和页脚。
  • 从文字处理软件导出。 从编辑器中保存 PDF 文件，并保留 .docx 文件以备招聘门户网站要求时使用。
  • 采用职位描述中的措辞。 如果招聘启事中提到 电子取证 或 文档即代码，请使用完全相同的术语，以便匹配功能能识别出来。

:::提示 为大多数申请准备一份简洁的简历。Sweepy 可以针对每个职位轨道发送不同的文件，因为 tracks[].route_keywords 会自动选择要附加的简历。 该设置不会影响匹配分数。 :::

基于提取文本的模型评分​

通过模型上下文协议（MCP），您的助手会从 resume_documents 中接收每条简历轨道的提取文本。它会按照职位发布方 ATS 的解析方式对该文本进行评分。 出现在表格、页眉、页脚、图片或侧边栏中的术语，其权重低于出现在 Experience 或 Skills 部分中的相同术语。

模型还可以记录损失情况。当您的布局隐藏了内容时，可能会出现类似“侧边栏中的技能可能无法解析”这样的 concerns 提示行。 采用与格式化表格名称相同的修复方案：保留一列真实文本。

关键词来自 must_have_skills​

Sweepy 根据两项重叠度指标对每个职位发布进行评分：

重叠度权重衡量内容
要求重合度60%您的简历中已包含该职位要求的比例
关键词重合度40%职位描述中重复出现的词汇与您简历中词汇的重合比例

职位描述定义了匹配的含义，因此“要求重合度”占总评分的 60%。必备资格的权重是未标注术语的两倍，优先资格的权重为其一半。

您的术语列表结合了 must_have_skills 以及一个简短的内置常用技术和法律术语列表。 Alex 的个人资料中列出了相同的技能：

profiles/paralegal_nyc.yaml
resume:
  path: "Alex_Rivera_Resume.pdf"
  must_have_skills:
    - "Westlaw"
    - "LexisNexis"
    - "电子取证"
    - "合同审查"
    - "法律研究"

由于内置列表涵盖的术语较少，因此 Sweepy 还会直接读取您的简历。它将术语分为四个等级，按强度从高到低排序：

  1. 您的“技能”部分。
  2. 内置列表。
  3. 您简历中出现频率最高且非停用词的术语。
  4. 更高等级中已包含的大写短语。

最终保留排名前60的术语，按上述顺序排列。职位发布中的术语遵循相同规则，上限为25个，且来源于职位描述中的“要求”或“资格”部分（如有标注）。

:::提示 将 must_have_skills 视为您的实际术语列表。请添加以下内容：

  • 简历中提及的每项技能、工具和平台，例如 Westlaw、Relativity 或 case management。
  • 行业常用术语，即使简历中的表述方式不同，例如 e-discovery 或 litigation support。
  • 目标职位发布中出现的精确短语。 Sweepy 匹配的是完整单词，因此在关键情况下请复制职位发布中的原话。 :::

:::注意 每个术语都会计入关键词重叠率的分母。如果列表过长，而职位要求中大部分内容与之不符，分数仍会降低，因此请将列表限定在您实际具备的术语范围内。 :::

添加行业专用术语​

匹配过程不区分大小写，并支持复数形式。Sweepy 内置了常见技术缩写词的别名列表，包括：

  • API / 应用程序编程接口
  • UX / 用户体验
  • WCAG / 网页内容无障碍指南

添加 resume.synonyms 以涵盖您所在领域其余的术语：

profiles/paralegal_nyc.yaml
resume:
  synonyms:
    - ["电子取证", "ediscovery", "electronic discovery"]
    - ["法律研究", "判例法研究"]
    - ["案件登记", "案件日程安排"]
    - ["法律助理", "法律秘书"]
    - ["合同审查", "合同分析", "协议审查"]

Sweepy 将组中的每个术语视为可互换。发布信息中写有 electronic discovery 的，会匹配简历中写有 e-discovery 的，反之亦然。

  • 一个组至少需要包含两个术语。Sweepy 会忽略仅含一个术语的组。
  • 匹配仍需完整短语。若希望同时计入 法律研究 和 法律研究员，请将它们作为独立术语列出。

配置参考 按字段详细说明了此设置。

排名机制​

匹配百分比衡量词汇重合度。即使某个职位通过上下文符合要求，其得分仍可能较低。高重合度会标记该职位，提示您进一步审查。是否录用由您决定。

将 Sweepy 连接到 AI

Sweepy 仅比较术语，绝不会推测意图。若希望 Sweepy 在结果中运用上下文和高级推理，请 通过模型上下文协议 (MCP) 连接大型语言模型 (LLM)。
