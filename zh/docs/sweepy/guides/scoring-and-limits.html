Sweepy 如何对您的简历进行评分及其局限性

每张卡片上的百分比仅衡量一件事：您的简历与职位描述中词汇的重合程度。Sweepy 仅统计共同出现的词汇，绝不对其进行语义解读。这种设计确保了扫描过程的免费、快速且可重复。但也因此设定了评分上限。

Sweepy 如何计算匹配百分比​

Sweepy 会读取您的简历一次，然后将该文本与所有经过验证的职位发布进行比对。

该评分综合了两种重叠度指标：

  • 职位要求重叠度（60%）： 您的简历中已包含职位发布原文表述的比例。
  • **关键词重合度（40%）：**职位发布中重复了您简历中多少词汇。

职位要求重合度在综合评分中占 60%，因为职位发布本身定义了匹配的含义。

在职位要求重合度中，招聘信息会为每个术语设定权重：

  • 必备术语的权重是未标注术语的两倍。
  • 优先术语的权重为必备术语的一半。
  • 未标注术语采用基础权重。

Sweepy 将这两项指标合并为一个数值。随后，该数值会乘以您的 keywords_weight 设置，并将结果上限设为 100。向导默认写入 1.5，而 Sweep 设置 面板会对其进行调整。未包含关键术语的个人资料得分为 1.0。

  • 提高 keywords_weight 值以奖励关键词重叠。
  • 当评分集中在较高区间时，将其调低至接近 1.0。
备注

您的 resume.must_have_skills 列表会首先进入关键词池，并处于最高层级。 这些术语会影响您评分的所有职位，当某个职位无法提取可读术语时，评分将仅基于关键词重叠度。

每张卡片还会列出数字背后的术语。Sweepy 会显示每个职位最多六个匹配术语和最多三个缺失术语。

卡片标签​

每张卡片都会显示带标签的分数。该标签表明该分数由谁生成。

  • KEYWORD OVERLAP 标记的是 Sweepy 通过标准扫描生成的计数。该值综合了职位要求重叠度和关键词重叠度，凡是普通扫描生成的卡片都会显示此标签。
  • MATCH 标记的是模型通过 MCP 客户端读取职位描述并自行设定匹配百分比的卡片。

MATCH 卡片反映的是主观判断，而 KEYWORD OVERLAP 卡片反映的是共同词汇。两者都能对列表进行排序，但只有前者能衡量语义。

注意事项​

确定性评分以速度牺牲了理解力。主观判断不计入评分。

  • 同义替换。 招聘信息中可能列出“开发者指南”，而简历中则列出“API 文档”。逐字匹配时，这两者的评分均为零。
  • 职级与职责范围。 领导和支持的提取方式相同。工作年限、团队规模和预算管理权限等要素永远不会影响评分。
  • 跨领域技能转换。 来自其他领域的技能只有在简历中明确指出重叠点时才会被计入。 除非你的简历中也提到教学设计，否则课程规划无法与任何职位发布匹配。
  • 职业方向与成果。 一条匹配度为 30% 的简历可能比一条匹配度为 60% 但共享词汇更多的简历更适合该职位。评分机制无法识别你的职业目标。

请将百分比视为阅读顺序的指引。它告诉你哪些职位值得你花时间。

两种模式各有所长，互为补充。全量扫描模式对大量招聘信息进行排名，而模型则像真人一样阅读您的入围名单。

模型评分中的解析简历​

get_jobs 会将解析后的简历文本通过 resume_documents 传递给您的助理，该文本位于卡片旁边。它还会报告 resume_default_path 和 resume_guidance。随后，助理将根据该文件进行评估，而非您的 must_have_skills 列表。

请要求进行两次评估，因为它们能发现不同的不足之处。招聘人员会综合考量可迁移技能、工作范围、职级、专业领域和成果，而解析器则遵循章节标题、标准字体和单栏文本格式。

解析器的读取结果可以解释那些令人意外的评分。双栏布局可能会将您的技能列表放在侧边栏中。提取器随后会将该文本放在教育背景部分之后，或者直接省略。模型读取的是相同的顺序，但评分较低，丢失的内容会记录在 concerns 中。

当“申请”链接显示时，请确保解析器与职位发布要求相匹配。Workday 门户和 Greenhouse 门户对简历的解析方式不同，而 concerns 行可以指出是哪一方丢失了文本。

如何缩小差异​

请按以下列表逐步操作。每一步都会缩小两种模式之间的差距。

  1. 声明字段的同义词。 在 resume.synonyms 中添加等效项，例如 docs-as-code 和 documentation as code。这一步对真实匹配的评分提升效果最为显著。
  2. 精心筛选 must_have_skills。 这些术语以最高级别进入关键词池，因此会影响您评分的所有职位发布。
  3. 按目标职位分类简历。 为每个 resume.tracks[] 条目分配独立的 path。随后，Sweep 会根据该职位家族对应的简历对该职位进行评分。
  4. 调整 keywords_weight。 Sweep 设置 模块会在下一次扫描时为每张卡片应用新的权重。
  5. 阅读每张卡片上的匹配列表。 missing_skills 显示需要添加的术语。匹配术语列表则显示求职信中应重点突出的内容。
  6. 连接 MCP 客户端并运行混合流程。 让模型读取您的顶级卡片和已解析的简历，然后通过 submit_judgments 设置 match_pct。这些卡片将重新渲染为 NN% MATCH。参见 MCP 集成。
  7. 手动评估一个样本。 亲自对 20 到 30 个职位发布进行评分，将其分为“强”、“部分匹配”或“弱”。将您的排序结果与 Sweepy 的进行比较。当两者在同类职位上存在分歧时，将缺失的概念添加到 resume.synonyms 或 must_have_skills 中。

:::提示 请同时运行两种模式。先让 run_sweep 对完整候选池进行排序，然后将排名前 10 的候选人通过您的 MCP 客户端进行二次评估。这样既能保留广泛筛选的结果，又能获得二次判断。仅处理候选名单会消耗模型令牌。 :::
