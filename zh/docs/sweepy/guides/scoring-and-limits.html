Sweepy 如何为简历评分及其局限

每张卡片上的百分比只衡量一件事：简历与职位共有多少词汇。Sweepy 统计共有词条，从不解释其含义。这一设计让扫描免费、快速且可重复，同时也划定了上限。

Sweepy 如何计算百分比​

Sweepy 只读取一次简历，随后将该文本与每个通过验证的职位比对。

分数由两项重合度指标合成：

  • 任职要求重合度（60%）： 职位原文中你的简历已体现的比例。
  • 关键词重合度（40%）： 职位中重复出现的简历词汇比例。

任职要求重合度占合成分的 60%，因为职位决定了匹配的含义。

在任职要求重合度内部，职位为每个词条设定权重：

  • 必需词条的权重是未标注词条的两倍。
  • 优选词条的权重为一半。
  • 未标注词条按基础权重计算。

Sweepy 将两项指标合成为一个数值，再乘以你的 keywords_weight 设置，并将结果上限设为 100。向导写入 1.5，你可在扫描设置板块中修改。省略该键的配置文件按 1.0 计算。

  • 提高 keywords_weight 以强调重合度。
  • 分数普遍接近上限时，将其调低到接近 1.0。
备注

resume.must_have_skills 列表以最高层级首先进入关键词池。这些词条会计入你评分的每个职位；当职位提取不到可读词条时，分数只按关键词重合度计算。

每张卡片还列出数字背后的词条。Sweepy 为每个职位最多显示六个匹配词条和三个缺失词条。

卡片标签​

每张卡片都在分数旁打印标签。标签说明该数字的来源。

  • KEYWORD OVERLAP 表示标准扫描中 Sweepy 自身的统计结果。该数值混合任职要求重合度和关键词重合度，普通扫描生成的每张卡片都带此标签。
  • MATCH 表示该卡片由模型通过 MCP 客户端读取职位后自行设定百分比。

MATCH 卡片反映评估判断。KEYWORD OVERLAP 卡片反映共有词汇。两者都能为列表排序，但只有前者能衡量含义。

需要注意的地方​

确定性评分以速度为优先，牺牲了理解能力。判断性内容不参与计数。

  • 同义改写。 职位写 guides for developers，简历写 API documentation，逐词匹配会给出零分。
  • 资历与职责范围。 Led 和 supported 的提取方式相同。工作年限、团队规模和预算责任从不进入分数。
  • 跨领域迁移。 其他领域的技能只有在简历点明重合时才算数。简历未写 instructional design 之前，lesson planning 匹配不到任何职位。
  • 职业方向与成果。 30% 的一行可能比共享词汇更多的 60% 一行更合适。分数看不到你的目标。

把百分比当作阅读顺序。它告诉你哪些职位值得花时间。

两种模式各覆盖对方的盲区。扫描为大范围职位排序，模型则像人一样阅读你的入围名单。

如何缩小差距​

按顺序逐项处理。每一步都能缩小两种模式的差距。

  1. 声明本领域的同义词。 向 resume.synonyms 添加等价词，例如 docs-as-code 与 documentation as code。这一步对真实匹配的提分效果最大。
  2. 精心维护 must_have_skills。 这些词条以最高层级进入关键词池，因此会参与你评分的每个职位。
  3. 按目标拆分简历。 为每个 resume.tracks[] 条目设置独立的 path。Sweepy 会用针对该类职位撰写的简历评分。
  4. 调整 keywords_weight。 扫描设置板块会在下次扫描时把新权重应用到每张卡片。
  5. 阅读每张卡片上的匹配列表。 missing_skills 显示可补充的词条。匹配词条列表显示求职信应先强调什么。
  6. 连接 MCP 客户端并运行混合流程。 让模型读取你的头部卡片，并通过 submit_judgments 设置 match_pct。这些卡片会重新渲染为 NN% MATCH。参见 MCP 集成。
  7. 手动给样本评分。 自己把 20 到 30 条职位评为强、部分或弱匹配。将你的排序与 Sweepy 的排序对比。若两者对同类职位的判断不一致，就把缺失的概念加入 resume.synonyms 或 must_have_skills。
提示

两种模式都运行。让 run_sweep 为全部职位排序，再把前 10 条通过 MCP 客户端送去复审。你既保留了大范围扫描，又获得了评估环节。只有入围名单会消耗模型 token。
