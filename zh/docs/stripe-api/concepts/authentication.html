身份验证与密钥管理

发送给Stripe的请求必须在Authorization头部包含API密钥。该密钥用于标识您的账户，并继承创建该密钥的用户所拥有的权限。如果密钥泄露，会导致账户中的所有交易、客户信息和支付记录被公开。

关键字类型​

每个账户都有三种类型的密钥，其中只有一种密钥可以用于服务器。

关键字前缀是否可在浏览器中使用用途
可发布pk_test_, pk_live_是客户端令牌化（client-side tokenization）及 Stripe.js 技术；该方案不会授予 API 访问权限。
秘密sk_test_, sk_live_否需进行服务器端 API 调用；需具备完整账户权限。
受限制rk_test_, rk_live_否服务器端调用仅限于特定资源及操作。

秘钥可以读取和写入该账户所拥有的所有资源。受限键则仅允许访问特定资源（例如仅允许读取相关数据）。在不需要访问整个账户信息的集成场景中，应使用受限键。

危险

绝不要将任何敏感或受限制的密钥放入客户端代码、移动应用程序的二进制文件、公共代码库或支持工单中。 任何拥有该密钥的人都可以进行资金操作。

发送密钥​

存储密钥

curl https://api.stripe.com/v1/balance \
  -u "$STRIPE_SECRET_KEY:"
Node.js
const response = await fetch("https://api.stripe.com/v1/balance", {
  headers: { Authorization: `Bearer ${process.env.STRIPE_SECRET_KEY}` },
});
Python
import os, requests

response = requests.get(
    "https://api.stripe.com/v1/balance",
    auth=(os.environ["STRIPE_SECRET_KEY"], ""),
)

验证连接

权限管理​

示例：

.env
STRIPE_SECRET_KEY=sk_test_51N...
server.js
if (!process.env.STRIPE_SECRET_KEY) {
  throw new Error("STRIPE_SECRET_KEY is not set");
}

将环境变量文件添加到 .gitignore 中。托管平台会将该环境变量的值存储在加密的存储系统中，并将其注入到应用程序的运行环境中。这样，该密钥就不会被包含在代码仓库或构建日志中。

验证连接​

发送一个读取请求。系统会返回一个 200 格式的响应，其中包含余额信息、基础地址以及网络路径。

curl -s https://api.stripe.com/v1/balance -u "$STRIPE_SECRET_KEY:" | jq '.object, .livemode'

输出结果为 "balance" 和 false，表示测试密钥。401 表示该账户的密钥错误、被撤销或缺失。403 表示受限密钥缺乏对该资源的权限。

将某个受限制的键（restricted key）纳入权限管理范围​

一个受限的权限密钥会列出每个资源的权限。请仅授予集成所需的最小权限集。

集成建议的权限
报告工作根据费用记录核对交易明细及支付情况。
结账服务器负责处理支付相关操作（如确认付款意图、退款请求等）；同时也会接收客户的反馈信息。
报告任务用于查看费用、交易记录和支付信息。

为每个配置键（key）起一个与该键所对应的服务名称作为其名称。例如，使用名称 checkout-api-prod 可以加快事件审查的速度，因为审计日志会显示是哪个配置键被触发了（即哪个服务执行了相关操作）。

密钥轮换机制：​

密钥轮换步骤：

  1. 创建一个具有相同权限的备用密钥；
  2. 将新密钥以新名称添加到密钥存储库中；
  3. 部署使用新密钥的服务；
  4. 确认新密钥能否正常处理业务流量；
  5. 在控制台中撤销旧密钥的权限；
  6. 查看部署后的日志，确认是否有旧密钥发起的请求。
注意

在撤销旧密钥之前，必须先部署新密钥，并观察这两个步骤之间的错误率变化。

如何处理密钥泄露的情况​

如果发现密钥存在于代码库、日志或聊天消息中，应立即将其视为已被泄露。

  1. 在“仪表板”（Dashboard）的“开发者”（Developers）→“API密钥”（API Keys）选项中撤销该密钥。
  2. 创建一个新的密钥并部署它。
  3. 查看请求日志，检查是否存在未知的IP地址或不寻常的请求端点。
  4. 核对账户余额和支付记录，确认是否有未经授权的交易发生。
  5. 如果发现未经授权的活动，请联系Stripe的技术支持。

密钥的撤销会立即生效；被撤销的密钥在下次请求时将无法正常使用。

常见问题及解决方法​

症状原因解决方法
401 Invalid API Key provided密钥不完整、已被撤销，或属于其他账户所有从仪表板重新复制密钥。
在某个资源上，使用了 403。某个受限的密钥缺乏所需的权限。请为该密钥添加相应的权限，或使用权限范围更广的密钥。
401 仅在生产环境中使用。在该部署中，环境变量为空。请检查生产环境的密钥存储（secret store）。
请求被延迟，随后失败代理服务器阻止了从 HTTPS 到 api.stripe.com 的出站连接。允许端口 443 上的主机进行通信。
