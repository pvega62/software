资金如何在Stripe中流动

一笔支付在进入您的银行账户之前会经过五个中间环节。每个环节记录了支付流程中的某个具体步骤。按顺序阅读这些信息，您就可以追踪从首次尝试到最终支付的整个过程。

支付的各个阶段​

阶段对象记录的内容
1PaymentIntent客户尝试支付的金额以及支付是否成功。
2Charge用于完成支付的支付方式及实际收取的金额。
3BalanceTransaction移动费用，以及实际到账的净金额。
4Balance账户当前可以支付的金额。
5Payout是什么让账户里的钱被转到了银行，以及具体是什么时候发生的？

这些阶段是按顺序执行的，各个环节之间存在关联关系；您可以随时查看任意一个阶段的信息，并追溯到最初的支付意图（PaymentIntent）。

阶段1：系统记录用户的支付尝试​

一个 PaymentIntent 对象包含了交易金额、使用的货币以及交易状态。即使在支付尝试失败后，该对象仍然会保留下来，以便客户可以使用另一张卡再次尝试完成相同的支付操作。

状态含义下一步
requires_payment_method目前尚无可用的支付方式。请附上相应的支付方式并确认相关信息。
requires_confirmation准备确认。请确认您的意图。
requires_action发行者需要客户进行身份验证。在客户端中完成相关挑战（或任务）。
processing网络仍然可以正常使用。请等待 Webhook 的响应。
requires_capture已获得授权，但尚未被捕获。请在授权时间内完成捕获。
succeeded资金已转移。请完成订单处理。
canceled支付失败，且该错误无法被恢复。请创建一个新的尝试请求（intent），以便重新进行支付操作。
注意

客户提供结果，但最终决定权在服务器手中。 succeeded 作为客户的提示，请通过 Webhook 或数据检索请求来确认订单的状态，然后再执行订单处理。

第二阶段：系统会完成资金的转移。​

确认操作会生成一个 Charge。该记录会包含支付方式、实际收取的金额以及卡片网络的处理结果。每次成功的支付请求都会对应一条收费记录；一旦费用结算完成，该记录将不再被修改。

您可以选择同时授权和扣款，或者分别进行这两步操作。将 capture_method 设置为 manual 可以先暂时冻结资金，再后续进行扣款。某些需要在收费前完成商品交付的市场平台要求这种分离处理方式；请确保在冻结期限结束前完成扣款操作。

第三阶段：余额交易记录了实际的支出金额。​

每次资金变动都会生成一条 BalanceTransaction 记录，其中包含以下三项信息：

  • amount：表示以最小货币单位计量的完整金额。
  • fee：Stripe 收取的转账手续费。
  • net 对象会将资金分为两个数组：

退款会生成一笔金额为负数的交易记录（即“余额减少”）。付款操作也会产生类似的交易记录。请根据该账本进行对账处理；其他任何记录中都不会显示费用信息。

第四阶段：余额中包含已结算的资金​

Balance 对象将资金分成两个数组：

数组含义
available您现在可以提取或转账的资金。
pending这些费用尚未结算。

第三个字段 refund_and_dispute_prefunding 用于存放预留的资金，以备将来退款、处理争议或应对负余额的情况。每个数组中包含每种货币对应的金额记录。

备注

账户余额显示的是您可以提取的金额，并不代表您的收入。如需查看收入情况，请将该期间内所有涉及 net 的交易金额相加。

第五阶段：资金从账户中支出​

A 0 将可用资金转入系统中记录的银行账户。您的付款频率（每日、每周、每月或手动）由您自行设定。结算时间因国家及支付方式的不同而有所差异。

一次支付可以涵盖多笔费用；若需将某次支付与对应的费用明细对账，可使用 payout={payout_id} 作为筛选条件来查看相关交易记录。

实例说明​

客户购买了一个月度服务，费用为 21.20 美元；平台按标准费率（2.9% + 0.30 美元）从客户的信用卡中扣款。

阶段对象金额备注
1PaymentIntent pi_...2120使用 amount=2120、currency=usd 创建。
2Charge ch_...2120发卡机构批准了该笔收费。
3BalanceTransaction txn_...amount: 2120fee: 91, net: 2029, type: charge.
4账户余额available: 2029资金会在结算延迟后显示在账户中。
5Payout po_...2029与其他已结算的收费一起进行支付。

费用为91美分：2.9%的手续费为61.48美分，固定费用为30美分，总计91美分。账户最终增加20.29美元，而非21.20美元。

什么会导致支付路径发生变化？​

支付被拒绝的情况​

支付被拒绝后，尝试会终止且不会产生任何费用。该笔交易的状态会回到requires_payment_method状态，并保留其原始金额。使用相同的支付方式重试可以避免重复下单。

支付被拒绝的情况可分为两类：

  • 直接拒绝（Hard Declines）：发卡机构直接拒绝该笔交易（例如lost_card或stolen_card）。这种情况下不应重试。
  • 暂时拒绝（Soft Declines）：发卡机构暂时拒绝该笔交易（例如insufficient_funds），之后可能允许再次尝试。

退款操作​

退款会生成一个新的Refund记录，并触发一笔负金额的余额调整交易。退款不会退还之前的处理费用。

退款类型余额调整交易对账户余额的影响
Fullamount: -2120, fee: 0, net: -2120完全取消该笔收费。
Partialamount: -1000, fee: 0, net: -1000部分取消该笔收费。
可进行两次或多次部分退款。每次退款对应一笔单独的财务记录（即一个独立的账目条目）。每次退款各自对应一条账目记录。

账户仍需支付最初的91美分手续费；全额退款需退还21.20美元（含该手续费）。

争议处理：​

退款操作会撤销原收费，并收取争议处理费。当发卡机构发起争议时，Stripe 会从 available 中扣除争议金额；在美国，还会收取 15 美元的固定争议处理费。

争议可能会导致账本中新增三条交易记录。第一条记录表示资金的提取；第二条记录表示平台收取的固定争议费用；如果银行裁决支持您，第三条记录会恢复被提取的资金。请通过 Dispute 对象来跟踪整个争议处理过程，而不仅仅是查看账户余额。

部分捕获​

手动捕获的金额可能低于授权的限额。例如，当实际捕获金额为40美元时，系统会收取50美元的费用（用于4000），并将剩余的10美元退还给客户。单笔余额交易会记录下这40美元的金额。

接下来该去哪里​

  • 身份验证与密钥管理：用于发送第一个请求。
  • 幂等请求：用于重试支付操作，以避免重复支付。
  • 错误处理与重试机制，用于应对交易失败、速率限制以及系统故障等情况。
  • 查询余额交易记录，以获取完整的交易属性列表。
