分页与列表端点

列表端点会返回一页结果数据，以及一个指向下一页的标识符（marker）。客户端会不断遍历这些数据，直到标识符has_more的值变为false为止。

列表数据的结构​

{
  "object": "list",
  "url": "/v1/charges",
  "has_more": true,
  "data": [
    { "id": "ch_3Rsx4dDtWMrPDtgt1", "object": "charge", "amount": 2120 }
  ]
}
字段含义
data当前页面上的对象。
has_more当存在其他页面时，显示 true。
url生成当前页面的端点路径。

最新的对象会显示在列表的首位，且不同页面之间的数据顺序保持不变（因为分页是通过对象索引而非数字偏移量来实现的）。

设置页面大小​

limit用于设置页面大小，可接受的值范围是1到100；默认值为10，这种设置适合交互式仪表盘，但在批量处理任务中会浪费网络请求次数。

curl -s -G https://api.stripe.com/v1/charges \
  -u "$STRIPE_SECRET_KEY:" \
  -d limit=100 | jq '.data | length, .has_more'

更大的页面可以减少请求次数和总延迟，但也会增加内存消耗以及请求失败时的影响；因此，对于大多数同步任务来说，100条数据是最合适的数量。

跟随光标移动​

读取页面上最后一个对象的id值，并将其作为starting_after传递；重复此过程，直到has_more变为false为止。

curl -s -G https://api.stripe.com/v1/charges \
  -u "$STRIPE_SECRET_KEY:" \
  -d limit=100 \
  -d starting_after=ch_3Rsx4dDtWMrPDtgt1
Node.js
async function listAllCharges() {
  const charges = [];
  let startingAfter;

  while (true) {
    const url = new URL("https://api.stripe.com/v1/charges");
    url.searchParams.set("limit", "100");
    if (startingAfter) url.searchParams.set("starting_after", startingAfter);

    const response = await fetch(url, {
      headers: { Authorization: `Bearer ${process.env.STRIPE_SECRET_KEY}` },
    });

    if (!response.ok) throw new Error(`Stripe returned ${response.status}`);

    const page = await response.json();
    charges.push(...page.data);

    if (!page.has_more) break;
    startingAfter = page.data.at(-1).id;
  }

  return charges;
}
提示

官方库会自动处理分页功能：在Node.js中，使用stripe.charges.list({ limit: 100 })和for await进行迭代；在Python中，对返回的列表调用.auto_paging_iter()方法；在Java中，对StripeCollection对象调用autoPagingIterable()方法。在使用这些功能之前，请先确认其与您安装的SDK版本兼容。

在服务器端进行过滤​

过滤器可以在Stripe进行分页之前缩小数据集的范围；如果在客户端进行过滤（即在数据获取之后再进行过滤），则必须读取全部数据。

过滤条件示例适用范围
时间范围created[gte]=1735689600&created[lt]=1738368000费用、退款、余额交易
状态status=available余额交易
客户信息customer=cus_QyJ8...费用、支付意图、发票
支付记录payout=po_1N...单次支付中的余额交易

可以组合多个过滤条件，以便将对账任务的数据全部显示在同一页面上。例如，每天读取昨日的费用数据（使用created时间范围）就可以显示在一页内。

光标分页与偏移量分页的对比：​

这种设计对客户端有以下两个影响：

搜索接口的分页机制：

  • 没有页码：标准的列表端点不会提供page=2或total_count这样的标识符。如果需要知道总结果数量，请自行统计数据。不同类型的搜索端点的实现方式可能有所不同（详见下一节）。
  • 无法随机访问页面：只能使用starting_after向前翻页，使用ending_before向后翻页；无法直接跳转到第40页（例如，在总共200页的数据中）。

搜索端点的分页方式不同​

这些搜索接口会接收一个查询字符串作为输入，并返回一个 next_page 标识符，而不是对象形式的查询结果。

curl -s -G https://api.stripe.com/v1/charges/search \
  -u "$STRIPE_SECRET_KEY:" \
  -d query="amount>1000 AND status:'succeeded'" | jq '.next_page'

将令牌以 page 的形式传回，以便读取下一页。包含 next_page: null 的响应表示页面已结束。搜索结果中不包含 starting_after，因此在客户端中需要将这两种分页方式区分开来处理。

端点类型光标参数结束信号
标准列表starting_afterhas_more: false
搜索pagenext_page: null

确保批量数据读取在规定的速率限制范围内进行​

对于超过一年未处理的交易记录，系统可能会一次性发送数千条请求。为减轻服务器负担，请在Stripe限制并发请求时暂停操作。

  • 每次只读取一页数据；当并发请求达到上限时，可以并行处理同一数据集的不同部分。
  • 请确保在429中正确使用Retry-After头部信息。详情请参阅错误与重试机制。
  • 将当前处理到的数据位置（即光标位置）缓存到持久化存储中，以便系统重启后能从上次中断的地方继续处理，而无需从头开始。
  • 相比遍历整个数据集，建议仅获取有限范围的数据（例如created范围内的数据）。
