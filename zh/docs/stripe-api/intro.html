Stripe API简介

Stripe API负责在客户、您的平台以及您的银行账户之间进行资金转移。本参考文档中的所有接口都基于同一组共享数据对象进行操作。在发送第一个请求之前，请先阅读此页面。

所有接口都使用相同的基地址：https://api.stripe.com。

支付对象模型​

每笔支付都会生成五个相关对象。通过追踪这些对象，您可以了解资金流动的完整路径（从用户结账到最终到达您的银行账户）。每个对象记录了一个具体的处理阶段，便于后续审计。

对象ID前缀功能
Customercus_存储付款人信息、保存的支付方式以及账单历史记录（一次性支付可选）。
PaymentIntentpi_记录每次收款尝试的详细信息（包括金额、货币及当前状态）。
Chargech_记录资金通过特定支付方式的转移情况；成功的支付请求会生成一个Charge对象。
BalanceTransactiontxn_记录Charge、退款或资金发放对您账户余额的影响（包含相关费用）。
Payoutpo_根据支付计划，将已结算的余额转入您的银行账户。

一笔付款首先以“PaymentIntent”的形式开始记录；该记录会包含付款金额和状态，直到付款方式完成确认。确认后，系统会生成相应的“Charge”记录并转移资金；随后，“BalanceTransaction”记录下总金额、Stripe费用以及实际到账金额。已结算的资金会显示在账户余额中，并通过“Payout”流程完成转账。

文章《资金如何在Stripe中流动》通过具体示例详细说明了每个处理阶段，包括支付失败、退款及争议处理等情形。

规范说明​

请求与响应数据的结构在整个平台内保持一致；本参考文档中的代码示例均遵循这些规范。

规范名称规则内容示例说明
金额必须使用最小货币单位表示（不能使用小数）。2120：收费金额为21.20美元（USD）。
时间戳采用UTC时间格式（以秒为单位）。1754447247
货币代码使用ISO 4217标准的小写形式。usd, eur, jpy
字段名称snake_case.payment_method_types
对象类型所有响应数据都会在object中明确标注其类型。"object": "payment_intent"
Nullability如果某个字段未被设置或为空，其返回值为 null；该字段本身仍然会保留原样。"customer": null
备注

对于像日元（JPY）这样的零小数货币，金额会被视为整数单位。例如，1000 表示收费 1,000 日元，而不是 10.00 日元。

一目了然的认证流程​

每个请求都必须附带一个秘密 API 密钥，该密钥应作为 Basic Auth 的用户名并使用空密码进行验证。测试用密钥以 sk_test_ 开头，生产环境密钥以 sk_live_ 开头。由于秘密密钥具有完整的账户权限，因此只能通过服务器代码发送。

curl https://api.stripe.com/v1/balance \
  -u "$STRIPE_SECRET_KEY:"

认证与密钥管理 部分介绍了受限密钥的使用及轮换机制，还说明了如何安全地存储密钥。

测试模式与生产模式​

每个账户都有两个独立的环境：在测试模式下创建的对象不会涉及实际资金交易。

模式键前缀数据类型用途
测试sk_test_与生产数据隔离开发、自动化测试、演示用途
实时状态sk_live_实际费用与支付记录生产环境

测试模式会将卡片编号映射到特定的结果，包括“交易被拒绝”和“身份验证失败”。文档“测试模式与测试卡片”列出了该参考资料在示例中使用的卡片编号。

一目了然地查看错误​

当请求失败时，系统会返回一个包含稳定状态 type 和人类可读信息的 message 的响应；code 和 param 可进一步帮助诊断问题原因。

{
  "error": {
    "code": "parameter_invalid_integer",
    "doc_url": "https://stripe.com/docs/error-codes/parameter-invalid-integer",
    "message": "Invalid integer: 21.20",
    "param": "amount",
    "type": "invalid_request_error"
  }
}
HTTP 状态错误类型常见原因
400invalid_request_error缺少参数、参数格式错误或参数值超出范围。
401invalid_request_error该密钥已丢失、被撤销，或属于其他账户。
402card_error发卡机构拒绝了这笔交易请求。
403invalid_request_error该密钥没有访问此资源的权限。
404invalid_request_error在这种模式下，该对象不存在。
429rate_limit_error该密钥的请求频率超出了限制。

错误与重试 将每种错误类型映射到相应的恢复步骤，并说明哪些失败情况可以安全地重新尝试。

API版本​

Stripe 会为您的账户指定一个固定的 API 版本。如果没有包含 Stripe-Version 标头的请求，系统会使用这个固定版本；因此，服务器升级不会对响应格式造成任何影响（也不会发出任何警告）。在测试新功能时，您可以针对每个请求手动覆盖该 API 版本。

curl https://api.stripe.com/v1/balance \
  -u "$STRIPE_SECRET_KEY:" \
  -H "Stripe-Version: 2024-06-20"

API版本控制与升级详细介绍了升级流程，并解释了“pin”（固定机制）的作用。

通过幂等性确保重试的安全性​

当网络请求超时后，您无法确定 Stripe 是否已经处理了该请求。此时，您需要发送一条消息来确认请求的状态。重试时 POST 会携带相同的 Idempotency-Key；Stripe 会返回原始结果，而不会重复收费。

幂等请求介绍了如何选择密钥，以及Stripe会存储结果多长时间。该文档还解释了当您使用相同的密钥但新的参数重新发起请求时可能出现的错误。
