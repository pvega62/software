提交信息​

Fix encoding/decoding of F-ordered NumPy arrays

`bytes(arr.data)` materializes the buffer contents in C order, so encoding a
Fortran-ordered array pairs C-ordered bytes with Fortran strides. Decoding
then reads those bytes with the wrong strides and returns a scrambled array.

Record the memory order in a new `order` field of the `Ndarray` message, and
let `ndarray_to_numpy` transpose and reshape when that field reports "F".
Buffers encoded before 0.2.4 have an empty `order` field, so decoding them
yields C-ordered arrays.

Closes #63

提交请求（Pull Request）​

摘要​

当使用 Fortran 排序的 NumPy 数组进行 Protobuf 数据交换时，数据会被破坏：原本按 Fortran 排序的数组在解码后其元素位置会发生变化。解码器不会报错，但调用者会接收到一个顺序混乱的数组。

Round-trip test
arrF = numpy.array([[1, 2, 3], [4, 5, 6]], order="F")
numpy.testing.assert_array_equal(
    arrF,
    ndarray_to_numpy(ndarray_from_numpy(arrF)),  # returns [[1, 3, 5], [2, 4, 6]] without the fix
)

根本原因​

ndarray_from_numpy 将原始缓冲区存储在数组步长（array strides）旁边；这两个值描述了不同的内存布局：

  1. 编码：bytes(arr.data)会按照C语言的数组顺序对数据进行编码；因此，如果源数组是按照Fortran语言的顺序排列的，那么编码后的字节序列也会保持相同的顺序。
  2. “Strides”：ndarray_from_numpy完全复制了strides的内容，因此它们仍然描述的是Fortran语言的代码布局。
  3. 解码（Decode）：numpy.ndarray(buffer=..., strides=...)操作会将Fortran风格的数组索引方式应用于按C语言顺序排列的字节数据。这种索引方式会导致访问错误的字节位置，从而返回错误的结果。

修复​

在编码过程中记录内存访问的顺序；在解码过程中按照该顺序重新执行这些操作。

  • protobufs/npproto/ndarray.proto 以及生成的 mcbackend/npproto/__init__.py 在 Ndarray 消息中新增了一个名为 order 的字符串字段（标签为 5）。
  • 在编码过程中，mcbackend/npproto/utils.py会将数据写入order="CF"[arr.flags.f_contiguous]；一个按照Fortran顺序排列的数组用于存储这些数据（"F"）。在解码过程中，ndarray_to_numpy会对这些数据进行转置和重新排序（nda.order == "F"），从而将数据恢复成Fortran格式。
  • mcbackend/test_npproto.py负责添加参数test_byteorders，该参数用于同时控制*shape和order*的行为。

测试​

TestUtils.test_byteorders需要同时设置参数shape和order；每个测试用例*(5,)、(2, 3)、(2, 3, 5)以及(5, 2, 1, 7)都会运行两次（分别对应两种内存排序方式）。所有测试用例都需要验证nda.order与arr.flags.f_contiguous*的结果是否一致，并对数组进行完整的编码和解码操作。

*TestUtils.test_conversion*目前仍支持整数（int）、浮点数（float）、标量（scalar）、字符串（string）、对象（object）以及日期时间类型（datetime）的数据处理。

备注​

  • 将版本号更新为*0.2.4*。
  • ndarray_to_numpy功能会执行转置操作，并且会保留原有的缓冲区处理机制以及数据类型（dtype）的处理方式。
  • 在*0.2.4之前被编码的数据缓冲区中，order*字段为空；解码这些数据时会得到一个按照C语言顺序排列的数组。

测试方法​

Verify the fix
pytest mcbackend/test_npproto.py

测试套件会先使用新的*test_byteorders*功能进行两种内存排序方式的测试，然后再重新运行原有的数据类型相关测试用例。
