错误与问题详情

每次失败都会返回一个包含 RFC 9457 格式信息的响应（application/problem+json）。该响应内容涵盖了验证错误、授权问题、数据缺失以及冲突情况；因此，客户端需要根据这些信息来编写相应的解析逻辑。

409 Conflict
{
  "type": "https://api.bludhavenpets.com/errors/adoption-hold-conflict",
  "title": "Adoption Hold Conflict",
  "status": 409,
  "detail": "Animal pet_krypto_210 is currently reserved under active hold hld_77a28f expiring at 2026-11-17T08:15:00Z.",
  "instance": "/adoptions/holds",
  "request_id": "req_6c1f90ab3d4e"
}

字段​

字段是否必填用途
type是用于标识错误的唯一 URI；客户端应基于此 URI 创建相应的代码分支。
title是表示错误类型的简短人类可读标签。
status是HTTP 状态码（会在错误信息中重复出现）。
detail是用于描述具体出错的记录、字段或限制条件的简短描述。
instance否生成错误的请求路径。
request_id否用于支持工单的 X-Request-Id 请求头字段的值。

在 type 处创建分支。该 URI 在所有版本中保持不变，而 detail 则是供人类阅读的说明性文本；如果客户端尝试匹配这些文本，那么在内容首次发生变化时就会出错。

错误目录​

type状态码出现原因
/errors/invalid-request400参数或请求体字段不符合规范。
/errors/unauthorized401请求未携带凭证，凭证已过期，或凭证不在注册表中。
/errors/insufficient-scope403令牌已通过认证，但缺乏该路由所需的权限范围。
/errors/record-not-found404不存在与该标识符匹配的记录。
/errors/microchip-already-registered409该微芯片编号已被其他动物使用。
/errors/adoption-hold-conflict409该动物已被其他申请人申请。
/errors/duplicate-refund409该费用已在申请中得到退款。
/errors/business-rule-rejected422请求已被解析，但被相应的规则拒绝。
/errors/rate-limited429传递的凭证超出了当前窗口的有效期限。

为节省表格显示空间，前缀 https://api.bludhavenpets.com 被省略了。如需构建完整的 URI，请在相应值前加上该前缀。

当出现 429 错误时，会返回这些错误信息；这并非数据问题。速率限制指南 中介绍了每个凭证的允许请求次数（Retry-After）以及重试策略。

区分 401 和 403​

  • 401 错误可能由以下原因引起：缺少必要的请求头、签名伪造或令牌过期（超出有效期 2 分钟）；

  • 401 涵盖了缺失的标头、伪造的签名以及已过期（exp）的令牌。WWW-Authenticate 标头携带 error="invalid_token"。

  • 状态码 403 表示请求的令牌有效，但缺少路由所规定的权限范围。此时，服务器会返回一个包含错误代码（error="insufficient_scope"）以及一个参数（scope），该参数指明了需要请求的具体资源或操作内容。

无论是哪种错误类型，服务器返回的响应中都会在 type 字段中重复说明错误原因；因此，客户端应根据 /errors/unauthorized 或 /errors/insufficient-scope 这些参数来决定后续的处理流程（即执行不同的操作）。

区分 400 和 422​

这两种情况都表示请求出现了错误；区别在于由谁来修复这个错误。

  • 400 表示数据格式错误：要么某个必填字段缺失，要么应该使用整数的地方使用了字符串，要么数值超出了允许的范围。
  • 422 表示数据格式正确，但平台仍拒绝处理请求。常见原因包括：被隔离的动物、缺货的商品、或申请者未通过家庭环境检查。

向发送请求的客户端返回一个错误代码“400”；同时，向用户需要查看的业务规则系统返回一个错误代码“422”。

422 Unprocessable Content
{
  "type": "https://api.bludhavenpets.com/errors/business-rule-rejected",
  "title": "Business Rule Rejected",
  "status": 422,
  "detail": "Animal pet_krypto_210 is under medical quarantine until 2026-11-24 and cannot accept a hold.",
  "instance": "/adoptions/holds",
  "request_id": "req_9a02ce41b8f7"
}

按状态划分的重试策略​

状态重试次数原因
400不需要重试同一请求再次失败。
401重试一次，并使用新的令牌令牌已过期。
403在请求该权限范围后提供更广泛的权限或重新获取用户同意即可解决问题。
404不需要重试该标识符对应的记录不存在。
409在锁定期限结束后锁定会自动解除（在 expires_at 时刻）。
422在业务规则变更后隔离措施解除、货物到货或顾问介入后问题可解决。
429在 Retry-After 秒后重试窗口会自动重新打开。

每次重试（POST）之前都需要先进行一次Idempotency-Key 处理；POST /refunds 次重试同样适用；如果使用相同的令牌进行重试，系统会退还原付款金额而非再次收费。

追踪生产环境中的故障​

错误代码（X-Request-Id）会出现在所有响应中（包括成功响应）。请将其记录在日志中，并在支持信息中引用该错误代码。支持人员可以直接查看平台的相关追踪信息，无需您重复操作。

客户报告问题症状后，系统会使用一个唯一的标识符将该报告转换为日志记录。Animal is stuck as reserved表示日志中的一行，其中包含问题的原因说明。

相关指南​

  • 身份验证与权限范围：导致401错误（“未授权”）的认证规则。
  • 速率限制：与429错误（“请求过多”）相关的机制及重试策略。
  • 请求处理与并发控制：由第二位客服人员处理的409错误（“请求已被拒绝”）相关内容。
  • 故障排除：需要修复的具体问题症状。
