Blüdhaven Pets的领域模型

Blüdhaven Pets平台负责协调宠物的接收、市政许可申请、兽医健康检查，并管理三个实体门店及在线领养目录中的零售库存。

架构概览

本文档详细说明了Blüdhaven Pets OpenAPI 3.1合约背后的业务逻辑、状态机以及监管要求。

实体门店（Branch）​

共有三个实体门店为Blüdhaven提供服务，合约将这些门店的标识符定义为BranchId枚举类型。所有宠物接收记录、领养待处理信息及供应订单名称均使用该标识符进行唯一标识。

字段类型约束条件描述
idstringBranchId enumloc_harbor_04, loc_downtown_01, or loc_westend_08.
name字符串（string）无特定约束实体门店的交易名称。
kind字符串（string）intake、retail或transitional枚举类型必填项
city字符串-该设施服务的行政区划。
address字符串-客户来访的街道地址。
phone字符串+1 国家代码前台电话号码。
services字符串数组自由文本可预订的服务（例如 spay-neuter）。

动物​

用于追踪宠物在各个行政区域之间的接收、兽医护理及领养过程的中央系统。

字段类型约束条件描述
id字符串前缀 pet_独有的平台标识符。
name字符串最长60个字符被分配的宠物名称。
species字符串枚举类型允许的值包括 dog、cat、rabbit、bird 或 small_mammal。
breed字符串最长100个字符主要认定的品种或混血类型。
age_months整数大于等于0入院时的年龄（以整月计）。
sex字符串枚举类型male 或 female
weight_kg数字浮点数最后一次体检时的体重（单位：千克）。
microchip_id字符串必须包含15位数字符合ISO 11784和11785标准的微芯片标识符。
status字符串枚举类型状态机的当前阶段。
intake_branch_id字符串BranchId枚举类型
intake_date字符串（日期）根据ISO 8601格式官方记录的动物被收容或领养的时间戳。
adoption_fee_cents整数分（货币单位）收容费用：Harbor分部每只狗收取15000分（即150美元）。
temperament_tags字符串数组自由文本用于筛选领养申请的信息，例如good-with-cats所示的内容。
health_record对象AnimalHealthRecord动物的详细临床记录。
photo_urlsURI数组绝对URL地址从媒体服务器加载的图片链接。

健康记录​

存储动物的临床评估结果、免疫接种记录以及强制隔离期间的关键信息。

字段类型约束条件描述
rabies_tag_number字符串格式 RB-YYYY-XXXX必填的狂犬病疫苗接种证书代码。
rabies_expiration_date字符串（日期）ISO 8601 格式狂犬病疫苗证书的有效期；过期日期将导致申请被拒绝。
spay_neuter_certified布尔值必填根据市政法规，这是收养流程完成的法定前提条件。
quarantine_release_date字符串（日期时间）可为空被咬伤或收容动物必须接受 14 天观察后的才能获准领养。
veterinarian_license字符串格式 DVM-XXXXX发证兽医的州级执照编号。
last_exam_date字符串（日期）ISO 8601 格式最近一次临床检查的日期。

收养暂缓​

在现场面试和背景调查期间，用于锁定动物的专属预留状态。

字段类型约束条件描述
id字符串前缀 hld_唯一的暂缓记录标识符。
animal_id字符串外键引用目标动物信息。
applicant_id字符串前缀 usr_经过验证的采用者信息（参考资料）。
branch_id字符串外键面试发生的分支（branch）。
expires_at字符串（日期时间）ISO 8601 格式自创建后强制生效的 30 分钟过期时间戳。
seconds_remaining整数计算值用于计算读取路径返回的时间，以便客户端无需解析时间戳。
status字符串枚举类型状态可以是 ACTIVE、EXPIRED、RELEASED 或 CONVERTED。

动物的状态生命周期​

每只动物都会按照严格的状态机进行转换；未注册或未经认证的状态会直接返回到初始状态（422 Unprocessable Content）。

   │                                                     │

   │ (Adoption fee paid & license filed)
   ▼
[ADOPTED]

生命周期状态​

  • INTAKE：动物通过市政收容所或流浪动物救助程序被接收。此时其信息在目录中不可查看。
  • VET_CLEARANCE：动物正在接受临床检查及法定微芯片植入。
  • MEDICAL_QUARANTINE：因感染性疾病或被咬伤等原因，动物被隔离。客户无法查看或接触相关记录。
  • AVAILABLE：动物经持证兽医检查合格后，状态变为 spay_neuter_certified: true，并会被列入网站目录及可供购买。
  • RESERVED_HOLD：由店员或客户端应用程序创建的专属30分钟预订锁定机制，用于防止重复预订。
  • ADOPTED：宠物领养手续完成，相关费用已缴纳，且宠物的微芯片信息已录入注册系统。

并发控制规则与30分钟锁定期限​

为防止店内顾客与线上申请人同时尝试预订同一只动物而出现竞态条件：

  1. 原子性持有位置检查（Atomic Hold Placement）：该机制确保目标动物在写入包含POST /adoptions/holds的锁定记录之前，会先存储status: "AVAILABLE"。
  2. 冲突处理机制（Conflict Response）会返回一个 HTTP 409 Conflict 使用 RFC 9457 标准 ProblemDetails 当该动物已被列入“待处理”（active hold）状态时，不得再次对其进行相关操作。
  3. 当申请人在 1,800 秒内未完成付款时，系统会自动将动物的状态设置为 AVAILABLE（“待处理”）。此时，系统会通过 adoption.hold.expired 触发器（webhook）将相关信息发送给合作伙伴。

监管与市政合规性要求​

根据《Blüdhaven市动物管理条例》，有三项不可更改的规定：

  1. 完整的安全限制规定：未经验证的访问（spay_neuter_certified: true）将禁止动物进入AVAILABLE或ADOPTED状态。
  2. 法定微芯片格式要求microchip_id必须符合ISO标准，且包含恰好15位数字。
  3. 根据规定，狂犬病标签验证要求12周以上的狗和猫在离开场所（VET_CLEARANCE）之前必须记录下有效的rabies_tag_number信息。
