动物领养的临时保留机制与并发处理

Blüdhaven Pets通过三个实体零售门店和一个在线公共门户平台协调宠物领养流程。店内咨询师和在线申请人可以同时申请同一只宠物。该平台使用API来确保预订操作的原子性（即操作要么全部完成，要么全部失败），从而防止重复预订。

30分钟等待机制的运作方式​

当求职者开始面试或在线完成注册流程时，您的客户端应用程序必须请求暂时暂停相关操作（即“临时冻结”相关流程）。

[Available Animal] ──► POST /adoptions/holds ──► [30-Minute Hold Granted]
                             │
                             ▼ (Second concurrent request)
                    [HTTP 409 Conflict]
  1. 状态验证：该 API 确认动物存储了 status: "AVAILABLE" 的信息，并从 health_record.spay_neuter_certified 中读取了 true 的数据。
  2. 创建锁记录：该API会写入一条AdoptionHold记录，并将动物的状态设置为RESERVED_HOLD。
  3. 过期时间（TTL）：服务器会在数据创建后 1,800 秒时为其分配一个不可更改的过期时间戳。
  4. 分辨率（Resolution）。
    • 如果申请人完成相关文件填写并支付领养费用，工作人员会提交申请，此时领养流程将进入 CONVERTED 阶段。
    • 如果30分钟内未完成，后台自动回收机制会将该保留标记为EXPIRED，并将该动物恢复为AVAILABLE状态。

暂停预订​

向 /adoptions/holds 发送一个 POST 请求，其中包含动物标识符和申请者标识符。

cURL
curl -X POST https://api.bludhavenpets.com/v1/adoptions/holds \
  -H "Authorization: Bearer <STAFF_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "animal_id": "pet_krypto_210",
    "applicant_id": "usr_9921bc",
    "notes": "In-person consultation at the Downtown adoption floor"
  }'

响应成功​

201 Created

Response
{
  "id": "hld_77a28f",
  "animal_id": "pet_krypto_210",
  "applicant_id": "usr_9921bc",
  "branch_id": "loc_harbor_04",
  "status": "ACTIVE",
  "created_at": "2026-11-17T07:45:00Z",
  "expires_at": "2026-11-17T08:15:00Z",
  "seconds_remaining": 1782
}

处理 409 冲突冲突​

当其他员工或在线申请者抢先认领某只动物时，系统会返回一个相应的提示信息。 HTTP 409 Conflict 使用 RFC 9457 标准 ProblemDetails standard.

409 Conflict Response
{
  "type": "https://api.bludhavenpets.com/errors/adoption-hold-conflict",
  "title": "Adoption Hold Conflict",
  "status": 409,
  "detail": "Animal pet_krypto_210 is currently reserved under active hold hld_77a28f expiring at 2026-11-17T08:15:00Z.",
  "instance": "/adoptions/holds"
}

提前解除限制（或：提前释放资源）​

一旦面试失败或申请人离开，咨询员会立即解锁（相关系统）。否则，在接下来的半小时内，这只动物对其他领养者来说将处于“不可见”状态（即无法被看到）。

cURL
curl -X DELETE https://api.bludhavenpets.com/v1/adoptions/holds/hld_77a28f \
  -H "Authorization: Bearer <STAFF_TOKEN>"

当 204 No Content 被确认后，动物会立即返回到 AVAILABLE。如果某个已被处理的请求（hold）已经被转换为正式的申请（application），那么该请求会返回到 409；因为一旦提交申请，就无法再撤销它了。

推荐的客户端恢复流程​

  1. 解析detail中的消息内容，或查看目标动物的相关信息。
  2. 查看当前待处理的请求（hold）中的expires_at。
  3. 如果客户希望等待，提示他们加入通知队列；当当前的等待时间到期且仍未完成交易时，系统会向他们发送提醒。
  4. 提供与客户选择的宠物品种和性格特征相匹配的替代宠物作为陪伴动物。
