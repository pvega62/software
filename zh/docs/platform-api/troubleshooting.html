排查请求失败的原因

大多数故障问题可以通过以下三种方法解决，请按顺序尝试：

  1. status：列出故障的类别。
  2. type：指出触发该故障的具体规则（参见错误目录）。
  3. request_id：将此次请求与平台日志关联起来（以便进一步分析）。

受保护的调用将返回 401 状态码​

WWW-Authenticate头部字段包含了路由所要求的协议相关信息。

WWW-Authenticate: Bearer realm="bludhaven", error="invalid_token"

会导致这种错误的常见原因有五种：

  • 标题缺失。这可能是由于浏览器壳层或代理服务器导致的。
  • “scheme”这个词的用法有误。Authorization: Basic在处理基于“bearer”认证的路由时出现了问题（即无法正常工作）。
  • 该令牌已被伪造或篡改。网关会验证 HMAC 签名，因此只有它自己生成的令牌才能通过验证。
  • 传递的令牌为 exp。需要重新生成一个新令牌（参见 认证 部分）。
  • 如果键输入错误、已被停用，或者被发送到了仅接受令牌的路由上，系统会提示 “ApiKey” 而非 “Bearer”。

在没有身份验证要求的路由上，永远不会返回 401 错误（例如：GET /animals、GET /animals/{animalId}、POST /applicants、POST /sessions、POST /webhooks/test-dispatch 这些路由都不需要凭证）。

受保护的调用返回 403 错误​

网关识别出了令牌，但该路由所需的权限范围（scope）并未包含在令牌中；系统会明确指出缺失的权限范围。

WWW-Authenticate: Bearer realm="bludhaven", error="insufficient_scope", scope="write:animals"

type 的内容是 https://api.bludhavenpets.com/errors/insufficient-scope；detail 用于在文本中指代缺失的部分（即“缺失的范围”）。

会出现以下两种情况：

  • 客户端凭据令牌请求的范围过窄。请使用挑战中指定的范围重新提交令牌请求。

  • 当请求与动物相关的数据时，系统会返回 404 错误。​

问题出在授权环节。使用相同的令牌重试仍会返回相同的 403 错误。

动物名称也会返回 404​

GET /animals/{animalId} 接受以 pet_ 开头的收容标识符。输入微芯片编号、名称或全大写形式时，均会返回 404 错误。

首先发送 GET /animals?status=AVAILABLE，然后从页面中复制一个 id。该操作可以确认标识符的格式以及存放该动物的分支信息。

一个原本有效的保留ID现在返回404错误​

根据设计，有两个目标会自动释放它们所持有的动物。

目标为什么该标识符会失效？
浏览器演示重新加载页面会清除标签页中的持有记录。
沙箱网关被回收的边缘设备会释放其内存中保存的持有信息。

这两个系统都没有通过 API 释放动物；需要重新创建一个新的持有记录并继续处理。将 404 视为缺失的记录，而非已释放的动物。

生产环境中的持有记录在两种情况下都能保留下来，因为它们存储在持久化存储中。

保留操作因 422 错误而失败​

即使没有持有记录存在，平台也会拒绝接收不符合条件的动物。

  • 动物的状态可能与 AVAILABLE 不同（例如为 MEDICAL_QUARANTINE）。
  • spay_neuter_certified 的值为 false，且市政法规阻止了放生。
  • 狂犬病相关文档的有效期在暂停窗口之前就已过期。

阅读动物记录，并将 status 提供给咨询师；在此情况下，等待列表中的条目比重试更有效，因为请求中的任何内容都无法改变最终结果。

演示正常运行，而沙箱则拒绝请求​

沙箱网关执行了 浏览器演示 中未涉及的安全检查，这种差异解释了两者之间的几乎所有区别。

通过网关提供的任意非开放路由发送一个令牌；可以使用客户端凭证生成令牌，或点击参考链接中的 “Connect” 按钮进行操作。伪造的字符串会返回 401，而具有正确路由范围的真实令牌则会返回 403。

网关对已记录的操作返回了 404 响应​

这可能是由于部署版本过旧导致的；请确认网关加载的合约版本是否正确。

curl https://sandbox.bludhaven-pets.workers.dev/health

当前版本的部署会返回 operations: 24 和 secured: 19；如果返回的数值较低，说明边缘节点仍在使用旧版本的响应数据，重新部署即可解决问题（参见 版本控制。

升级处理​

发送邮件至 budbaker@bludhavenpets.com，并附上四个值。

  • 失败响应中的 X-Request-Id。
  • 操作内容及其目标环境（生产环境或沙箱环境）。
  • 状态信息以及对应的type URI地址。
  • 带有时区信息的时间戳。

支持无需用户重新执行操作即可获取追踪数据的功能；若未提供该功能，报告生成将需要额外网络请求（即产生往返通信开销）。
