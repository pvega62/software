  • 身份验证与权限范围（Authentication and Scopes）

身份验证与权限范围（Authentication and Scopes）

有两种凭证（credentials）可用于访问受保护的路由；选择哪种凭证取决于代码的运行环境。

凭证类型传输方式使用者有效期
承载令牌（Bearer Token）Authorization: Bearer <token>适用于员工门户及合作伙伴集成系统有效期为 1 小时，刷新令牌的有效期为 30 天。
API 密钥（API Key）X-API-Key: <key>用于服务器任务及 POS 终端直到管理员更换密钥为止。

这两种认证方式都可以在沙箱网关上使用，每个受保护的路由会验证它所接受的任意一种认证方式。这两种方式是互斥的（即不能同时使用），不存在固定的使用顺序。如果在零售路由上发送 X-API-Key，请求将无需令牌即可通过验证。

有五条路由对所有用户开放（GET /animals、GET /animals/{animalId}、POST /applicants、POST /sessions、POST /webhooks/test-dispatch），这些路由无需任何安全验证。潜在用户可在创建账户前浏览相关目录；接收方在进行测试时也不需要任何凭证。

从参考代码登录​

沙箱网关负责运行授权服务器，因此点击“Connect”按钮后才能完成真正的登录流程。

  1. 打开 交互式参考。下拉列表中首先显示的是 Sandbox gateway，因此如果出现其他目标，请选择它。
  2. 打开身份验证面板，然后在 bludhaven_oauth 上点击 连接。
  3. 同意相关条款：该界面会列出客户端请求的权限范围；用户可以选择 “Approve”（批准）或 “Deny”（拒绝）。
  4. 控制台会返回一个授权令牌（token）。客户端需使用该令牌发送安全请求，网关会验证令牌的有效性、过期时间以及权限范围。

同意条款界面会显示在网关页面上，因此用户需要暂时离开当前页面；如果代码是在嵌入内容中运行的且弹窗无法返回授权码，请打开 独立的授权页面 进行登录。

授权码流程​

网关发布了这两个端点，而合约则在 bludhaven_oauth 下声明了它们。

  1. 客户端生成验证器（verifier）：客户端会生成该验证器的 SHA-256 哈希值，并通过 code_challenge 发送给 https://sandbox.bludhaven-pets.workers.dev/oauth/authorize。
  2. 网关会向客户端发送一个有效期为两分钟的授权码。
  3. 网关会将授权码重定向至客户端，该授权码有效期为两分钟。
  4. 客户端将代码和原始验证器发布到 https://sandbox.bludhaven-pets.workers.dev/oauth/token。
  5. 响应内容：响应中包含 access_token、token_type、expires_in、被授予的权限范围（scope）以及 refresh_token。

在这里，PKCE非常重要，因为合作伙伴的集成是在一个无人控制的设备上运行的。如果没有验证器，截获到的代码是毫无用处的。

客户端ID为bludhaven-staff-portal。由于公开演示无法保密，因此该客户端仅使用PKCE进行身份验证，不存在任何可泄露的秘密信息。

使用 curl 生成令牌​

该脚本没有浏览器来处理用户同意流程；客户端凭据可在一次请求中生成令牌（即在一个POST操作中完成）。

curl -X POST https://sandbox.bludhaven-pets.workers.dev/oauth/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=client_credentials" \
  -d "client_id=bludhaven-staff-portal" \
  -d "scope=read:animals write:animals"
200 OK
{
  "access_token": "blud_at_eyJzdWIiOiJjbHVk...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "scope": "read:animals write:animals"
}

省略 scope；网关会授予四种读取权限。如果请求超出目录范围内的权限，调用会返回 400 以及相关的权限信息（invalid_scope）。

后续的所有请求都必须在请求头中包含该令牌。

curl https://sandbox.bludhaven-pets.workers.dev/animals/pet_krypto_210/health-records \
  -H "Authorization: Bearer <ACCESS_TOKEN>"

某个特定路由需要read:animals作为认证参数，因此只有包含write:animals的令牌才能通过该路由；否则会返回403。

刷新令牌​

在访问令牌过期前重新生成令牌；网关会返回新的令牌对，旧的访问令牌将失效。

curl -X POST https://sandbox.bludhaven-pets.workers.dev/oauth/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=refresh_token" \
  -d "refresh_token=<REFRESH_TOKEN>" \
  -d "client_id=bludhaven-staff-portal"

客户端凭据生成的令牌本身不包含刷新令牌的功能，因为客户端可以随时重新生成新的令牌。

使用 API 密钥进行身份验证​

注册终端和夜间执行的脚本都没有浏览器支持，也没有会话机制；它们各自使用独立的密钥，且每个密钥仅用于其所需处理的路由。

沙箱环境会发布两把有效的密钥；测试用凭据需要具备可复制性，因此这些密钥是公开可用的。

密钥可访问范围常见调用者
bpk_sandbox_pos_7f3a91c4read:retail, write:retail销售点收银机
bpk_sandbox_ops_2d8be05fread:animals, write:animals, write:adoptions, read:retail每日集成任务

将密钥作为请求头发送，并跳过所有中间处理步骤；

curl https://sandbox.bludhaven-pets.workers.dev/retail/inventory \
  -H "X-API-Key: bpk_sandbox_pos_7f3a91c4"

该密钥用于读取库存信息并下达采购订单；若将同一密钥用于动物记录的更新操作，系统会拒绝请求；

curl -X POST https://sandbox.bludhaven-pets.workers.dev/animals \
  -H "X-API-Key: bpk_sandbox_pos_7f3a91c4" \
  -H "Content-Type: application/json" \
  -d '{"name": "Orion", "species": "dog", "microchip_id": "985141002348999", "intake_branch_id": "loc_harbor_04"}'
403 Forbidden
{
  "type": "https://api.bludhavenpets.com/errors/insufficient-scope",
  "title": "Insufficient Scope",
  "status": 403,
  "detail": "This API key lacks write:animals. Use a key assigned that scope, or send an OAuth token.",
  "instance": "/animals"
}

将操作密钥替换进去后，同一条请求会返回 201。密钥携带的是作用域集，而非整个目录：一个在计数器上过夜的寄存器，不应能提取动物记录。

无效的密钥会返回 401，系统会提示错误原因（即密钥对应的操作类型）而非具体的错误信息；

WWW-Authenticate: ApiKey realm="bludhaven", error="invalid_key"

密钥的轮换分为三个步骤：

  1. 发布新的密钥；
  2. 部署新密钥；
  3. 在最后一个调用者使用旧密钥后将其删除。

如果在周五晚上更换密钥，收银机将在周六无法正常销售商品。

当调用失败时​

网关会识别出两种类型的错误，并通过请求头来区分它们。

状态含义问题原因
401未提供有效的凭证；凭证被伪造或已过期；会话已失效；或者使用的凭证不在权限注册表中Bearer … error="invalid_token" 或 ApiKey … error="invalid_key"
403提供了有效的凭证，但该凭证的权限范围（scope）不符合路由的要求error="insufficient_scope", scope="write:animals"

403 中指出了 detail 中缺失的变量/作用域名称。需要在授权时请求该变量/作用域的访问权限，之后再重试操作。在生产环境中，当某个员工门户在登录时尝试访问该变量/作用域时，请求的权限信息不足（即请求的权限级别过低）。

在401部分的请求体中会用文字说明具体原因，以便读者了解路由实际需要哪种凭证；仅接受令牌（token）的路由会拒绝使用That route takes an OAuth bearer token, not an API key.类型的凭证。

权限范围目录​

每个权限范围只能用于执行一项特定的操作。请根据工作流程的需求请求相应的权限范围；因为使用admin:adoptions类型的凭证可以覆盖某些限制（例如临时权限）。

权限范围（Scope）可执行的操作
read:animals动物记录的查询、录入历史以及领养资格信息的查看
write:animals动物记录的创建、修改和删除操作
read:adoptions存储和审核收养申请信息。
write:adoptions管理申请的暂存状态、发布流程及提交操作。
read:applicants在咨询师审核期间管理申请人账户信息。
write:applicants创建和修改申请人账户。
vet:clearance提交兽医相关证书（仅限持证从业者）。
read:retail监控库存水平并处理采购订单。
write:retail下达或取消采购订单。
admin:adoptions解决订单冲突并退还相关费用。

采用者的会话​

申请者永远看不到该范围。公共门户会将电子邮件和密码兑换为一个短效令牌。

curl -X POST https://sandbox.bludhaven-pets.workers.dev/sessions \
  -H "Content-Type: application/json" \
  -d '{"email": "nadia.okafor@fastmail.com", "password": "<PASSWORD>"}'
200 OK
{
  "token": "blud_sess_eyJzdWIiOiJ1c3JfOTkyMWJjIn0.9c1f4d2b7a",
  "expires_at": "2027-01-15T21:04:11Z",
  "scope": "read:applicants write:applicants"
}

该网关在每次调用时都会生成一个新的令牌；因此，请从自己的响应中获取该令牌的值。上面的示例展示了该令牌的格式，但该格式的令牌并不能用于实际操作（即无法用于认证或授权）。

员工门户会将令牌存储在内存中，绝不会将其写入数据库。令牌仅用于读取操作，因此即使被窃取，也无法影响系统的其他功能。DELETE /sessions/current 会自动失效，后续使用该令牌的请求将再次返回 401。

哪个目标负责验证什么​

目标凭据检查
浏览器演示无需凭证即可完成所有操作。
沙箱网关需要验证令牌签名、有效期及权限范围；也可以通过注册表查询权限范围。无效的凭证会返回 401，权限范围缺失会返回 403。
生产环境执行相同的验证流程，并对每个凭证进行可撤销的客户端注册表记录及审计追踪。

生产环境并未增加沙箱环境中无法实现的功能，因为演示版本已经包含了真实的授权服务器。

平台支持的方案​

共有四种认证方式可供使用：其中三种被合同明确指定为安全认证方案，第四种则作为令牌类型使用（基于“bearer”认证机制）。

合同中规定的认证方案该方案的具体用途适用场景
bludhaven_oauth（授权码）需员工或合作伙伴同意后才能使用适用于员工门户及合作伙伴集成场景
bludhaven_oauth（客户端凭证）适用于无需人工干预的服务场景例如夜间任务、数据对账脚本等
api_key适用于设备或集成系统例如POS终端、服务器间数据同步等场景
来自 POST /sessions 的令牌用于一个浏览器会话的采用者公开采用门户

OAuth 用于需要用户凭证的集成场景，而密钥（Key）则用于存储在设备上的凭证。

生产环境新增的功能​

生产环境包含两项额外功能，因为公共演示版本无法展示这些功能。

  • 员工单点登录（Staff Single Sign-On）：OpenID Connect 将登录请求转发给市政身份提供商（Municipal Identity Provider），令牌交换过程保持不变。
  • 双向 TLS（Mutual TLS）：后端系统会在自定义域名上展示客户端证书；但由于 Cloudflare 的 workers.dev 服务器不支持这种证书格式，因此沙箱环境无法演示该功能。

出站 Webhook 使用 HMAC 请求签名机制（X-Bludhaven-Signature），沙箱环境提供了接收实时测试请求的接口（Webhook 指南）。

在生产环境中，基本认证方式（HTTP Basic Authentication）不再使用；所有请求中都会以明文形式传输 Base64 编码的凭证对，而承载令牌则用于处理服务器之间的通信，并附带相应的权限范围（Scope）。

请求凭据​

如需获取合作伙伴客户端 ID 或分配的 API 密钥，请发送邮件至 budbaker@bludhavenpets.com。请明确说明集成所需的权限范围以及所服务的具体分支，并附上任何失败响应中的相关信息（包括 X-Request-Id）。
