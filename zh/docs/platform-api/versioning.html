版本控制与变更政策

这个API由两个数字标识，它们分别回答了不同的问题。

编号值说明
路径类型（major）/v1该URL对应的是哪个合同版本生成方式
合同版本（contract version）2026.11.0您正在查看的是该版本生成的哪一次修订内容

路径仅在请求或响应出现错误时才会发生变化；合同版本会在每次发布时更新，而大多数发布都是对现有功能的补充。

不带新主版本号的发布内容​

这些变更会被包含在v1范围内，但可能不会被那些从未阅读过变更日志的客户所察觉。

变更内容对客户的影响
新端点（new endpoint）无
新的可选请求字段无
新的响应字段如果客户端忽略未知的字段，则该字段不存在于响应中
新的错误代码 type如果客户端使用已知字段集但处理失败，则返回该错误代码
带有默认值的新查询参数无

哪些地方需要 /v2​

修改内容的原因以及为何会导致问题
删除或重命名字段用户会丢失已存储的数据
将可选字段设为必填字段正常的请求会因此失败
改变数据类型（例如将整数改为字符串）解析器会拒绝之前能正确处理的请求数据
向枚举类型中添加新值（而客户端只能使用已有的值）客户端会遇到从未使用过的选项
对相同的结果使用不同的状态码重试逻辑会在错误的条件下触发
更改路径所有已保存的URL都会失效

那行枚举值（enum row）正是开发团队所忽略的部分。当客户在六个枚举值（AnimalStatus）中写入switch (status)并尝试添加第七个值时，会导致系统出错。平台新增状态（state）后，应该为default分支（branch）赋予实际的功能，而不是让它仅仅触发异常处理。

持久化客户端的四条规则​

  1. 忽略未知字段。 解析所需的键，其余的则舍弃。
  2. 在 type 处进行分支操作，而不是在 detail 处。错误 URI 是一个稳定的标识符（参见 errors）。
  3. 处理未知状态码。 将其记录下来，显示一个通用错误提示，并继续运行。
  4. 将合同版本固定在您的测试套件中。 这样，不同版本之间的差异会以测试失败的形式显示出来，而不是通过客户报告来体现。

规则四的执行会占用 CI 测试中的一个执行步骤（即一行代码）。需要获取合同内容，将 info.version 中的数值与固定值进行比较；如果数值发生变化，则构建过程会失败。随后会有人专门阅读这些差异信息。

弃用项​

那些被标记为“待移除”的字段仍会在指定的期限内继续正常使用。平台会在该期限开始之前，在开发者门户上公布这些字段的停用日期。

本合同目前不包含任何Deprecation或Sunset类型的响应头信息。请参考变更日志（change log）以获取最新信息，并在https://developers.bludhavenpets.com处订阅发布通知。

删除操作仅在重大版本更新时才会发生。在 v1 中被标记为“已弃用”的字段，在 v2 版本发布之前仍然有效（即可以继续使用）。

检查当前达到的生成版本​

沙箱网关会报告其所服务的合约信息。

curl https://sandbox.bludhaven-pets.workers.dev/health
{
  "status": "ok",
  "contract": "static/openapi/bludhaven-pets.yaml",
  "operations": 24,
  "secured": 19,
  "live_holds": 0
}

包含24个操作内容的列表用于描述当前的部署状态；如果该列表中的操作数量较少，说明部署已过时，这是当某个操作的返回结果为404时需要首先检查的情况。

相关指南​

  • 错误与问题详情：客户端应使用稳定的type URI来获取这些详细信息。
  • 测试请求：列出每个请求的目标以及它们所对应的合约版本。
  • 交互式API参考：可以在控制台中查看当前的info.version版本信息。
