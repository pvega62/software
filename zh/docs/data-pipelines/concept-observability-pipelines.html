事件流与可观测性管道

现代系统会产生大量遥测数据。 日志、指标、追踪、安全事件以及大型语言模型（LLM）交互数据都会同时涌入。本文将阐述可观测性管道如何实时收集、处理、路由和评估这些数据，并说明Datadog和Galileo在其中发挥的作用。

可观测性管道的重要性​

原始遥测数据通常成本高昂，且质量参差不齐。可观测性管道位于应用程序与监控工具之间，用于解决这些问题：

  • 降低成本：在海量日志进入昂贵的存储系统或安全信息与事件管理（SIEM）工具之前，对其进行过滤或采样。
  • 通过解析、规范化和元数据丰富来提升数据质量。
  • 保护隐私，方法是在处理流程的早期阶段对个人身份信息（PII）进行遮盖或删除。
  • 各层协同工作：Datadog报告问题发生的情况，而Galileo揭示问题产生的原因。

事件流的概念​

该技术栈结合了传统的云服务与基于大型语言模型（LLM）的功能，同时采用了两层独立的遥测系统。每一层都需要使用相应的工具来进行监控和管理。

使用 Datadog 进行操作遥测（Operational Telemetry）​

Datadog 负责监控基础设施和应用程序层。它收集日志和指标数据，然后通过管道将这些数据转发到相应的警报系统或存档系统中。您可以发送一条错误日志（payment-gateway），并使用 Grok Parser 来提取其中的关键信息（transaction_id）。之后，您可以将这些事件（status:error）转发到 Slack 警报系统或 S3 存档中。

Datadog 提供用于数据采集和管道处理的 日志管理。可观测性管道 可从您自身基础设施中的工作节点大规模路由遥测数据。日志浏览器 提供了实时搜索和实时尾部监视功能。

使用 Galileo 进行模型遥测（Model Telemetry）​

Galileo 负责处理大型语言模型（LLM）的相关功能。它会追踪每次模型调用的过程，记录输入数据、输出结果以及每个处理阶段的延迟时间，并使用评估指标对模型的响应进行评分。这样您就能判断您的payment-query大型语言模型函数是否能够返回准确、有条理且简洁的答案，以及部署环境的变化是否会对模型性能产生影响。

Galileo 是一款专为人工智能应用设计的工具。它将应用程序的评估功能与监控（observability）功能相结合，其支持的 Python 和 TypeScript 开发工具包（SDKs）可以集成到主流的大型语言模型（LLM）提供商的服务中。

这些组件协同工作：Datadog用于报告问题的发生；Galileo则用于分析模型质量下降的原因。

事件流概念​

事件流会按照时间顺序、且不间断地传输遥测数据。在现代应用程序架构中，事件流会同时来自多个来源：

  • 应用程序日志，例如 payment-gateway 错误事件
  • 基础设施指标，如 CPU 使用率、内存使用情况和延迟。
  • 来自应用性能监控（APM）工具的分布式追踪数据。
  • 安全审计和身份验证日志。
  • 大语言模型（LLM）的调用记录，包括输入内容、输出结果、处理延迟以及使用的令牌数量。
  • 容器和 Kubernetes 相关事件。
  • 物联网设备的遥测数据。

大语言模型调用记录是最近新增到该列表中的数据类型。随着越来越多的应用程序加入人工智能功能，捕获并分析这些交互行为变得与捕获传统应用日志同样重要。

核心流水线组件​

1. 消息摄取层（Ingestion Layer）​

原始的遥测数据在数据采集层（ingestion layer）被系统接收并存储。

对于操作数据，您需要将 JSON 格式的负载数据发送到 Datadog 日志摄取 API。请将请求指向 https://http-intake.logs.{dd_site}/api/v2/logs 并使用 DD-API-KEY 头部信息进行身份验证。请将 {dd_site} 替换为您所在地区的主机地址（例如 datadoghq.com 或 datadoghq.eu）。

当输入的 JSON 格式不正确时，Datadog 会返回 400 Bad Request。

对于大型语言模型（LLM）的数据，需要使用 @log 装饰器或 GalileoLogger 实例来封装相关函数。之后，Galileo SDK 会自动捕获这些函数的执行轨迹（即运行过程中的数据）。

Galileo SDK 从环境变量 GALILEO_API_KEY 中读取其配置密钥，并根据 GALILEO_PROJECT 和 GALILEO_LOG_STREAM 的值来确定目标项目及日志流的路径。

2. 处理层​

一旦数据进入 Datadog 的处理流程，处理程序会先对数据进行转换，然后再将其路由到相应的目的地。

  • 敏感数据扫描器：在数据存储之前会对个人身份信息（PII）进行加密处理。该工具能够识别电子邮件地址和信用卡号码等敏感数据模式。
  • Grok Parser：从原始日志字符串中提取结构化字段。
  • 重映射器（Remapper）：用于重新映射嵌套属性，例如 meta.customer_id。
  • 查找处理程序：利用外部参考数据对日志进行丰富处理，例如将 service 名称映射到 team_owner 标签。

在 Galileo 中，您可以在每个日志流上配置相应的 指标（metrics）。Luna SLM 会评估每个记录的响应在正确性、上下文一致性以及语气方面的表现。

3. 路由层​

路由层决定了处理后的事件会被发送到哪里。路由规则会根据内容、业务需求或合规性要求来制定。在 Datadog 中，您可以通过 日志管道（Log Pipelines） 和 索引（Indexes） 来配置路由规则。

  • 将status:error日志同时路由到待命警报系统和S3存档中。
  • 应用采样规则，以减少传入索引的status:info日志量。
  • 将与安全相关的事件转发至SIEM集成系统。
  • 使用 日志转发 功能，将特定的日志子集发送到外部 HTTP 端点。

在 Galileo 中，您可以通过将数据记录分组到不同的项目和日志流中来管理遥测数据。这种结构使您能够评估和比较不同的数据轨迹（即 dev、staging 和 production）。

4. 目标层（Destination Layer）​

可观测性（Observability）管道会将处理后的事件发送到专门负责特定任务的下游系统或工具中。

目标类型示例
对象存储Amazon S3, Google Cloud Storage (GCS), Azure Blob Storage
SIEMSplunk、Chronicle、QRadar
搜索与分析Elastic、OpenSearch、Snowflake
监控与警报Datadog 日志浏览器、仪表盘、监控工具
人工智能评估Galileo 日志流、实验结果

更高效的路由机制能够降低成本并缩短查询时间。直接推送到 SIEM 的原始日志会占用大量可观测性资源（即“可观测性预算”）。

常见使用场景​

  • 跨环境比较：使用相同的标准，对比 status:error 和 payment-gateway 环境中的模型运行行为。

  • 成本降低：在对status:info日志进行索引之前，应用10%的采样规则。

  • 安全分析：将身份验证失败记录和审计日志转发至 SIEM。

  • 数据规范化：使用 Grok 解析器来统一不同语言编写的服务中的日志格式。

  • LLM追踪：记录您使用AI功能时输入的每个提示（prompt）以及AI给出的所有回答，按会话（session）和追踪路径（trace）进行分类。

  • 响应评估：使用Luna评分系统来评估模型输出的准确性和对上下文的遵循程度。

  • 提示实验：在将更改部署到您的production日志流之前，先在Galileo实验中运行A/B测试来验证这些提示（prompt）的变化效果。

  • 跨环境比较：在不同环境中对比模型的表现。 staging vs production 使用相同的标准。

管道设计原则​

  • 现代应用程序会生成两种遥测数据流：一种包含操作日志，另一种包含与大型语言模型（LLM）的交互记录。
  • Datadog负责处理这些数据的采集、处理和路由，其管道架构专为高吞吐量的基础设施数据而设计。
  • 数据处理过程会对数据进行清洗和优化；数据路由会将每条记录发送到相应的目标系统。
  • 一个设计良好的管道能够降低成本并确保数据可靠性；它将基础设施质量指标和AI模型质量指标整合到一个统一的监控体系中。
  • 一个设计良好的管道能够降低成本并确保数据的可靠性。它通过统一的监控策略，同时报告基础设施和人工智能系统的运行状态以及模型质量的相关信息。
