Profile configuration reference

This page lists every setting a Sweepy profile accepts. Keep it open while you edit your profile. For a guided walkthrough, see Setting up Sweepy instead.

Where profiles live​

Sweepy reads profiles from the profiles/ folder inside your Sweepy directory. Each profile uses YAML, a plain-text format organized by indentation and colons. Open one in Notepad, VS Code, or any text editor you already have.

Start from config.sample.yaml or a preset such as profiles/paralegal_nyc.yaml. Copy a template, rename it, and edit the values:

Terminal
copy config.sample.yaml profiles\my_search.yaml
notepad profiles\my_search.yaml

Then point a sweep at that file:

Terminal
sweepy --profile profiles/my_search.yaml
note

A profile holds your entire configuration. Create as many profiles as you want: one per city or role family. Sweepy keeps sweep state outside the profile, in the discovery cache, the history database, and the logs/ and results/ folders.

caution

Indent with spaces, never with tabs. YAML rejects tabs, and one stray tab makes the whole profile unreadable.

Complete profile example​

The example below shows Alex's complete profile. Lines that start with # act as comments, and Sweepy ignores them:

profiles/paralegal_nyc.yaml
# ─────────────────────────────────────────────────
# Sweepy — Alex's Paralegal Profile (New York City)
# ─────────────────────────────────────────────────

# Your name. It appears in the PDF report header.
name: "Alex Rivera"

# Set true to write rotating debug logs under logs/.
debug: false

# ─── Job search ───────────────────────────────────
search:
  # Every title Sweepy searches at the same time.
  titles:
    - "Paralegal"
    - "Legal Assistant"
    - "Litigation Support Specialist"
    - "Legal Secretary"

  # Your target market.
  location: "New York, NY"

  # true keeps remote roles only. false keeps remote, hybrid, and on-site roles.
  remote_only: false

  # false removes hybrid roles from every report.
  include_hybrid: true

  # Annual salary floor. Use 0 to skip salary filtering.
  min_salary: 65000

  # true reads pay from the posting text when a board omits structured pay.
  salary_from_description: true

# ─── Resume ───────────────────────────────────────
resume:
  # Path to a PDF or DOCX resume. Forward slashes work on Windows.
  path: "Alex_Rivera_Resume.pdf"

  # Terms that carry the most weight when Sweepy scores a posting.
  must_have_skills:
    - "Westlaw"
    - "LexisNexis"
    - "e-discovery"
    - "Contract Review"
    - "Legal Research"

  # 1.0 is standard. Raise it to reward exact skill matches.
  keywords_weight: 1.5

  # Interchangeable terms. Sweepy matches every member of a group either way.
  synonyms:
    - ["e-discovery", "ediscovery", "electronic discovery"]
    - ["legal research", "case law research"]
    - ["docketing", "case calendaring"]
    - ["legal assistant", "legal secretary"]
    - ["contract review", "contract analysis", "agreement review"]

  # Optional: one resume per role family. Sweepy picks the best fit for each posting.
  tracks:
    - name: "Paralegal Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Paralegal.pdf"
      color: "#1D4ED8"
      route_keywords: ["paralegal", "litigation", "e-discovery"]
    - name: "Legal Assistant Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Legal_Assistant.pdf"
      color: "#7E22CE"
      route_keywords: ["legal assistant", "legal secretary", "scheduling"]

# ─── Platforms ────────────────────────────────────
platforms:
  greenhouse: true
  ashby: true
  lever: true
  workable: true
  aggregators: false

  # Extra ATS domains. Sweepy labels matching postings with this name.
  custom:
    - name: "SmartRecruiters"
      domain: "smartrecruiters.com"
      enabled: true
    - name: "Breezy HR"
      domain: "breezy.hr"
      enabled: true

# ─── Sources ──────────────────────────────────────
sources:
  jobspy:
    linkedin: true
    indeed: true
    glassdoor: true
    zip_recruiter: true

  # Leave a list empty to fall back to the seed lists in data/sources/.
  ashby:
    orgs:
      - "crosby"
      - "normlaw"
      - "hargrove-firm"
      - "lawhive"
  workable:
    slugs:
      - "shegerianand-associates-1"
      - "harper-james"
      - "legalvision"
  builtinnyc:
    enabled: true
    categories:
      - "jobs/legal"
      - "jobs/legal/search/paralegal"

# ─── Cache and history ────────────────────────────
cache:
  enabled: true
  ttl_seconds: 3600       # reuse discovery results for an hour

history:
  enabled: true
  retention_days: 4       # hide a reported posting for four days
  match: "url+role"       # "url" matches only an identical posting address
  path: null              # null uses ~/.sweepy/history.db

orchestrator:
  timeout_per_source_seconds: 180
  circuit_breaker:
    failure_threshold: 5
    cooldown_seconds: 30

# ─── Report layout ────────────────────────────────
report:
  style: "cards"          # "cards" (default) or "legacy"
  cards_per_page: 6       # cards on each PDF page
  max_cards: 24           # 0 or less shows every match
  destinations: []        # extra folders for a copy of the PDF
  assessment: "agent"     # "keyword" accepts reports without agent judgments

# ─── Exports ──────────────────────────────────────
export:
  format: "pdf,csv,json"  # add "png" for page images
  output_dir: "results"
  tracking: true          # job-tracking columns in the CSV
  description_chars: 1000 # posting excerpt length in the CSV and JSON

Resume tracks​

A track is a named resume. Use tracks when you target two different roles/titles and want each posting scored against the right document.

profiles/paralegal_nyc.yaml
resume:
  tracks:
    - name: "Paralegal Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Paralegal.pdf"
      color: "#1D4ED8"
      route_keywords: ["paralegal", "litigation", "e-discovery"]
    - name: "Legal Assistant Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Legal_Assistant.pdf"
      color: "#7E22CE"
      route_keywords: ["legal assistant", "legal secretary", "scheduling"]

Each entry takes four fields:

  • name labels the track. The report card shows this label, so write one or two words.
  • path points at that track's resume PDF or DOCX file.
  • color sets the badge color. Use a hex code such as #1D4ED8, or a color name such as navy.
  • route_keywords decide which postings Sweepy assigns to this track.

Sweepy routes each posting by keyword overlap. It counts whole-word matches between the posting's title and description and each track's route_keywords. Sweepy assigns the posting to the track with the highest count. When two tracks tie, Sweepy uses the first one in your list.

tip

route_keywords send a posting to a resume, and they never change the match percentage. Add the phrases each role family actually uses in its postings.

Leave tracks out and Sweepy uses resume.path as one implicit track.

Resume synonyms​

resume.synonyms holds groups of words that mean the same thing. Sweepy treats every word in a group as equal to the others. Matching then works either way. See Adding industry-specific terms for the wider formatting checklist.

profiles/paralegal_nyc.yaml
resume:
  synonyms:
    - ["e-discovery", "ediscovery", "electronic discovery"]
    - ["legal research", "case law research"]
    - ["docketing", "case calendaring"]
    - ["legal assistant", "legal secretary"]
    - ["contract review", "contract analysis", "agreement review"]

A group needs at least two terms, or Sweepy ignores it. Matching ignores case and handles regular singular and plural forms. The engine still matches whole phrases, so list legal research and legal researcher as separate terms when you want both to count.

Alex writes e-discovery on a resume. A posting that says electronic discovery now matches it, because both terms belong to the same group.

tip

Add a group whenever you notice the same miss twice. Copy the posting's exact wording into the group beside your own term.

Common formatting mistakes​

Most broken profiles trace back to a couple of common errors.

Windows paths need forward slashes or doubled backslashes. YAML reads one backslash as an escape character. A path such as C:\Users\Alex will break the file.

profiles/paralegal_nyc.yaml
resume:
  path: "C:/Users/Alex/Documents/Alex_Rivera_Resume.pdf"     # ✅ works
  # path: "C:\\Users\\Alex\\Documents\\Alex_Rivera_Resume.pdf"  # ✅ also works
  # path: "C:\Users\Alex\Documents\Alex_Rivera_Resume.pdf"      # ❌ breaks YAML
caution

One stray backslash in a path stops Sweepy from reading your profile. The setup wizard writes forward slashes for you, so copy that style when you edit by hand.

Comments start with #. Sweepy ignores everything after a # on that line. Use comments to note why a value matters, as the example profile does.

Indentation sets the structure. Indent each level by two spaces. One tab anywhere in the file breaks YAML.
