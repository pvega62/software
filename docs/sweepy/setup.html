Setting up Sweepy

You've installed Sweepy! Now you need a profile.

A configuration profile specifies to Sweepy the jobs to find and the resume to score them against. It also sets your target location.

A profile is a small text file in YAML format. YAML, which rhymes with camel, organizes data with indentation, colons, and line breaks. You don't need to write code: if you can read a grocery list, you can read YAML.

Option A: Run the interactive setup wizard​

The setup wizard creates a working profile from plain answers. It opens the search launchpad before the questionnaire and writes the configuration file for you.

Run this command:

Terminal
sweepy --setup

The wizard prints its banner, then the launchpad. The status line under the tiles shows the loaded profile, such as Current profile: Alex Rivera / 4 titles / Ready. With nothing loaded yet, it reads Current profile: none loaded / build one to start.

The launchpad shows six tiles. Launch Sweep runs the loaded profile. Load Profile opens a saved search. Build Profile starts a new search and asks plain-English questions. Sweep Settings controls ranking, cards, and history. Sweepy's Toolbox holds profile editing, engine management, aggregator management, the debug toggle, help, recent logs, document conversion, and updates. Exit Sweepy saves your changes and closes the wizard.

The command reference lists the flags behind each entry.

tip

Re-run sweepy --setup at any time to create a new profile or edit an existing one. The wizard writes to the file it names and leaves your other profiles alone.

To skip the launchpad and edit a saved profile straight away, pass the --profile flag:

Terminal
sweepy --setup --profile profiles/paralegal_nyc.yaml

Option B: Edit the config file manually​

To type your settings directly, copy the sample template and open it in a plain-text editor such as Notepad or VS Code. Avoid word processors, which replace straight quotes with curly quotes and break YAML.

  • Windows
  • macOS / Linux
Terminal
copy config.sample.yaml profiles\alex_rivera_paralegal.yaml
notepad profiles\alex_rivera_paralegal.yaml
Terminal
cp config.sample.yaml profiles/alex_rivera_paralegal.yaml
open profiles/alex_rivera_paralegal.yaml    # macOS
# or: nano profiles/alex_rivera_paralegal.yaml   # Linux

Alex's profile​

The wizard writes this file to profiles/alex_rivera_paralegal.yaml. Lines that start with # are comments: they explain each setting, and Sweepy ignores them. Sweepy fills in a default for any section or setting you leave out.

profiles/alex_rivera_paralegal.yaml
# ─────────────────────────────────────────────────
# Sweepy — Alex's Paralegal Profile
# ─────────────────────────────────────────────────

# Your name (appears in the PDF report header)
name: "Alex Rivera"

# ─── Job Search Settings ──────────────────────────
search:
  # List every job title you want to find.
  # The engine searches for ALL of these titles simultaneously.
  titles:
    - "Paralegal"
    - "Legal Assistant"
    - "Litigation Support Specialist"
    - "Legal Secretary"

  # Your target city and state.
  location: "New York, NY"

  # Set to true to ONLY see remote roles.
  # Set to false to see remote, hybrid, and on-site roles.
  remote_only: false

  # Set to false to exclude hybrid positions.
  include_hybrid: true

  # Minimum annual salary filter (optional).
  # Leave as 0 or remove this line to skip salary filtering.
  min_salary: 65000

# ─── Resume Settings ─────────────────────────────
resume:
  # The full path to your resume PDF on your computer.
  # On Windows, use double backslashes (\\) or forward slashes (/).
  path: "Alex_Rivera_Resume.pdf"

  # Must-have skills to prioritize for the match percentage.
  must_have_skills:
    - "Westlaw"
    - "LexisNexis"
    - "e-discovery"
    - "Contract Review"
    - "Legal Research"

  # How heavily to weigh keyword matches when scoring roles.
  # 1.0 = standard weight. Increase to 2.0 if you want
  # exact skill matches to dominate the score.
  keywords_weight: 1.5

# ─── Platform Settings ────────────────────────────
# Set each platform to true or false to enable or disable it.
platforms:
  greenhouse: true
  ashby: true
  lever: true
  workable: true
  aggregators: false   # Free feeds like Remotive, Adzuna

  # Optional: custom ATS endpoints or company career domains
  custom:
    - name: "SmartRecruiters"
      domain: "smartrecruiters.com"
      enabled: true
    - name: "Breezy HR"
      domain: "breezy.hr"
      enabled: true

# ─── Export Settings ──────────────────────────────
export:
  # Comma-separated list of output formats.
  # Options: pdf, csv, json
  format: "pdf,csv"

  # Where to save the output files.
  # The engine creates this folder if it does not exist.
  output_dir: "results"
caution

On Windows: use double backslashes (\\) or forward slashes (/) in YAML paths. One backslash (\) breaks YAML formatting.

✅ Correct: "C:\\Users\\Alex\\Documents\\resume.pdf" or "C:/Users/Alex/Documents/resume.pdf"

❌ Incorrect: "C:\Users\Alex\Documents\resume.pdf"

Using preset profiles​

Sweepy includes ready-to-use profile presets in the profiles/ folder. These four cover common searches:

FileCareer pathTitles searched
paralegal_nyc.yamlLegalParalegal, Legal Assistant, Litigation Support Specialist, Legal Secretary
frontend_developer.yamlSoftware engineeringFront End Developer, React Developer, UI Engineer
tech_writer.yamlTechnical writingTechnical Writer, UX Writer, Content Designer
template_custom.yamlAny careerSample titles you swap out. Each setting has a comment.

To use a preset, pass its filename when you run a sweep:

Terminal
sweepy --profile profiles/frontend_developer.yaml
tip

You can create as many profiles as you want. Store a different one for each job title variation or city you target. Switch between them instantly using the --profile flag.

Option C: Automate with a chat assistant​

A chat assistant can build profiles and run sweeps for you. Sweepy includes a built-in Model Context Protocol (MCP) server, so the assistant reads and writes your profiles directly. The MCP integration guide covers client setup for Antigravity, Claude Desktop, and VS Code, and the MCP tool reference lists all of Sweepy's tools.

Look up every setting​

The configuration reference lists every setting a profile accepts, from debug and resume.tracks to sources.* and report.*. Keep it open while you edit your profile.

Check where Sweepy looks for jobs​

Sweepy queries four public applicant tracking systems by default. That group covers Greenhouse, Ashby, Lever, and Workable. It also queries Built In NYC, a New York job board. Aggregator feeds from LinkedIn, Indeed, Glassdoor, and ZipRecruiter run through python-jobspy when your profile enables them.

Optional engines add boards. The options are HireHunt, OpenRoles, JobDrop, and Apify. OpenRoles requires a company list before it runs. Apify requires an APIFY_TOKEN. JobDrop conflicts with JobSpy's dependency pin. The setup wizard's Download job engines option installs them.

The sources and platforms page covers optional engines, seed files, custom platform entries, and compatibility caveats.

Your profile is ready. It's time to run your first sweep.
