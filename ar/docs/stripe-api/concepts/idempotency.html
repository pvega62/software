الطلبات المتكررة

في حالة انتهاء المدة المحددة للطلب (timeout)، يظل النتيجة غير معروفة؛ قد يتم شحن البطاقة ولكن الاستجابة قد تضيع أثناء إرسالها مرة أخرى. إعادة التنفيذ دون استخدام هذا المفتاح قد تؤدي إلى شحن ثاني.

يقوم الرأس (header) Idempotency-Key بإزالة تلك المخاطر؛ حيث يقوم Stripe بتخزين نتيجة الطلب الأول تحت ذلك المفتاح، ويعيد نفس النتيجة في كل محاولة إعادة طلب (retry).

آليات المفتاح​

  1. يقوم العميل بإنشاء مفتاح فريد لكل عملية منطقية.
  2. يصل طلب POST إلى Stripe ومفتاحه في الترويسة.
  3. تقوم خدمة Stripe بتنفيذ الطلب وتخزين الرد مقابل المفتاح المحدد لمدة ٢٤ ساعة.
  4. عند إعادة المحاولة باستخدام نفس المفتاح، يتم إرجاع الاستجابة المخزنة دون تنفيذ العملية مرة أخرى.

يقوم Stripe بتخزين الأخطاء بالإضافة إلى النجاحات في الذاكرة المؤقتة (cache)؛ إذا أعاد الطلب الأول قيمة 400، فإن كل محاولة إعادة طلب باستخدام نفس المفتاح ستعيد نفس القيمة 400.

إرسال مفتاح​

curl https://api.stripe.com/v1/payment_intents \
  -u "$STRIPE_SECRET_KEY:" \
  -H "Idempotency-Key: a1b2c3d4-0001-4f8e-9a1c-7d2e3f4a5b6c" \
  -d "amount=2120" \
  -d "currency=usd"
Node.js
const key = crypto.randomUUID();

const response = await fetch("https://api.stripe.com/v1/payment_intents", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.STRIPE_SECRET_KEY}`,
    "Content-Type": "application/x-www-form-urlencoded",
    "Idempotency-Key": key,
  },
  body: new URLSearchParams({ amount: "2120", currency: "usd" }),
});
Python
import os, uuid, requests

response = requests.post(
    "https://api.stripe.com/v1/payment_intents",
    auth=(os.environ["STRIPE_SECRET_KEY"], ""),
    headers={"Idempotency-Key": str(uuid.uuid4())},
    data={"amount": 2120, "currency": "usd"},
)

اختر قيمة المفتاح​

يجب أن يكون المفتاح فريدًا لكل عملية وثابتًا عند إعادة المحاولات. أي سلسلة نصية بطول يصل إلى 255 حرفًا مقبولة. تستخدم معظم الأنظمة إحدى الاستراتيجيتين التاليتين:

الاستراتيجيةزوج المفتاح والقيمةالمقابل
المُولّد تلقائيًامعرف فريد عالميًا (UUID) يتم إنشاؤه مرة واحدة لكل عملية ويتم تمريره إلى طبقة إعادة المحاولة.سريع في الإنشاء؛ يجب على العميل الاحتفاظ بهذا المفتاح حتى اكتمال العملية.
المُشتققيمة ثابتة مثل order-4471-charge-1.سهلة القراءة في السجلات؛ لكن يتطلب قواعد لضمان فرادتها.
تحذير

قم بإنشاء المفتاح مرة واحدة خارج حلقة إعادة المحاولات؛ استدعاء crypto.randomUUID() داخل حلقة إعادة المحاولات سيؤدي إلى إنشاء مفتاح جديد لكل محاولة، مما يجعل كل محاولة طلبًا جديدًا.

التعامل مع النتائج الثلاثة​

النتيجةالمعنىالإجراء
نفس الاستجابة، نفس المحتوىقامت خدمة Stripe بإعادة تنفيذ النتيجة المخزنة.تعاملها كنجاح أو فشل عادي.
409 Conflictالطلب الذي يحتوي على هذا المفتاح لا يزال قيد التنفيذ.انتظر ثم حاول مرة أخرى باستخدام نفس المفتاح.
400 مع idempotency_errorقام المستخدم باستعادة المفتاح مع معلمات مختلفة.استخدم مفتاحًا جديدًا للعملية الجديدة.

حالة استخدام المفتاح idempotency_error تشير إلى وجود خطأ، حيث تم إرسال نفس المفتاح مع كمية أو عملة أو مجموعة من المعلمات مختلفة؛ يرفض Stripe تخمين الطلب الذي قصده المستخدم.

{
  "error": {
    "message": "Keys for idempotent requests can only be used with the same parameters they were first used with.",
    "type": "idempotency_error"
  }
}

تعيين فترة الاحتفاظ​

تقوم خدمة Stripe بالاحتفاظ بالنتائج لمدة 24 ساعة، وهذه الفترة تؤدي إلى ثلاث حالات خاصة:

  • عمليات إعادة المحاولة الطويلة. عندما تستمر إعادة المحاولة في قائمة الانتظار لأكثر من 24 ساعة، تصل إلى نافذة لا تحتوي على أي نتيجة مخزنة. وعندئذٍ تُنفَّذ عملية إعادة المحاولة كطلب جديد. لذا، يجب تحديد مدة نافذة إعادة المحاولة بما لا يزيد عن 24 ساعة، أو التحقق من حالة الكائن قبل إعادة المحاولة.
  • التسوية المتأخرة. تواجه المهمة التي تعيد تنفيذ طلبات الأمس نفس المشكلة. اقرأ الكائن باستخدام معرّفه بدلاً من إعادة تنفيذ عملية الكتابة.
  • إعادة استخدام المفاتيح عبر الأيام: المفاتيح المبنية على التاريخ (مثل charge-2026-11-09) قد تتعارض مع محاولات إعادة الطلب لنفس المفتاح في اليوم التالي؛ يجب تضمين معرف الكائن (object ID) في المفتاح، وليس فقط التاريخ نفسه.

تحقق من السلوك​

أرسل القيمة POST مرتين باستخدام نفس المفتاح ونفس المحتوى. تُرجع الاستجابة الثانية نفس رقم معرف الدفع (PaymentIntent ID).

KEY=$(uuidgen)

curl -s https://api.stripe.com/v1/payment_intents \
  -u "$STRIPE_SECRET_KEY:" \
  -H "Idempotency-Key: $KEY" \
  -d "amount=2120" -d "currency=usd" | jq -r '.id'

curl -s https://api.stripe.com/v1/payment_intents \
  -u "$STRIPE_SECRET_KEY:" \
  -H "Idempotency-Key: $KEY" \
  -d "amount=2120" -d "currency=usd" | jq -r '.id'

كلا الأمرين يطبعان نفس القيمة pi_.... الآن قم بتغيير قيمة amount في المرة الثانية واحتفظ بالمفتاح ذاته. تُرجع خدمة Stripe القيمة idempotency_error.

أين يتم تطبيقه​

ضع مفتاحًا (key) على كل رمز POST يقوم بإنشاء أو تغيير المال.

  • إنشاء كائن من نوع PaymentIntent لإجراء عمليات استرداد أموال، دفع، أو اشتراك.
  • تسجيل عملية شحن مصرح بها.
  • إنشاء عميل عندما يمكن للمتصل المحاولة مرة أخرى.

تجاهل القسمين الموجودين بين GET وDELETE؛ فالقسم GET لا يغير شيئًا، وإعادة تنفيذ القسم DELETE تعيد نفس النتيجة بطبيعة الحال.

الخطوات التالية​

  • الأخطاء وإعادات المحاولة لجداول إعادة المحاولة وقواعد التأخير في التنفيذ.
  • كيفية تحرك الأموال عبر منصة Stripe للكائنات التي تنشئها هذه الاستدعاءات.
