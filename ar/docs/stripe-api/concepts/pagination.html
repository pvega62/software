تصفية النتائج ونقاط النهاية القوائم

تُرجع نقطة النهاية القائمة صفحة واحدة من النتائج بالإضافة إلى مؤشر يشير إلى الصفحة التالية؛ يتبع العميل هذا المؤشر حتى يصبح قيمة has_more تساوي false.

معلومات حول نقطة النهاية القائمة​

{
  "object": "list",
  "url": "/v1/charges",
  "has_more": true,
  "data": [
    { "id": "ch_3Rsx4dDtWMrPDtgt1", "object": "charge", "amount": 2120 }
  ]
}
الحقلالمعنى
dataالعناصر الموجودة في هذه الصفحة.
has_moreقيمة true عند وجود صفحة أخرى.
urlمسار نقطة النهاية القائمة التي أنتجت هذه الصفحة.

يظهر أحدث العناصر أولاً، ولا يتغير ترتيب العناصر بين الصفحات لأن المؤشر يشير إلى عنصر معين وليس إلى قيمة رقمية.

ضبط حجم الصفحة​

يتحكم رمز limit في حجم الصفحة، ويقبل قيم من رموز 1 إلى 100؛ القيمة الافتراضية هي 10، وهي مناسبة للواجهات التحكم التفاعلية وتقلل من عدد المرات التي تتم فيها عمليات الاسترجاع للبيانات في المهام الجماعية.

curl -s -G https://api.stripe.com/v1/charges \
  -u "$STRIPE_SECRET_KEY:" \
  -d limit=100 | jq '.data | length, .has_more'

تقليل حجم الصفحة يقلل من عدد الطلبات وإجمالي زمن الاستجابة، لكنه يزيد من استهلاك الذاكرة وتأثير فشل الطلبات؛ لذا فإن حجم الصفحة ١٠٠ يناسب معظم المهام المتزامنة.

اتبع المؤشر​

اقرأ قيمة id لآخر عنصر في الصفحة واستخدمها كقيمة starting_after، وكرر العملية حتى تصبح قيمة has_more خاطئة (false).

curl -s -G https://api.stripe.com/v1/charges \
  -u "$STRIPE_SECRET_KEY:" \
  -d limit=100 \
  -d starting_after=ch_3Rsx4dDtWMrPDtgt1
Node.js
async function listAllCharges() {
  const charges = [];
  let startingAfter;

  while (true) {
    const url = new URL("https://api.stripe.com/v1/charges");
    url.searchParams.set("limit", "100");
    if (startingAfter) url.searchParams.set("starting_after", startingAfter);

    const response = await fetch(url, {
      headers: { Authorization: `Bearer ${process.env.STRIPE_SECRET_KEY}` },
    });

    if (!response.ok) throw new Error(`Stripe returned ${response.status}`);

    const page = await response.json();
    charges.push(...page.data);

    if (!page.has_more) break;
    startingAfter = page.data.at(-1).id;
  }

  return charges;
}
تلميح

التطبيقات الرسمية تتولى عملية التصفية تلقائيًا: في Node.js، استخدم حلقة تكرارية مع قيم stripe.charges.list({ limit: 100 }) وfor await؛ في Python، استدعِ الدالة .auto_paging_iter() على القائمة المُرجعة؛ في Java، استدعِ الدالة autoPagingIterable() على القيمة StripeCollection. تأكد من أن التوقيع المستخدم متوافق مع إصدار الـ SDK المثبت لديك قبل الاعتماد عليه.

التصفية على الخادم​

التصفية على الخادم (Filter on the server): تُقلل عملية التصفية من حجم البيانات قبل أن تقوم خدمة Stripe بتقسيمها إلى صفحات؛ أما التصفية على الجانب العميل بعد استرجاع البيانات فهي تجبرك على قراءة جميع البيانات دفعة واحدة

مثال على التصفية:

فلترمثالنطاق
النطاق الزمنيcreated[gte]=1735689600&created[lt]=1738368000الرسوم، الاستردادات، معاملات الرصيد
الحالةstatus=availableمعاملات الميزانية
العميلcustomer=cus_QyJ8...الرسوم، نوايا الدفع، الفواتير
الدفعpayout=po_1N...تجميع المعاملات في دفعة واحدة

يمكن دمج الفلاتر لعرض نتائج عملية المطابقة (reconciliation) على صفحة واحدة فقط. العمل اليومي الذي يقوم بقراءة تكاليف اليوم السابق، والذي يتم تحديده باستخدام نطاق created، يمكن عرضه بشكل كامل على هذه الصفحة.

مقارنة بين تصفح الفهرس (Pagination) باستخدام المؤشر (Cursor) وتصفح الفهرس باستخدام المعاملات المباشرة​

عند استخدام طريقة التصفح بالمعاملات المباشرة، يتم طلب الصفحة رقم 2 في السطر رقم 100؛ لكن قد يحدث تغيير في بيانات قاعدة البيانات بين الطلبات، مما يجعل السطر رقم 100 يصبح السطر رقم 101 ويظهر نفس السجل مرتين. أما المؤشر فهو يشير إلى آخر عنصر تم عرضه، وعند وصول سجلات جديدة فإنها تظهر أمام المؤشر دون أن يتأثر ترتيب العناصر.

لهذا النظام تأثيران رئيسيان على المستخدم:

  • لا يوجد رقم صفحة. نقاط النهاية القوائم القياسية لا توفر أي من رموز page=2 أو total_count؛ يمكنك حساب العدد الإجمالي للنتائج بنفسك إذا كنت بحاجة إلى ذلك. نقاط النهاية البحث تختلف، كما سيتم شرحه في القسم التالي.
  • يجب إعادة استخدام هذا الرمز (starting_after) لقراءة الصفحة التالية، بينما يشير الرد الذي يحتوي على ending_before إلى نهاية عملية البحث.

أنواع نقاط النهاية البحث​

تقبل نقاط النهاية البحث سلسلة استعلامات وتعيد رمزًا خاصًا (next_page) بدلاً من مؤشر للبيانات المراد عرضها.

curl -s -G https://api.stripe.com/v1/charges/search \
  -u "$STRIPE_SECRET_KEY:" \
  -d query="amount>1000 AND status:'succeeded'" | jq '.next_page'

أرسل الرمز مرة أخرى كـ page لقراءة الصفحة التالية؛ الاستجابة التي تحتوي على الرمز next_page: null تشير إلى نهاية العملية. لا يوجد رمز starting_after في عملية البحث، لذا احرص على فصل نماذج التصفح (pagination) هاتين في برنامجك العميل (client).

نوع نقطة النهاية (Endpoint Type)معلمة المؤشر (Cursor Parameter)إشارة الانتهاء (End Signal)
القائمة القياسيةstarting_afterhas_more: false
البحثpagenext_page: null

يجب الحفاظ على عمليات القراءة الكبيرة ضمن حدود السرعة المسموح بها​

يمكن أن يؤدي تجميع الرسوم المتراكمة على مدار عام إلى إرسال آلاف الطلبات في وقت واحد؛ لذا، من الضروري توزيع العبء بشكل متساوٍ وتقليل عدد الطلبات عندما يواجه نظام Stripe صعوبات في التعامل معها.

  • قم بقراءة صفحة واحدة في كل مرة؛ استخدم طرق متوازية لمعالجة نفس المجموعة من البيانات، مع الالتزام بحدود التزامن المسموح بها.
  • احترم رأس القسم المُشار إليه بـ Retry-After داخل القسم المُشار إليه بـ 429. راجع معلومات الأخطاء وإعادات المحاولة.
  • قم بتخزين الموقع الحالي للمؤشر في مكان موثوق، بحيث يمكن استئناف العملية من نقطة التوقف دون الحاجة إلى بدءها من جديد.
  • من الأفضل استخدام نطاق ضيق من البيانات (created) بدلاً من معالجة جميع البيانات في المجموعة بأكملها.

الخطوات التالية…​

  • توسيع الكائنات المتداخلة لإثراء المحتوى دون الحاجة إلى إرسال طلبات إضافية.
  • الأخطاء وإعادات المحاولة تتعلق بسياسة التأخير في عمليات القراءة الجماعية للبيانات.
  • استرجاع معاملات الرصيد تتعلق بقوائم الخصائص المرتبطة بكل سطر من البيانات.
