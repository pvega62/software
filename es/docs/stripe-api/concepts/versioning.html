Versionado y actualizaciones de la API

Stripe versiona toda la API, no solo sus puntos finales (endpoints) individuales. Una cadena de versión indica un estado concreto de los campos y el comportamiento de la misma. Tu cuenta asigna una versión fija; todas las solicitudes que no especifiquen lo contrario utilizarán esa versión predeterminada.

Fuentes de las versiones​

CapaConfiguraciónÁmbito de aplicación
CuentaVersión de API predeterminada en el panel de controlTodas las solicitudes que omitan el encabezado correspondiente
SolicitudEncabezado Stripe-VersionCada solicitud enviada
Biblioteca del clienteVersión incluida con el lanzamiento del SDKSolicitudes realizadas a través de dicha biblioteca

La asignación de una versión fija evita problemas inesperados: aunque Stripe lance una nueva versión predeterminada, tu integración seguirá procesando los datos según la versión anteriormente almacenada.

Sobrescribir la versión​

Envía el encabezado Stripe-Version para probar una versión diferente sin modificar la configuración predeterminada de la cuenta.

curl https://api.stripe.com/v1/payment_intents/pi_3Rsx4dDtWMrPDtgt0mUrePJ9 \
  -u "$STRIPE_SECRET_KEY:" \
  -H "Stripe-Version: 2024-06-20"
Node.js
const stripe = new Stripe(process.env.STRIPE_SECRET_KEY, {
  apiVersion: "2024-06-20",
});

El encabezado acepta una versión con fecha, como 2024-06-20. Algunas versiones incluyen un nombre en clave, que debe copiarse exactamente del panel de control (Dashboard).

nota

Una modificación (override) cambia el comportamiento de una solicitud, no solo sus campos; lea primero el registro de cambios (changelog).

¿Qué puede cambiar?​

Algunos cambios se aplican a todas las versiones; otros requieren una nueva versión; la tabla los clasifica según esto.

CambioVersiones en las que se aplicaRequiere una nueva versión
Nuevo parámetro opcional de solicitudSíNo
Nuevo campo de respuestaSíNo
Nuevo tipo de evento para webhooksSíNo
Campo renombradoNoSí
Tipo de campo modificadoNoSí
Campo eliminadoNoSí
Cambiado el valor predeterminadoNoSí

Un cliente que ignora los campos desconocidos acepta cualquier cambio adicional. Los clientes que validan las respuestas según un esquema fijo fallan al encontrar un nuevo campo.

Construir un analizador compatible con futuras actualizaciones​

Leer solo los campos necesarios e ignorar el resto. Nunca fallar la interpretación de una respuesta por la presencia de un campo no esperado.

Node.js
function readAmount(intent) {
  const amount = intent.amount;

  if (typeof amount !== "number") {
    throw new Error("amount is missing from the PaymentIntent response");
  }

  return amount;
}

La comprobación confirma el campo del que dependes; el resto del objeto se mantiene sin cambios. amount_details Que un nuevo valor de clave o de estado no cause que el analizador (parser) se bloquee o fallen.

aviso

No basar las comparaciones en toda la estructura de la respuesta. Stripe añade nuevos campos en casi todas las actualizaciones, y una comparación estricta podría fallar en versiones futuras.

Actualizar en modo de prueba​

Ejecutar esta secuencia antes de realizar cualquier cambio en la configuración del cuenta.

  1. Abrir el registro de cambios de la API y leer cada entrada entre tu versión actual y la versión objetivo.
  2. Identificar los campos que tu código lee y los parámetros de solicitud que envía.
  3. Enviar solicitudes reales con el encabezado Stripe-Version establecido en el valor correspondiente a la versión objetivo.
  4. Comparar las respuestas obtenidas con el resultado del análizador que has desarrollado, no solo con las diferencias visuales entre las dos versiones.
  5. Ejecutar el conjunto de pruebas de integración con la versión objetivo.
  6. Implementa el código que maneje los formatos de respuesta antiguos y nuevos, si es necesario debido al cambio.
  7. Cambia el valor predeterminado de la cuenta en el Panel de Control.
  8. Observa la tasa de errores y la tasa de fallos de los webhooks durante un ciclo de pago.
consejo

Realiza pruebas con una clave restringida que solo afecte a los recursos incluidos en el conjunto de herramientas; usar una clave secreta completa en una prueba de versión puede dejar objetos no deseados en la cuenta.

Mantén alineadas las versiones del SDK y de la API​

Cada lanzamiento del SDK incluye una versión predeterminada de la API. Actualizar la biblioteca puede hacer que tus solicitudes utilicen una versión más reciente, incluso si el valor predeterminado de la cuenta no ha cambiado.

AcciónEfecto en la versión de la API
Actualice el SDK y acepte sus opciones predeterminadas.Las solicitudes deben utilizar la versión incluida con el lanzamiento del producto.
Actualiza el SDK y establece el valor de apiVersion.Las solicitudes deben utilizar la versión que hayas especificado.
Cambiar la configuración predeterminada del panel de controlAfecta a las solicitudes que omiten el encabezado y al cliente apiVersion

Establece explícitamente el valor apiVersion al actualizar la biblioteca. Esto mantendrá la versión de la API fija mientras revisas los cambios en el SDK por separado.

Gestiona los webhooks entre diferentes versiones​

Un evento de webhook registra la versión de la API que lo ha generado, bajo api_version. Stripe envía los eventos con la versión asociada al endpoint específico, no con la versión del cuenta.

Consulte las posibles consecuencias antes de compartir un mismo gestor (handler) para ambos caminos de acceso.

  • Separe las versiones utilizadas: Un endpoint puede enviar eventos basados en una versión diferente de la que utiliza su propia API.
  • Cambios en los campos: Un campo leído de una respuesta API puede no estar presente en el contenido del evento.

Lea el valor de api_version del evento al registrar el contenido recibido, y valide únicamente los campos necesarios para el gestor, en lugar de todo el objeto completo.

Siguientes pasos​

  • Errores y reintentos cuando un cambio de versión interrumpe una llamada en producción.
  • Solicitudes idénticas (Idempotent requests) para el comportamiento de reintentos durante una actualización.
  • Registro de cambios en la API de Stripe para cada versión.
