Solicitudes idémpotentes

Un tiempo de espera (timeout) puede hacer que el resultado sea incierto; es posible que la tarjeta haya sido cargada pero que la respuesta se haya perdido en el camino de vuelta. Reintentar sin la clave conlleva el riesgo de un segundo cargo.

El encabezado Idempotency-Key elimina este riesgo. Stripe almacena el resultado de la primera solicitud bajo esa clave y devuelve el mismo resultado en cada intento posterior.

Mecánica de las claves​

  1. El cliente genera una clave única para cada operación lógica.
  2. El dato POST es enviado a Stripe junto con la clave incluida en el encabezado.
  3. Stripe procesa la solicitud y almacena la respuesta bajo ese clave durante 24 horas.
  4. Un intento de reenvío (retry) con la misma clave devuelve la respuesta almacenada sin ejecutar la operación nuevamente.

Stripe almacena en caché tanto los errores como los éxitos. Si la primera solicitud devuelve un valor de 400, cada intento posterior con ese mismo clave también devolverá el mismo valor de 400.

Enviar una clave​

curl https://api.stripe.com/v1/payment_intents \
  -u "$STRIPE_SECRET_KEY:" \
  -H "Idempotency-Key: a1b2c3d4-0001-4f8e-9a1c-7d2e3f4a5b6c" \
  -d "amount=2120" \
  -d "currency=usd"
Node.js
const key = crypto.randomUUID();

const response = await fetch("https://api.stripe.com/v1/payment_intents", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.STRIPE_SECRET_KEY}`,
    "Content-Type": "application/x-www-form-urlencoded",
    "Idempotency-Key": key,
  },
  body: new URLSearchParams({ amount: "2120", currency: "usd" }),
});
Python
import os, uuid, requests

response = requests.post(
    "https://api.stripe.com/v1/payment_intents",
    auth=(os.environ["STRIPE_SECRET_KEY"], ""),
    headers={"Idempotency-Key": str(uuid.uuid4())},
    data={"amount": 2120, "currency": "usd"},
)

Elige el valor de la clave​

La clave debe ser única para cada operación y mantenerse estable durante los intentos de reenvío (retries). Cualquier cadena de hasta 255 caracteres es válida. La mayoría de las integraciones utilizan una de estas dos estrategias:

EstrategiaPar pareja clave-valorCompromiso
GeneradaUn identificador universalmente único (UUID) creado una vez por operación y transmitido al mecanismo de reenvío.Rápido de generar; el cliente debe conservar esta clave hasta que la operación finalice.
DerivadaUn valor fijo, como order-4471-charge-1.Legible en los registros de actividad del sistema; requiere que se establezca una regla de unicidad.
aviso

Genere la clave una sola vez, fuera del ciclo de reenvíos. Si se utiliza crypto.randomUUID() dentro del ciclo de reenvíos, se creará una nueva clave para cada intento, convirtiendo así cada reenvío en una solicitud independiente.

Gestiona los tres resultados​

ResultadoSignificadoAcción a tomar
La misma respuesta, mismo contenidoStripe ha reenviado el resultado almacenado previamente.Trátelo como un éxito o fracaso normal.
409 ConflictUna solicitud con esta clave todavía está en proceso.Espere y luego intente de nuevo con la misma clave.
400 con idempotency_errorEl solicitante reutilizó la misma clave con parámetros diferentes.Utilice una nueva clave para la nueva solicitud.

El caso de idempotency_error puede indicar la existencia de un error: la misma clave se ha enviado con cantidades, monedas o conjuntos de parámetros distintos. En este caso, Stripe no puede determinar cuál fue la solicitud pretendida por el solicitante.

{
  "error": {
    "message": "Keys for idempotent requests can only be used with the same parameters they were first used with.",
    "type": "idempotency_error"
  }
}

Establece el periodo de retención​

Stripe conserva los resultados durante 24 horas. Este período genera tres casos especiales:

  • Reintentos prolongados. Una cola que lleva más de 24 horas intentando una operación llega a un intervalo en el que no hay ningún resultado almacenado. En ese caso, el reintento se ejecuta como una nueva solicitud. Limita el intervalo de reintentos a menos de 24 horas o comprueba el estado del objeto antes de volver a intentarlo.
  • Reconciliación retrasada. Una tarea que reproduce las solicitudes de ayer se encuentra con el mismo problema. Lee el objeto por su ID en lugar de reproducir la escritura.
  • Reutilización de claves entre días. Una clave basada en la fecha, como charge-2026-11-09, entra en conflicto con el reintento de mañana con la misma clave. Incluye el ID del objeto en la clave, no solo la fecha.

Comprueba cómo funciona​

Envíe lo mismo. POST Se realiza dos veces con la misma clave y el mismo cuerpo de datos; la segunda respuesta devuelve el mismo ID de PaymentIntent.

KEY=$(uuidgen)

curl -s https://api.stripe.com/v1/payment_intents \
  -u "$STRIPE_SECRET_KEY:" \
  -H "Idempotency-Key: $KEY" \
  -d "amount=2120" -d "currency=usd" | jq -r '.id'

curl -s https://api.stripe.com/v1/payment_intents \
  -u "$STRIPE_SECRET_KEY:" \
  -H "Idempotency-Key: $KEY" \
  -d "amount=2120" -d "currency=usd" | jq -r '.id'

Ambos comandos imprimen el mismo valor pi_.... Ahora cambie el valor de amount en la segunda llamada y mantenga el mismo valor para la clave. Stripe devuelve el valor idempotency_error.

Dónde aplicarlo​

Aplique una clave a cada POST que genere o modifique dinero.

  • Creación de un PaymentIntent, reembolso, pago o suscripción.
  • Realizar un cobro autorizado.
  • Creación de un cliente; el llamante puede intentar de nuevo.

Omitir los encabezados en GET y DELETE. Un GET no cambia nada, y una resolicitud de DELETE devuelve el mismo resultado.
