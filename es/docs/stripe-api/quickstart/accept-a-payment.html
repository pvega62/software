Aceptar un pago con tarjeta

  • Público objetivo: Desarrolladores que realizan el primer pago a través de la API de Stripe.
  • Requisitos previos: Cuenta de Stripe en modo de prueba, clave secreta configurada en el entorno, y Node.js 18 o una versión posterior.
  • Objetivo: Recibir el pago con tarjeta, consultar su estado y completar el pedido únicamente después de que el servidor confirme el cargo.

Al final, dispondrás de un punto final de servidor (server endpoint) que genera un objeto de tipo PaymentIntent y un cliente (client) que lo confirma. Todos los resultados provienen del modo de prueba (test mode). Ejecutar este proceso no incurre en ningún costo.

Flujo de solicitud​

Cada etapa se ejecuta en un lugar específico, y el tipo de credencial utilizada depende de la ubicación donde se realice dicha etapa.

Cada etapa se lleva a cabo en un lugar específico, y el tipo de clave utilizada corresponde a esa ubicación.

EtapaSe ejecuta enCredencial
Crear el PaymentIntentTu servidorClave secreta
Recopilar detalles de la tarjetaClienteClave publicable
Confirmar el pagoClienteclient_secret
Informar del resultadoStripeFirma del webhook

Gestión de webhooks de pago abarca la última etapa del proceso; esta página se detiene en un estado verificado.

1. Crear el PaymentIntent​

Se crea un intent por cada pedido en el servidor; la respuesta incluye una client_secret que el cliente utiliza para confirmar el pago.

server.js
import express from "express";

const app = express();
app.use(express.json());

app.post("/create-payment-intent", async (req, res) => {
  const orderId = req.body.orderId;

  if (!orderId) {
    return res.status(400).json({ error: "orderId is required" });
  }

  const params = new URLSearchParams({
    amount: "2120",
    currency: "usd",
    "automatic_payment_methods[enabled]": "true",
    "metadata[order_id]": orderId,
  });

  const response = await fetch("https://api.stripe.com/v1/payment_intents", {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.STRIPE_SECRET_KEY}`,
      "Content-Type": "application/x-www-form-urlencoded",
      "Idempotency-Key": `order-${orderId}`,
    },
    body: params,
  });

  if (!response.ok) {
    const failure = await response.json();
    return res.status(response.status).json({ error: failure.error.message });
  }

  const intent = await response.json();
  res.json({ clientSecret: intent.client_secret });
});

app.listen(4242, () => console.log("Listening on port 4242"));
  • amount utiliza la unidad monetaria más pequeña. 2120 cobra 21,20 $, no 2.120 $.
  • Idempotency-Key reutiliza el ID del pedido. Una solicitud reintentada devuelve el intent original en lugar de crear uno nuevo.
  • metadata[order_id] vincula el intent con el pedido correspondiente. El gestor del webhook lo lee directamente sin necesidad de consultar una base de datos.
aviso

La client_secret pertenece únicamente a un pedido concreto; no se debe registrar ni reutilizar entre clientes.

Confirme que el punto final de conexión (endpoint) responde correctamente antes de escribir cualquier código del lado del cliente.

curl -X POST http://localhost:4242/create-payment-intent \
  -H "Content-Type: application/json" \
  -d '{"orderId":"ord_8842"}'

La respuesta incluye un valor de tipo clientSecret que comienza con pi_ y contiene el dato _secret_.

2. Confirma el pago en el lado del cliente​

Cargue Stripe.js y confirme la intención del cliente con su tarjeta. Stripe se encarga de procesar los datos de la tarjeta; por lo tanto, el número de la tarjeta nunca llega a su servidor.

checkout.html
<div id="card-element"></div>
<script src="https://js.stripe.com/v3/"></script>
<script>
  const stripe = Stripe("pk_test_REPLACE_WITH_YOUR_KEY");
  const elements = stripe.elements();
  const cardElement = elements.create("card");
  cardElement.mount("#card-element");

  async function pay() {
    const response = await fetch("/create-payment-intent", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ orderId: "ord_8842" }),
    });

    const { clientSecret } = await response.json();

    const result = await stripe.confirmCardPayment(clientSecret, {
      payment_method: { card: cardElement },
    });

    if (result.error) {
      showDecline(result.error.message, result.error.decline_code);
      return;
    }

    if (result.paymentIntent.status === "succeeded") {
      showConfirmation();
    } else {
      showPending();
    }
  }
</script>

El campo status indica el estado del proceso de pago. Un estado succeeded significa que el emisor de la tarjeta ha aprobado el pago; un estado requires_action indica que el cliente aún necesita completar algún requisito adicional, y Stripe.js lo solicita durante este proceso.

3. Verifica el estado del pago en el servidor​

El cliente informa el resultado del pago, pero el navegador puede mentir. Consulta siempre la información proporcionada por Stripe antes de enviar los productos.

server.js
app.get("/orders/:orderId/status", async (req, res) => {
  const intentId = await lookupIntentId(req.params.orderId);

  const response = await fetch(
    `https://api.stripe.com/v1/payment_intents/${intentId}`,
    { headers: { Authorization: `Bearer ${process.env.STRIPE_SECRET_KEY}` } }
  );

  const intent = await response.json();

  res.json({
    fulfilled: intent.status === "succeeded",
    status: intent.status,
    amountReceived: intent.amount_received,
  });
});

Compare también amount_received con amount. Una captura parcial deja que amount_received quede por debajo de amount. La diferencia indica cuánto se debe reembolsar o liberar.

consejo

Almacena el resultado del pago en caché durante unos segundos por cada pedido; de lo contrario, la página de pago rápida podría consultar la API demasiado frecuentemente.

4. Realiza el envío solo cuando el estado del pago esté confirmado​

El webhook asociado al valor payment_intent.succeeded ofrece una forma más segura de gestionar el proceso de pago que el navegador: se envía una única vez, incluso si el cliente cierra la pestaña, y incluye una firma verificable.

fulfillment.js
async function handleSucceeded(intent) {
  const orderId = intent.metadata.order_id;

  if (!orderId) {
    console.warn("No order_id on intent", intent.id);
    return;
  }

  if (intent.amount_received < intent.amount) {
    console.warn("Underpaid intent", intent.id);
    return;
  }

  await markOrderPaid(orderId, intent.id);
}

El ID del pedido proviene de los metadatos que configuraste en el paso 1; este dato elimina la necesidad de buscar información adicional posteriormente.

Gestiona los casos en los que el pago es rechazado​

Una tarjeta rechazada deja la información correspondiente en requires_payment_method. El monto y los datos del cliente se mantienen, por lo que el cliente puede intentar nuevamente con otra tarjeta para realizar la misma transacción.

client.js
function showDecline(message, code) {
  const copy = {
    insufficient_funds: "That card can't cover this order. Try another card.",
    expired_card: "That card has expired. Add a new one.",
    incorrect_cvc: "The security code doesn't match. Check it and try again.",
  };

  showMessage(copy[code] ?? "That card was declined. Try another payment method.");
}

Reemplaza el contenido de decline_code por tu propia información correspondiente, en lugar de mostrar el texto sin procesar de message. Este texto sin procesar identifica al emisor de la tarjeta y no se adapta bien a un formulario de pago.

Prueba los cuatro resultados posibles​

Ejecuta cada número de tarjeta desde la opción Modo de prueba y confirma el comportamiento del sistema.

TarjetaResultado esperadoLo que se debe verificar
4242 4242 4242 4242El pago se ha realizado con éxito.El estado del pedido cambia a “Pagado” (succeeded).
4000 0000 0000 9995Rechazo debido a fondos insuficientes.Se muestra el motivo del rechazo, y la transacción permanece abierta.
4000 0025 0000 3155Se requiere autenticación.La prueba comienza y el flujo de eventos continúa después de ello.
4000 0000 0000 0002Rechazo genérico.La copia de respaldo se muestra, y el pedido permanece sin pagar.

Luego reproduce la llamada de confirmación con el mismo clave de idempotencia. Stripe devuelve la intención original, lo que mantiene el orden de los cargos en una sola transacción.

Poner en marcha​

Pasar del modo de prueba al modo en vivo de una sola vez.

  1. Cambia el par de claves de prueba por las claves reales en el almacén de secretos de producción.
  2. Registre el punto final del webhook de producción y guarde la clave de firma.
  3. Envíe un cargo en tiempo real de bajo valor y reembolseelo.
  4. Confirme el calendario de pagos y la cuenta bancaria registrada.
  5. Active las notificaciones para las respuestas de 5xx y los webhook que fallen.
