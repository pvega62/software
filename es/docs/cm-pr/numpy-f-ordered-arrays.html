Corrección de la matriz ordenada por F

Planteamiento del problema​

La codificación y decodificación de matrices de NumPy con Protobuf falla si estas tienen ordenación F

Pruebas​

import numpy

from mcbackend.npproto.utils import ndarray_from_numpy, ndarray_to_numpy

arrC = numpy.array([
    [1,2,3],
    [4,5,6],
], order="C")

arrF = numpy.array([
    [1,2,3],
    [4,5,6],
], order="F")

assert arrC.strides != arrF.strides

numpy.testing.assert_array_equal(
    arrC,
    ndarray_to_numpy(ndarray_from_numpy(arrC)),
)
numpy.testing.assert_array_equal(
    arrF,
    ndarray_to_numpy(ndarray_from_numpy(arrF)),
)

Mensaje de confirmación​

Corregir la codificación y decodificación de matrices NumPy ordenadas por F

`bytes(arr.data)` materializa el contenido del búfer en orden C, por lo que al codificar una matriz ordenada en Fortran se emparejan bytes en orden C con pasos de Fortran. La decodificación lee entonces esos bytes con pasos incorrectos y devuelve una matriz desordenada.

Registra el orden de memoria en un nuevo campo `order` del mensaje `Ndarray`, y deja que `ndarray_to_numpy` realice la transposición y la remodelación cuando ese campo indique «F». Los búferes codificados antes de la versión 0.2.4 tienen el campo `order` vacío, por lo que al descodificarlos se obtienen matrices ordenadas según el orden C.

Closes #63

Solicitud de incorporación​

Resumen​

La conversión de ida y vuelta con Protobuf corrompe las matrices de NumPy que utilizan el orden de Fortran. Una matriz ordenada según el orden de Fortran se devuelve con los valores en posiciones incorrectas. El decodificador no genera ningún error y el llamante acepta una matriz desordenada.

Round-trip test
arrF = numpy.array([[1, 2, 3], [4, 5, 6]], order="F")
numpy.testing.assert_array_equal(
    arrF,
    ndarray_to_numpy(ndarray_from_numpy(arrF)),  # returns [[1, 3, 5], [2, 4, 6]] without the fix
)

Causa principal​

ndarray_from_numpy almacena el búfer sin procesar junto a los pasos del array, y esos dos valores describen diferentes distribuciones de memoria:

  1. Codificación: bytes(arr.data) materializa el búfer en orden C, por lo que una matriz de origen ordenada en Fortran genera bytes ordenados en C.
  2. Strides: ndarray_from_numpy copia strides sin modificarlos, por lo que siguen describiendo la disposición de Fortran.
  3. Decodificación: numpy.ndarray(buffer=..., strides=...) aplica los pasos de Fortran a bytes ordenados según el formato C. Esas direcciones apuntan a celdas erróneas y devuelven valores incorrectos.

Corrección​

Registra el orden de la memoria durante la codificación. Reprodúcelo durante la decodificación.

  • protobufs/npproto/ndarray.proto y el archivo generado mcbackend/npproto/__init__.py incorporan un campo de cadena order (etiqueta 5) en el mensaje Ndarray.
  • mcbackend/npproto/utils.py escribe order="CF"[arr.flags.f_contiguous] durante la codificación. Una matriz ordenada según Fortran almacena "F". Durante la decodificación, ndarray_to_numpy transpone y remodela cuando nda.order == "F". Ese paso reconstruye la disposición de Fortran a partir de los bytes ordenados según C.
  • mcbackend/test_npproto.py añade test_byteorders, que parametriza shape y order conjuntamente.

Pruebas​

TestUtils.test_byteorders parametriza shape y order conjuntamente. Cada uno de los casos (5,), (2, 3), (2, 3, 5) y (5, 2, 1, 7) se ejecuta dos veces, una por cada orden de memoria. En cada caso se comprueba que nda.order coincida con arr.flags.f_contiguous y, a continuación, se realiza un ciclo completo del array a través de las funciones de codificación y decodificación.

TestUtils.test_conversion sigue cubriendo los tipos de datos int, float, scalar, string, object y datetime.

Notas​

  • Actualiza la versión a 0.2.4.
  • La función ndarray_to_numpy incorpora el paso de transposición y mantiene el manejo actual de los búferes y los tipos de datos.
  • Los buffers codificados antes de la versión 0.2.4 tienen el campo order vacío. Al decodificar uno de ellos, se obtiene una matriz ordenada según el orden C.

Cómo realizar la prueba​

Verify the fix
pytest mcbackend/test_npproto.py

La suite ejecuta los nuevos casos de test_byteorders en ambos órdenes de memoria y vuelve a ejecutar los casos de dtype ya existentes.
