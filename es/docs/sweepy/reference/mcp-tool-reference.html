Referencia del herramienta Sweepy MCP

El servidor MCP en server.py ofrece trece herramientas. La página de integración de MCP explica el proceso de registro y los flujos de trabajo comunes. Esta página enumera todas las opciones disponibles, lo que permite predecir el funcionamiento de cada herramienta antes de que un asistente la ejecute.

Carga útil de la respuesta​

Cada herramienta devuelve una cadena JSON dentro de un bloque de contenido de texto. Las respuestas correctas empiezan por "status": "ok". Las respuestas fallidas empiezan por "status": "error" e incluyen un message que explica la causa. Un barrido fallido también informa de job_id y sweep_status: "failed".

Un asistente activa una herramienta mediante una solicitud tools/call. Esta ejecuta un barrido con una espera de bloqueo prolongada:

Request
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "run_sweep",
    "arguments": {
      "profile_path": "profiles/tech_writer.yaml",
      "wait_seconds": 300
    }
  }
}
Response, truncated
{
  "status": "ok",
  "sweep_status": "completed",
  "job_id": "b41e9c0d7a12",
  "discovered_count": 137,
  "new_count": 41,
  "previously_seen_count": 96,
  "active_count": 137,
  "top_match": {
    "title": "Senior Technical Writer",
    "company": "Acme",
    "match_score": 92,
    "url": "https://example.com/jobs/4412"
  },
  "reports": {
    "pdf": "C:\\Users\\Alex\\sweepy\\results\\tech_writer_mcp_2026-10-27-223115.pdf",
    "csv": "C:\\Users\\Alex\\sweepy\\results\\tech_writer_mcp_2026-10-27-223115.csv"
  },
  "card_count": 24,
  "assessment_mode": "agent",
  "assessment_required": true,
  "elapsed_seconds": 214.6,
  "message": null
}

El contenido completo del payload también incluye los valores top_roles, job_ids, skipped_sources y debug_log.

Herramientas de perfil y difusión de información​

create_profile​

Valida cada motor habilitado y luego crea el archivo de perfil YAML.

ParámetroTipoValor por defectoDescripción
namecadena de textoObligatorioNombre completo que se incluirá en el perfil.
titlesarreglo de cadenas de textoObligatorioTítulos de empleo objetivo, como ["Technical Writer", "UX Writer"].
locationcadena de textoObligatorioUbicación objetivo, como "New York, NY".
resume_pathcadena de textoObligatorioRuta hacia un PDF o un currículo en formato DOCX.
resume_tracksarreglo de objetosnullUna entrada por cada puesto de trabajo; cada una incluye información adicional sobre el currículo (name) y, opcionalmente, otros datos complementarios (path). Sweepy evalúa cada publicación según el puesto al que corresponde.
portfoliosUna matriz de objetosnullEntradas del portafolio; cada una con una lista opcional de track, url o path, y una lista opcional de pieces.
pieces_per_cardentero3Número de elementos del portafolio que se muestran en cada tarjeta, de 1 a 10.
remote_onlybooleanofalseRestringe los resultados a puestos 100% remotos.
include_hybridbooleanotrueIncluye puestos híbridos en los resultados.
min_salaryentero0Salario base anual mínimo. El valor cero indica que no hay requisito mínimo.
must_have_skillsarreglo de cadenas de textonullTérminos relacionados con las habilidades que aumentan las posibilidades de coincidencia con los requisitos del puesto.
synonymsarreglo de arreglosnullGrupos de términos intercambiables, como [["docs-as-code", "documentation as code"]].
platformsobjetonullInformación sobre las plataformas utilizadas, incorporada al bloque platforms del perfil.
sources_configobjetonullSelección del motor utilizado para procesar los datos, incorporada al bloque sources del perfil. Cada motor es validado antes de escribir los datos.
cache_configObjetonullAjustes de caché: enabled y ttl_seconds.
orchestrator_configobjetonullConfiguraciones de tiempo de espera y mecanismos de detención automática de errores.
history_configobjetonullParámetros que determinan qué publicaciones se omitirán durante el proceso de difusión de información.
job_trackingbooleantrueAgrega las columnas de seguimiento de tareas al archivo CSV y mantiene los valores anteriores.
assessmentstring"agent"Puerta de control de informes: agent bloquea la generación de un informe siempre que al menos una de las tarjetas utilizadas tenga palabras clave en común. keyword permite la creación de informes que contengan únicamente palabras clave.
output_filenamestringnullRuta personalizada para el procesamiento de datos; por defecto, utiliza la ruta profiles/{name}_{title}.yaml. Sweepy convierte en minúsculas ambas partes de la ruta y reemplaza todos los caracteres no alfanuméricos por _.

orchestrator_config toma el objeto timeout_per_source_seconds y los objetos circuit_breaker, junto con failure_threshold y cooldown_seconds.

history_config recibe como argumentos a enabled, retention_days, match y path. retention_days utiliza por defecto el valor de 4; match acepta los valores de url o url+role; path utiliza por defecto el valor de ~/.sweepy/history.db.

portfolios acepta una URL en línea, un archivo PDF local, texto en formato Markdown, un archivo en formato texto, o una lista de elementos. Asigne un nombre a cada elemento (track) para mantener un portafolio separado para cada pieza de trabajo, y luego envíe los elementos seleccionados a submit_judgments según las instrucciones indicadas (portfolio_highlight). Utilice set_portfolio para cambiar el portafolio asociado a un perfil que ya existe.

Devuelve profile_path, enabled_engines, engines_not_enabled y resume_documents del nuevo perfil. Cada entrada del currículo indica su path y las pistas (tracks) que la utilizan, sin el texto analizado (parsed).

set_portfolio​

Añade o sustituye las carteras que envía un perfil guardado. Llámalo después de que el usuario haya dado nombre a una cartera.

ParámetroTipoValor por defectoDescripción
profile_pathcadena de textoObligatorioRuta a un archivo de perfil existente YAML.
portfoliosArray de objetosnullEntradas a agregar. Una entrada sin track se aplica a todas las pistas. Pase una lista vacía con replace para eliminar todos los portafolios.
replacebooleanfalseElimina los portafolios guardados antes de agregar los nuevos.
pieces_per_cardEntero3Piezas del portafolio listadas por tarjeta. Deje este campo sin definir para mantener el valor almacenado.

Pasa portfolios, pieces_per_card o ambos. Una entrada admite un track opcional, un url o path opcional y una lista opcional pieces de {title, url, tags}.

Devuelve profile_path, resume_tracks, portfolio_configured, portfolio_sources, portfolio_pieces_per_card y portfolio_guidance. Cuando el perfil no tiene portafolio, portfolio_guidance indica qué preguntar al usuario.

run_sweep​

Ruta al archivo del perfil a utilizar. Si se omite, Sweepy utiliza el último perfil guardado, luego el más reciente.

ParámetroTipoValor por defectoDescripción
profile_pathcadena_de_caracteresnullRuta al perfil YAML. Cuando se omite, Sweepy utiliza el último perfil guardado; a continuación, el perfil más reciente que se encuentre en profiles/; y por último, el primer perfil convencional en el disco: profiles/custom_profile.yaml, profiles/paralegal_nyc.yaml o config.sample.yaml.
deduplicatebooleantrueFusiona URL repetidas y publicaciones que coincidan de diferentes foros para esta ejecución.
include_seenbooleanfalseReporta publicaciones de barridos anteriores y actualiza su historial.
wait_secondsEntero45El tiempo de espera más largo antes de que la llamada devuelva información sobre su progreso. Se mantiene en el rango de 0 a 600.
timestampcadena de textonullLa hora local del usuario para los nombres de los informes, según el formato YYYY-MM-DD-HHMMSS o ISO 8601. Un asistente proporciona la hora que ya conoce a partir de la conversación, y esta se utiliza para marcar cada informe con la hora del usuario en lugar de la del servidor.

Una operación de limpieza en tiempo real („live sweep“) suele durar más que el tiempo de espera establecido por el cliente. El proceso se encarga de cubrir ese intervalo ejecutándose en un hilo de fondo. Una llamada que devuelve el valor sweep_status: "running" incluye también el valor job_id; este identificador debe ser pasado a la función get_sweep_status hasta que el estado final sea completed.

Una segunda llamada con el mismo perfil y parámetros se une al trabajo en ejecución en lugar de iniciar otro nuevo. El proceso del servidor debe seguir funcionando. Los identificadores de los trabajos en ejecución permanecen en la memoria; un reinicio los elimina.

Devuelve uno de los tres tipos de resultados:

  • Ejecución: sweep_status, job_id, progress con step, total y label, además de elapsed_seconds, debug_log y message.
  • Completadas: sweep_status, job_id, discovered_count, new_count, previously_seen_count, active_count, top_match, top_roles, reports, job_ids, card_count, assessed_count, assessment_mode, assessment_required, skipped_sources, elapsed_seconds, debug_log y message. top_roles corresponde a los primeros cinco puestos.
  • Error: status: "error", message, job_id y sweep_status: "failed".

Espera a que el trabajo iniciado por job_id finalice y luego informa sobre su progreso.

Cuando cada publicación descubierta es una resolicitud, previously_seen_count informa el número total de resolicitudes y active_count informa cero. Llame a run_sweep con include_seen configurado en true para revisarlas.

Un proceso de limpieza („sweep“) realizado por MCP escribe los mismos nombres de los artefactos que la línea de comandos y agrega un marcador mcp, como en los archivos results/tech_writer_mcp_2026-10-27-223115.pdf, .csv y .json correspondientes. Una interfaz de línea de comandos (CLI) o un asistente (wizard) escriben el nombre sin el marcador, de modo que la carpeta muestra qué ruta generó cada informe. Se debe pasar el parámetro timestamp para estampar los archivos con la fecha y hora del usuario. De lo contrario, Sweepy obtiene la información de la hora actual del perfil (export.timezone).

get_sweep_status​

Espera a que se complete la operación iniciada por run_sweep y informa sobre su progreso.

ParámetroTipoValor por defectoDescripción
job_idcadena_de_caracteresnullID de la limpieza obtenido de run_sweep. Por defecto, se utiliza el último trabajo realizado.
wait_secondsEntero45El tiempo de espera más largo antes de que la llamada devuelva información sobre su progreso. Se mantiene en el rango de 0 a 600.

Cada respuesta devuelve los mismos campos que el resultado correspondiente a run_sweep. Si job_id falta o es desconocido, se genera un error que remite a run_sweep.

Una limpieza final también carga sus tarjetas en la sesión en vivo; por lo tanto, get_jobs, submit_judgments y render_report funcionan una vez que el estado se muestra como completed.

get_jobs​

Devuelve los registros de tarjetas almacenados en la sesión actual, clasificados según la coincidencia de palabras clave o la puntuación del resultado enviado.

ParámetroTipoValor por defectoDescripción
profile_stemcadena de textonullIdentificador de perfil utilizado para cargar una sesión guardada, como pedro_writer.
results_dircadena_de_caracteres"results"Carpeta que contiene a report_session.json.
limitEnteronullNúmero de tarjetas a devolver. Omítalo para devolver todas las tarjetas. Sweepy exige que se devuelva al menos una tarjeta.
needs_descriptionbooleannulltrue devuelve únicamente tarjetas sin contenido de publicación. false devuelve únicamente tarjetas con contenido de publicación.

Devuelve los valores count, session_count, needs_description_count y jobs, así como los documentos de resumen del perfil activo. Mientras se realiza una limpieza (sweep), el contenido enviado añade los valores sweep_status, running_job_id y progress, además de un aviso (message) que indica que dichas tarjetas (cards) existían antes de dicha limpieza.

Documentos de currículo​

resume_documents enumera una entrada por archivo de currículum. Cada entrada indica path, los tracks que usan ese archivo y text, el documento analizado. Los tracks que comparten un archivo comparten una entrada, así que Sweepy nunca repite el texto. La carga útil también incluye resume_default_path, resume_configured y resume_guidance.

Tu asistente evalúa ese texto. Los campos must_have_skills y synonyms del perfil solo determinan si el candidato cumple con los requisitos básicos. La puntuación obtenida a partir de estos campos mide el rendimiento del mismo, no del candidato en sí.

El asistente lee el archivo del mismo modo en que lo haría un reclutador: considera habilidades transferibles, experiencia, conocimientos del sector, herramientas utilizadas y otros aspectos relevantes. Luego asigna una puntuación al archivo según lo interpreta el sistema de seguimiento de candidatos (ATS, por sus siglas en inglés) utilizado por la empresa que publicó el anuncio.

  • Cualquier término presente en las secciones estándar Experience o Skills cuenta como evidencia válida para la evaluación.
  • El mismo término que aparezca dentro de tablas, encabezados, pies de página, imágenes o barras laterales de dos columnas no se tiene en cuenta, ya que su importancia es menor.
  • El asistente indica el nombre del sistema ATS utilizado por la empresa cuando se muestra el enlace para enviar la solicitud.
  • Todo lo que el sistema de análisis omita o no pueda procesar se incluye en el campo concerns.

Un archivo faltante o ilegible devuelve el valor text y no genera ningún error. La ruta del archivo sigue apareciendo en la salida, por lo que el asistente puede informar del problema.

submit_judgments​

La evaluación realizada por el asistente se incorpora en una única tarjeta de información sobre el candidato o en un lote completo de tarjetas. Solo los campos que no contengan valores nulos se modifican.

ParámetroTipoValor por defectoDescripción
job_idcadena de textonullID de la tarjeta estable (stable card) proveniente de run_sweep o get_jobs. Es obligatorio a menos que se proporcione judgments.
match_pctEnteronullPorcentaje de coincidencia entre 0 y 100. Lea primero el valor de resume_documents, luego califique el archivo según el método de análisis (ATS) utilizado en el post. Al proporcionar este valor, la etiqueta del elemento se cambiará a MATCH.
resume_trackcadena_de_caracteresnullRuta del currículo que se mostrará en la tarjeta.
resume_colorCadena de textonullColor del badge para esa pista.
domainCadena de textonullEl dominio del rol que se muestra en la tarjeta.
summaryCadena de textonullTexto resumido de la tarjeta.
requirementscadena_de_caracteresnullTexto de requisitos.
alignmentcadena_de_caracteresnullTenga en cuenta que esto conecta las pruebas de su currículo con el puesto de trabajo solicitado.
concernsstringnullFactores que desventajan al candidato: requisitos no cumplidos, brechas en la experiencia profesional, incompatibilidad con el área de conocimiento requerida, expectativas del puesto no satisfechas, salario por debajo del mínimo establecido, o contenido que no podría ser procesado o interpretado adecuadamente por los sistemas correspondientes.
has_extended_responsebooleannullMarca una publicación que requiere respuestas escritas.
app_formatCadena de textonullFormato de la aplicación, como un portal o un correo electrónico.
compcadena_de_caracteresnullLínea de compensación.
benefitscadena_de_caracteresnullLínea sobre beneficios.
page_themecadena_de_caracteresnullSobrescripción del tema de la tarjeta.
portfolio_fitEnteronullPuntuación del portafolio que varía de 0 a 100. La tarjeta la muestra como PORTFOLIO FIT.
portfolio_highlightcadenanullNombra los elementos que se enviarán con esta aplicación; una tarjeta sin este campo enumera los elementos guardados en el perfil.
descriptioncadenanullCuerpo del mensaje publicado, leído desde la URL de la tarjeta (en caso de que Sweepy no haya podido analizarla correctamente).
judgmentsarraynullLista de objetos relacionados con la tarjeta, cada uno incluyendo un campo adicional (job_id). No combinar este campo con job_id.

Se evalúa el documento, no el perfil: get_jobs devuelve el texto del currículo analizado (resume_documents), mientras que must_have_skills y synonyms proporcionan datos utilizados únicamente para el proceso de análisis. Registra cualquier información que el analizador omita (concerns), como las habilidades mostradas en gráficos laterales.

Se devuelve la tarjeta fusionada en formato PDF (job); una solicitud en lotes incluye applied, jobs y rejected; rejected indica los elementos cuyo identificador falta en la sesión actual.

import_jobs​

import_jobs Añade roles encontrados y verificados mediante investigación independiente; por defecto, Sweepy no los confirma

Añade roles que han sido identificados y verificados por investigaciones independientes. Sweepy no los confirma de forma predeterminada.

ParámetroTipoValor por defectoDescripción
jobs_jsonbooleanoComprueba cada URL antes de su importación.
validatebooleanfalseProcesa cada URL con el comprobador de enlaces antes de su importación.

Se devuelven los valores «imported» y «skipped». Las respuestas relacionadas con límites de uso o protección contra bots se consideran no verificadas, por lo que no demuestran que una publicación esté desactivada.

render_report​

Genera un PDF con las tarjetas de la sesión actual.

ParámetroTipoValor por defectoDescripción
profile_stemcadena de textonullIdentificador de perfil utilizado para cargar una sesión guardada.
results_dircadena de texto"results"Carpeta para la salida predeterminada y la sesión guardada.
output_filenamecadena_de_caracteresnullRuta explícita al archivo PDF. Debe estar dentro del espacio de trabajo. Un valor vacío escribirá «{profile_stem}_mcp_{YYYY-MM-DD-HHMMSS}.pdf» en «results_dir». Este nombre coincide con los nombres especificados en la línea de comando y añade un marcador «mcp».
playbookCadena de texto""Nota de estrategia en texto plano. Los símbolos & y los corchetes angulares se renderizan en negrita (**bold**). Los saltos de línea se convierten en nuevos renglones. Sweepy guarda el texto junto con la sesión, por lo que una nueva llamada sin esta opción reutiliza el texto ya almacenado. Un valor vacío sin texto guardado genera un “playbook” predeterminado.
timestampcadena de textonullLa hora local del usuario para el nombre de archivo predeterminado, en formato YYYY-MM-DD-HHMMSS o ISO 8601. Solo se aplica cuando output_filename está vacío.

Devuelve pdf_report, pages, card_count y playbook_saved.

Los perfiles por defecto están configurados en report.assessment: "agent", lo que impide la visualización de los resultados mientras alguna tarjeta tenga solamente coincidencias de palabras clave. Las opciones unassessed_job_ids y unassessed_titles se utilizan para indicar los errores que deben ser considerados; esto ayuda al asistente a tomar las decisiones adecuadas. Puede establecerse report.assessment: "keyword" para permitir informes mixtos, o SWEEPY_REQUIRE_JUDGMENTS=1 para aplicar ciertas restricciones a todos los perfiles, o incluso export_report para configuraciones específicas.

Herramientas de resultados e historial​

get_results​

Lee la información más reciente sobre el proceso de limpieza (sweep) almacenada en el disco (JSON). Nunca ejecuta nuevamente los procedimientos de detección ni de puntuación.

ParámetroTipoValor por defectoDescripción
profile_stemcadena de textonullIdentificador del perfil que filtra los archivos de resultado. Omítalo para leer el archivo de resultado más reciente.
results_dircadena de texto"results"Carpeta que contiene los archivos de resultado.
limitentero10Número de roles principales a devolver; rango: 1 a 100.

Devuelve result_file, pdf_report, csv_report, total_roles y top_roles. Cada rol contiene title, company, location, match_score, match_kind, resume_track, domain, url y playbook.

Las puntuaciones marcadas como KEYWORD OVERLAP son valores determinísticos obtenidos en la primera pasada. Usa get_jobs y submit_judgments antes de presentarlos como coincidencias.

export_report​

Reconstruye los archivos de informe a partir de un análisis previo (JSON).

ParámetroTipoValor por defectoDescripción
json_sourcecadena de textonullRuta al análisis (JSON); tiene prioridad sobre profile_stem.
profile_stemcadena de textonullIdentificador del perfil utilizado para encontrar la última coincidencia (JSON).
results_dircadena de texto"results"Carpeta que contiene los archivos de resultado.
formatsarreglo de cadenas de texto["pdf"]Formatos de salida: pdf, png, csv o json.
candidate_namecadena de texto"Job Seeker"Nombre que se mostrará en el encabezado del PDF.
output_dircadena de textonullCarpeta de salida; por defecto, es la misma que contiene el archivo fuente (JSON).
job_trackingbooleanonullIncluir columnas de seguimiento del trabajo en la exportación en CSV; déjalo desactivado para seguir la configuración del perfil (export.tracking).

Devuelve los valores source_file, roles_exported, generated y errors. El objeto generated contiene los valores pdf, pdf_pages, png, csv, csv_rows y json cuando la solicitud incluye dichos formatos. Una solicitud en formato PNG renderiza primero el archivo PDF. La salida generada por JSON escribe el contenido de {stem}_export.json, por lo que nunca sobrescribe el archivo fuente (el “sweep file”) del cual proviene la información.

clear_history​

Olvida los resultados ya reportados para que el siguiente análisis pueda volver a generarlos.

ParámetroTipoValor por defectoDescripción
profile_pathcadena de textonullRuta al perfil (YAML).
profile_stemcadena de textonullIdentificador del perfil (pedro_writer).

Devuelve scope, cleared y remaining. Los registros históricos se guardan por perfil; llama a la herramienta sin estos parámetros después de un análisis para borrar los datos del perfil correspondiente. En ese caso, se lee el estado del servidor en ejecución; utiliza profile_path o profile_stem después de reiniciar.

Herramientas de conversión de documentos​

convert_document​

Convierte .docx, .doc, .txt, .md o .pdf en PDF. Los archivos en formato legado (.doc) requieren procesamiento con Microsoft Word.

ParámetroTipoValor por defectoDescripción
document_pathcadena de textoObligatorioRuta del archivo que se va a convertir.
pdf_pathcadena de textonullRuta de salida. Por defecto, utiliza la carpeta de origen.

Devuelve los valores de pdf_path y source_path.

convert_docx​

Los perfiles se convierten en archivos PDF utilizando los valores «python-docx» y «reportlab». Si está disponible Microsoft Word, se utiliza el formato «docx2pdf» para generar los archivos PDF.

ParámetroTipoValor por defectoDescripción
docx_pathcadenaObligatorioRuta al archivo .docx.
pdf_pathcadena_de_caracteresnullRuta de salida. Por defecto, utiliza la carpeta DOCX.

Escribir rutas​

Los herramientas que generan salida la guardan dentro de la carpeta “Sweepy”. Cualquier intento de ejecución que se produzca fuera de esa carpeta fallará, a menos que se cambie el valor de SWEEPY_ALLOW_EXTERNAL_WRITES a 1. Los archivos de entrada pueden estar en cualquier ruta que el proceso pueda abrir.

Devuelve pdf_path.
