Referencia para desarrolladores de Sweepy

Sweepy funciona como un pequeño proyecto Python con un motor sencillo. Esta página relaciona cada etapa del proceso con el módulo correspondiente, para que sepas dónde realizar cambios.

Público objetivo​

Público objetivo: Lee esta página si planeas modificar el código de Sweepy o agregar nuevas fuentes de datos. Los revisores pueden utilizarla como guía para solicitudes de colaboración. Abarca únicamente aspectos internos: módulos, dependencias y versiones de Python

Lea esta página si tiene intenciones de modificar el código de Sweepy o agregar una nueva fuente de datos para su procesamiento. Los revisores pueden utilizarla como guía para evaluar las solicitudes de cambio. Esta información abarca únicamente los aspectos internos del sistema: módulos, dependencias y versiones de Python.

consejo

Si deseas realizar operaciones de limpieza (sweep), ignora esta página. Comienza por Instalación.

Etapas y módulos del pipeline​

swee.py ejecuta cinco etapas en orden. La terminal muestra cada etapa con los nombres [1/5] hasta [5/5].

EtapaMóduloQué hace
1. Cargando el perfilengine/config.pyCarga y valida tu perfil. El asistente dentro de este mismo módulo lo genera automáticamente.
2. Descubriendo funciones y rolesengine/discovery.pyLos feeds de agregación de consultas se procesan a través de python-jobspy y se clasifican según la plataforma correspondiente.
2. Descubriendo funciones y herramientasengine/sources/Recupera las tablas de información de Greenhouse, Ashby, Lever, Workable y Built In NYC desde puntos finales (endpoints) públicos.
2. Deduplicaciónswee.pyFusiona los resultados del agregador y de la fuente en una única tarjeta por enlace de trabajo.
3. Validación de URLengine/validator.pyComprueba cada enlace mediante una solicitud HTTP HEAD y un plan de respaldo GET. Elimina los contenidos obsoletos o inactivos.
4. Evaluación de los currículosengine/scorer.pyExtrae términos de los anuncios y de los currículos, y luego evalúa la coincidencia en requisitos y palabras clave. Etiqueta los anuncios que requieren respuestas escritas.
5. El sistema de enrutamiento resume las pistasengine/enrich.pyElige la pista con la mayor coincidencia de términos y le asigna el color del correspondiente distintivo.
5. Tarjetas enriquecidasengine/enrich.pyGenera resúmenes de las tarjetas, líneas de información sobre compensaciones y texto personalizado para las propinas.
5. PDF de la tarjeta por defectoengine/report.pyRenderiza el diseño de la tarjeta (seis tarjetas por página por defecto) y devuelve el número de páginas.
5. PDF de tabla heredadaengine/pdf_builder.pyMuestra el diseño de la tabla cuando tu perfil está configurado con report.style: legacy.
5. Exportación de datosengine/exporter.pyEscribe archivos CSV y JSON. Rasteriza imágenes en formato PNG a solicitud.
5. Seguimiento de tareasengine/tracking.pyAñade las columnas de seguimiento y lee las exportaciones anteriores para que los valores que introduzcas se mantengan.

engine/session.py almacena la información relativa a las “tarjetas” (cards) en el flujo del Protocolo de Contexto de Modelo con Estado. Estas tarjetas se guardan en un mapa seguro para múltiples hilos (thread-safe), indexadas mediante un hash estable generado a partir de cada enlace de trabajo (job link).

¿Dónde realizar un cambio?​

Quieres cambiarComienza en
Fuente de empleo o su punto final de conexiónengine/sources/, más una lista inicial en data/sources/
Cómo se calcula la puntuación de las coincidenciasengine/scorer.py
Qué muestra la “tarjeta” de informaciónengine/enrich.py, y luego engine/report.py
Cómo se verifican los enlacesengine/validator.py
Una opción de línea de comandosswee.py
Una herramienta MCPserver.py
consejo

server.py importa los mismos módulos que la herramienta de línea de comandos. Pruebe la ruta de acceso a MCP después de cualquier cambio en los módulos, ya que una corrección puede afectar ambos puntos de entrada.

Referencia al módulo​

Puntos de entrada​

MóduloPropósito
swee.pyOrquestador principal y punto de entrada en la línea de comandos (argparse) para el proceso en cinco etapas.
server.pyServidor del Protocolo de Contexto del Modelo (stdio) que expone las herramientas del motor a los asistentes de inteligencia artificial. get_jobs devuelve el texto del currículo analizado para que el asistente evalúe el documento, no la lista de palabras clave del perfil.

Módulos del motor​

MóduloPropósito
engine/config.pyAsistente interactivo, así como herramientas para la carga y validación de datos.
engine/discovery.pyOrquestación de scrapers para python-jobspy y detección de fuentes determinísticas, Sistema de Seguimiento de Candidatos (ATS), así como deduplicación de datos.
engine/validator.pyVerificación del estado de funcionamiento de los enlaces, con detección de errores tipo 404. Los enlaces no verificados se mantienen en el proceso.
engine/scorer.pyExtracción de términos del currículo, cálculo de porcentajes de coincidencia, etiquetado de datos y puntuación de cada elemento del currículo.
engine/enrich.pyEnriquecimiento de la información mostrada en las “tarjetas” de información, para resúmenes, detalles sobre compensaciones, redirección de datos y consejos personalizados.
engine/session.pyAlmacén de datos seguro para uso en múltiples procesos simultáneos (thread-safe), con identificadores únicos para el flujo de trabajo de MCP.
engine/report.pyPDF con diseño predeterminado para la presentación de las tarjetas de información.
engine/pdf_builder.pyPDF con diseño de tabla heredado para report.style: legacy.
engine/exporter.pyExportación de datos en formato CSV y JSON, además de la conversión de los informes en formato PNG.
engine/tracking.pyColumnas de seguimiento y recuperación de datos de exportaciones anteriores.
engine/docx.pyConversión de los datos en formato PDF utilizando DOCX, junto con python-docx y reportlab; también se proporciona una opción de respaldo en formato Microsoft Word.
engine/documents.pyProceso de envío de documentos para el conversor --convert y el sistema MCP, que abarca formatos como DOC, texto, Markdown y PDF.
engine/logging.pyRegistro de errores bajo el control de logs/.
engine/cache.pyCaché de datos extraídos de bases de datos SQLite, organizado por consulta y configuración del motor de procesamiento; la información permanece activa durante una hora.
engine/circuit_breaker.pyConteo de errores consecutivos en el proceso de extracción de datos, así como pausas en las llamadas al motor durante períodos de inactividad.
engine/engine_defaults.pyListas de puestos de trabajo y configuraciones del motor compartidas entre los sistemas; su mantenimiento se realiza sin necesidad de importaciones para evitar ciclos innecesarios.
engine/engines.pyRegistro de adaptadores y herramientas de instalación para motores opcionales como hirehunt, openroles, apify y jobdrop.
engine/history.pyRegistro persistente de los anuncios de empleo ya reportados; solo se generan informes diarios sobre puestos nuevos.
engine/normalize.pyProcesamiento de los datos brutos extraídos por los motores para adaptarlos a los formatos comunes utilizados en el sistema.
engine/salary.pyExtracción de información sobre salarios del texto de los anuncios cuando estos no contienen datos estructurados al respecto.
engine/sweep_config.pyAplicación de las configuraciones predeterminadas del motor a los perfiles de los usuarios.
engine/updater.pyVerificación de actualizaciones basada en repositorios Git y reinstalación de dependencias necesarias.

Fuentes de datos determinísticas​

MóduloPropósito
engine/sources/__init__.pyFunción para descargar datos y cargar listas iniciales desde data/sources/.
engine/sources/_common.pyHerramientas comunes para el manejo de encabezados de los anuncios y la conversión de datos en formato de texto.
engine/sources/greenhouse.pyHerramienta para recuperar información de tablones de empleo de tipo “Greenhouse”.
engine/sources/ashby.pyHerramienta para recuperar información de tablones de empleo de tipo “Ashby”.
engine/sources/lever.pyHerramienta para recuperar publicaciones de LinkedIn.
engine/sources/workable.pyHerramienta para interactuar con widgets relacionados con la visualización de datos.
engine/sources/builtinnyc.pyHerramienta para extraer información de tablones de empleo de la ciudad de Nueva York.

Adaptadores de motores de procesamiento​

MóduloPropósito
engine/adapters/__init__.pyRegistro que asigna cada nombre de motor a su correspondiente adaptador.
engine/adapters/base.pyClase base ScraperAdapter, encabezado compartido User-Agent y herramientas para dar forma al resultado.
engine/adapters/jobspy_adapter.pypython-jobspy Adaptador de agregadores para LinkedIn, Indeed, Glassdoor y ZipRecruiter.
engine/adapters/ats_adapter.pyUn adaptador que reemplaza a los mecanismos determinísticos de obtención de datos de empleos (ATS) utilizados en engine/sources/.
engine/adapters/hirehunt_adapter.pyAdaptador opcional para motores de búsqueda de empleos.
engine/adapters/openroles_adapter.pyAdaptador opcional para motores de gestión de puestos abiertos.
engine/adapters/apify_adapter.pyAdaptador opcional para herramientas de automatización de procesos.
engine/adapters/jobdrop_adapter.pyAdaptador opcional para sistemas de publicación de ofertas de trabajo.

Datos, scripts y pruebas​

RutaPropósito
data/sources/*.txtListas de referencia para tableros de información, empresas, organizaciones y categorías.
scripts/make_sample.pyHerramienta para generar informes de ejemplo almacenados en docs/.
tests/Conjunto de pruebas (pytest) que incluye archivos específicos para cada área: adaptadores, configuraciones, documentos, informes, etc. Otros archivos tratan temas como salarios, servidores, fuentes de datos, seguimiento de procesos, actualizaciones y validación de datos.
nota

Agrega un archivo de prueba dedicado cada vez que modifiques los elementos discovery.py, exporter.py o pdf_builder.py; colócalo en la carpeta tests/.

Dependencias​

Los paquetes necesarios para el funcionamiento del sistema provienen de requirements.txt; las versiones mencionadas coinciden con las especificadas en ese archivo.

PaqueteVersiónFunción para Sweepy
reportlab5.0.1Genera informes en formato PDF con enlaces interactivos.
pymupdf1.28.2Extrae texto de currículos en formato PDF y convierte imágenes en formato PNG.
python-docx1.2.0Lee los currículos contenidos en .docx y reconstruye el texto de DOCX en formato PDF, sin necesidad de usar Word.
requests2.32.5Accede a los puntos finales de los sistemas ATS y verifica si los enlaces a empleos están activos.
beautifulsoup44.15.0Procesa datos provenientes de fuentes como Greenhouse, Lever y Built In NYC.
pyyaml6.0.3Lee y escribe perfiles de empleados.
questionary2.1.1Gestiona las preguntas del asistente interactivo.
prompt-toolkit3.0.53Controla la entrada de texto en el asistente interactivo.
python-jobspy1.2.0Recopila información de LinkedIn, Indeed, Glassdoor y ZipRecruiter sin necesidad de credenciales API.
pandas2.2.3Organiza los datos recopilados y genera archivos en formato CSV y JSON.
mcp1.30.0Ejecuta el servidor que utiliza el Model Context Protocol.
anyio4.12.1Ejecuta el transporte asincrónico de MCP.
tzdata2026.5Suministra la base de datos de la zona IANA en Windows; por lo tanto, export.timezone acepta un nombre como America/New_York.

requirements.txt También enumera un paquete opcional. Descomente docx2pdf cuando Word deba generar el PDF.

  • docx2pdf: Convierte DOCX en PDF mediante Microsoft Word en Windows. Sweepy lo llama siempre que Microsoft Word esté instalado en el equipo.
nota

mcp Se mantiene deliberadamente en la versión 1.x. El SDK 2.x solo es compatible con el protocolo del 28 de julio de 2026. Un cliente que prueba con server/discover y luego recurre a la opción initialize recibe un error de tipo -32022. VS Code Copilot sigue este procedimiento de respaldo.

consejo

pandas Se mantiene deliberadamente en la versión 2.x. Pandas 3.x requiere Python 3.11 o una versión más reciente, pero el proceso de integración continua (CI) todavía prueba con Python 3.10.

Requisitos y versiones de Python soportadas​

RequisitoDetalles
Requisito mínimo de PythonSweepy exige Python 3.10 o una versión más reciente; todos los módulos utilizan la sintaxis de Python 3.10.
Rango de pruebasEl flujo de trabajo de CI en .github/workflows/ci.yml ejecuta Python 3.10, 3.11 y 3.12 en Ubuntu.
Objeto de revisión de código (Lint target)pyproject.toml establece las reglas de formato (ruff target-version = "py310"). Una construcción disponible únicamente para versiones más recientes hace que el proceso de revisión de código (lint) falle.
Pasos del proceso de integración continuaEl proceso instala ambos archivos necesarios y ejecuta E501 antes de iniciar las pruebas.
Pasos de CIEl proceso instala ambos archivos de requisitos y ejecuta ruff check . antes de ejecutar pytest.
nota

pyproject.toml declara requires-python = ">=3.10", así que pip rechaza un intérprete más antiguo durante la instalación. La matriz de CI y el objetivo de ruff definen el rango probado. Python 3.13 funciona en la práctica, pero queda fuera de ese rango.

Python 3.13

El paquete pymupdf puede compilarse a partir del código fuente cuando no existe una versión precompilada. Instale las Herramientas de Compilación de C++ de Microsoft y seleccione la opción de “Desarrollo de escritorio con C++” antes de instalar las dependencias.

Diseño del repositorio​

Repository layout
swee.py              CLI entry point and sweep orchestrator
server.py            MCP server over stdio
engine/              Pipeline modules
engine/sources/      Deterministic ATS fetchers
engine/adapters/     Aggregator and optional engine adapters
data/sources/        Seed lists for each fetcher
profiles/            YAML search profiles
results/             Generated PDF, CSV, JSON, and PNG files
logs/                Opt-in debug logs
styles/              Vale style rules for the docs
tests/               pytest suite

Cuando cambies la firma de una herramienta en server.py, actualiza la referencia a la herramienta MCP en el mismo commit.
