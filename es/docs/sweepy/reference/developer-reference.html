Referencia para desarrolladores de Sweepy

Sweepy se ejecuta como un pequeño proyecto de Python con un motor plano. Esta página asigna cada etapa del proceso al módulo que la ejecuta, para que sepas dónde realizar un cambio.

Destinatarios​

Lee esta página si tienes pensado modificar el código de Sweepy o añadir una fuente de ofertas de empleo. Los revisores pueden utilizarla como guía para una solicitud de incorporación de cambios. Solo abarca aspectos internos: módulos, dependencias y versiones de Python.

Omite esta página si deseas ejecutar barridos. Empieza por Instalación.

Etapas del proceso y módulos​

swee.py ejecuta cinco etapas en orden. La terminal muestra cada etapa como [1/5] hasta [5/5].

EtapaMóduloQué hace
1. Carga del perfilengine/config.pyCarga y valida tu perfil YAML. El asistente del mismo módulo crea uno.
2. Detección de rolesengine/discovery.pyConsulta las fuentes del agregador a través de python-jobspy y clasifica cada plataforma.
2. Detección de rolesengine/sources/Obtiene los tablones de Greenhouse, Ashby, Lever, Workable y Built In NYC a partir de puntos de acceso públicos.
2. Deduplicaciónswee.pyFusiona los resultados del agregador y de las fuentes en una sola ficha por enlace de oferta de empleo.
3. Validación de URLengine/validator.pyComprueba cada enlace con una solicitud HTTP HEAD y una alternativa GET. Elimina las ofertas inactivas.
4. Puntuación frente al currículumengine/scorer.pyExtrae los términos de la oferta y del currículum y, a continuación, puntúa la coincidencia entre los requisitos y las palabras clave. Etiqueta las ofertas que exigen respuestas por escrito.
5. Asignación de perfiles de currículumengine/enrich.pySelecciona el perfil con mayor coincidencia de términos y le asigna el color de insignia correspondiente.
5. Enriquecimiento de tarjetasengine/enrich.pyCrea resúmenes de tarjetas, líneas de remuneración y texto de consejos personalizados.
5. PDF predeterminado de las fichasengine/report.pyGenera el diseño de las fichas, con seis fichas por página de forma predeterminada, y devuelve el número de páginas.
5. PDF de tabla heredadaengine/pdf_builder.pyGenera el diseño de tabla cuando tu perfil establece report.style: legacy.
5. Exportaciones de datosengine/exporter.pyCrea archivos CSV y JSON. Rasteriza imágenes de páginas en formato PNG cuando se solicita.
5. Seguimiento de trabajosengine/tracking.pyAñade las columnas de seguimiento y lee exportaciones anteriores para que se recuperen los valores introducidos.

engine/session.py contiene el almacén de tarjetas para el flujo del Protocolo de Contexto de Modelo (MCP) con estado. Mantiene las tarjetas en un mapa seguro para subprocesos, indexado mediante un hash estable de cada enlace de trabajo.

Dónde realizar un cambio​

Quieres cambiarEmpieza en
Una fuente de trabajo o su punto finalengine/sources/, además de una lista de semillas en data/sources/
Cómo se puntúan las coincidenciasengine/scorer.py
Lo que muestra una fichaengine/enrich.py, y luego engine/report.py
Cómo se comprueban los enlacesengine/validator.py
Un indicador de línea de comandosswee.py
Una herramienta MCPserver.py

server.py importa los mismos módulos del motor que la herramienta de línea de comandos. Comprueba la ruta del MCP tras cualquier cambio en el motor, ya que una corrección afecta a ambos puntos de entrada.

Referencia de módulos​

Puntos de entrada​

MóduloFinalidad
swee.pyCoordinador principal y punto de entrada de línea de comandos argparse para el proceso de cinco etapas.
server.pyServidor del Protocolo de Contexto de Modelo (stdio) que expone las herramientas del motor a los asistentes de IA. get_jobs devuelve el texto analizado del currículum para que sea el asistente quien evalúe el documento, y no la lista de palabras clave del perfil.

Módulos del motor​

MóduloFinalidad
engine/config.pyAsistente interactivo, además de carga y validación de YAML.
engine/discovery.pyCoordinación de rastreadores para python-jobspy y las fuentes determinísticas, detección del sistema de seguimiento de candidatos (ATS) y deduplicación.
engine/validator.pyComprobaciones de disponibilidad de enlaces con detección de «soft-404». Los enlaces no verificables permanecen en la ejecución.
engine/scorer.pyExtracción de términos del currículum, coincidencia porcentual, etiquetado y puntuación por vía de búsqueda.
engine/enrich.pyEnriquecimiento de fichas para resúmenes, remuneración, enrutamiento de vías y consejos personalizados.
engine/session.pyAlmacenamiento de fichas seguro para subprocesos con identificadores estables para el flujo MCP con estado.
engine/report.pyPDF con diseño predeterminado de fichas.
engine/pdf_builder.pyPDF con diseño de tabla heredado para report.style: legacy.
engine/exporter.pyExportaciones a CSV y JSON, además de rasterización a PNG de los PDF de los informes.
engine/tracking.pySeguimiento de columnas y lectura de datos heredados de exportaciones anteriores.
engine/docx.pyConversión de DOCX a PDF con python-docx y reportlab, además de una opción alternativa para Microsoft Word.
engine/documents.pyEnvío de documentos para --convert y el conversor MCP, que abarca DOCX, DOC, texto, Markdown y PDF.
engine/logging.pyRegistros de depuración activables en logs/.
engine/cache.pyCaché de extracción de datos en SQLite indexada por consulta y conjunto de motores, con un tiempo de vida de una hora.
engine/circuit_breaker.pyCuenta los errores consecutivos en la fuente y pausa las llamadas durante un periodo de espera.
engine/engine_defaults.pyListas de sitios predeterminadas compartidas y configuración de motores, sin importaciones para evitar bucles.
engine/engines.pyRegistro de adaptadores e instalador para los motores opcionales hirehunt, openroles, apify y jobdrop.
engine/history.pyRegistro persistente de las ofertas ya notificadas. Una limpieza diaria solo notifica los nuevos puestos.
engine/normalize.pyNormaliza las filas sin procesar del motor en las columnas compartidas de las ofertas.
engine/salary.pyExtracción de la remuneración del texto de la oferta cuando una bolsa de empleo omite la información estructurada sobre el salario.
engine/sweep_config.pyAplica los valores predeterminados compartidos del motor a la configuración de los perfiles.
engine/updater.pyComprobación de actualizaciones basada en Git y reinstalación de dependencias para el checkout.

Datos, scripts y pruebas​

RutaFinalidad
data/sources/*.txtListas iniciales de tableros, empresas, organizaciones y categorías.
scripts/make_sample.pyGenerador del informe de muestra almacenado en docs/.
tests/Conjunto de pruebas pytest con un archivo por área: adaptadores, configuración, documentos, docx, motores, enriquecimiento, historial, registro y informes. Otros archivos abarcan salarios, puntuador, servidor, sesión, fuentes, swee, seguimiento, actualizador y validador.

Añade un archivo de prueba específico cuando modifiques discovery.py, exporter.py o pdf_builder.py. Coloca el archivo en tests/.

pandas2.2.3Estructura las ofertas de empleo y genera las exportaciones en formato CSV y JSON.
mcp1.30.0Ejecuta el servidor del Protocolo de Contexto de Modelos (MCP).

El archivo requirements.txt también incluye un paquete opcional. Descomenta docx2pdf cuando se desee que Word genere el PDF.

  • docx2pdf (0.5.2, opcional) convierte archivos DOCX a PDF mediante Microsoft Word en Windows. Sweepy lo invoca siempre que Microsoft Word esté instalado en el equipo.

mcp se mantiene en la versión 1.x a propósito. El SDK 2.x solo es compatible con la era de protocolo del 28 de julio de 2026. Un cliente que sondee server/discover y luego recurra al protocolo de enlace initialize obtendrá un error -32022. VS Code Copilot sigue ese procedimiento alternativo.

pandas se mantiene en la versión 2.x a propósito. Pandas 3.x requiere Python 3.11 o posterior, y la matriz de CI sigue realizando pruebas con Python 3.10.

pip install -r requirements-dev.txt
ruff check .
pytest -q

Requisitos y versiones de Python compatibles​

ElementoDetalle
Versión mínima de PythonSweepy requiere Python 3.10 o posterior y utiliza la sintaxis de 3.10 en todos los módulos.
Rango probadoEl flujo de trabajo de CI en .github/workflows/ci.yml se ejecuta con Python 3.10, 3.11 y 3.12 en Ubuntu.
Objetivo de lintpyproject.toml establece ruff target-version = "py310". Una construcción que solo admita versiones más recientes hace que falle la tarea de lint.
Longitud de líneaRuff impone un límite de 100 caracteres por línea e ignora E501.
Pasos de CIEl proceso instala ambos archivos de requisitos y ejecuta ruff check . antes de pytest.

pyproject.toml declara requires-python = ">=3.10", por lo que pip rechaza un intérprete más antiguo en el momento de la instalación. La matriz de CI y el objetivo ruff definen el rango probado. Python 3.13 funciona en la práctica, pero queda fuera de ese rango.

:::precaución[Python 3.13] El paquete pymupdf puede compilarse desde el código fuente si no existe ningún archivo wheel precompilado. Instala las Herramientas de compilación de Microsoft C++ y selecciona la carga de trabajo «Desarrollo de escritorio con C++» antes de instalar las dependencias. :::

Estructura del repositorio​

Estructura del repositorio
swee.py Punto de entrada de la CLI y coordinador de barridos
server.py Servidor MCP a través de stdio
engine/ Módulos del pipeline
engine/sources/ Recopiladores ATS determinísticos
engine/adapters/     Agregador y adaptadores opcionales del motor
data/sources/ Listas de semillas para cada recuperador
profiles/ Perfiles de búsqueda en YAML
results/ Archivos generados en formato PDF, CSV, JSON y PNG
logs/ Registros de depuración activables
styles/ Reglas de estilo Vale para la documentación
tests/ Conjunto de pruebas pytest

Cuando modifiques la firma de una herramienta en server.py, actualiza la referencia de herramientas MCP en la misma confirmación.
