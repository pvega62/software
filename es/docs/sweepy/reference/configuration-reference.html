Referencia de configuración del perfil

Esta página enumera todas las opciones que acepta un perfil de Sweepy. Mantenla abierta mientras editas tu perfil. Para un tutorial paso a paso, consulta Configurar Sweepy.

Dónde se guardan los perfiles​

Sweepy lee los perfiles de la carpeta profiles/ dentro de tu directorio de Sweepy. Cada perfil usa YAML, un formato de texto sin formato organizado mediante sangrías y dos puntos. Abre uno en el Bloc de notas, VS Code o cualquier editor de texto que ya tengas.

Empieza con config.sample.yaml o un ajuste preestablecido como profiles/paralegal_nyc.yaml. Copia una plantilla, cámbiale el nombre y edita los valores:

Terminal
copy config.sample.yaml profiles\my_search.yaml
notepad profiles\my_search.yaml

Luego, apunta un barrido a ese archivo:

Terminal
sweepy --profile profiles/my_search.yaml
nota

Un perfil contiene toda tu configuración. Crea tantos perfiles como quieras: uno por ciudad o familia de roles. Sweepy guarda el estado del barrido fuera del perfil, en la caché de descubrimiento, la base de datos del historial y las carpetas logs/ y results/.

precaución

Aplica sangría con espacios, nunca con tabulaciones. YAML rechaza las tabulaciones, y una sola tabulación perdida hace que todo el perfil sea ilegible.

Ejemplo de perfil completo​

El siguiente ejemplo muestra el perfil completo de Alex. Las líneas que empiezan con # funcionan como comentarios y Sweepy las ignora:

profiles/paralegal_nyc.yaml
# ─────────────────────────────────────────────────
# Sweepy — Alex's Paralegal Profile (New York City)
# ─────────────────────────────────────────────────

# Your name. It appears in the PDF report header.
name: "Alex Rivera"

# Set true to write rotating debug logs under logs/.
debug: false

# ─── Job search ───────────────────────────────────
search:
  # Every title Sweepy searches at the same time.
  titles:
    - "Paralegal"
    - "Legal Assistant"
    - "Litigation Support Specialist"
    - "Legal Secretary"

  # Your target market.
  location: "New York, NY"

  # true keeps remote roles only. false keeps remote, hybrid, and on-site roles.
  remote_only: false

  # false removes hybrid roles from every report.
  include_hybrid: true

  # Annual salary floor. Use 0 to skip salary filtering.
  min_salary: 65000

  # true reads pay from the posting text when a board omits structured pay.
  salary_from_description: true

# ─── Resume ───────────────────────────────────────
resume:
  # Path to a PDF or DOCX resume. Forward slashes work on Windows.
  path: "Alex_Rivera_Resume.pdf"

  # Terms that carry the most weight when Sweepy scores a posting.
  must_have_skills:
    - "Westlaw"
    - "LexisNexis"
    - "e-discovery"
    - "Contract Review"
    - "Legal Research"

  # 1.0 is standard. Raise it to reward exact skill matches.
  keywords_weight: 1.5

  # Interchangeable terms. Sweepy matches every member of a group either way.
  synonyms:
    - ["e-discovery", "ediscovery", "electronic discovery"]
    - ["legal research", "case law research"]
    - ["docketing", "case calendaring"]
    - ["legal assistant", "legal secretary"]
    - ["contract review", "contract analysis", "agreement review"]

  # Optional: one resume per role family. Sweepy picks the best fit for each posting.
  tracks:
    - name: "Paralegal Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Paralegal.pdf"
      color: "#1D4ED8"
      route_keywords: ["paralegal", "litigation", "e-discovery"]
    - name: "Legal Assistant Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Legal_Assistant.pdf"
      color: "#7E22CE"
      route_keywords: ["legal assistant", "legal secretary", "scheduling"]

# ─── Platforms ────────────────────────────────────
platforms:
  greenhouse: true
  ashby: true
  lever: true
  workable: true
  aggregators: false

  # Extra ATS domains. Sweepy labels matching postings with this name.
  custom:
    - name: "SmartRecruiters"
      domain: "smartrecruiters.com"
      enabled: true
    - name: "Breezy HR"
      domain: "breezy.hr"
      enabled: true

# ─── Sources ──────────────────────────────────────
sources:
  jobspy:
    linkedin: true
    indeed: true
    glassdoor: true
    zip_recruiter: true

  # Leave a list empty to fall back to the seed lists in data/sources/.
  ashby:
    orgs:
      - "crosby"
      - "normlaw"
      - "hargrove-firm"
      - "lawhive"
  workable:
    slugs:
      - "shegerianand-associates-1"
      - "harper-james"
      - "legalvision"
  builtinnyc:
    enabled: true
    categories:
      - "jobs/legal"
      - "jobs/legal/search/paralegal"

# ─── Cache and history ────────────────────────────
cache:
  enabled: true
  ttl_seconds: 3600       # reuse discovery results for an hour

history:
  enabled: true
  retention_days: 4       # hide a reported posting for four days
  match: "url+role"       # "url" matches only an identical posting address
  path: null              # null uses ~/.sweepy/history.db

orchestrator:
  timeout_per_source_seconds: 180
  circuit_breaker:
    failure_threshold: 5
    cooldown_seconds: 30

# ─── Report layout ────────────────────────────────
report:
  style: "cards"          # "cards" (default) or "legacy"
  cards_per_page: 6       # cards on each PDF page
  max_cards: 24           # 0 or less shows every match
  destinations: []        # extra folders for a copy of the PDF
  assessment: "agent"     # "keyword" accepts reports without agent judgments

# ─── Exports ──────────────────────────────────────
export:
  format: "pdf,csv,json"  # add "png" for page images
  output_dir: "results"
  tracking: true          # job-tracking columns in the CSV
  description_chars: 1000 # posting excerpt length in the CSV and JSON

Canales de currículum​

Un canal es un currículum con nombre. Usa canales cuando busques dos puestos o títulos distintos y quieras puntuar cada oferta con el documento correcto.

profiles/paralegal_nyc.yaml
resume:
  tracks:
    - name: "Paralegal Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Paralegal.pdf"
      color: "#1D4ED8"
      route_keywords: ["paralegal", "litigation", "e-discovery"]
    - name: "Legal Assistant Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Legal_Assistant.pdf"
      color: "#7E22CE"
      route_keywords: ["legal assistant", "legal secretary", "scheduling"]

Cada entrada usa cuatro campos:

  • name etiqueta el canal. La ficha del informe muestra esta etiqueta, así que escribe una o dos palabras.
  • path apunta al currículum en PDF o DOCX de ese canal.
  • color define el color de la insignia. Usa un código hexadecimal como #1D4ED8 o un nombre de color como navy.
  • route_keywords deciden a qué canal asigna Sweepy cada oferta.

Sweepy enruta cada oferta según el solapamiento de palabras clave. Cuenta las coincidencias de palabras completas entre el título y la descripción de la oferta y los route_keywords de cada canal. Sweepy asigna la oferta al canal con el recuento más alto. Si dos canales empatan, Sweepy usa el primero de tu lista.

consejo

Los route_keywords envían una oferta a un currículum y nunca cambian el porcentaje de compatibilidad. Añade las frases que cada familia de puestos usa realmente en sus ofertas.

Si omites tracks, Sweepy usa resume.path como un único canal implícito.

Sinónimos del currículum​

resume.synonyms contiene grupos de palabras que significan lo mismo. Sweepy trata cada palabra de un grupo como equivalente a las demás. Así, la coincidencia funciona en ambos sentidos. Consulta Incorporación de términos específicos del sector para ver la lista de comprobación de formato completa.

profiles/paralegal_nyc.yaml
resume:
  synonyms:
    - ["e-discovery", "ediscovery", "electronic discovery"]
    - ["legal research", "case law research"]
    - ["docketing", "case calendaring"]
    - ["legal assistant", "legal secretary"]
    - ["contract review", "contract analysis", "agreement review"]

Un grupo necesita al menos dos términos o Sweepy lo ignora. La coincidencia ignora las mayúsculas y admite las formas regulares en singular y plural. El motor sigue comparando frases completas, así que incluye legal research y legal researcher como términos separados si quieres que ambos cuenten.

Alex escribe e-discovery en un currículum. Una oferta que dice electronic discovery ahora coincide, porque ambos términos pertenecen al mismo grupo.

consejo

Añade un grupo cada vez que detectes la misma omisión dos veces. Copia el texto exacto de la oferta en el grupo, junto a tu propio término.

Errores de formato habituales​

La mayoría de los perfiles que fallan se deben a un par de errores habituales.

Las rutas de Windows necesitan barras inclinadas o barras invertidas dobles. YAML interpreta una barra invertida como carácter de escape. Una ruta como C:\Users\Alex rompe el archivo.

profiles/paralegal_nyc.yaml
resume:
  path: "C:/Users/Alex/Documents/Alex_Rivera_Resume.pdf"     # ✅ works
  # path: "C:\\Users\\Alex\\Documents\\Alex_Rivera_Resume.pdf"  # ✅ also works
  # path: "C:\Users\Alex\Documents\Alex_Rivera_Resume.pdf"      # ❌ breaks YAML
precaución

Una sola barra invertida suelta en una ruta impide que Sweepy lea tu perfil. El asistente de configuración escribe barras inclinadas por ti, así que copia ese estilo cuando edites a mano.

Los comentarios empiezan por #. Sweepy ignora todo lo que sigue a un # en esa línea. Usa comentarios para anotar por qué importa un valor, como hace el perfil de ejemplo.

La indentación define la estructura. Indenta cada nivel con dos espacios. Una sola tabulación en cualquier parte del archivo rompe YAML.
