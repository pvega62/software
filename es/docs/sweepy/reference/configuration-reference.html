Referencia de configuración del perfil

Esta página enumera todos los ajustes que acepta un perfil de Sweepy. Manténgala abierta mientras edita su perfil. Para una guía paso a paso, consulte Configuración de Sweepy.

Dónde se guardan los perfiles​

Sweepy lee los perfiles de la carpeta profiles/ que hay dentro de tu directorio de Sweepy. Cada perfil utiliza YAML, un formato de texto sin formato que se organiza mediante sangrías y dos puntos. Abre uno en el Bloc de notas, VS Code o cualquier editor de texto que ya tengas.

Un perfil contiene toda su configuración. Cree tantos perfiles como desee. Sweepy almacena la información adicional fuera del perfil, en la caché de descubrimiento, la base de datos de historial y las carpetas config.sample.yaml y profiles/paralegal_nyc.yaml.

Terminal
copy config.sample.yaml profiles\my_search.yaml
notepad profiles\my_search.yaml

Utilice espacios para la indentación; los tabuladores no son compatibles con este formato. Un solo tabulador puede hacer que todo el perfil sea ilegible.

Terminal
sweepy --profile profiles/my_search.yaml
nota

Un perfil contiene toda tu configuración. Puedes crear tantos perfiles como quieras: uno por ciudad o familia de roles. Sweepy almacena el estado de las búsquedas fuera del perfil, en la caché de descubrimiento, en la base de datos de historial y en las carpetas logs/ y results/.

precaución

Saca sangría con espacios, nunca con tabulaciones. YAML no admite tabulaciones, y una sola tabulación de más hace que todo el perfil sea ilegible.

Ejemplo de perfil completo​

El ejemplo a continuación muestra el perfil completo de Alex. Las líneas que comienzan con # funcionan como comentarios, y Sweepy las ignora:

profiles/paralegal_nyc.yaml
# ─────────────────────────────────────────────────
# Sweepy — Alex's Paralegal Profile (New York City)
# ─────────────────────────────────────────────────

# Your name. It appears in the PDF report header.
name: "Alex Rivera"

# Set true to write rotating debug logs under logs/.
debug: false

# ─── Job search ───────────────────────────────────
search:
  # Every title Sweepy searches at the same time.
  titles:
    - "Paralegal"
    - "Legal Assistant"
    - "Litigation Support Specialist"
    - "Legal Secretary"

  # Your target market.
  location: "New York, NY"

  # true keeps remote roles only. false keeps remote, hybrid, and on-site roles.
  remote_only: false

  # false removes hybrid roles from every report.
  include_hybrid: true

  # Annual salary floor. Use 0 to skip salary filtering.
  min_salary: 65000

  # true reads pay from the posting text when a board omits structured pay.
  salary_from_description: true

# ─── Resume ───────────────────────────────────────
resume:
  # Path to a PDF or DOCX resume. Forward slashes work on Windows.
  path: "Alex_Rivera_Resume.pdf"

  # Terms that carry the most weight when Sweepy scores a posting.
  must_have_skills:
    - "Westlaw"
    - "LexisNexis"
    - "e-discovery"
    - "Contract Review"
    - "Legal Research"

  # 1.0 is standard. Raise it to reward exact skill matches.
  keywords_weight: 1.5

  # Interchangeable terms. Sweepy matches every member of a group either way.
  synonyms:
    - ["e-discovery", "ediscovery", "electronic discovery"]
    - ["legal research", "case law research"]
    - ["docketing", "case calendaring"]
    - ["legal assistant", "legal secretary"]
    - ["contract review", "contract analysis", "agreement review"]

  # Optional: one resume per role family. Sweepy picks the best fit for each posting.
  tracks:
    - name: "Paralegal Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Paralegal.pdf"
      color: "#1D4ED8"
      route_keywords: ["paralegal", "litigation", "e-discovery"]
    - name: "Legal Assistant Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Legal_Assistant.pdf"
      color: "#7E22CE"
      route_keywords: ["legal assistant", "legal secretary", "scheduling"]

# ─── Platforms ────────────────────────────────────
platforms:
  greenhouse: true
  ashby: true
  lever: true
  workable: true
  aggregators: false

  # Extra ATS domains. Sweepy labels matching postings with this name.
  custom:
    - name: "SmartRecruiters"
      domain: "smartrecruiters.com"
      enabled: true
    - name: "Breezy HR"
      domain: "breezy.hr"
      enabled: true

# ─── Sources ──────────────────────────────────────
sources:
  jobspy:
    linkedin: true
    indeed: true
    glassdoor: true
    zip_recruiter: true

  # Leave a list empty to fall back to the seed lists in data/sources/.
  ashby:
    orgs:
      - "crosby"
      - "normlaw"
      - "hargrove-firm"
      - "lawhive"
  workable:
    slugs:
      - "shegerianand-associates-1"
      - "harper-james"
      - "legalvision"
  builtinnyc:
    enabled: true
    categories:
      - "jobs/legal"
      - "jobs/legal/search/paralegal"

# ─── Cache and history ────────────────────────────
cache:
  enabled: true
  ttl_seconds: 3600       # reuse discovery results for an hour

history:
  enabled: true
  retention_days: 4       # hide a reported posting for four days
  match: "url+role"       # "url" matches only an identical posting address
  path: null              # null uses ~/.sweepy/history.db

orchestrator:
  timeout_per_source_seconds: 180
  circuit_breaker:
    failure_threshold: 5
    cooldown_seconds: 30

# ─── Report layout ────────────────────────────────
report:
  style: "cards"          # "cards" (default) or "legacy"
  cards_per_page: 6       # cards on each PDF page
  max_cards: 24           # 0 or less shows every match
  destinations: []        # extra folders for a copy of the PDF
  assessment: "agent"     # "keyword" accepts reports without agent judgments

# ─── Exports ──────────────────────────────────────
export:
  format: "pdf,csv,json"  # add "png" for page images
  output_dir: "results"
  tracking: true          # job-tracking columns in the CSV
  description_chars: 1000 # posting excerpt length in the CSV and JSON
  timezone: "local"       # clock behind the report filename stamp

Los bloques opcionales hirehunt, openroles, jobdrop y apify también están incluidos bajo sources; la referencia de comandos enumera los parámetros que los configuran.

Perfiles de currículum​

Una «track» es un currículum con nombre. Usa las «tracks» cuando te dirijas a dos puestos o cargos diferentes y quieras que cada oferta se evalúe en función del documento adecuado.

profiles/paralegal_nyc.yaml
resume:
  tracks:
    - name: "Paralegal Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Paralegal.pdf"
      color: "#1D4ED8"
      route_keywords: ["paralegal", "litigation", "e-discovery"]
    - name: "Legal Assistant Resume"
      path: "C:/Users/Alex/Documents/Alex_Rivera_Legal_Assistant.pdf"
      color: "#7E22CE"
      route_keywords: ["legal assistant", "legal secretary", "scheduling"]

Sweepy asigna las publicaciones basándose en la coincidencia de palabras clave entre el título y la descripción de la publicación con la etiqueta de la ruta. En caso de empate, utiliza la primera ruta de la lista.

  • name sirve para identificar la pista. El informe muestra esta etiqueta; por lo tanto, escriba una o dos palabras que la describan.
  • path hace referencia al PDF del currículo de esa persona o al archivo correspondiente a la opción DOCX.
  • color establece el color del distintivo. Utilice un código hexadecimal como #1D4ED8 o un nombre de color como navy.
  • route_keywords determina qué publicaciones Sweepy asignará a esta categoría.

Sweepy analiza cada publicación en función de la coincidencia de palabras clave. Cuenta las coincidencias de palabras completas entre el título y la descripción de la publicación y los route_keywords de cada categoría. Sweepy asigna la publicación a la categoría con el mayor número de coincidencias. Cuando dos categorías empatan, Sweepy utiliza la primera de tu lista.

consejo

route_keywords Envía un currículo, y el porcentaje de coincidencia nunca cambia. Añade las frases que cada familia de roles realmente utiliza en sus anuncios de empleo.

Omite tracks y Sweepy utiliza resume.path como una pista implícita.

Sinónimos del currículum​

Los símbolos como resume.synonyms se utilizan para indicar grupos de palabras que significan lo mismo; en Sweepy, cada palabra dentro de un grupo es tratada de forma igual a las demás. Por lo tanto, la búsqueda funciona en ambos sentidos. Consulte Añadir términos específicos de la industria para obtener una lista completa de formatos a seguir.

profiles/paralegal_nyc.yaml
resume:
  synonyms:
    - ["e-discovery", "ediscovery", "electronic discovery"]
    - ["legal research", "case law research"]
    - ["docketing", "case calendaring"]
    - ["legal assistant", "legal secretary"]
    - ["contract review", "contract analysis", "agreement review"]

Un grupo debe contener al menos dos términos; de lo contrario, “Sweepy” lo ignora. El proceso de coincidencia ignora mayúsculas y minúsculas y maneja tanto las formas singulares como las plurales. El motor sigue detectando frases completas; por lo tanto, incluya a legal research y legal researcher como términos separados si desea que ambos se computen.

Alex escribe “e-discovery” en su currículo. Un anuncio que dice “electronic discovery” ahora coincide con ello, porque ambos términos pertenecen al mismo grupo.

consejo

Agrega un grupo cada vez que observes que una misma falta se repite dos veces. Copia la redacción exacta del mensaje al grupo, junto a tu propio término.

Errores comunes de formato​

La mayoría de los perfiles que no funcionan correctamente se deben a un par de errores comunes.

Las rutas de archivos en Windows requieren barras diagonales hacia adelante o dobles barras diagonales (). La notación YAML interpreta una sola barra diagonal como un carácter de escape; por lo tanto, una ruta como C:\Users\Alex puede causar problemas al intentar abrir el archivo.

profiles/paralegal_nyc.yaml
resume:
  path: "C:/Users/Alex/Documents/Alex_Rivera_Resume.pdf"     # ✅ works
  # path: "C:\\Users\\Alex\\Documents\\Alex_Rivera_Resume.pdf"  # ✅ also works
  # path: "C:\Users\Alex\Documents\Alex_Rivera_Resume.pdf"      # ❌ breaks YAML
precaución

Una barra invertida (“\”) aislada en una ruta de archivo impide que Sweepy lea tu perfil. El asistente de configuración escribe barras normales (“/”) en su lugar; por lo tanto, copia ese estilo cuando edites el archivo manualmente.

Los comentarios comienzan con #. Sweepy ignora todo lo que sigue después de # en esa línea. Utilice los comentarios para explicar por qué un valor es importante, tal como se hace en el ejemplo del perfil.

La indentación determina la estructura. Indente cada nivel con dos espacios. El uso de una tabuladora en cualquier parte del archivo rompe el formato establecido por YAML.
