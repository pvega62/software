Ingesta de eventos con la API de ingesta de registros de Datadog

Envía eventos de registro JSON directamente a Datadog Log Management con la API de ingesta de registros. Puedes enviar registros desde aplicaciones en la nube, microservicios o cualquier sistema que genere telemetría. Los registros aparecen en Log Explorer en cuestión de segundos. Usa Log Pipelines para procesarlos, enrutarlos y archivarlos.

Este punto final admite la ingesta en tiempo real y de alto rendimiento de cargas útiles JSON estructuradas y semiestructuradas.

Acciones que admite esta API​

  • Envía registros directamente desde aplicaciones en la nube sin instalar el Agente de Datadog.
  • Aplica procesadores de canalización, como Grok Parser, Remapper y Lookup Processor, a los datos entrantes.
  • Enruta los registros a índices, archivos o destinos de alertas según su contenido.
  • Reduce el coste de indexación combinando este punto final con reglas de muestreo y filtrado.
nota

Consulta Claves de API y de aplicación de Datadog para gestionar las credenciales.

Antes de empezar​

Asegúrate de tener:

  • Una clave de API de Datadog con permisos de ingesta de registros. La encontrarás en Configuración de la organización → Claves de API.

  • Tu dirección del sitio de Datadog. Esta dirección varía según la región:

    RegiónDirección del sitio
    EE. UU. Estedatadoghq.com
    US3 Oesteus3.datadoghq.com
    US5 Centralus5.datadoghq.com
    UEdatadoghq.eu
    AP1 Japónap1.datadoghq.com
    AP2 Australiaap2.datadoghq.com

  • curl o Postman instalado.

  • Cargas útiles de registro en formato JSON.

Punto final de ingesta​

POST https://http-intake.logs.{dd_site}/api/v2/logs

Sustituye {dd_site} por la dirección del sitio de tu región, por ejemplo datadoghq.com o ap2.datadoghq.com.

Encabezados de la solicitud​

EncabezadoValorObligatorioDescripción
DD-API-KEY<your_api_key>SíTu clave de API de Datadog
Content-Typeapplication/jsonSíFormato de la carga útil
Content-EncodinggzipOpcionalFormato de carga útil comprimida. Datadog lo recomienda para lotes de gran volumen.

Cuerpo de la solicitud​

El cuerpo de la solicitud es una matriz JSON con uno o varios objetos de registro. Cada objeto de registro admite los siguientes campos:

CampoTipoObligatorioDescripción
messagestringSíEl cuerpo del mensaje de registro
ddsourcestringRecomendadoEl nombre de la integración de la tecnología que genera el registro, por ejemplo python o nginx
ddtagsstringOpcionalEtiquetas separadas por comas, por ejemplo env:prod,team:payments
hostnamestringOpcionalEl nombre del host que generó el registro
servicestringRecomendadoEl nombre de la aplicación o del servicio
statusstringRecomendadoLa gravedad del evento de registro, por ejemplo info o ERROR
timestampstringOpcionalLa hora del evento, por ejemplo 2025-11-15T08:30:00Z. Consulta la nota sobre el formato de la marca de tiempo.
nota

Incluye message. Datadog usa service, ddsource y ddtags para filtrar, crear facetas y hacer coincidir canalizaciones. El resto de campos son opcionales.

Ejemplo de carga útil​

Payload: single log
[
  {
    "message": "Transaction failed: Gateway timeout",
    "ddsource": "java",
    "ddtags": "env:prod,region:us-east-1",
    "hostname": "payments-host-01",
    "service": "payment-gateway",
    "status": "ERROR",
    "timestamp": "2025-11-15T08:30:00Z",
    "transaction_id": "txn_998877",
    "customer_id": "cus_554433"
  }
]
nota

Usa el formato 8601 de la Organización Internacional de Normalización (ISO) para el Tiempo Universal Coordinado (UTC) en timestamp. Datadog alinea la línea de tiempo de los registros en Log Explorer con este valor. Los registros sin marca de tiempo usan la hora de ingesta. Datadog acepta una marca de tiempo de hasta 18 horas en el pasado.

Ejemplo con cURL​

cURL
export DD_API_KEY="your_datadog_api_key_here"
export DD_SITE="datadoghq.com"

curl -X POST "https://http-intake.logs.$DD_SITE/api/v2/logs" \
  -H "DD-API-KEY: $DD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '[
    {
      "message": "Transaction failed: Gateway timeout",
      "ddsource": "java",
      "ddtags": "env:prod,region:us-east-1",
      "hostname": "payments-host-01",
      "service": "payment-gateway",
      "status": "ERROR",
      "transaction_id": "txn_998877"
    }
  ]'

Códigos de respuesta​

CódigoEstadoDescripción
202AcceptedCarga útil aceptada y en cola para su indexación
400Bad requestError de formato o de validación
401UnauthorizedFalta el encabezado DD-API-KEY
403ForbiddenLa clave de API no es válida o no tiene permisos de ingesta de registros
408Request timeoutLa solicitud agotó el tiempo de espera. Reinténtala tras una breve pausa.
413Payload too largeLa carga útil supera los 5 MB sin comprimir
429Too many requestsEl cliente superó el límite de velocidad de ingesta
500Internal server errorDatadog encontró una condición inesperada. Reinténtala tras una breve pausa.
503Service unavailableDatadog está al límite de su capacidad. Reinténtala tras una breve pausa.

202 Accepted​

Una respuesta 202 Accepted confirma que Datadog recibió la carga útil. El cuerpo de la respuesta contiene un objeto JSON vacío. Los eventos de registro aparecen en Log Explorer en unos segundos.

Response: 202 Accepted
HTTP/1.1 202 Accepted
Content-Type: application/json
Response body: 202 Accepted
{}

400 Bad Request​

Datadog devuelve este código cuando la carga útil no supera la validación:

  • Sintaxis JSON incorrecta o caracteres sin escapar.
  • La carga útil omite el campo obligatorio message.
  • La carga útil sin comprimir supera el límite de 5 MB.
Response: 400 Bad Request
{
  "errors": [
    {
      "detail": "Invalid JSON",
      "status": "400",
      "title": "Bad Request"
    }
  ]
}

401 Unauthorized y 403 Forbidden​

Datadog devuelve 401 Unauthorized cuando falta el encabezado DD-API-KEY. Datadog devuelve 403 Forbidden cuando la clave de API no supera la validación o no tiene permisos de ingesta de registros:

Response: 403 Forbidden
{
  "errors": [
    {
      "detail": "Forbidden",
      "status": "403",
      "title": "Forbidden"
    }
  ]
}

413 Payload Too Large​

Datadog devuelve este código cuando la carga útil de la solicitud supera los 5 MB sin comprimir.

Response: 413 Payload Too Large
{
  "errors": [
    {
      "detail": "Payload too large",
      "status": "413",
      "title": "Payload Too Large"
    }
  ]
}

429 Too Many Requests​

Enviaste demasiadas solicitudes. Envía menos o agrupa los objetos de registro en una carga útil de tipo matriz.

Otros errores reintentables​

Datadog también devuelve 408 Request Timeout, 500 Internal Server Error y 503 Service Unavailable en fallos transitorios. Reintenta la solicitud con retroceso exponencial. Envía lotes más pequeños si 408 Request Timeout persiste.

Agrupación de eventos de registro​

Envía hasta 1.000 entradas de registro en una solicitud pasando una matriz. Datadog lo recomienda para servicios de gran volumen.

Payload: batched logs
[
  {
    "message": "User login succeeded",
    "service": "auth-service",
    "ddsource": "python",
    "ddtags": "env:prod",
    "status": "INFO"
  },
  {
    "message": "Transaction failed: Gateway timeout",
    "service": "payment-gateway",
    "ddsource": "python",
    "ddtags": "env:prod",
    "status": "ERROR",
    "transaction_id": "txn_998877"
  }
]

Límites:

  • Tamaño de la carga útil: 5 MB sin comprimir
  • Tamaño de cada registro: 1 MB
  • Entradas de la matriz: 1.000 objetos de registro

Casos de uso habituales​

  • Ingesta de registros desde microservicios sin desplegar el Agente de Datadog.
  • Envío de eventos JSON estructurados desde funciones sin servidor, como Amazon Web Services (AWS) Lambda o Google Cloud Run.
  • Transmisión de telemetría desde dispositivos IoT o servicios de borde.
  • Enrutamiento de eventos enriquecidos a sistemas de gestión de eventos e información de seguridad (SIEM), S3 o destinos de alertas mediante Log Pipelines.
  • Envío de registros desde canalizaciones de integración y entrega continuas (CI/CD) o scripts de despliegue.

Solución de problemas​

ProblemaCausa probableSolución
401 UnauthorizedClave de API incorrecta o ausenteVerifica DD_API_KEY en Configuración de la organización → Claves de API
400 Bad RequestJSON mal formadoCompruébalo con jq . payload.json antes de enviar
Registro ausente en ExplorerFiltro de canalización que excluye el registroBorra los filtros. Después, revisa las reglas de enrutamiento de índices.
Marca de tiempo fuera de ordenFormato distinto de UTC o ISO 8601, o anterior a 18 horasUsa el formato "2025-11-15T08:30:00Z". Envía los registros dentro de las 18 horas posteriores al evento.
429 Too Many RequestsLímite de velocidad superadoAgrupa los objetos de registro en una carga útil de tipo matriz
