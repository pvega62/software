Retenciones y concurrencia

Blüdhaven Pets coordina las adopciones de animales de compañía a través de tres sucursales físicas y un portal público en línea. Un asesor en tienda y un solicitante en línea pueden solicitar el mismo animal al mismo tiempo. La API aplica bloqueos de reserva atómicos para evitar dobles reservas.”

Cómo funcionan las retenciones de 30 minutos​

Cuando un solicitante inicia una entrevista o comienza el proceso de pago en línea, la aplicación de su cliente debe solicitar una retención temporal de los datos del solicitante.

[Available Animal] ──► POST /adoptions/holds ──► [30-Minute Hold Granted]
                             │
                             ▼ (Second concurrent request)
                    [HTTP 409 Conflict]
  1. Verificación del estado: La API confirma que el animal almacena el valor status: "AVAILABLE" y lee el valor true desde la fuente health_record.spay_neuter_certified.
  2. Creación de un candado: La API escribe un registro con el código AdoptionHold y establece el estado del animal en RESERVED_HOLD.
  3. Vencimiento TTL. El servidor asigna una marca de tiempo de vencimiento inmutable exactamente 1800 segundos después de la creación.
  4. Resolución.
    • Si el solicitante completa los documentos y paga las tasas de adopción, el personal presenta la solicitud y el estado del proceso pasa a CONVERTED.
    • Si transcurren 30 minutos sin que se complete el proceso, un sistema automático marca la posición EXPIRED como “en espera” y devuelve el animal a la posición AVAILABLE.

Retener una reserva​

Envía una solicitud POST a /adoptions/holds junto con los identificadores del animal y del solicitante.

cURL
curl -X POST https://api.bludhavenpets.com/v1/adoptions/holds \
  -H "Authorization: Bearer <STAFF_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "animal_id": "pet_krypto_210",
    "applicant_id": "usr_9921bc",
    "notes": "In-person consultation at the Downtown adoption floor"
  }'

Respuesta exitosa​

201 Created

Response
{
  "id": "hld_77a28f",
  "animal_id": "pet_krypto_210",
  "applicant_id": "usr_9921bc",
  "branch_id": "loc_harbor_04",
  "status": "ACTIVE",
  "created_at": "2026-11-17T07:45:00Z",
  "expires_at": "2026-11-17T08:15:00Z",
  "seconds_remaining": 1782
}

Gestionar conflictos de tipo 409​

Cuando otro miembro del personal o un solicitante en línea reclama un animal en primer lugar, el punto final devuelve el valor HTTP 409 Conflict utilizando el estándar RFC 9457 ProblemDetails.

409 Conflict Response
{
  "type": "https://api.bludhavenpets.com/errors/adoption-hold-conflict",
  "title": "Adoption Hold Conflict",
  "status": 409,
  "detail": "Animal pet_krypto_210 is currently reserved under active hold hld_77a28f expiring at 2026-11-17T08:15:00Z.",
  "instance": "/adoptions/holds"
}

Liberar una reserva anticipadamente​

Un asesor libera el animal en cuanto la entrevista falla o el solicitante abandona el proceso. De lo contrario, el animal permanece “invisible” para otros adoptantes durante el resto del tiempo estipulado.

cURL
curl -X DELETE https://api.bludhavenpets.com/v1/adoptions/holds/hld_77a28f \
  -H "Authorization: Bearer <STAFF_TOKEN>"

204 No Content confirma la liberación, y el animal regresa inmediatamente a AVAILABLE. Una reserva que ya se ha convertido en una solicitud oficial vuelve a ser tratada como tal (se envía un mensaje 409), ya que una liberación no puede anular una solicitud presentada previamente.

Flujo recomendado para el cliente​

  1. Analiza el mensaje detail o examina el perfil del animal objetivo.
  2. Comprobar el estado de la posición expires_at en la lista de animales en espera activa.
  3. Si el cliente desea esperar, pídele que se una a una cola de notificaciones que le avisará cuando la reserva activa expire sin que se produzca ninguna conversión (es decir, sin que se realice ninguna transacción).
  4. Ofrezca animales de compañía alternativos que coincidan con la misma especie y perfil de temperamento del animal solicitado.
