Firmas y verificación de webhooks

La plataforma Blüdhaven Pets envía webhooks asincrónicos cuando ocurren eventos del ciclo de vida de los animales fuera de un ciclo de solicitud directo desde HTTP.

Dos eventos enviados hoy:

EventoSe activa cuandoEl contenido del “payload” es destacado
adoption.hold.expiredUna reserva se cancela automáticamente después de 30 minutos sin que se realice ninguna acciónhold_id, animal_id, reason
veterinary.clearance.filedUn veterinario municipal emite un certificado, lo que hace que el animal sea elegible para adopciónanimal_id, certificate_number, status

Cada entrega se realiza mediante un formato específico, con un contenido (JSON) y una firma (HMAC–SHA256) incluidas en el encabezado (X-Bludhaven-Signature).

¿Por qué verificar las firmas?​

Un punto final de webhook público acepta tráfico proveniente de internet (representado por HTTP). Este tráfico no se verifica criptográficamente.

  • Un atacante puede falsificar un evento de tipo adoption.hold.expired para liberar a los animales de manera prematura.
  • Un atacante puede inyectar un evento falso (veterinary.clearance.filed) para evitar la cuarentena obligatoria contra la rabia.
  • Un atacante puede reproducir un payload válido anterior para causar un procesamiento duplicado.

La verificación de la firma demuestra que Blüdhaven Pets es el autor de los datos enviados y que el contenido es fresco.

Formato del encabezado de la firma​

El encabezado X-Bludhaven-Signature contiene una marca de tiempo UNIX y un resumen hexadecimal de los datos contenidos entre HMAC y SHA256.

X-Bludhaven-Signature: t=1795123456,v1=5d41402abc4b2a76b9719d911017c5926c459992f026a0b72a6a8b1a7f05252b
  • t: La marca de tiempo de la era UNIX, en segundos, cuando el gateway firmó la entrega.
  • v1: El resumen hexadecimal en minúsculas generado a partir de los datos contenidos en t={timestamp},v1={raw_body}, utilizando tu secreto de firma de webhook.

Comprobar la firma en Node.js​

La verificación requiere el cuerpo de solicitud en texto sin formato exacto antes del análisis por parte de JSON. Un analizador puede modificar los espacios en blanco y el orden de los campos, lo que afecta negativamente la validación criptográfica.

verify-webhook.mjs
import crypto from 'node:crypto';

export function verifyWebhookSignature({ rawBody, signatureHeader, secret, toleranceSeconds = 300 }) {
  if (!signatureHeader) {
    throw new Error('Missing X-Bludhaven-Signature header');
  }

  // 1. Extract timestamp and signature from the header
  const elements = Object.fromEntries(
    signatureHeader.split(',').map((pair) => pair.split('='))
  );

  const timestamp = parseInt(elements.t, 10);
  const expectedSignature = elements.v1;

  if (isNaN(timestamp) || !expectedSignature) {
    throw new Error('Malformed X-Bludhaven-Signature header');
  }

  // 2. Reject replays outside tolerance window (default 5 minutes)
  const currentTime = Math.floor(Date.now() / 1000);
  if (Math.abs(currentTime - timestamp) > toleranceSeconds) {
    throw new Error('Webhook timestamp falls outside tolerance window');
  }

  // 3. Recreate the signed string: t={timestamp},v1={raw_body}
  const signedPayload = `t=${timestamp},v1=${rawBody}`;

  // 4. Compute expected HMAC-SHA256
  const computedSignature = crypto
    .createHmac('sha256', secret)
    .update(signedPayload, 'utf8')
    .digest('hex');

  // 5. Compare in constant time to prevent timing attacks. A digest of the
  // wrong length makes timingSafeEqual throw RangeError, so check the length.
  const computed = Buffer.from(computedSignature, 'hex');
  const expected = Buffer.from(expectedSignature, 'hex');
  const valid =
    computed.length === expected.length &&
    crypto.timingSafeEqual(computed, expected);

  if (!valid) {
    throw new Error('Invalid webhook signature');
  }

  return JSON.parse(rawBody);
}

Verificar la firma en Python​

verify_webhook.py
import hmac
import hashlib
import time
import json

def verify_webhook(raw_bytes: bytes, sig_header: str, secret: str, tolerance: int = 300) -> dict:
    parts = dict(item.split("=", 1) for item in sig_header.split(","))
    timestamp = int(parts.get("t", 0))
    expected_hex = parts.get("v1", "")

    if abs(time.time() - timestamp) > tolerance:
        raise ValueError("Timestamp outside acceptable replay window")

    signed_data = f"t={timestamp},v1=".encode("utf-8") + raw_bytes
    computed_hex = hmac.new(secret.encode("utf-8"), signed_data, hashlib.sha256).hexdigest()

    if not hmac.compare_digest(computed_hex, expected_hex):
        raise ValueError("Signature mismatch")

    return json.loads(raw_bytes.decode("utf-8"))

Proceso de envío de pruebas en el entorno de prueba​

La puerta de enlace del entorno de pruebas (sandbox) proporciona un punto final de envío para pruebas. Este punto final firma el contenido del mensaje y devuelve los encabezados (headers) correspondientes. Dirija su receptor hacia este punto final para probar el manejo de las firmas sin tener que esperar a ningún evento en segundo plano.

La consola de referencia lista la misma llamada bajo Webhooks. Seleccione el servidor Browser demo y envíela allí. La demostración se firma en el momento de la solicitud con la clave secreta publicada; por lo tanto, el encabezado que copia de la consola debe coincidir con whsec_sandbox_bludhaven_test_secret_9981. Un archivo de prueba almacenado contendría una marca de tiempo obsoleta y un resumen (digest) incorrecto.

curl -X POST https://sandbox.bludhaven-pets.workers.dev/webhooks/test-dispatch \
  -H "Content-Type: application/json" \
  -o webhook-dispatch.json

No envíe ningún cuerpo de datos; el gateway firmará todo el contenido del payload. Envíe {"event": "veterinary.clearance.filed"} y ese objeto se convertirá en el payload.

webhook-dispatch.json
{
  "dispatched": true,
  "event": "adoption.hold.expired",
  "secret_used": "whsec_sandbox_bludhaven_test_secret_9981",
  "headers": {
    "Content-Type": "application/json",
    "X-Bludhaven-Signature": "t=1795123456,v1=5d41402abc4b...",
    "X-Bludhaven-Timestamp": "1795123456"
  },
  "payload": {
    "id": "evt_wh_901ab2cd",
    "event": "adoption.hold.expired",
    "created_at": "2026-11-19T13:30:00Z",
    "data": {
      "hold_id": "hld_a8f90b",
      "animal_id": "pet_krypto_210",
      "reason": "30_MINUTE_WINDOW_LAPSED"
    }
  },
  "verification_guide": {
    "scheme": "HMAC-SHA256",
    "signed_template": "t={timestamp},v1={raw_body}",
    "header_format": "t={timestamp},v1={hex_signature}"
  }
}

La respuesta incluye la clave secreta utilizada para la firma, la firma calculada y el propio payload. Compruebe estos datos con el verificador ubicado en el repositorio del sandbox worker.

node scripts/verify-webhook.mjs webhook-dispatch.json
Output
event             adoption.hold.expired
secret            whsec_sandbox_bludhaven_test_secret_9981
signature header  t=1795123456,v1=5d41402a...
computed header   t=1795123456,v1=5d41402a...
signature match   YES
delivery age      2s (tolerance 300s): fresh

PASS: HMAC-SHA256 signature verified.

El verificador lee la respuesta del archivo y recalcula el resumen. Nunca pases el contenido del payload a través de una variable de shell o una cadena de texto tipo node -e; de lo contrario, los caracteres anidados se considerarán inválidos y el resultado será ReferenceError en lugar de un veredicto correcto.

Cambie un carácter del contenido del “payload” (carga útil) y el verificador saldrá de estado 1 y pasará a FAIL: signature does not match.

El verificador también rechazará las solicitudes que sean más antiguas de 300 segundos; en este caso, la ventana de reproducción de pruebas se cerrará. Envíe --ignore-age al reproducir un archivo de prueba archivado.
